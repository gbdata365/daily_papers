OpenMobile-2: Building Versatile Mobile Agents with Scalable Environments and App-Native Tools

오픈모바일-2: 확장 가능한 환경과 앱 네이티브 도구로 만드는 범용 모바일 에이전트

상업용 앱을 충실히 재현한 대규모 모바일 시뮬레이션 환경과 약 12K개의 학습 궤적, 2K개 이상의 검증 가능한 강화학습 과제, 그리고 GUI 조작과 앱 네이티브 툴 호출을 혼합하는 하이브리드 인터페이스를 모두 공개하여, 오픈소스만으로도 프런티어급에 근접한 모바일 에이전트 OpenMobile-2를 학습시킨 연구다.

한 줄 요약

상업용 앱을 충실히 재현한 대규모 모바일 시뮬레이션 환경과 약 12K개의 학습 궤적, 2K개 이상의 검증 가능한 강화학습 과제, 그리고 GUI 조작과 앱 네이티브 툴 호출을 혼합하는 하이브리드 인터페이스를 모두 공개하여, 오픈소스만으로도 프런티어급에 근접한 모바일 에이전트 OpenMobile-2를 학습시킨 연구다.

배경 및 문제의식

비전-언어 모델 기반 모바일 에이전트는 다양한 앱과 작업에 걸친 대규모 상호작용 경험을 필요로 하지만, 이러한 데이터는 상업적으로 민감해 공개되기 어렵고 오픈 커뮤니티의 학습 자원은 상대적으로 빈약하다. 실제 Android 기기나 에뮬레이터에서 상용 앱을 그대로 사용하면 로그인 절차, 되돌릴 수 없는 부작용, 비싼 리셋 비용 때문에 대규모 학습이 사실상 불가능하고, 기존의 시뮬레이션 기반 환경들은 앱 수와 상호작용 깊이가 얕아 확장성 있는 레시피가 없었다. 또한 GUI만을 사용하는 상호작용은 범용적이지만 비효율적인 반면, 최근 컴퓨터 사용 에이전트 분야에서는 구조화된 함수 호출(API/MCP 등)을 함께 쓰는 하이브리드 방식이 주목받고 있으나 모바일 영역에서는 이를 체계적으로 다룬 연구가 부족했다.

핵심 기여

논문은 크게 세 가지 축의 기여를 제시한다. 첫째, MobileGym을 확장한 MobileGym++ 환경으로, 35개의 고충실도 상업 스타일 앱(여행, 쇼핑, 금융, 콘텐츠, 소셜, 오피스, 로컬 서비스 등)을 새로 구현하고 기존 Android 에뮬레이터 앱들과 합쳐 110개 이상의 앱으로 구성된 플레이그라운드를 구축했으며, 모든 앱은 완전한 리셋·검증 가능성을 유지한다. 둘째, OpenMobile-Data-v2라는 약 11.6K개의 시연 궤적과 2K개 이상의 검증 가능한 RL 과제로 이루어진 대규모 오픈 학습 데이터를 공개했다. 셋째, 앱이 GUI와 함께 자체적인 "앱 네이티브 툴"(구조화된 함수 호출)을 노출하여 에이전트가 한 작업 내에서 GUI 동작과 툴 호출을 섞어 쓸 수 있는 하이브리드 상호작용 방식을 50개 이상의 앱, 300개 이상의 툴로 구현했다. 이와 함께 GUI 전용/하이브리드 평가를 같은 과제 세트에서 비교할 수 있는 MobileGym++ Bench(215개 과제)도 함께 제시한다.

방법론

MobileGym++의 35개 앱은 실제 상업 앱의 데이터 스키마와 상호작용 그래프를 먼저 설계한 뒤 인터페이스를 구현하는 방식으로 제작되었으며, 사람 주석자가 실제 앱과 반복 비교하며 기능·시각적 충실도를 맞추고, 각 상호작용이 선언된 상태 변화를 실제로 일으키는지 커버리지 체크와 리플레이로 검증했다. 각 앱은 지속되는 비즈니스 상태(주문, 예산, 일정 등)를 유지하며 전체 기기 상태를 직렬화·복원할 수 있어 깨끗한 리셋과 병렬화가 가능하다. 하이브리드 툴은 각 앱의 비즈니스 객체에 대한 구조화된 조회/기록 연산으로 설계되어 GUI 조작과 동일한 상태를 변경하고 동일한 종료 조건으로 평가되므로, 같은 과제를 GUI로만 풀 수도, 툴을 섞어 풀 수도 있다. 데이터 구축 파이프라인은 각 앱에 대해 상태-행동 전이 그래프를 만들고(에뮬레이터 앱은 직접 탐색, MobileGym++ 앱은 백엔드 명세에서 도출), Gemini-3.1-Pro-Preview가 사용자 지시문을 생성한 뒤 같은 모델을 교사 에이전트로 삼아 각 과제를 직접 실행해 성공한 궤적만 필터링해 수집한다. 완료 여부는 에뮬레이터 앱에서는 비전-언어 판정기로, MobileGym++에서는 프로그램적 검증기로 판단한다. 학습은 기반 모델(Qwen3.5-9B, Qwen3.6-27B)에서 GUI 전용 SFT와 하이브리드(GUI+툴) SFT 두 가지를 각각 수행한 뒤, 하이브리드 SFT 체크포인트에서 GRPO 계열의 DAPO 목적함수로 RL을 추가로 학습시키는 구조다.

실험 설정 및 결과

AndroidWorld, MobileWorld, MobileGym, MobileGym++ Bench, 그리고 실제 기기 평가인 SPA-Bench까지 총 5개 벤치마크에서 평가했다. OpenMobile-Data-v2로 학습한 모델은 기반 모델 대비 일관되게 성능이 향상되었으며, 9B 모델은 AndroidWorld에서 54.3에서 74.0으로, 27B 모델은 67.1에서 79.9로 크게 개선되었다(MobileWorld 50.4, AndroidWorld 79.9 기록). 하이브리드 SFT는 GUI 전용 SFT 대비 MobileGym++ 하이브리드 평가에서 추가적인 성능 향상을 보였고(9B: 41.9→44.7, 27B: 57.7→65.6), MobileWorld의 미관측 툴에 대해서도 일반화된 툴 사용 능력을 보여 하이브리드 학습이 특정 API 암기가 아닌 일반적 툴 사용 전략을 학습시킴을 시사했다. RL은 학습 환경과 정합성이 높은 MobileGym에서는 성능을 더 끌어올렸지만(9B 35.9→38.3, 27B 48.4→51.2) 다른 벤치마크에서는 이득이 제한적이었다. 실제 기기 평가인 SPA-Bench에서는 하이브리드 SFT만으로도 기반 모델 대비 큰 향상을 보였고(9B 25.5→48.9, 27B 31.9→57.4), RL 적용 시 27B 모델은 59.6까지 추가 상승해 오픈 가중치 모델 중 선두권 성능을 기록했다. 추가 분석에서는 학습 데이터에 포함되는 앱 종류(coverage)가 늘어날수록 미지의 앱에 대한 전이 성능이 향상되었고, 툴을 제공하는 것만으로는 효과가 제한적이며 하이브리드 학습이 병행되어야 툴 사용이 실제로 유용해짐을 보였다.

한계점

논문 본문에는 별도의 "한계점" 절이 명시되어 있지 않다(논문에 명시되지 않음). 다만 저자들이 본문에서 언급한 제약으로는, 하이브리드 GUI·툴 상호작용을 "실험적(experimental)" 설정으로 소개하고 있다는 점, RL을 통한 성능 향상이 학습 환경과 정합성이 높은 벤치마크(MobileGym)에서는 뚜렷하지만 다른 벤치마크에서는 이득이 제한적이라는 점, 그리고 시뮬레이션 앱이 실제 화면 픽셀만을 관찰 대상으로 하고 접근성 트리(accessibility tree)를 제공하지 않는다는 설계상 제약이 있다.

시사점

이 연구는 상업용 앱의 민감성과 실제 기기 환경의 비용 문제로 막혀 있던 모바일 에이전트 학습 데이터의 "오픈화"를 환경·데이터·학습 레시피까지 통째로 공개함으로써 돌파하려는 시도로, 이후 오픈소스 모바일 에이전트 연구의 재현 가능한 기준점 역할을 할 수 있다. 또한 GUI와 앱 네이티브 툴을 같은 상태 위에서 상호 전환 가능하게 설계한 하이브리드 인터페이스는, 컴퓨터 사용 에이전트 전반에서 논의되는 "언제 GUI를 쓰고 언제 구조화된 호출을 쓸지"의 문제를 모바일 도메인에 구체적으로 적용한 사례로서, 향후 앱 개발자들이 에이전트 친화적인 네이티브 API를 노출하는 방향에도 시사점을 준다.
