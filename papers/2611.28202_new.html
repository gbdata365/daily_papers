AutoPILOT: A Visual Agent Harness for Real-Time Gameplay

AutoPILOT: 실시간 게임플레이를 위한 비주얼 에이전트 하네스

한 줄 요약

멀티모달 모델 호출 1회가 단일 행동이 아니라 매크로(open-loop)나 모델이 직접 작성한 파이썬 컨트롤러(closed-loop)로 다수의 행동을 커버할 수 있게 하는 비주얼 에이전트 하네스 AutoPILOT을 제안해, 멈추지 않고 진행되는 실시간 게임에서 기존 하네스 대비 성공률을 거의 두 배로 끌어올린다.

배경 및 문제의식

멀티모달 파운데이션 모델은 게임이 자신을 기다려 줄 때는 잘 플레이하지만, 게임 시계가 멈추지 않고 흘러가면 성능이 크게 떨어진다. 저자들은 그 원인이 "모델이 무엇을 보고 기억하는가"를 개선해 온 기존 하네스(예: VISTA)가 아니라, "모델의 출력이 시간에 따라 어떻게 행동으로 바뀌는가"에 있다고 본다: 표준 ReAct류 단일-스텝 루프는 모델 호출 1회당 행동 1개만 내보내므로, 에이전트는 모델이 생각하는 속도로만 행동할 수 있고 그 행동은 이미 지난(stale) 화면 정보에 기반한다. 실제로 게임 시계를 멈추지 않으면 VISTA의 GameWorld 성공률은 84.1%에서 42.9%로 추락하며, 시각 메모리·검사 도구를 갖춘 VISTA도 실시간에서는 평범한 Codex 하네스와 별 차이가 없고(38.3% vs 38.9%), 추론 노력을 높여도 개선은 미미하다(4~7점).

핵심 기여

  • 시간에 따른 행동 변환을 하네스 설계 요소로 규정: 모델 출력이 시간이 지나며 행동으로 바뀌는 방식을 명시적 설계 축으로 다루고, 모델 호출 1회가 원시 행동, 오픈루프 매크로, 모델이 실행 시점에 작성하는 클로즈드루프 파이썬 컨트롤러 중 하나를 시작할 수 있는 AutoPILOT을 제안.
  • AFK-Bench 구축: 비활동(inaction)에 대한 반응 방식(적대적 실시간/온건한 실시간/턴 기반)으로 3분류된 120개 브라우저 게임 벤치마크를 구축, 실시간과 일시정지 두 가지 시계 프로토콜로 플레이 가능하게 설계.
  • 성능 및 비용 우위 입증: GPT-6.1 Sol 기준 AFK-Bench 실시간 성공률 68.6%(VISTA 38.3%), GameWorld에서 80.0%(VISTA 42.9%)를 달성하며, 토큰 사용량 47% 감소 및 VISTA의 최종 성공률을 1/5 비용으로 재현.
  • 세밀한 원인 분석: 재시도 회복력, 호출 예산, 생성 속도, 추론 노력에 따른 성능 변화와 각 구성요소(매크로·컨트롤러)의 기여도를 ablation으로 분리 분석.

방법론

AutoPILOT은 VISTA(Codex 하네스 기반)를 확장하여, 매 모델 호출 시 세 가지 실행 모드 중 하나를 선택하게 한다: (1) act: 모델이 직접 하나의 행동(키보드/마우스 이벤트 또는 대기)을 보냄, (2) run_macro: 모델이 작성한 행동 시퀀스를 워커가 화면을 보지 않고 그대로 전송, (3) python 컨트롤러: 모델이 실행 시점에 짧은 파이썬 함수 run(api)를 작성하면, 샌드박스(CPU 1개, 메모리 1GB, 네트워크 차단) 안에서 워커가 이를 최대 120초간 실행하며 약 0.4초마다 화면을 읽고(api.observe()) 행동(api.act())을 보내 추가 모델 호출 없이 플레이를 지속한다. 컨트롤러나 매크로가 실행되는 동안 모델의 호출은 블로킹되고, 제어권은 여섯 가지 "각성 이벤트(wake event)" 중 하나가 발생할 때 모델로 반환된다: 핸드오프 요청, 정상 종료/에러, 매크로 완료, 결정 화면 도달, 화면 급변(scene change), 타임아웃(120초). 게임 재시작은 매크로는 즉시 멈추고 모델을 깨우지만, 컨트롤러는 멈추지 않고 재시작된 상태에서도 계속 플레이할 수 있다. 이 구조는 모델이 호출당 담당하는 환경 스텝 수를 스스로 선택하게 하여, 호출-응답 지연(latency) 문제와 모델 호출 예산 낭비 문제를 동시에 줄인다.

실험 설정 및 결과

AFK-Bench(120개 브라우저 게임, 적대적 실시간/온건한 실시간/턴 기반 각 40개, 실시간·일시정지 두 프로토콜)와 외부 벤치마크 GameWorld(170개 과제)에서 평가했다. 예산은 모델 호출 100회, 환경 스텝 2000회, 게임 시간 2000초로 제한. 비교 대상은 VISTA, 순수 Codex/Claude Code 하네스, no-op/랜덤 정책이며, GPT-6.1 Sol과 Claude Opus 5.5를 주 모델로, DeepSeek-V4.1-Flash·Qwen4-Max·GLM-5.3-Flash·Hy4-flash를 추가 모델로 사용했다. 주요 결과: 실시간에서 AutoPILOT은 GPT-6.1 Sol 기준 AFK-Bench 전체 성공률 68.6%(VISTA 38.3%, Codex 38.9%), 적대적 실시간 환경에서는 62.5%(VISTA 16.7%)로 특히 격차가 크다. 일시정지 상태에서도 AutoPILOT이 VISTA를 17.0~21.7점 앞서, 단순 지연(latency) 문제 해소를 넘어 "모델 호출당 전체 계획 실행"이 주는 이득이 핵심임을 보였다. Ablation에서 컨트롤러 제거 시 적대적 실시간 성공률이 62.5%→50.8%로, 매크로 제거 시 턴 기반에서 하락이 두드러졌고 둘 다 제거하면 45.8%로 급락했다. 실패 후 재시도 회복력에서도 AutoPILOT은 20회 재시도까지 꾸준히 상승(54.2%)하는 반면 VISTA는 7회 전후로 성능이 정체(15.8%)된다. 예산을 늘려도(모델 호출 3배) VISTA는 55.0%에 머무르고 비용이 6배(에피소드당 $5.28) 증가하는 반면, AutoPILOT은 표준 예산에서 69.2%를 기록하며 VISTA의 최종 성공률을 1/5 비용(GPT-6.1 Sol 기준 $37 vs $180)으로 재현한다. GameWorld에서도 실시간 전환 시 VISTA는 41.2점 하락하지만 AutoPILOT은 2.9점만 하락해 다른 게임 집합에도 견고함이 일반화됨을 보였다.

한계점

논문에 명시된 명시적 한계 섹션은 없으나, 본문에서 드러나는 제약으로는: 평가가 전적으로 스크린 기반·학습 없는(training-free) 설정에 한정되어 텍스트 상태를 읽거나 사전 학습이 필요한 방법들과 직접 비교가 어려움; 컨트롤러는 1 CPU·1GB 메모리·네트워크 차단 샌드박스에서만 실행되어 더 복잡한 연산이 필요한 게임에는 제약이 있을 수 있음; 평가 대상 게임이 모두 브라우저 기반이며 GameWorld를 제외하면 모두 자체 수집한 벤치마크(AFK-Bench)에 의존함.

시사점

이 연구는 "모델이 무엇을 보고 기억하는가"뿐 아니라 "모델 출력이 시간에 따라 어떻게 행동으로 번역되는가" 역시 에이전트 하네스 설계의 핵심 축임을 실증적으로 보여준다. 모델이 직접 작성하는 클로즈드루프 컨트롤러를 통해 지각(screen reading)까지 포함한 반응형 실행을 위임하는 설계는, 실시간으로 진행되는 게임뿐 아니라 실시간 웹 인터페이스 제어나 로봇 조작 등 "기다려주지 않는 세계"에서 동작해야 하는 다른 에이전트 응용에도 일반적으로 적용 가능한 설계 원칙을 제시한다.
