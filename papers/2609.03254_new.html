What Else Needs Fixing? Exploring Cost-Effective Test-Time Compute for Revision Propagation in Artifacts Generated Through Conversation

대화를 통해 생성된 아티팩트의 수정 전파를 위한 비용 효율적 테스트타임 컴퓨트 탐구

대화를 통해 만들어진 JSON 아티팩트(여행 일정, 인보이스 등)를 한 부분만 수정해 달라고 요청했을 때 LLM이 그 수정과 연쇄적으로 관련된 다른 부분까지 빠짐없이 반영하는지를 측정하는 새 벤치마크 RevPropBench를 제안하고, 비용 대비 효과가 가장 좋은 테스트타임 컴퓤트(test-time compute) 기법을 실험적으로 찾아낸 논문이다.

한 줄 요약

대화를 통해 만들어진 JSON 아티팩트(여행 일정, 인보이스 등)를 한 부분만 수정해 달라고 요청했을 때 LLM이 그 수정과 연쇄적으로 관련된 다른 부분까지 빠짐없이 반영하는지를 측정하는 새 벤치마크 RevPropBench를 제안하고, 비용 대비 효과가 가장 좋은 테스트타임 컴퓤트(test-time compute) 기법을 실험적으로 찾아낸 논문이다.

배경 및 문제의식

LLM과의 대화를 통해 문서, 코드, 계획 같은 결과물(artifact)을 생성하고 다듬는 과정에서, 사용자는 흔히 "B 목적지를 빼줘"처럼 국소적인 수정만 요청한다. 이때 예산이나 일정처럼 그 항목에 의존하던 다른 값들도 함께 갱신되어야 하는데, 사용자가 이를 일일이 지적하기는 번거롭다. 기존 연구들(리포지토리 수준 코드 편집, 지식 편집, 문서 편집)은 호출 그래프·지식 그래프·문서 구조처럼 의존관계가 명시적이거나 정적으로 분석 가능한 상황을 다뤄왔다. 반면 대화로 생성된 아티팩트에서는 항목 간 의존관계가 아티팩트 자체가 아니라 그것을 만들어낸 대화 기록 속에 암묵적으로만 존재하는 경우가 많다는 점에서, 이 논문은 아직 다뤄지지 않은 실용적 설정을 겨냥한다.

핵심 기여

  • 대화를 통해 생성된 JSON 아티팩트에서 LLM의 수정 전파(revision propagation) 능력을 평가하는 새로운 벤치마크 RevPropBench를 제안했다.
  • 9종의 수정 방법(단일 추론 기반선, 순차적 반성(reflection), 병렬 샘플링 기반 여러 변형)을 6종의 LLM에 대해 종합적으로 평가하여 비용 효율적인 방법 선택에 대한 실용적 지침을 제공했다.
  • 벤치마크 인스턴스, 데이터 샘플링·주석 도구를 공개하여 재현성과 향후 확장을 지원한다.

방법론

RevPropBench는 생성 단계와 수정 단계로 구성된다. 생성 단계에서는 LLM이 사용자와 여러 턴의 대화를 통해 JSON 아티팩트에 항목을 점진적으로 추가한다. 수정 단계에서는 사용자가 국소적인 수정 요청을 하고, LLM은 RFC 6902 JSON 패치 형태로 필요한 모든 항목을 갱신해야 한다. 평가는 생성된 패치가 정답 패치(gold patch)와 경로·값 모두 정확히 일치하는지를 기준으로 한다.

데이터는 GPT-5.5 같은 강력한 LLM으로 시나리오를 브레인스토밍하여 합성 대화와 수정 요청을 생성하고, Claude-Opus-4.8이 임시 정답 패치를 만든 뒤 사람 주석자가 전용 GUI 도구로 검토·수정하는 방식(LLM 보조 인간 주석)으로 구축되었다. 벤치마크는 여행 일정, 인보이스, 장바구니, 프로젝트 일정, 강의 계획, 데이터 파이프라인, 소프트웨어 배포 설정, 조직 접근 계획, 제조 자재명세서(BOM) 등 9개 도메인에 걸친 50개 시나리오로 구성되며, 각 시나리오마다 항목 수가 10/50/100개인 아티팩트를 각각 만들어 총 150개 샘플(개발용 30개, 테스트용 120개)을 확보했다. 수정 패턴은 산술 재계산, 시간 이동, 참조 치환, 임계값 게이팅, 구조적 추가/삭제, 상태 전파의 6가지로 분류된다.

평가 대상 방법은 (1) 최종 아티팩트(J), 대화 기록(H), 또는 둘 다(J+H)를 컨텍스트로 주는 단일 추론 기반선, (2) J+H에서 생성한 패치를 반복적으로 개선하는 순차적 반성(REFLECT), (3) 여러 패치를 병렬 생성한 뒤 규칙 기반으로 합치는 방법(OR·AND·MAJ, 최소 베이즈 위험 디코딩에서 착안한 medoid 선택 MED), (4) 여러 후보 중 LLM 스스로 하나를 고르는 LLM 기반 선택(SELECT)이다. gpt-oss-20b/120b, gpt-5.4-mini, qwen3.5-9b/27b/122b 총 6개 모델에 대해 5개의 서로 다른 시드로 반복 평가했다.

실험 설정 및 결과

모든 모델에서 기반선 성능은 일관되게 J < H < J+H 순서를 보여, 대화 기록이 아티팩트만으로는 알 수 없는 의존관계 정보를 담고 있음을 시사했다. J+H 기반선의 완료율(completion rate)은 모델에 따라 68.3%에서 93.0%까지 폭넓게 분포했고, 대체로 모델 규모가 클수록 성능이 높았다.

테스트타임 컴퓤트 방법 중에서는 SELECT가 J+H 대비 가장 일관된 개선(+3.3~12.5%)을 보였고, MED가 그다음으로 일관된 개선(+1.8~7.7%)을 보였다. 규칙 기반 병합 방법 중 AND는 만장일치를 요구하는 특성 때문에 모든 모델에서 J+H보다 크게 낮은 성능(−13.2~21.3%)을 보였고, OR과 MAJ는 모델에 따라 성능이 들쭉날쭉했다. 실패 유형을 분석하면 대부분의 방법에서 "누락(miss)"이 주된 오류 원인이었으며, 즉 모델은 수정을 지나치게 적게 전파하는 경향이 있었다.

비용 대비 효과를 분석한 결과, 세 번의 병렬 샘플 중 하나를 LLM 기반 또는 medoid 기반으로 선택하는 방식이 가장 비용 효율적이며 정확도를 2.2~9.7% 개선함을 확인했다. 저자들은 실용적 선택지로 4회 호출의 SELECT를 권장하되, 지연시간(latency)이 중요한 경우에는 병렬 샘플링 한 단계만 필요한 3회 호출의 MED를 대안으로 제시했다.

한계점

  • 이 연구는 리포지토리 수준 코드 편집, 지식 편집, 문서 편집처럼 의존관계가 사전에 명시적으로 존재하는 기존 문제 설정에는 일반화되지 않는다.
  • 대화는 시나리오에 기반해 LLM이 합성 생성한 것으로, 실제 사람과 LLM 간 상호작용 데이터가 아니며, 신뢰할 수 있는 자동 평가를 위해 의존관계를 결정론적으로 통제했기 때문에 실제 대화에서 발생할 수 있는 모호한 사례는 다루지 않는다.
  • 150개 샘플, 9개 도메인, 6개 전파 패턴을 다루지만 모든 패턴을 빠짐없이 포괄하지는 못하며, 대화가 GPT-5.5로 생성되어 GPT 계열 모델에 유리할 가능성이 있다(다만 시나리오는 Claude-Opus-4.8로 사람이 작성해 편향을 완화하려 했다).
  • gpt-5.4-mini가 이미 93%의 완료율을 보여, 향후 모델 성능이 향상될수록 비교가 어려워지는 성능 포화 문제가 우려된다.

시사점

사용자가 국소적인 수정만 요청해도 LLM이 대화 맥락 속 암묵적 의존관계를 스스로 파악해 관련 항목을 함께 갱신해야 하는 실용적 시나리오에서, 단순히 모델 크기를 키우기보다 소수의 병렬 샘플과 선택 기법을 결합하는 것이 비용 효율적인 개선 경로가 될 수 있음을 보여준다. 특히 금융 데이터나 인보이스 처리처럼 사소한 누락도 큰 오류로 이어질 수 있는 영역에서는, 저자들이 부록에서 제안하듯 LLM이 제안한 변경 사항을 사람이 최종 승인하는 안전장치를 함께 고려할 필요가 있다.
