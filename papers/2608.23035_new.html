MobilePA-Bench: Benchmarking Mobile Planner Agents on Complex Real-World Tasks

모바일PA벤치: 복잡한 실세계 과제에서 모바일 플래너 에이전트 벤치마킹

GUI 화면 조작이나 정적 함수 호출 매칭에 그치던 기존 모바일 에이전트 평가의 한계를 넘어, 실시간 상태를 유지하는 실행 가능한 샌드박스에서 모바일 플래너 에이전트의 도구 사용·서브에이전트 협업·메모리 활용·스킬 활용 능력을 종합 평가하는 벤치마크 MobilePA-Bench를 제안한다.

한 줄 요약

GUI 화면 조작이나 정적 함수 호출 매칭에 그치던 기존 모바일 에이전트 평가의 한계를 넘어, 실시간 상태를 유지하는 실행 가능한 샌드박스에서 모바일 플래너 에이전트의 도구 사용·서브에이전트 협업·메모리 활용·스킬 활용 능력을 종합 평가하는 벤치마크 MobilePA-Bench를 제안한다.

배경 및 문제의식

온디바이스 LLM 에이전트가 개인 비서(코파일럿)로 진화하면서 모바일 운영체제 환경에서의 엄밀한 평가가 중요해지고 있다. 그러나 기존 벤치마크는 크게 두 갈래로 나뉘며 각기 치명적 사각지대를 갖는다. 첫째, AndroidWorld·OSWorld·MobiBench 등 GUI 중심 벤치마크는 화면 클릭과 픽셀 단위 시각 인식만 평가할 뿐 백그라운드 도구 호출이나 장기 계획(long-horizon planning) 능력을 간과한다. 둘째, BFCL·ToolBench·DroidCall·AppBench 등 정적 함수 호출 벤치마크는 오프라인 문자열/JSON 매칭 방식이라 실제 런타임 제약(권한 차단, 의존성, 상태 변화 등)과 동떨어져 있다. 저자들은 실제 사용자 요청(예: 3일간의 상하이 여행 계획)이 API 호출이나 GUI 자동화 단독으로는 해결될 수 없으며, 메모리 조회·구조화된 스킬 실행·멀티모달 도구 사용·서브에이전트 위임을 통합적으로 수행하는 '모바일 플래너 에이전트' 개념이 필요하다고 주장한다.

핵심 기여

  • 종합 진단 스위트: 13개 기능 도메인, 212개 현실적인 모바일 도구를 아우르는 1,705개의 실제 사용자 과제를 구축하고, 이를 Basic Tool Use·Sub-agent Collaboration·Memory Usage·Skill Usage의 4가지 능력 차원으로 체계화.
  • 인터랙티브 평가 샌드박스: 실시간 애플리케이션 데이터베이스를 유지하며 구조화된 피드백을 반환하는 상태 기반(stateful) 시뮬레이션 환경을 구축, 중앙 플래너의 판단을 저수준 시각 파싱 부담과 분리.
  • 실증적 인사이트 및 개방형 인프라: 최상위 프런티어 LLM들의 실패 유형을 분석하고, 전체 벤치마크 과제·평가 데이터셋·고처리량 샌드박스를 오픈소스로 공개하여 향후 에이전트 훈련 및 강화학습에 활용 가능하게 함.

방법론

MobilePA-Bench는 사용자 의도 q, 초기 실행 상태 S0, 대화 이력 H0, 후보 행동 집합 A0로 과제를 정식화하고, 매 스텝마다 중앙 플래너가 행동 a_t를 예측하면 실행 가능한 샌드박스가 이를 처리해 새로운 상태와 피드백을 반환하는 폐루프(closed-loop) 구조를 취한다. 전체 행동 공간은 (1) 직접 모바일 도구(Basic Tool Use), (2) 서브에이전트 진입 도구(Sub-agent Collaboration, 예: GUI 서브에이전트로의 위임), (3) 메모리 도구(search_user_memory 등), (4) 스킬 로딩 도구(호출 시 다단계 절차와 관련 도구를 동적으로 노출)의 네 범주로 통일된 함수 호출 스키마로 표현된다. 샌드박스는 도구 스키마·도구 구현 코드·공유 상태 데이터베이스(연락처 등 실제 애플리케이션 상태 및 운영 로그) 3계층으로 구성되며, 누락된 파라미터나 권한 차단 같은 현실적 장애 요소를 초기 설정에 주입해 오류 복구 능력을 테스트한다.

평가는 완료 근거의 성격에 따라 세 가지 질의 버킷으로 나뉜다: Bucket 1(Tool Call, 정확한 도구·인자·순서 매칭), Bucket 2(State Change, 최종 데이터베이스 상태 변화 매칭), Bucket 3(Agent Behavior, 서브에이전트 호출 및 적절한 후속 대응 등 행동 기반 평가). 메모리 검색이나 골드 스킬 로딩이 필요한 과제에는 별도의 게이트(gate) 조건이 추가로 적용된다. 최종 종합 점수는 Basic Tool Use 50%, Sub-agent Collaboration 10%, Memory Usage 20%, Skill Usage 20%의 가중합으로 산출된다.

실험 설정 및 결과

Claude-Opus-5, Claude-Fable-5, Kimi-K3, Qwen-3.8-Max, Gemini-3.6-Flash/3.1-Pro, GLM-5.2, GPT-5.6-Sol/5.5, Seed-2.1-Pro, Kimi-2.6 등 13개 최신 LLM을 대상으로, 1,705개 과제(Basic Tool Use 1,040개, Sub-agent Collaboration 89개, Memory Usage 376개, Skill Usage 200개, 후보 도구 회수 수 N=15, 최대 스텝 T_max=15)에 대해 평가했다. 최고 성능 모델인 Claude-Opus-5는 전체 가중 점수 75.52%(Basic Tool Use 83.85%, Sub-agent 62.92%, Memory 58.51%, Skills 78.00%)를 기록했으며, 13개 모델 중 7개가 70% 미만에 머물렀다. Sub-agent Collaboration(43.82%~77.53%)과 Memory Usage(33.78%~64.63%)가 특히 취약한 영역으로 나타났고, 어느 한 모델도 모든 차원에서 우위를 보이지 않는 능력 트레이드오프가 관찰되었다(예: Gemini-3.1-Pro는 Sub-agent에서 최고이나 Memory는 48.67%에 불과). Skill Usage는 평균적으로 Memory Usage보다 높아, 사전 패키징된 스킬 재사용이 장기 계획 오류 누적을 완화함을 시사했다. Qwen3.6-27B로 3회 반복 평가한 안정성 실험에서는 전체 점수의 표준편차가 0.5%p 이하로 나타나 벤치마크의 재현성이 확인되었다.

한계점

논문에서 명시적으로 언급된 한계는 제한적이나, 다음과 같은 자체 지적 사항이 있다: Sub-agent Collaboration 평가는 표본 수가 89개로 상대적으로 적어 반복 실행 간 변동 폭(최대 2.25%p)이 다른 차원보다 크게 나타났다. 또한 13개 시나리오·89개 하위 카테고리로 구성된 1,530개 질의 분석 스냅샷은 어디까지나 서술적(descriptive) 통계일 뿐 1,705개 과제의 공식 평가 분모와는 별개임을 저자들이 명확히 구분해 밝히고 있다. 논문은 현재 프런티어 LLM들이 권한 제한, 예기치 못한 런타임 오류, 애매한 제약 상황에서 명확화 질문을 하기보다 성급하게 환각적인 도구 호출을 시도하는 경향이 있다는 점을 주요 실패 양상으로 지적한다.

시사점

이 연구는 모바일 에이전트 평가를 화면 조작 중심 또는 정적 API 매칭 중심의 단편적 접근에서 벗어나, 실시간 상태를 가진 실행 환경에서 도구 사용·협업·메모리·스킬을 통합적으로 검증하는 방향으로 확장했다는 점에서 의미가 크다. 최고 성능 모델조차 전체 점수가 75.52%에 그치고 서브에이전트 협업 및 메모리 활용에서 뚜렷한 취약점을 보인다는 결과는, 개별 능력의 부재보다 여러 능력에 걸친 오류가 누적되는 '복합적 신뢰성' 문제가 실제 배포의 핵심 걸림돌임을 보여준다. 저자들은 이 벤치마크가 단순 리더보드를 넘어, 상태 기반 피드백에 대한 강화학습, 에이전트 간 통신 규율화, 개인화된 메모리 검색과 도구 인자 접지(grounding)의 긴밀한 통합 등 차세대 모바일 에이전트 설계·훈련의 진단 도구로 활용될 수 있다고 제안하며, 전체 인프라를 오픈소스로 공개해 후속 연구를 촉진하고자 한다.
