AutoSaddler: Automatic Harness Optimization with Durable Updates from Agent Execution Traces

오토새들러: 에이전트 실행 흔적으로부터 지속 가능한 업데이트를 만드는 자동 하네스 최적화

LLM 에이전트를 감싸는 "하네스(harness)"—프롬프트, 도구, 미들웨어—를 실행 실패 흔적으로부터 자동으로 진단·수정·검증하여, 특정 사례에만 맞춘 임시방편이 아니라 일반화되는 지속적인 개선을 만들어내는 오프라인 학습 프레임워크 AutoSaddler를 제안한다.

한 줄 요약

LLM 에이전트를 감싸는 "하네스(harness)"—프롬프트, 도구, 미들웨어—를 실행 실패 흔적으로부터 자동으로 진단·수정·검증하여, 특정 사례에만 맞춘 임시방편이 아니라 일반화되는 지속적인 개선을 만들어내는 오프라인 학습 프레임워크 AutoSaddler를 제안한다.

배경 및 문제의식

LLM은 능력이 빠르게 향상되었지만 여전히 "들쭉날쭉한 지능(jagged intelligence)"을 보이며, 특히 여러 단계에 걸친 장기 과제(long-horizon task)에서는 작은 국지적 실패가 누적되어 전체 과제 실패로 이어지는 문제가 있다. 이를 보완하기 위해 LLM 주위에 프롬프트, 도구 구성, 제어 로직 등으로 이루어진 "하네스"를 설계해 에이전트 행동의 견고성을 높이는 접근이 떠오르고 있다. 그러나 하네스 설계는 지금까지 수작업으로 이루어져 왔고, 방대한 설계 공간을 탐색해야 하는 데다 각 후보 하네스의 평가 비용이 크며(에이전트가 성공/실패를 알기까지 여러 단계를 실행해야 함), 그 결과로 나온 장기 실행 궤적을 분석하는 것 자체도 상당한 수작업을 필요로 한다. 따라서 새로운 LLM으로 전환하거나 에이전트를 새로운 도메인에 배포할 때에도 효율적으로 하네스를 자동 적응시킬 방법이 절실하다.

핵심 기여

  • 하네스 자동 최적화를 프롬프트·도구·미들웨어에 대한 오프라인 학습 문제로 정식화하고, 에이전트 실행 흔적에서 얻은 실패 신호를 활용하는 틀을 제시.
  • 근거 기반 진단(evidence-grounded diagnosis), 구조화된 패치 생성, 일반화 인식 선택(generalization-aware selection)을 결합한 AutoSaddler를 제안.
  • GAIA2, SWE-Bench Pro, Terminal-Bench 2.0 세 가지 어려운 에이전트 벤치마크에서 광범위한 실험을 수행해 장기 과제 성능 향상을 입증.
  • 효과적인 하네스 최적화에는 (1) 얕은 반성이 아닌 심층 디버깅, (2) 제약 없는 편집이 아닌 목표 지향적 수정, (3) 단일 궤적 수리가 아닌 일반화 인식 선택이라는 세 가지 요소가 필요함을 어블레이션으로 입증.

방법론

AutoSaddler는 하네스 파라미터를 θ = (θ_prompt, θ_tool, θ_middleware)로 정의하고, 유한한 롤아웃 예산 안에서 개발 셋 성능을 최대화하는 후보를 찾는 예산 제약 최적화 문제로 접근한다. 데이터는 학습(train)/개발(dev)/테스트(test) 셋으로 분리되며, 미니배치 단위로 반복 학습하는 표준 머신러닝 관행을 텍스트 기반 하네스 최적화에 적용한다.

각 반복(iteration)은 다음 순서로 진행된다. 1. 테스트: 현재 하네스 H_n을 학습 셋의 미니배치에서 실행. 2. 진단-패치 세션(Diagnosis-Patch Session): 실패한 실행 흔적을 분석하는 진단-패치 에이전트가 근거 기반으로 원인을 규명하고, 프롬프트/도구/미들웨어 세 계층 중 하나 이상을 겨냥한 구조화된 패치 Δθ_n을 생성. 패치는 다시 코드/로직을 바꾸는 "능력 패치(Capability Patch)"와 텍스트만 수정하는 "조향 패치(Steering Patch)"로 나뉘며, 표준 학습률 스케줄링에 비유되는 "단계적 패치 스케줄링(Phased Patch Scheduling)"을 적용해 초반에는 능력 패치, 이후 조향 패치로 전환. 3. 검증: 패치된 하네스 H'n을 같은 미니배치에서 재평가해 성능이 개선되었는지 확인하고, 개선 시 개발 셋에서 일반화 여부도 추가 평가. 4. 반성 세션(Reflection Session): 패치 전후 궤적을 비교해 "수정됨/회귀함/여전히 실패/여전히 성공"의 네 범주로 결과를 정리하고, 그 교훈과 점수를 EvoDAG(진화 이력을 추적하는 방향성 비순환 그래프)의 노드 속성으로 저장. 5. 진화 세션(Evolution Session): EvoDAG 전체를 참고해 진화 에이전트가 이전에 탐색된 여러 하네스의 요소를 재조합함으로써 다음 후보 H(n+1)을 합성(진화적 탐색과 유사한 병합 연산으로 국소 최적점 탈출을 도움).

이 과정은 롤아웃 예산이 소진될 때까지 반복되며, 최종적으로 개발 셋 점수가 가장 높은 후보를 선정해 테스트 셋에서 단 한 번 평가한다. 세 에이전트(진단-패치, 반성, 진화)는 모두 Claude Agent SDK(CA-SDK) 기반으로 구현되었다.

실험 설정 및 결과

GAIA2(스마트폰 환경 시뮬레이션, ReAct 기반 기본 에이전트), SWE-Bench Pro(기업 규모 소프트웨어 엔지니어링, SWE-agent 기반), Terminal-Bench 2.0(시스템 관리·ML·보안 등 89개 과제, Terminus 2 기반) 세 벤치마크에서 평가했으며, 최적화에는 기본적으로 Claude Opus 4.6을 사용했다. 비교 대상은 수작업 기본 하네스, 프롬프트 중심 자동 최적화 기법 GEPA, 하네스 최적화 기법 Meta-Harness이다.

  • AutoSaddler는 GAIA2에서 기본 하네스 대비 +9.0%p(53.0% → 62.0%), SWE-Bench Pro에서 +8.4%p(37.3% → 46.9%), Terminal-Bench 2.0에서 +10.0%p(40.0% → 50.0%) 향상시켰다.
  • 가장 강력한 자동 베이스라인 대비로도 GAIA2 +7.4%p, SWE-Bench Pro +6.2%p, Terminal-Bench 2.0 +4.4%p 우위를 보였으며, Terminal-Bench 2.0에서는 전문가가 수작업 튜닝한 Terminus KIRA 대비로도 +2.5%p 앞섰다.
  • 최적화 효율 면에서 AutoSaddler는 약 1,000회의 태스크 실행만으로 개발 셋 정확도 72.3%에 도달했지만, GEPA와 Meta-Harness는 약 2,800회를 소모하고도 각각 64.6%, 61.5%에서 정체되었다. 학습에 활용된 롤아웃 수 기준으로는 147회 만에 최고 성능에 도달, Meta-Harness(1,400회) 대비 약 10배 효율적이었다.
  • 어블레이션 결과, 심층 진단을 제거하면 GAIA2 Pass@1이 62.0%→57.8%로, 구조화된 개입(패치 분류·단계적 스케줄링)을 제거하면 56.9%로, 일반화 인식 선택(반성+개발 셋 평가)을 제거하면 50.6%로 각각 크게 하락했다. 구조화된 개입이 없으면 패치의 91.5%가 손쉬운 "조향 패치"에 편중되는 반면, AutoSaddler는 프롬프트·도구·미들웨어에 걸쳐 고르게 패치를 분산시켰다. 또한 일반화 인식 선택이 없으면 반복이 진행될수록 회귀율이 증가하는 반면, AutoSaddler는 반복이 진행될수록 회귀율이 감소하는 경향을 보였다.
  • Haiku 4.5로 기반 LLM을 교체해도 Opus 4.6으로 최적화된 하네스가 기본 하네스 대비 +5.6%p 개선을 유지해, 어느 정도의 모델 간 전이 가능성을 시사했다.

한계점

논문은 별도의 "한계점" 절을 명시적으로 두지 않았으나, 본문 내용을 통해 다음과 같은 제약을 확인할 수 있다. - 하네스를 프롬프트, 도구, 미들웨어 세 범주로만 한정하고, 메모리나 스킬 큐레이션 등 다른 구성 요소는 다루지 않음(과제가 상태 비의존적이고 독립적이라는 가정 하에). - 자기 참조적(self-referential) 확장을 목표로 하지 않으며, 유한한 롤아웃 예산 내에서의 오프라인 최적화만 다룸(온라인 지속 학습이나 자기 진화 에이전트와는 다른 설정). - 최적화 과정에서 진단-패치 세션이 다수의 도구 호출과 파일 접근을 요구해, 최적화 측 비용(연산·비용)이 증가할 수 있음이 언급됨. - 논문에 명시되지 않음: 매우 긴 실행 궤적이나 완전히 새로운 도메인으로의 전이 성능에 대한 구체적 한계.

시사점

하네스(에이전트 외부 레이어) 설계를 수작업이 아닌 자동화된 오프라인 학습 문제로 재정의함으로써, LLM 에이전트 시스템의 신뢰성과 성능을 개선하는 새로운 최적화 축을 제시한다. 특히 실패 흔적에 대한 얕은 반성이 아닌 심층적·근거 기반 진단, 무제한 편집이 아닌 구조화된(카테고리화된) 패치 개입, 그리고 단일 궤적이 아닌 분포 전체에 대한 일반화 인식 선택이라는 세 가지 설계 원칙이 지속 가능한(durable) 개선을 만드는 데 핵심적임을 실증적으로 보여준다. 이는 향후 에이전트를 새로운 LLM이나 새로운 배포 도메인으로 옮길 때 하네스를 저비용으로 자동 재적응시키는 실용적 경로를 제공하며, 프롬프트 최적화(GEPA)나 종단 간 하네스 최적화(Meta-Harness) 같은 기존 접근을 능가하는 효율성과 성능을 보여준다는 점에서, 자동 하네스 최적화가 보다 견고한 장기 과제 에이전트 시스템 구축의 유망한 방향임을 시사한다.
