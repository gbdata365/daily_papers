Agent Lightning v1.0: Towards Harnessed Agentic RL

에이전트 라이트닝 v1.0: 하네스 기반 에이전틱 강화학습을 향하여

Claude Code, OpenHands 같은 실제 배포용 "에이전트 하네스"를 그대로 강화학습(RL) 훈련 루프에 연결하는 "하네스 기반 에이전틱 RL(harnessed agentic RL)" 패러다임을 정식화하고, 이때 발생하는 새로운 문제들(재토큰화, 어드밴티지 계산, 손실 정규화 등)을 규명한 뒤 이를 해결하는 경량 프레임워크 Agent Lightning v1.0을 제시한 연구다.

한 줄 요약

Claude Code, OpenHands 같은 실제 배포용 "에이전트 하네스"를 그대로 강화학습(RL) 훈련 루프에 연결하는 "하네스 기반 에이전틱 RL(harnessed agentic RL)" 패러다임을 정식화하고, 이때 발생하는 새로운 문제들(재토큰화, 어드밴티지 계산, 손실 정규화 등)을 규명한 뒤 이를 해결하는 경량 프레임워크 Agent Lightning v1.0을 제시한 연구다.

배경 및 문제의식

현대 LLM 에이전트는 단독 모델이 아니라 도구 호출, 컨텍스트 구성, 제어 흐름을 관리하는 "하네스" 위에서 동작한다(mini-SWE-agent, OpenHands, Claude Code, Codex 등). 그러나 verl, AReaL, slime 같은 기존 RL 프레임워크는 에이전트 루프를 훈련 프레임워크 내부에 직접 재구현하도록 요구해, 복잡한 기존 하네스를 그대로 재사용하기 어려웠다. 저자들의 이전 연구인 Agent Lightning은 LLM 엔드포인트 프록시를 통해 임의의 에이전트를 RL 훈련에 연결하는 분리형(disaggregated) 구조를 제안했고, 이후 verl Uni-Agent, AReaL 2.0, slime v0.3.0, Polar 등도 유사한 프록시 기반 접근을 채택했다. 이 논문은 이런 패러다임을 "하네스 기반 에이전틱 RL"로 명명하고, 이것이 전통적 에이전틱 RL과 근본적으로 다르다는 점—훈련 엔진이 환경과의 상호작용 루프를 소유하는 대신, 하네스가 이를 소유하고 훈련 엔진은 LLM 요청-응답 쌍의 시퀀스만 관찰한다는 점—을 부분관측 마르코프 결정과정(POMDP) 관점에서 정식화한다.

핵심 기여

  1. 하네스 기반 에이전틱 RL을 전통적 에이전틱 RL과 대비되는 새로운 패러다임으로 정식화하고, 이로 인해 발생하는 4가지 핵심 난제—재토큰화/샘플 병합, 어드밴티지 계산, 손실 정규화, 훈련 백엔드 스케줄링—를 체계적으로 최초로 규명했다.
  2. 약 3,500줄의 코드로 구현된 경량 프레임워크 Agent Lightning v1.0을 공개했으며, 임의의 에이전트 하네스를 지원하면서 위 난제들에 대한 자체 설계 선택(롤아웃 단위 어드밴티지·손실 정규화 등)을 내장했다.
  3. 코딩 에이전트 훈련을 위한 완전한 데이터 정제 파이프라인과 재현 가능한 훈련 스크립트를 공개하여, SWE-smith 데이터셋 기반으로 6천 개의 훈련 예제와 적은 컴퓨팅 자원만으로 Qwen3.5-9B의 SWE-bench Verified 성능을 41.8%에서 56.4%로 절대 14.6%p 향상시켰다.

방법론

Agent Lightning v1.0은 API Gateway, Rollout Controller, Customized Trainer 세 컴포넌트로 구성된다. API Gateway는 롤아웃·모델·이벤트를 저장하는 단일 상태 저장 서비스로, 에이전트 하네스의 OpenAI 호환 LLM 호출을 프록시하며 각 호출을 프롬프트·응답 토큰 ID와 로그 확률로 기록한다. Rollout Controller는 쿠버네티스 Job(또는 로컬 프로세스)으로 에이전트 실행을 스케줄링하고 조정(reconcile)한다. Customized Trainer는 VERL 위에 구축되며, 기록된 이벤트를 훈련 샘플로 조립하는 Sample Adapter를 포함한다.

핵심 설계 선택은 다음과 같다. (1) 재토큰화 문제(같은 텍스트라도 챗 템플릿 비합성성, 디코드-재토큰화 드리프트, 도구 호출 출력 변형 등으로 토큰 경계가 달라져 두 호출을 단순 병합할 수 없는 문제)에 대해, 토큰 수준 접두사 조건이 실제로 성립할 때만 병합하는 "최선 노력(best-effort) 시퀀스 병합" 전략을 채택했다—이는 독립 호출 재계산과 트리 구조 학습의 중간 지점이다. (2) 하나의 롤아웃이 서브에이전트 생성이나 컨텍스트 요약 등으로 인해 여러 개의 훈련 샘플을 만들어낼 수 있는데(코딩 에이전트 실험에서 롤아웃당 평균 2.41개 샘플), 어드밴티지는 샘플 단위가 아닌 롤아웃 단위로 계산해야 재토큰화 등 부수적 요인이 그룹 베이스라인을 왜곡하지 않는다고 주장한다. (3) 손실 정규화 역시 롤아웃 단위 토큰-평균(rollout-level token-mean) 방식을 채택해, 샘플을 많이 만들어내는 롤아웃이 불균형하게 큰 가중치를 갖지 않도록 했다. 또한 롤아웃과 가중치 업데이트가 동일 GPU 풀을 시간 분할로 공유하는 "Collocated Async RL"을 제안해 동기식 대비 약 2배의 종단 속도 향상을 GPU 추가 없이 달성했고, 네트워크 장애에 대비한 멱등적(idempotent) API 설계와 재시도 호출 중복 제거, 상용 샌드박스 대신 자체 호스팅 쿠버네티스 클러스터를 사용하는 구조, 리워드 해킹 탐지를 위한 모니터링 시스템을 갖췄다.

실험 설정 및 결과

세 가지 에이전트 설정에서 검증했다. (1) 검색 에이전트: Search-R1 설정을 따라 Llama-3.2-3B-Instruct를 GRPO로 HotpotQA에서 훈련, 6개 QA 벤치마크 검증 결과 정확일치(EM) 보상이 25.1%에서 41.7%로 향상(+16.6%p). (2) 범용 지시-수행 에이전트: LLM-in-Sandbox 설정을 따라 Qwen3-4B-Instruct-2507을 RLOO로 Instruction Pre-Training 데이터셋에서 훈련, 검증 보상이 51.9%에서 70.2%로 향상(+18.3%p). (3) 코딩 에이전트: mini-SWE-agent 하네스와 SWE-smith 데이터셋을 사용해 Qwen3.5-9B를 훈련. 원본 데이터의 결측 문제 기술, 누락된 문제 브랜치, 과도한 테스트 수 등을 정제하고 모델 기반 난이도 필터링으로 약 6천 개 훈련 예제를 구축했으며, git 히스토리 열람 차단·네트워크 아웃바운드 차단 등으로 정답 코드를 직접 가져오는 리워드 해킹을 방지했다. 어드밴티지·손실 정규화를 샘플 단위로 한 기준선(35.0%) 대비 롤아웃 단위 어드밴티지만 적용한 경우(33.1%)보다, 롤아웃 단위 어드밴티지와 롤아웃 단위 손실 정규화를 함께 적용한 경우가 검증 보상 38.2%로 가장 높고 엔트로피도 더 안정적으로 증가함을 확인했다. 이 최종 체크포인트는 SWE-bench Verified에서 41.8%→56.4%(+14.6%p)를 기록했다.

한계점

논문에 별도의 "한계점" 절은 없으나 본문에서 다음이 확인된다. 최선 노력 병합 전략은 재토큰화 드리프트가 발생하면 병합률이 낮아져 중복된 프리픽스 연산이 남는 트레이드오프가 있다(정확성은 보장하되 완전한 계산 재사용은 아님). 롤아웃 내 여러 샘플 간의 더 정교한 크레딧 할당(credit assignment) 문제는 향후 연구 과제로 남겨두었다고 명시했다. 또한 실행 인프라로 쿠버네티스 클러스터를 전제로 하며, 실험은 상대적으로 작은 규모의 모델(3B~9B급)과 세 가지 태스크 유형에 한정되어 있어 더 큰 규모나 더 복잡한 멀티에이전트 하네스에 대한 일반화는 논문 범위 밖이다.

시사점

이 연구는 RL 훈련이 배포 시점에 실제로 사용하는 에이전트 하네스(도구 프로토콜, 컨텍스트 정책, 서브에이전트 구조 등)를 그대로 보존하면서 이루어질 수 있게 함으로써, 훈련과 실사용 사이의 괴리를 줄이는 실용적 경로를 제시한다. 특히 재토큰화·어드밴티지·손실 정규화에 대한 원칙적 분석은 verl Uni-Agent, AReaL 2.0, slime, Polar 등 유사 계열 프레임워크들이 암묵적으로 서로 다른(때로는 상충하는) 선택을 하고 있음을 드러내며, 이 분야의 설계 공간을 명확히 정리한 기준점 역할을 할 수 있다. 또한 상용 샌드박스 없이 자체 호스팅 쿠버네티스만으로 코딩 에이전트 RL을 재현 가능하게 만든 공개 파이프라인은, 대규모 컴퓨팅 자원이 부족한 연구자나 팀이 실전형 코딩 에이전트 RL 연구에 참여할 수 있는 문턱을 낮춘다는 실질적 의의가 있다.
