FACET: Preserving Source Intent and Executable State in Terminal Task Synthesis

페이싯: 터미널 작업 합성에서 원천 의도와 실행 가능 상태 보존하기

한 줄 요약

터미널 에이전트 학습용 태스크를 만들 때 원본 스킬의 의도를 보존하고, 실제로 빌드된 실행 환경 상태를 지시문·솔루션·검증기가 공유하도록 설계한 합성 파이프라인 FACET을 제안하고, 이렇게 만든 데이터로 파인튜닝하면 Terminal-Bench 2.1에서 여러 모델 규모에서 일관된 성능 향상을 얻는다.

배경 및 문제의식

터미널 에이전트를 학습시키려면 지시문(instruction), 초기화된 환경(environment), 참조 솔루션(reference solution), 실행 가능한 검증기(verifier)가 하나로 묶인 태스크가 대량으로 필요하다. 그런데 기존 합성 파이프라인들은 두 가지 문제를 겪는다. 첫째, 여러 단계를 거치며 생성하는 과정에서 원본 자료(스킬 패키지 등)에 담긴 의존관계, 중간 상태, 절차적 제약 등 풍부한 정보가 점점 압축되어 단순한 태스크로 축소된다. 둘째, 지시문·솔루션·검증기를 독립적으로 생성하면 서로 다른 가정 위에서 만들어져 파일명이나 스키마가 어긋나는 등 아티팩트 간 불일치(drift)가 발생해 태스크 자체가 풀 수 없거나 잘못 평가될 수 있다.

핵심 기여

  • 이질적인 에이전트 스킬(스킬 패키지) 모음으로부터 복잡하고 검증 가능한 터미널 태스크를 합성하는 프레임워크 FACET을 제안. 스킬을 단순 템플릿으로 다루지 않고 배경 시나리오와 워크플로우를 먼저 재구성해 원본 정보의 풍부함을 보존.
  • 실제로 빌드된 컨테이너 상태(executable state)를 공유 기준점으로 삼아 지시문·솔루션·검증기를 함께 조율하는 "실행 상태 그라운딩" 구성 방식을 제안. 개별 요소를 각각 그럴듯하게 만드는 대신 전체를 하나의 일관된 실행 가능 태스크로 구성.
  • 환경 실현부터 태스크 검증·수리(repair)까지 포함하는 완전한 합성·검증 파이프라인을 구축하고, 생성 방식별 효과를 분석하는 동시에 여러 모델 규모에서 사후학습(post-training) 실험으로 데이터 효과를 입증.

방법론

FACET은 3단계로 구성된다.

1단계(정보원 수집): OpenClaw, ClawHub, GitHub 등에서 공개 스킬 패키지를 수집·정제해 7만여 개의 유효 스킬을 확보하고, 각 스킬에서 가능한 사용 시나리오를 추출해 임베딩 기반으로 유사한 시나리오를 묶어 스킬 조합 후보(scenario–skill pair)를 만든다. 모델 기반 심사(judge)가 관련성·비중복성·실행 가능성을 평가해 최종 저장소(P)를 구성한다.

2단계(시나리오 재구성 및 참조 생성): 후보 스킬 조합을 목표(goal), 맥락(context), 능력(capability), 상태(state), 입출력/도구(io-tool)의 다섯 차원으로 재구성하는 에이전틱 파이프라인(스킬 분석 → 시나리오 탐색 → 연관성 필터링 → 워크플로우 복원 → 정보 확장)을 거쳐 하나의 자연어 시나리오 설명(C)으로 통합한다. 이를 바탕으로 먼저 솔루션 참조(R_S)를, 이어서 지시문 참조(R_I)를 생성하고, 일관성 검사 모델이 두 참조의 초기·목표 상태가 일치하는지 확인한다.

3단계(실행 상태 기반 태스크 구성): 재구성된 명세로부터 환경 매니페스트를 계획하고 파일·서비스·의존성을 실제로 만든 뒤, 빌드에 실패하면 최대 3회까지 오류 로그와 명세를 함께 참고해 환경을 수리한다. 빌드된 컨테이너의 실제 상태(e0)를 관측한 뒤 이를 공유 컨텍스트로 삼아 지시문 → 솔루션 → 검증기 순서(Forward)로 순차 생성한다. 완성된 태스크 번들은 Harbor 포맷으로 패키징되고, 클린 환경에서의 빌드·초기 상태 미통과·솔루션 실행·최종 상태 통과 조건을 모두 검사한다. 검증 실패 시 실패 지점(환경/솔루션/검증기/지시문)을 특정해 해당 아티팩트만 국소적으로 수리하며(최대 5회), 예산을 소진해도 유효하지 않으면 태스크를 폐기한다.

실험 설정 및 결과

DeepSeek-V4-Pro 기반 Terminus-2 에이전트로 약 6천 개의 검증된 태스크에서 롤아웃을 생성하고, 그중 성공한 1.2K개의 완전한 궤적만 선별해 Qwen3.5-4B/9B/27B를 LLaMA-Factory로 지도 파인튜닝했다. 평가는 Terminal-Bench 2.1(Terminus-2 스캐폴드, 태스크당 3회 시도, 평균 pass rate)로 진행했다.

  • 기존 데이터셋 대비: FACET은 학습 궤적 수(1.2K)는 적지만 평균 턴 수(11.86)가 가장 길고, 태스크당 평균 실행 가능 체크(테스트) 수가 22.77개로 비교 대상 중 가장 많다. 대신 체크가 많은 만큼 P@1 27.00 / P@3 35.00으로 다른 데이터셋보다 낮은 통과율을 보인다.
  • 파인튜닝 성능: Qwen3.5-4B는 17.60→24.72(+7.12), 9B는 27.34→35.58(+8.24), 27B는 40.82→47.57(+6.75)로 세 모델 규모 모두에서 일관되게 향상되었다. 파인튜닝된 27B 모델(47.57)은 약 15배 큰 Qwen3.5-397B(49.06)에 근접하는 성능을 보였다.
  • 태스크 분석: 완료된 교사 롤아웃 중 89.40%의 개별 체크는 통과했지만 전체 태스크 성공률은 20.94%에 불과해, 부분적으로는 잘 수행했지만 결합(conjunctive) 성공 기준 때문에 최종 실패하는 경우가 많음을 보였다. 실패 롤아웃의 54%는 검증 체크를 1~2개만 놓친 "근접 성공"이었다.
  • 생성 순서 비교(Forward vs Reverse vs Joint): 동일한 100개 시나리오-스킬 쌍에 대해 지시문→솔루션→검증기 순으로 생성하는 Forward 방식이 초기 유효율(46.5%)과 최종 수율(83/100) 모두에서 가장 우수했으며, 특히 검증기를 솔루션보다 먼저 생성하는 Reverse 방식보다 통계적으로 유의하게(p=0.0017) 우수해 "솔루션을 먼저 만들고 이를 기반으로 검증기를 생성"하는 순서의 중요성을 뒷받침했다.
  • 부록의 파이프라인 비교(500개 공통 입력)에서도 FACET은 TerminalWorld 스타일 재현 파이프라인(TW) 및 시나리오 재구성 없는 Baseline보다 최종 수율(70.0% vs 27.8%, 15.6%)이 크게 앞섰고, 이는 태스크를 더 쉽게 만들어서가 아니라(오히려 P@1이 가장 낮고 명령어 수가 가장 많음) 아티팩트 간 일관성을 더 잘 확보했기 때문임을 보였다.

한계점

논문에 별도의 "한계점" 절은 없으나 본문 곳곳에서 다음을 명시한다. 스킬 태그별 통과율 분석은 샘플 수가 적어 신뢰구간이 넓고 태그 간 상관관계가 있어 인과적 해석은 어렵다(서로 독립적이지 않은 태그 그룹). Forward/Reverse/Joint 비교는 수리(repair) 예산이 서로 달라(5회 vs 3회) 완전히 통제된 비교는 아니다. TerminalWorld 재현(TW)은 원 논문 코드가 아닌 최선을 다한 재구현이라 원 시스템과 차이가 있을 수 있다. 명령어 수준 행동 분석은 성공한 궤적만을 다루어 성공 원인을 인과적으로 규명하지는 못하며, 동적으로 생성되는 셸 명령을 완전히 파싱하지 못하는 한계도 언급된다. 저자들은 향후 더 다양한 절차적 지식 원천과 상호작용 환경으로 FACET을 확장하고, 강화학습과의 결합을 탐구할 계획이라고 밝힌다.

시사점

터미널 에이전트 학습 데이터의 품질은 단순히 태스크 수나 소스 다양성을 늘리는 것보다, 지시문·환경·솔루션·검증기가 동일한 실행 상태에 기반해 상호 일관되게 만들어지는지가 더 중요함을 실증적으로 보여준다. 특히 검증기를 솔루션 실행 결과에 기반해 나중에 생성하는 순서가 아티팩트 간 정합성을 크게 높인다는 점, 그리고 소량(1.2K)이라도 실행 검증을 통과한 고품질 궤적이면 소형 모델(4B)부터 대형 모델(27B)까지 데이터 효율적인 성능 향상을 이끌어낼 수 있다는 점은 합성 데이터 파이프라인 설계 시 "규모보다 그라운딩된 일관성"을 우선해야 한다는 원칙을 제시한다.
