OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory

오픈VL하네스: 멀티모달 기억 기반 실세계 비주얼 에이전틱 도구 사용

멀티모달 대형언어모델(MLLM)에 "능력 계층(capability layer)"과 "영속적 멀티모달 기억(persistent multimodal memory)"을 결합한 범용 도구사용 하네스 OpenVLHarness를 제안하여, 22개 벤치마크·8개 백본 모델에서 평균 9.7~12.6점의 성능 향상을 달성했다.

한 줄 요약

멀티모달 대형언어모델(MLLM)에 "능력 계층(capability layer)"과 "영속적 멀티모달 기억(persistent multimodal memory)"을 결합한 범용 도구사용 하네스 OpenVLHarness를 제안하여, 22개 벤치마크·8개 백본 모델에서 평균 9.7~12.6점의 성능 향상을 달성했다.

배경 및 문제의식

MLLM은 시각적 추론에서 빠르게 발전했지만, 조밀한 장면의 미세 객체 탐지, 롱테일 지식 검색, 중간 측정값 기반 계산 등은 모델 내부 추론만으로 해결하기 어렵다. 저자들은 22개 벤치마크에 대한 통제 실험에서 추론 예산(reasoning effort)을 늘려도 성능 향상이 미미함을 확인했다(예: GPT-6 Luna의 xhigh→max 단계에서 토큰 비용은 2.7배 늘지만 점수는 0.7점만 상승). 이는 단순한 추론 확장이 아니라 외부 도구를 통한 실제 증거 획득이 필요함을 시사한다. 기존 시각 도구사용 에이전트들은 (1) 이기종 백엔드의 서로 다른 호출 규약과 출력 형식(분할 마스크, 깊이 맵 등)을 모델이 해석 가능한 형태로 통일하는 문제와 (2) 이후 추론 단계에서 원본 산출물(수치 데이터 등)에 다시 접근해야 하는 문제를 동시에 해결하지 못한다는 한계가 있었다.

핵심 기여

  1. 이기종 지각·검색·연산 도구를 과업 단위 인터페이스로 통일하고, 그 출력을 모델이 읽을 수 있는 관찰(observation)로 변환하는 능력 계층(capability layer) 설계.
  2. 이미지, 구조화 데이터, 웹 참조를 질의 전체에 걸쳐 재사용 가능한 핸들로 유지하는 영속적 멀티모달 기억(persistent multimodal memory) 메커니즘.
  3. 22개 벤치마크·8개 오픈/독점 백본에 대한 대규모 평가, 구성요소 제거(ablation) 연구, 그리고 모델 가중치 업데이트 없이 하네스 자체를 특정 도메인에 특화시키는 "하네스 탐색"과 "도구 생성" 두 최적화 워크플로우 제시(전체 하네스·도구·평가 프로토콜 오픈소스 공개).

방법론

OpenVLHarness는 MLLM 오케스트레이터에 두 가지 보완적 장치를 결합한다. 능력 계층은 각 능력(capability)을 입력 타입·노출 정보로 정의하여, 예를 들어 Visual Grounding은 SAM 3나 Grounding DINO 등 다른 백엔드로 교체 가능하면서도 호출 규약은 동일하게 유지한다. 기본 구성은 지각 5종(Zoom-in, Visual Grounding, OCR, Depth Estimation, Camera Trajectory), 정보 탐색 3종(Text Search, Image Search, Webpage Visit), 그리고 중간 결과에 대한 연산을 수행하는 Python Coding Agent로 총 9개 능력을 포함한다. 각 능력에는 출력 처리기(output processor)가 있어 원시 출력(RLE 마스크, 수치 배열 등)을 시각적 첨부물·자연어 설명·압축된 구조 정보로 변환해 모델이 해석할 수 있게 한다.

영속적 멀티모달 기억은 질의별 아티팩트 레지스트리를 유지하며, 이미지 아티팩트·구조화 데이터 바인딩·웹 참조 세 범주로 나뉜다. 각 도구 호출 후 "환경 업데이트(Environment Update)"가 사용 가능한 핸들 목록을 모델에 제시하여, 이후 호출이 과거 증거(예: 그라운딩 마스크, 깊이 배열)를 식별자로 재참조할 수 있게 한다. Python Coding Agent는 오케스트레이터가 자연어로 지정한 계산 목표(예: "탐지된 각 영역의 평균 깊이 계산")를 받아, 동일 백본 모델 기반의 별도 코드 생성 세션에서 저장된 데이터를 변수로 실제 실행하는 프로그램을 작성한다.

실험 설정 및 결과

그라운디드 지각(5개), 시각 검색·심층 리서치(6개), 일반 VQA·환각(6개), 공간 추론(5개) 등 4개 도메인 22개 벤치마크에서 Qwen2.5-VL-7B, Qwen3-VL-8B/32B, Kimi K3 등 오픈 모델과 GPT-5, GPT-6 Luna/Sol/Astra 등 독점 모델 총 8개 백본으로 평가했다. Qwen3-VL-8B에서는 기본 34.2점에서 45.4점(+11.2)으로, 32B에서는 38.3점에서 50.9점(+12.6)으로 상승했으며, 기존 학습 불필요(training-free) 베이스라인인 OctoTools, Visual Sketchpad와 Codex를 모두 능가했다. 특히 GPT-6 Luna에서는 Codex가 오히려 도구 미사용 기본 모델보다 낮은 점수(43.8 vs 45.8)를 보인 반면 OpenVLHarness는 56.5점을 기록해, 코딩 에이전트 하네스가 자동으로 멀티모달 추론을 개선하지 않음을 보였다. 추론 노력(reasoning effort)을 5단계로 바꿔가며 비교한 결과, OpenVLHarness는 medium 수준의 비용만으로 다른 방법들의 max 수준 성능을 상회했으며(최대 37%의 토큰 비용), 제거 연구에서는 원시 도구 접근(+3.8~4.3점)에 능력 계층 추가(+3.2~3.4점), 그리고 영속적 멀티모달 기억 완성(+3.1~4.5점)이 각각 누적적으로 기여함을 확인했다. 실패 분석에서는 조밀한 장면(25개 이상 객체)에서의 지각 오류, 검색 도구 호출 누락, 공간추론에서의 복합 오류가 주요 원인으로 나타났으며, 이에 기반한 하네스 탐색(프롬프트·도구 설명 수정)과 도구 생성(신규 복합 도구 작성) 두 특화 기법이 각각 문제 유형에 맞게 성능을 추가로 끌어올렸다(예: SparBench에서 도구 생성으로 +8.2점).

한계점

논문에 별도의 "한계점" 절은 명시되어 있지 않다. 다만 실패 분석(3.5절)에서 다음과 같은 약점이 보고된다: 25개 이상의 객체가 밀집한 장면에서는 탐지 누락·병합으로 인한 지각 오류가 여전히 빈번하고(해당 도메인 실패의 75%), 시각 검색·심층 리서치 영역에서는 필요한 도구 호출이 누락되는 경우가 많으며(49%), 공간 추론과 일반 VQA에서는 도구 호출 누락과 모델 자체의 추론 오류가 혼재되어 나타난다. 또한 GPT 계열 결과는 API 비용 문제로 단일 실행(single run)만 수행되어 Qwen 계열(3회 평균)에 비해 통계적 변동성 검증이 제한적이다.

시사점

이 연구는 멀티모달 에이전트의 성능 향상이 단순히 추론 토큰(추론 노력)을 늘리는 것만으로는 한계가 있으며, 이기종 도구의 출력을 모델이 해석 가능한 형태로 렌더링하는 것과 그 기저 데이터를 여러 추론 단계에 걸쳐 주소 지정 가능하게 유지하는 기억 메커니즘이 상호보완적으로 중요하다는 점을 실증적으로 보여준다. 또한 모델 가중치를 갱신하지 않고도 실패 진단에 기반해 하네스 자체(프롬프트·도구 구성)를 도메인에 맞게 특화할 수 있다는 점은, 향후 범용 시각 에이전트를 특정 실무 도메인에 저비용으로 적응시키는 실용적 경로를 제시한다.
