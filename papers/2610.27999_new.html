Matrix-Game 4.0: Harnessing Video Models for Real-Time Playable Game Worlds

매트릭스-게임 4.0: 실시간 플레이 가능 게임 월드를 위한 비디오 모델 활용

게임 로직(규칙·상태)을 코드로 실행하는 경량 게임 엔진과 저화질 프록시 프레임을 고화질 영상으로 변환하는 실시간 비디오 생성 모델을 결합해, 소비자용 GPU 한 대에서 480p·60FPS·112ms 지연의 "플레이 가능한" 게임 월드를 구현한 시스템.

한 줄 요약

게임 로직(규칙·상태)을 코드로 실행하는 경량 게임 엔진과 저화질 프록시 프레임을 고화질 영상으로 변환하는 실시간 비디오 생성 모델을 결합해, 소비자용 GPU 한 대에서 480p·60FPS·112ms 지연의 "플레이 가능한" 게임 월드를 구현한 시스템.

배경 및 문제의식

Genie 계열 등 기존 인터랙티브 월드 모델은 비디오 생성만으로 세계 상태를 암묵적으로 유지하기 때문에, 화면 밖 영역의 상태가 소실되거나(지속적 외부 보정 부재), 자기회귀 생성 과정에서 오차가 누적되고, 압축되지 않은 과거 프레임이 쌓여 메모리 비용이 커지며, 내비게이션 위주의 제한적인 게임플레이만 지원하는 한계가 있다. 저자들은 디퓨전 모델이 통계적 상관관계를 학습할 뿐 인과적·물리적 이해를 갖춘 "비전 파운데이션 모델"은 아직 아니라고 지적하며, 세계 상태와 규칙 실행은 외부 시스템이 맡고 비디오 모델은 시각적 렌더링에만 집중하는 구조가 필요하다고 주장한다.

핵심 기여

논문은 게임 실행과 시각 생성을 분리하는 실행 가능한 하니스(harness) 구조를 갖춘 차세대 Matrix-Game 로드맵을 제시하고, 이를 구현한 Matrix-Game 4.0을 공개한다. (1) 단일 RTX 5090에서 480p·60FPS 플레이, 키 입력 후 112ms의 종단 지연을 달성하는 실시간 생성, (2) 게임 엔진·멀티모달 코딩 에이전트·비디오 생성 모델 3요소로 구성된 로드맵 제안, (3) 정합된 저화질-고화질 데이터 수집부터 학습, 자기회귀 증류, 실시간 추론까지 아우르는 파이프라인, (4) 코드·모델 가중치·저화질 게임 에셋의 오픈소스 공개가 주요 기여다.

방법론

시스템은 세 모듈로 구성된다. 게임 엔진은 체력, 인벤토리, 중력, 충돌, 퀘스트 진행 등 월드 상태와 규칙을 코드로 관리하며, 매 프레임 저폴리곤(low-poly) 구조 렌더링(프록시)을 출력한다. 멀티모달 코딩 에이전트는 엔진이 정의한 장면·이벤트를 텍스트 설명(동적 캡션)으로 번역해 비디오 모델에 전달하는 한편, 플레이어의 자연어 요청을 게임 코드·장면 구성으로 변환해 월드에 새로운 규칙이나 콘텐츠를 추가한다. 비디오 생성 모델(Wan2.2 5B Fun-Control 기반 causal DiT, 5B 파라미터)은 저폴리곤 프록시, 동적 캡션, 첫 프레임, 공간 메모리 참조 프레임을 조건으로 받아 한 번에 4프레임(1개 잠재 프레임) 단위 청크를 자기회귀적으로 생성한다. 학습 데이터는 Unreal Engine 5에서 동일 카메라·프레임으로 저폴리곤/고화질 영상을 쌍으로 캡처한 약 1,712시간 분량(성, 사막, 도시, 공중전 4개 장면)이며, 지도 미세조정 이후 Causal Forcing++ 방식을 따라 교사강제 자기회귀 학습 → 인과적 일관성 증류 → 분포 매칭의 3단계 증류를 거쳐 1~2스텝 디노이징 생성기로 변환한다. 추론 단계에서는 CUDA Graph 고정, FP8 양자화, Triton 융합 커널, TAEHV 경량 디코더, 링 버퍼 KV 캐시, split-KV FlashAttention 등을 순차 적용해 지연을 줄인다.

실험 설정 및 결과

성 슈팅, 사막 슈팅, 도시 주행 3개 게임에 대해 각각 전용 렌더링 모델을 학습하고, 홀드아웃 클립의 첫 프레임에서 시작해 961프레임(24FPS 기준 40초) 자기회귀 롤아웃을 수행해 평가했다. 추론 최적화를 단계별로 누적 적용한 결과 처리량이 4.5FPS→83.4FPS(약 19배), 지연은 1110ms→112ms(약 9.9배)로 개선되었으며, 1스텝 생성 시 83FPS·약 18.2GiB 메모리, 2스텝 시 57FPS를 기록했다. RTX 5080(약 67FPS), RTX 5070 Ti(약 58FPS) 등 16GiB급 소비자 GPU에서도 동작을 확인했다. Code World Model, StreamRender-H3, AgentGarten, Magpie 등 최근 코드 기반 인터랙티브 비디오 시스템과 비교해 Matrix-Game 4.0의 종단 지연이 가장 낮았고(차순위 시스템의 약 1/5), 데이터센터급 GPU가 아닌 단일 소비자 GPU로 구동되는 유일한 시스템이었다. 정성 평가에서는 40초 롤아웃 동안 장면의 레이아웃과 카메라 경로, 캐릭터 외형이 안정적으로 유지되었고, 코딩 에이전트를 통해 슈팅 게임에 실드·샷건·게임오버 조건을, 주행 게임에 체크포인트·충돌 페널티·추격 모드를 자연어 지시만으로 추가하는 사례를 시연했다.

한계점

현재 시스템은 게임별로 별도의 렌더링 모델을 학습해야 하며, 해상도는 480p 수준에 머물러 있고, 아직 상용 배포를 위한 하드웨어 요구사항 완화나 Steam 등 실제 플랫폼 출시 전 기술 프리뷰 단계에 있다. 또한 다중 플레이어 간 일관된 시점 렌더링, 생성 결과에 대한 보다 정밀한 제어, 다양한 게임 장르·장면으로의 확장은 추후 과제로 남겨져 있다.

시사점

게임 로직을 코드로, 시각화를 신경망 렌더러로 분리하는 구조는 월드 상태 유지와 규칙 실행의 신뢰성 문제를 해결하면서도 비디오 모델의 표현력을 활용할 수 있는 실용적 절충안을 제시한다. AI 코딩 에이전트의 발전과 결합하면, 자연어만으로 게임 규칙과 장면을 생성·수정할 수 있는 저비용 게임 개발·프로토타이핑 워크플로우로 이어질 잠재력이 있으며, 소비자용 GPU에서 실시간 구동이 가능하다는 점에서 생성형 게임 월드의 실제 배포 가능성을 한 단계 앞당긴 사례로 평가된다.
