From Production Traffic to Post-Training: Building a Self-Hosted LLM That Covers the Corporate Request Mix

프로덕션 트래픽에서 포스트트레이닝까지: 기업 요청 분포를 포괄하는 자체 호스팅 LLM 구축

프로덕션 트래픽 오류 분석을 바탕으로 지시사항 준수·함수 호출·사내 태스크 분포라는 세 축의 문제를 진단하고, 축별로 독립 학습한 GRPO 전문가 모델을 가중치 공간에서 병합하는 방식으로, 기존에 사용하던 자사 대비 약 7배 큰 모델 수준의 품질을 32B 모델 하나로 달성해 사내 LLM 서빙을 통합한 사례 연구다.

한 줄 요약

프로덕션 트래픽 오류 분석을 바탕으로 지시사항 준수·함수 호출·사내 태스크 분포라는 세 축의 문제를 진단하고, 축별로 독립 학습한 GRPO 전문가 모델을 가중치 공간에서 병합하는 방식으로, 기존에 사용하던 자사 대비 약 7배 큰 모델 수준의 품질을 32B 모델 하나로 달성해 사내 LLM 서빙을 통합한 사례 연구다.

배경 및 문제의식

데이터 상주(data-residency) 규제와 보안 요건 때문에 많은 기업이 LLM을 자체 호스팅하는데, 새로운 모델 세대가 계속 등장해도 기존 모델을 곧바로 폐기할 수 없어 사내에 여러 세대의 모델이 동시에 서빙되며 한정된 GPU 풀이 점점 파편화되는 문제가 있다. 저자들의 기업 플랫폼에는 200개가 넘는 사내 애플리케이션이 서로 다른 모델을 사용하고 있었고, 이를 단일 모델로 통합하려면 마이그레이션을 가로막는 품질 격차를 포스트트레이닝으로 메워야 했다. 프로덕션 트래픽 오류를 분석한 결과, 실패의 개선 여지가 큰 축은 크게 세 가지로 나타났다: (1) 지시사항 준수 및 형식 준수 오류가 전체 실패의 37.9%를 차지해 가장 비중이 크고, (2) 도구(함수) 호출이 필요한 요청이 트래픽의 약 12%를 차지하는데 여기서 성능 저하가 뚜렷했으며, (3) 고빈도 태스크 유형과 롱테일 워크플로 사이, 그리고 공개 학습 분포와 사내 실제 요청 분포 사이에 괴리가 존재했다. 특히 사내 애플리케이션의 롱테일은 하나의 앱이 충분한 트래픽을 축적해 신뢰할 만한 A/B 테스트를 하기도 전에 새로 생성되고 폐기되는 속도로 바뀌기 때문에, 모델은 특정 벤치마크에 과적합되지 않고 보지 못한 워크플로에도 일반화되는 폭넓은 능력을 유지해야 한다는 어려움이 있다.

핵심 기여

논문은 크게 세 가지를 기여한다. 첫째, 프로덕션 트래픽으로부터 내부 벤치마크를 구축하는 방법론으로, 결정론적 검증기(verifier) 또는 보정된 LLM 심판(judge)으로 채점하고 사람 평가자와의 일치도로 검증한다. 둘째, 약점 축마다 별도의 RL 전문가를 학습시키고 이를 가중치 공간에서 병합하는 모듈형 포스트트레이닝 레시피로, 여러 목표를 한 번에 최적화할 때 발생하는 교차 도메인 보상 간섭 문제를 우회한다. 셋째, 공동(joint) 다목적 학습을 가로막는 세 가지 보상 해킹(reward-hacking) 실패 모드—의미 붕괴(semantic collapse), 과도한 함수 호출(over-calling), 장황함 해킹(verbosity hacking)—를 각 축별로 규명하고, 축마다 필요한 맞춤형 해결책을 함께 제시한다.

방법론

기반 모델은 Qwen3-32B에 자체 개발한 키릴 문자 밀집 토크나이저를 적용한 것으로, 프로덕션 지연시간 및 생성 비용 제약 때문에 비추론(non-reasoning) 모드로만 동작하도록 학습된다. 학습은 세 단계로 구성된다.

  1. 공유 SFT 단계: 사내 프로덕션 데이터, 일반 도메인 데이터, 지시사항 준수 데이터, 함수 호출 데이터를 한꺼번에 섞은 단일 SFT 체크포인트를 만든다. 도메인별로 따로 SFT를 한 모델과 비교했을 때 품질 차이가 크지 않아, 이후 모든 RL 브랜치의 공통 출발점으로 사용한다.
  2. 도메인별 GRPO 전문가 학습: 이 SFT 체크포인트에서 세 개의 독립적인 GRPO(Group Relative Policy Optimization) 실행을 분기시켜 각각 검증 가능한 보상으로 수렴시킨다.
  3. 일반(General) 전문가: 별도의 검증 가능한 보상이 없으므로, 사내 프로덕션 로그(약 20%)와 대형 공개 러시아어 지시문 코퍼스(약 80%)를 혼합한 데이터로 학습하고, 응답 길이에 곱셈 페널티를 적용하며 KL 계수를 높여 분포 이탈을 억제한다.
  4. 지시사항 준수(IF) 전문가: AutoIF를 러시아어에 맞게 변형한 합성 파이프라인으로 43K개의 검증된 제약 조건과 26K개의 학습 예제를 생성한다. VerIF 스타일의 검증 가능 보상을 쓰되, 순수 검증기 기반 보상이 "형식적으로만 통과하는 의미 없는 빈 응답"을 만드는 해킹을 유발하는 것을 발견하여, 보상 모델 점수가 교사 모델 평균보다 낮으면 페널티를 주는 방식으로 이를 보완한다.
  5. 함수 호출(FC) 전문가: 영어 120만 개, 러시아어 30만 개 규모의 합성 도구 호출·다중턴 대화 데이터를 계획(planning)과 시뮬레이션을 분리한 파이프라인으로 생성한다. Tool-N1의 이진 정확 일치 보상을 사용하는데, 이 보상이 "애매하면 무조건 호출한다"는 지배적 편법(exploit)을 유발하는 것을 확인하고, 학습 데이터 분포에 무관성(irrelevance) 카운터 예제를 주입해 과도한 함수 호출을 교정한다.
  6. 가중치 병합: 세 전문가 체크포인트를 2단계 순차 SLERP(spherical linear interpolation)로 하나의 배포 모델로 합친다. SLERP는 비결합적(non-associative)이라 병합 순서가 결과에 영향을 주는데, 검증 가능한 보상을 가진 두 전문가(IF+FC)를 먼저 합친 뒤 일반 전문가를 접목하는 순서가 가장 좋은 성능을 보였다.

평가를 위해서는 약 10만 개 월간 쿼리에서 템플릿 인식 샘플링(변수 토큰을 마스킹하고 LSH로 근접 중복 프롬프트를 템플릿 단위로 묶은 뒤 템플릿별로 그리디 최대-최소 샘플링)으로 다양성과 프로덕션 대표성을 동시에 satisfy하는 사내 벤치마크를 구축했다. 채점은 태스크 유형에 따라 참조 기반 채점(분류, 정보 추출 등)과 체크리스트 보강 페어와이즈 심판(요약, 콘텐츠 생성 등 개방형 태스크)을 다르게 적용하는 태스크 특화 심판 파이프라인을 사용했다.

실험 설정 및 결과

비추론 모드 기준, 최종 병합 모델은 사내 Arena 벤치마크에서 69.57점(기존 사용하던 총 파라미터 수 약 7배 큰 Qwen3-235B-A22B-Instruct-2507의 65.83점보다 높음), 지시사항 준수(러시아어 IFEval)에서 0.85(비교 모델 0.83), 함수 호출(러시아어 BFCL)에서 0.79(비교 모델 0.77)를 기록해, 훨씬 큰 모델을 전반적으로 앞서거나 대등한 성능을 보였다. 특히 백본 규모가 지배적인 벤치마크(장문맥·자기일관성을 요구하는 ruMultiChallenge, 개방형 검색·종합을 요구하는 SmartSearch)에서 격차를 크게 좁혔다(SmartSearch F1 0.478→0.557, ruWildChat 52.0→80.7).

핵심 소거(ablation) 실험 결과는 다음과 같다. 공유 SFT는 도메인별 개별 SFT와 성능이 거의 동일해, SFT 단계에서는 데이터를 단순 혼합해도 충분하다는 것을 확인했다. 그러나 GRPO 단계에서는 단일 도메인 전문가를 다른 도메인에 적용했을 때 이득이 거의 전이되지 않았고(교차 도메인 전이 실패), 세 가지 보상을 하나의 GRPO에서 동시에 최적화하면(joint GRPO) 목표 간 간섭이 발생해 지시사항 준수가 개선되는 대신 함수 호출 성능이 기준선 아래로 떨어지는 등 트레이드오프가 나타났다. 전문가를 개별 학습 후 병합하는 방식이 joint GRPO보다 우수했고, 사내 데이터로 보상 모델(RM)을 추가 적응시키는 것은 오히려 응답 길이만 늘리고 성능 개선에는 기여하지 못했다. 배포 결과, 병합된 체크포인트는 단일 GPU FP8 복제본(vLLM 기반, 16~48개 파드)으로 월 1억 1600만 건, 초당 평균 45건(피크 110건)의 요청을 처리하며, 95퍼센타일 지연시간 3.2초, 최초 토큰까지 시간 0.3초를 기록했다. 기존 약 7배 큰 모델 대비 토큰당 비용을 2.8~3.9배(입출력 기준), 이전에 최대 규모 모델을 쓰던 서비스는 최대 4~9배 절감했다.

한계점

논문이 스스로 밝힌 한계는 다음과 같다. (1) 평가와 배포 범위가 러시아어와 영어로 한정되며, 사내 벤치마크는 단일 자체 호스팅 기업 플랫폼의 러시아어 트래픽으로만 구축되어 방법론 자체는 언어·조직에 종속적이지 않다고 주장하지만 다른 언어·도메인에서의 검증은 후속 과제로 남긴다. (2) 개방형 품질 평가는 사람 평가자와 보정된 LLM 심판에 의존하는데, 레시피를 다른 배포·언어·벤치마크 분포에 재사용할 경우 심판 품질을 다시 보정해야 한다. (3) 모든 실험이 Qwen3 모델 계열 하나에서만 수행되어 레시피가 다른 백본 계열에서도 통할지는 검증되지 않았다. (4) 프런티어급 에이전트 능력이 필요한 소수 팀은 32B 밀집 모델로는 충분하지 않아 롤백이 발생했다.

시사점

이 연구는 기업이 실제 프로덕션 트래픽 오류 분석에서 출발해 무엇을 개선할지 우선순위를 정하고, 목표(축)별로 별도의 RL 전문가를 학습한 뒤 가중치 병합으로 합치는 방식이 여러 보상을 한 번에 최적화하는 것보다 통제하기 쉽고 디버깅·감사·확장이 용이하다는 점을 보여준다. 각 축이 서로 다른 실패 모드(의미 붕괴, 과도한 호출, 장황함 해킹)를 노출한다는 관찰은 향후 유사한 사내 LLM 통합 프로젝트에서 보상 설계 시 참고할 수 있는 실용적 체크리스트가 된다. 또한 내부 데이터 없이 같은 레시피로 학습한 공개 체크포인트가 공개 벤치마크에서 비슷한 향상을 보였다는 사실은, 성능 개선의 상당 부분이 사내 고유 데이터가 아니라 레시피(방법론) 자체에서 나온다는 것을 시사하며, 이는 다른 조직이 동일한 접근을 채택할 때 재현 가능성에 대한 신뢰를 높여준다.
