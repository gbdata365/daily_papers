Continual Learning Exam: Benchmarking Long-Horizon RSI and Experiential Learning in LLM Agents

컨티뉴얼 러닝 이그잼: LLM 에이전트의 장기적 재귀적 자기개선과 경험 학습 벤치마킹

LLM 에이전트가 업무 경험을 축적하며 실제로 더 나아지는지를 측정하기 위해, 89개 직업·12개 산업 분야에 걸친 120개의 5단계 과제 사다리(총 600레벨)로 구성된 대규모 벤치마크 CLE를 제안하고, 최상위 시스템조차 전체 레벨의 47.7%만을 통과함을 보여 현재 프런티어 LLM 에이전트의 지속학습 능력이 매우 제한적임을 밝힌다.

한 줄 요약

LLM 에이전트가 업무 경험을 축적하며 실제로 더 나아지는지를 측정하기 위해, 89개 직업·12개 산업 분야에 걸친 120개의 5단계 과제 사다리(총 600레벨)로 구성된 대규모 벤치마크 CLE를 제안하고, 최상위 시스템조차 전체 레벨의 47.7%만을 통과함을 보여 현재 프런티어 LLM 에이전트의 지속학습 능력이 매우 제한적임을 밝힌다.

배경 및 문제의식

지속학습(continual learning)이란 에이전트가 시간이 지남에 따라 경험을 획득·정제·활용하면서도 기존에 유용했던 지식을 잃지 않는 능력을 말한다. 이는 장기간 배포되는 에이전트가 변화하는 환경에 적응하고 과거 실수를 반복하지 않기 위해 핵심적이다. 그러나 GAIA 같은 일반 에이전트 벤치마크는 과제를 독립적으로 채점해 경험 축적에 따른 성능 향상을 직접 측정하지 못하고, LoCoMo 등 메모리 벤치마크는 과거 정보 검색·추론 능력만을 평가할 뿐 그 지식이 이후 과제 수행을 실제로 개선하는지는 보지 않는다. WildClawBench 등 상태 유지형(stateful) 벤치마크도 지속적인 작업 흐름은 지원하지만, 경험을 거듭할수록 능력이 향상된다는 점을 직접 입증하지는 못한다. 저자들은 이러한 평가 공백을 메우기 위해, 통제된 피드백 조건 아래 연속된 과제 수행을 통해 누적 개선을 평가할 수 있는 벤치마크가 필요하다고 주장한다.

핵심 기여

  • 50명 이상의 산업 전문가가 직접 작성·검증한 120개 과제(89개 직무, 12개 산업 분야)를 5단계 난이도 사다리로 구성하여 총 600레벨의 대규모 지속학습 벤치마크 CLE를 제시했다.
  • 23,981개의 실제 입력 파일, 1,024개의 API를 노출하는 19개의 상태 유지형(stateful) 모의 애플리케이션, 16,125개의 전문가 작성 평가 기준(rubric)으로 구성된 실행 가능한 평가 환경을 구축했다.
  • 4개의 에이전트 하네스(Claude Code, Codex, Hermes-Agent, OpenClaw)와 11개의 백본 모델을 조합한 17개 구성으로 평가한 결과, 진단 피드백과 재제출 기회를 주어도 중앙값 기준 5.3퍼센트포인트(pp)의 개선에 그쳤고, 최상위 시스템도 레벨의 47.67%만을 통과했다.

방법론

CLE는 각 과제를 동일한 직무·업무 맥락 안에서 난이도가 높아지는 5개 레벨(L1~L5)의 사다리로 구성한다. 에이전트는 한 레벨을 통과해야 다음 레벨이 열리며, 뒤쪽 레벨은 앞선 레벨에서 얻은 정보·산출물·전략을 재사용해야 풀 수 있도록 설계되어 있다. 지식 전이는 "도구와 스킬", "데이터 의존성", "전략", "사용자 맥락", "도메인 지식"이라는 다섯 가지 형태로 분류된다. 또한 저자들은 학습 결정의 자율성과 범위에 따라 지속학습 능력을 T1(규칙 기반 유도 학습)부터 T5(자기 주도적 연구 의제 설정)까지 5단계 계층(capability hierarchy)으로 정리해, RSI(재귀적 자기개선)와 같은 상위 개념을 CLE가 측정하는 지점과 연결한다.

평가 과정은 "액터(피평가 에이전트) - 환경(도구/서비스) - 평가자(루브릭 기반 채점 에이전트)"의 상호작용을 부분관측 마르코프 결정과정(POMDP)으로 공식화한다. 각 레벨 제출물은 별도의 격리된 환경에서 실행되는 다중 턴 평가 에이전트(DeepSeek V4 Flash 기반)가 전문가 작성 루브릭과 대조해 채점하며, 모든 체크리스트 항목을 만족해야 통과로 인정된다. 제출 예산은 레벨당 K=1(피드백 없는 1회 제출)과 K=2(실패 시 루브릭 기반 진단 피드백을 받고 1회 재제출)로 나뉘며, 하네스 상태(메모리·스킬 등)는 120개 과제 전체에 걸쳐 고정된 순서로 유지된다. 데이터 구축은 전문가 설계 → 자동 리뷰 에이전트 심사(+실제 실행 검증) → 2인 교차 인간 검토의 파이프라인을 거쳐 최종 채택된다.

실험 설정 및 결과

평가 대상은 Claude Code, Codex, Hermes-Agent, OpenClaw 4개 하네스와 GPT-5.6 계열, Claude Opus 5/Sonnet 5, Gemini 3.7 Flash, Doubao-Seed-Evolving, Qwen3.8-Max, Hy3, DeepSeek V4 Pro, GLM 5.3 등 11개 백본으로 구성된 17개 조합이다. 최고 성능은 Claude Code + Opus 5로, Trial 1(피드백 없음)에서 42.17%, Trial 2(피드백+재제출)에서 47.67%의 레벨 완료율을 기록했으며 전체 5단계를 완주한 과제는 120개 중 28개(23.3%)에 불과했다. 17개 구성 중 16개가 Trial 2에서 완료율이 상승했고(중앙값 +5.33pp), Claude Sonnet 5는 +13.17pp로 가장 큰 개선 폭을 보였다. 그러나 레벨 1→2 통과율에 비해 레벨 4→5 통과율은 크게 낮아지는 "병목 현상"이 전반적으로 관찰되었으며, 레벨이 깊어질수록 완주 과제 수가 급격히 줄었다. 동일 백본에서는 Hermes-Agent가 OpenClaw보다 전 구간에서 높은 완료율을 보여 하네스(에이전트 설계) 자체의 영향도 크다는 점이 확인되었다. 비용·시간 측면에서는 완료율이 같아도 소요 비용과 시간이 크게 다를 수 있음을 보였다(예: Codex-Sol과 Codex-Terra는 완료율은 같지만 비용·완주 과제 수가 다름).

한계점

논문에 별도의 "한계점" 절은 명시되지 않았으나, 본문 논의에서 다음과 같은 한계가 드러난다. 첫째, 가장 우수한 설정조차 전체 레벨의 절반도 통과하지 못해(47.67%) 벤치마크가 현재 모델에 대해 전혀 포화되지 않았으며, 이는 역으로 결과 해석의 참조점이 제한적임을 의미한다. 둘째, 피드백에 의한 개선이 레벨 1~3 같은 초반부에서는 뚜렷하지만 후반 레벨(L4→L5)로 갈수록 적은 수의 과제에 의존해 신뢰도가 떨어진다. 셋째, 모델 세대가 새로워진다고 해서 일관되게 성능이 향상되지는 않았다(Gemini 3.8이 3.7보다 토큰을 더 쓰면서도 성능은 낮음). 넷째, 본 실험은 모델 파라미터를 고정한 상태(하네스 상태만 갱신)로만 평가했으며, 실제 파인튜닝·강화학습 기반의 파라메트릭 학습을 통한 지속학습 효과는 검증하지 않았다(다만 CLE 데이터를 사후 학습에 활용할 가능성은 제안함). 다섯째, 과제는 영어(508레벨)와 중국어(92레벨) 두 언어로 제한되어 있다.

시사점

CLE는 개별 과제 해결 능력이 아니라 "경험을 통해 실제로 더 나아지는가"를 측정하는 데 초점을 맞춘 평가 체계로서, 현재의 프런티어 LLM 에이전트들이 장기간에 걸친 경험 축적·재사용·자기개선(RSI) 능력에서 여전히 큰 한계를 지니고 있음을 정량적으로 보여준다. 특히 하네스(메모리·스킬 관리 방식)의 설계가 백본 모델 자체보다도 지속학습 성능에 상당한 영향을 미친다는 점은, 향후 에이전트 연구가 모델 스케일링뿐 아니라 경험 재사용 메커니즘(기억, 반성, 재귀적 자기개선 절차 등) 설계에 더 주목해야 함을 시사한다. 또한 CLE가 제공하는 대규모 전문가 작성 과제·루브릭 데이터는 지속학습 능력을 갖춘 에이전트를 사후 학습(post-training)시키는 데에도 활용될 수 있어, 벤치마크이자 학습 자원으로서의 이중적 가치를 지닌다.
