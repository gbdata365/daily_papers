EvoDuet: Bilevel Co-Evolution of Web Searching and Task Solving for Scientific Discovery

웹 검색과 과제 해결의 이중 레벨 공진화를 통한 과학적 발견

EvoDuet은 LLM 기반 진화적 탐색(evolutionary search)에서 "해답을 진화시키는 루프"와 "웹 검색 질의를 진화시키는 루프"를 이중 레벨(bi-level)로 맞물리게 함으로써, 모델이 스스로 지식 공백을 판단해 언제·무엇을 검색할지 결정하게 만드는 과학적 발견용 탐색 기법이다.

한 줄 요약

EvoDuet은 LLM 기반 진화적 탐색(evolutionary search)에서 "해답을 진화시키는 루프"와 "웹 검색 질의를 진화시키는 루프"를 이중 레벨(bi-level)로 맞물리게 함으로써, 모델이 스스로 지식 공백을 판단해 언제·무엇을 검색할지 결정하게 만드는 과학적 발견용 탐색 기법이다.

배경 및 문제의식

OpenEvolve, AlphaEvolve류의 LLM 기반 진화적 탐색 스캐폴드는 후보 해를 생성하고 평가자가 점수를 매겨 다음 세대를 만드는 "해 루프(solution loop)"만으로 작동하는 경우가 많다. EvoX 같은 후속 연구는 탐색 전략을 조정하는 "전략 루프"를 추가로 포장(loop packing)하지만, 결국 참고하는 지식의 원천은 그동안의 진화 이력과 LLM이 사전에 학습한 파라메트릭 지식 두 가지뿐이라 "닫힌 탐색(closed search)"이다. 그 결과 최신 라이브러리 사용법처럼 모델이 원래 모르는 외부 지식이 필요한 지점에서 탐색이 정체된다.

저자들은 예비 분석을 통해, 매 반복마다 정답에 가까운 "오라클 문서"를 제공하면 OpenEvolve의 평균 NDG(Normalized Discovery Gain, 초기 해와 SOTA 해 사이 격차를 얼마나 좁혔는지 나타내는 지표)가 개선됨을 보였다. 그러나 이 효과는 조건부였다: (1) 후보를 한 번에 1개만 생성할 때는 문서가 있어도 별 도움이 안 되고, 8개를 병렬 생성해야 비로소 효과가 나타났다(Sums/Diffs 과제). (2) 해 루프 안에서 LLM이 스스로 검색어를 만들게 하면(joint-level search), 해가 바뀌어도 질의가 따라 바뀌지 않아 동일 페이지를 반복 검색하고(Denoising 과제에서 반환 URL의 88.1%가 이미 본 페이지) 50회 반복 이후 더 이상 개선되지 않았다. 즉 단순히 검색 도구를 붙이는 것만으로는 부족하며, 검색 질의 자체도 해와 함께 "진화"해야 한다는 것이 핵심 문제의식이다.

핵심 기여

  • 해 진화(outer loop)와 검색 질의 진화(inner loop)를 이중 레벨 최적화로 공식화한 EvoDuet 제안. LLM 파라미터는 고정한 채, 지식 공백 기반 검색 게이트(retrieval gate)가 두 루프를 연결한다.
  • 21개 최적화 과제에서 OpenEvolve의 평균 NDG를 GPT-5.6-Luna 기준 74.1%→78.0%, Gemini-3.8-Flash 기준 61.3%→82.3%로 끌어올림(단, Qwen3.5-9B에서는 개선 없음).
  • Swap Reduction(양자 회로 컴파일), Rosetta 등 8개 과제에서 기존 보고된 최고 기록(SOTA)을 경신, 3개 과제에서 동률 달성. Denoising 과제에서는 기존 SimpleTES 대비 6.9배 낮은 비용으로 동등 이상 성능 달성.
  • Top-K, EvoX 등 다른 탐색 스캐폴드에도 검색 루프를 "포장(pack)"해 넣을 수 있음을 보여, 방법의 범용성(scaffold-agnostic)을 입증.
  • 검색된 문서가 실제로 어떻게 활용되는지(방법 전이, 공개 아티팩트 재사용 등 6가지 행동 패턴) 정성 분석.

방법론

EvoDuet은 세 가지 구성 요소로 이뤄진다.

  1. 외부(outer) 루프 – 해 최적화: 기존 진화적 스캐폴드와 동일하게 부모 해 x_t와 이력 H_t를 선택해 LLM이 자식 해 x_{t+1}을 생성하고 평가자 E가 점수를 매긴다. 차이점은, 검색된 문서 집합 S_t가 주어지면 이를 함께 프롬프트에 넣어 후보를 생성한다는 점이다. 또한 LOOK-UP/RETRIEVE가 발생한 반복에서는 후보를 N개 병렬로 생성해 그중 유효하고 가장 점수가 높은 것만 채택한다(병렬 생성이 오라클 문서의 효과를 극대화한다는 예비 분석 결과를 반영).

  2. 지식 공백 기반 검색 게이팅(retrieval gating): 매 반복마다 LLM이 현재 해에 대한 지식 상태 K_t를 요약하고, 저장된 검색 DB(D_s)와 비교해 세 가지 중 하나를 결정한다 — (a) NO-OP: 내부 지식으로 충분, (b) LOOK-UP: 저장된 문서를 재사용, (c) RETRIEVE: 새로 웹 검색 필요. 이는 EvoX의 "정체 여부"에만 기반한 휴리스틱 게이팅보다 더 정교하게 "무엇이 부족한지"를 판단한다.

  3. 내부(inner) 루프 – 질의 최적화: RETRIEVE가 선택되면, 본 해를 평가하지 않고 R라운드 동안 (i) 지식 공백을 겨냥한 질의 생성 → (ii) 웹 검색 실행 → (iii) "가상 증거 점수(hypothetical evidence scoring)": 각 문서를 사용했을 때 예측되는 해의 점수를 LLM이 추정 → (iv) 지식 상태 갱신, 의 사이클을 반복하며 매 라운드 예측 점수 상위 D개 문서만 남긴다. 이 예측 점수는 실제 평가자 점수 없이도 "이 문서가 도움이 될 것 같은가"를 가늠하는 대리 신호로 쓰이며, 최종적으로 상위 문서들만 외부 루프에 전달되어 해 생성에 사용된다.

이 전체 과정은 평가자 E를 공유하는 이중 레벨 최적화 문제로 공식화되며(내부 목적함수는 외부 목적함수의 근사치), 실제 후보 평가 없이도 "어떤 질의가 더 나은 결과로 이어질지"를 예측함으로써 탐색 비용을 절감한다.

실험 설정 및 결과

  • 과제: 양자 컴파일, 천체역학, 과학 알고리즘, AI 기초, 수학, 알고리즘 엔지니어링 등 영역에 걸친 21~31개 최적화 과제(평가자가 명확한 점수를 매길 수 있지만 최적해를 직접 계산할 수 없는 문제들).
  • 백본 모델: Qwen3.5-9B, GPT-5.6-Luna, Gemini-3.8-Flash를 OpenEvolve 위에서 비교.
  • 평가지표: NDG(Normalized Discovery Gain) — 초기 해와 기존 SOTA 해 사이의 격차를 얼마나 메웠는지 백분율로 표시.
  • 주요 결과: 1개 후보 생성 기준으로 GPT-5.6-Luna는 74.1%→78.0%(+3.9%p), Gemini-3.8-Flash는 61.3%→82.3%(+21.0%p) 개선. 반면 Qwen3.5-9B는 오히려 14.4%p 하락 — 샘플 분석 결과 검색된 방법을 아예 사용하지 않거나(6%) 잘못 구현(20%)하는 비율이 26%에 달해, 작은/약한 모델은 "검색은 하지만 활용을 못 한다"는 한계가 드러남.
  • 후보를 8개, 16개로 병렬 생성할수록 모든 모델에서 NDG가 단조 증가(GPT-5.6-Luna 89.6%→95.7%, Gemini-3.8-Flash 84.5%→89.6%, N=1→16).
  • 가상 증거 점수와 실제 평가 점수의 상관관계는 스피어만 ρ=+0.86(전체), 과제별 중앙값 +0.74로 높아, 예측 기반 문서 선별이 유효함을 뒷받침.
  • 유망한 문서(예측 점수가 부모 해보다 높은 문서)가 있을 때 자식 해가 부모를 능가할 확률은 67.1%로, 문서가 없을 때(52.1%)보다 뚜렷이 높음.
  • 가장 흔한 문서 활용 패턴은 "방법 전이"(검색된 원리나 기법을 자신의 해에 적용, 82회 중 55회)이며, 드물게는 공개된 해답(artifact)을 가져와 그대로 다듬는 경우도 있었음(82회 중 6회).
  • Table 1a 기준 Swap Reduction, Rosetta, Denoising 등 8개 과제에서 기존 최고 기록 경신, 3개 과제에서 동률. Denoising에서는 SimpleTES 대비 비용 6.9배 절감(약 $38.45 vs $265.39)하면서 동등 이상 성능 달성.
  • Top-K, EvoX 스캐폴드에 EvoDuet의 검색 루프를 결합해도 Sums/Diffs, Denoising 과제에서 추가 성능 향상 확인.

한계점

  • 효과가 모델 능력에 크게 의존한다: 상대적으로 약한 Qwen3.5-9B에서는 오라클 문서(정답에 가까운 문서)를 직접 줘도 도움이 되지만, 스스로 검색하고 활용을 판단해야 하는 EvoDuet 설정에서는 오히려 성능이 떨어졌다. 즉 "검색·적용 능력을 모두 갖춘 모델"에서만 공진화 효과가 나타난다.
  • 이미 기존 스캐폴드(OpenEvolve)가 95% 이상의 NDG를 달성한 "쉬운" 과제에서는 EvoDuet의 추가 이득이 거의 없다(중앙값 0.0%).
  • 가상 증거 점수로 유망하다고 예측된 문서라도 실제로는 더 나쁜 해를 유도하는 경우가 전체의 상당수(82회 런 중 29회)에 달해, 예측은 참고용일 뿐 반드시 실제 평가로 검증해야 한다.
  • 웹 검색을 반복적으로 수행하는 데 추가 비용이 들며(과제별 평균 약 $45.56), 공개 아티팩트를 그대로 재사용하는 경우 출처 표기·검증 등 윤리적 고려가 필요하다고 저자들도 명시. 생성된 프로그램은 다른 환경에 적용하기 전에 독립적인 검증이 필요하다.
  • 본 논문에서 다룬 과제들은 결정론적이고 검증 가능한 평가자가 존재하는 상황에 한정되어 있어, 평가자가 모호하거나 노이즈가 큰 실제 과학 문제로의 일반화는 추가 검증이 필요하다.

시사점

EvoDuet은 "검색 도구를 추가하는 것"과 "검색을 해의 진화와 함께 진화시키는 것"이 질적으로 다르다는 점을 명확히 보여준다. 단순히 해 루프 안에 검색 도구를 넣으면 똑같은 페이지만 반복 검색하다 정체되지만, 질의 자체를 별도의 최적화 루프로 분리해 지식 공백에 맞춰 진화시키면 더 다양한 문서를 찾고 더 오래 성능을 끌어올릴 수 있다. 이는 LLM 에이전트 설계에서 "언제 외부 지식을 찾을지"를 모델 스스로 판단하게 하는 게이팅 메커니즘과, "검색 품질을 후보 생성 전에 미리 예측"하는 대리 신호 설계가 비용 효율적인 과학적 발견 파이프라인에 중요한 구성 요소가 될 수 있음을 시사한다. 다만 이러한 이점이 모델의 검색-활용 능력에 크게 좌우된다는 점은, 향후 에이전트형 발견 시스템을 설계할 때 백본 모델의 "검색 결과를 올바르게 반영하는 능력" 자체를 별도로 강화하거나 평가해야 함을 보여준다.
