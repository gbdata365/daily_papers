IQuest-Q1: Advancing Foundation Capabilities for Agentic CLI Systems

IQuest-Q1: 에이전틱 CLI 시스템을 위한 기반 역량 강화

IQuest-Q1은 총 3,200억(320B) 파라미터 중 150억(15B)만 활성화되는 희소 MoE 구조를 기반으로, 사전학습·중간학습·후학습(SFT+RL+멀티티처 온폴리시 증류+모델 머징)으로 이어지는 3단계 파이프라인을 통해 CLI(커맨드라인 인터페이스) 환경에서 동작하는 에이전트형 모델의 코딩·범용 작업·보안 역량을 종합적으로 강화한 오픈소스 파운데이션 모델이다.

한 줄 요약

IQuest-Q1은 총 3,200억(320B) 파라미터 중 150억(15B)만 활성화되는 희소 MoE 구조를 기반으로, 사전학습·중간학습·후학습(SFT+RL+멀티티처 온폴리시 증류+모델 머징)으로 이어지는 3단계 파이프라인을 통해 CLI(커맨드라인 인터페이스) 환경에서 동작하는 에이전트형 모델의 코딩·범용 작업·보안 역량을 종합적으로 강화한 오픈소스 파운데이션 모델이다.

배경 및 문제의식

LLM 기반 에이전트는 단순 텍스트 생성이 아니라 반복적인 추론·행동·환경 상호작용을 통해 과제를 수행하며, 그중 커맨드라인 인터페이스(CLI)는 모델이 도구를 사용하고 파일에 접근하며 코드를 실행하는 가장 범용적인 상호작용 창구로 자리잡았다. 따라서 더 강력한 에이전트형 모델을 만들기 위해서는 CLI 환경에서의 안정적인 도구 사용, 다양한 에이전트 하니스(Claude Code, Codex, OpenCode 등) 간 호환성, 장기 호흡의 추론·실행 능력이 필수적이라는 문제의식에서 연구가 시작되었다. 기존 모델들은 특정 하니스나 과제 유형에 과적합되거나, 실세계 CLI 작업에서 요구되는 반복적 디버깅·검증 과정에 취약한 한계가 있었다.

핵심 기여

  • IQuest-Q1 모델 공개: 총 320B/활성 15B 파라미터의 희소 MoE 구조를 가진 오픈 웨이트 에이전트 모델로, 범용 작업·코딩 에이전트·CLI 상호작용 역량을 통합적으로 갖추고 커뮤니티 연구를 위해 가중치를 공개.
  • CLI 중심 학습 파이프라인: 사전학습 단계부터 CLI 기반 에이전트 상호작용에 필요한 능력을 단계적으로 구축하고, 후학습에서는 과제·환경 합성, 멀티스캐폴드 RL, MOPD(멀티티처 온폴리시 증류)로 여러 전문가 모델의 역량을 하나의 모델로 통합.
  • 인간 감독하의 반복적 모델 개발(Human-on-the-loop RSI): IQuest-Q1 자신이 모델 개발 인프라에 참여하여 성능 한계를 진단하고 개선안을 제안하며, 인간의 승인을 받아 다음 세대 모델 개선에 기여하는 재귀적 자기개선 파이프라인을 실증.

방법론

아키텍처: Transformer 기반 희소 MoE(총 88개 레이어, 은닉 차원 3,072, 라우팅 전문가 256개 중 8개 활성화)에 슬라이딩 윈도우 어텐션(SWA)과 전체 어텐션(FA)을 3:1 비율로 혼합한 하이브리드 구조를 사용한다. Query-Key 정규화(QKNorm)와 클리핑, 부분 RoPE, 쿼리 인식 싱크 토큰, 그리고 Pre-Norm과 Post-Norm의 장점을 결합한 'Stable SplitNorm'(어텐션 입력은 정규화하되 FFN 입력은 비정규화 상태로 유지)을 적용해 깊은 레이어의 활용도를 높였다. 최적화에는 Muon 옵티마이저와 μP(뮤 파라미터화)를 결합해 폭(width)과 깊이(depth) 양방향으로 학습률을 소규모 프록시 모델에서 목표 모델로 전이할 수 있도록 했으며, 추론 가속을 위해 다중 토큰 예측(MTP) 레이어를 재귀적 드래프터로 변환해 추측 디코딩에 활용한다.

학습 단계: (1) 사전학습은 29T 토큰 규모로 2단계 커리큘럼을 적용해 2단계에서 코드·STEM 데이터 비중을 40%에서 70%까지 높인다. (2) 중간학습은 자연어 코퍼스, QA, 에이전트 궤적 데이터를 결합하고 문맥 길이를 32K→128K→512K로 점진적으로 확장하며, 100만 개 이상의 실행 가능한 컨테이너화 환경에서 에이전트 궤적을 대량 수집한다. (3) 후학습은 SFT(2단계) 이후 환경 중심 RL(GRPO 기반, 멀티 하니스·멀티버전 에피소드)과 4개의 고정된 전문가 모델(사용자경험 전문가, 멀티하니스 전문가, 장기추론 전문가, 범용 에이전트 전문가)로부터의 지식을 증류하는 MOPD를 결합한다. 마지막으로 서로 다른 단계·전문가의 체크포인트를 파라미터 델타 기반으로 병합하는 '모델 머징'을 통해 충돌을 최소화하며 하나의 최종 모델로 통합한다. 보상 해킹을 방지하기 위해 환경 준비, 실행 중 검사, 궤적 감사의 3중 안전장치도 적용했다.

실험 설정 및 결과

DeepSWE v1.1, SWE-Bench Pro, NL2Repo-Bench, CyberGym, Terminal-Bench 2.1/3.0/4.0, PaperBench, LiveCodeBench 등 코딩·에이전트 벤치마크와 GPQA Diamond, Humanity's Last Exam, JobBench, Agents' Last Exam, BrowseComp, WideSearch 등 범용 능력 벤치마크, 그리고 자체 제작한 IQuest-CLIBench(인간-에이전트 협업 및 사용자 경험 평가용)를 사용해 Claude Opus 5, GPT-5.6 Sol 같은 프로프라이어터리 모델과 GLM-5.3-Flash, DeepSeek-V4-Flash, Tencent Hy3, MiniMax M3 같은 오픈소스 모델과 비교했다. IQuest-Q1은 DeepSWE v1.1에서 64.6점, CyberGym에서 84.5점, Terminal-Bench 2.1에서 83.2점을 기록했고, 일반 능력에서는 GPQA Diamond 93.3점, BrowseComp 85.5점, Toolathlon-Verified 75.0점 등 다수 벤치마크에서 비교 대상 오픈소스 모델들을 능가하거나 비등한 성능을 보였다. 다만 Humanity's Last Exam(도구 미사용 39.2점, 도구 사용 55.7점)에서는 상대적으로 낮은 점수를 보여 최상위 난이도의 전문가 수준 추론에는 아직 개선 여지가 있음을 확인했다. 또한 실제 사이버보안 전문가와의 3일간 협업 실험에서 IQuest-Q1 보조로 30건의 취약점 보고서를 생성해 모두 검증에 성공했다는 실사용 사례도 제시했다.

한계점

  • 입력 모달리티 제한: 이미지·음성·비디오 등 네이티브 멀티모달 입력을 지원하지 않고 텍스트 입력만 가능하다.
  • 출력 신뢰성 문제: 생성된 설명이나 코드가 틀릴 수 있어, 과제에 맞는 테스트로 검증·리뷰가 필요하다.
  • 도구 통합 의존성: IQuest 특화 챗 템플릿 형식의 도구 호출을 사용하므로, 호환 가능한 서빙 파서와 에이전트 하니스가 필요하다.
  • 실세계 CLI 작업의 어려움: 반복적 디버깅과 검증이 필요한 실제 CLI 작업에서 제약을 간과하거나 실패한 시도를 반복하거나 문제를 해결하지 못한 채 남기는 경우가 있어 인간의 감독이 여전히 필요하다.
  • 지속적 개발 필요성: 모델의 역량과 신뢰성에 여전히 한계가 있으며, 저자들은 향후에도 지속적으로 개선할 계획이라고 밝혔다.

시사점

IQuest-Q1은 아키텍처(Stable SplitNorm, Muon+μP), 데이터 커리큘럼(사전학습-중간학습-후학습 3단계), 그리고 다중 전문가 지식 증류(MOPD)와 모델 머징을 유기적으로 결합해 '에이전트형 CLI' 특화 파운데이션 모델을 구축하는 구체적 청사진을 제시한다. 특히 모델이 스스로 결함을 진단하고 데이터 개선안을 제안해 인간 승인 하에 다음 세대 학습에 반영되는 human-on-the-loop 재귀적 자기개선(RSI) 프로세스는, 완전 자동화된 자기개선이 아니더라도 모델 개발 주기를 가속화할 수 있는 실용적 경로를 보여준다. 이는 향후 오픈소스 에이전트 모델들이 벤치마크 성능뿐 아니라 실제 CLI 하니스 호환성과 보상 해킹 방지 같은 운영상의 디테일까지 함께 고려해야 함을 시사한다.
