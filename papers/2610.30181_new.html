Deep Search in Real-World Web Environments

실제 웹 환경에서의 딥서치(OpenDS-World)

실제 웹 환경에서 영상·이미지·문서·인터랙티브 페이지 등 이질적인 정보원을 자율적으로 탐색·접근·연결해야 하는 "OpenDS" 과제와, 이를 평가하는 200개 과제 규모의 벤치마크 "OpenDS-World"를 제안하고, 12개 최신 모델을 평가한 결과 최고 성능 모델도 정확도 39.0%에 그쳐 사람(21.1%)보다는 높지만 여전히 한계가 크다는 것을 보인 연구.

한 줄 요약

실제 웹 환경에서 영상·이미지·문서·인터랙티브 페이지 등 이질적인 정보원을 자율적으로 탐색·접근·연결해야 하는 "OpenDS" 과제와, 이를 평가하는 200개 과제 규모의 벤치마크 "OpenDS-World"를 제안하고, 12개 최신 모델을 평가한 결과 최고 성능 모델도 정확도 39.0%에 그쳐 사람(21.1%)보다는 높지만 여전히 한계가 크다는 것을 보인 연구.

배경 및 문제의식

  • Deep Search(딥서치) 에이전트는 복잡한 정보 탐색·연구 과제를 자율적으로 해결하는 것을 목표로 하며, 최근 멀티턴 검색·웹 브라우징·툴 사용 능력이 크게 발전했다.
  • 그러나 기존 평가 벤치마크들은 실제(open) 웹 환경이 가진 복잡성을 충분히 반영하지 못한다. 저자들은 그 복잡성을 세 가지로 정리한다.
  • 다양한 모달리티(Diverse Modalities): 텍스트·이미지·오디오·비디오가 혼재.
  • 이질적 포맷(Heterogeneous Formats): HTML, PDF, XML, Parquet 등 서로 다른 구조와 처리 방식이 필요한 자료 형식.
  • 상호작용적 접근 요건(Interactive Access Requirements): 단순 조회가 아니라 페이지 탐색, 인터페이스 조작, 파라미터 변경, 파일 다운로드 등 능동적 조작이 있어야만 얻을 수 있는 정보.
  • 기존 벤치마크들은 이 세 속성이 얽혀 있는 실제 웹의 증거 수집 과정을 체계적으로 다루지 못했다는 것이 이 논문의 문제의식이다.

핵심 기여

  • OpenDS(Open-Web Deep Search) 과제 정의: 에이전트가 사실 질문과 초기 단서(영상)로부터 출발하여, 모달리티·포맷·접근 방식이 서로 다른 복수의 웹 정보원을 자율적으로 탐색·접근·연결해 유일하고 검증 가능한 사실 답을 도출하도록 요구하는 과제.
  • OpenDS-World 벤치마크 구축: 문화·일상·과학·경제·역사·자연·사회·기술 등 8개 도메인에 걸친 200개 고난도 과제로 구성. 4개 모달리티, 42종의 파일/데이터 포맷, 7가지 접근(access) 유형을 포괄하며, 독립적인 사람 검증을 거쳐 증거의 타당성과 답의 유일성을 확보.
  • 대규모 모델 평가: 통일된 도구 환경과 실행 프로토콜 하에서 GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5.5, Claude Fable 5.1, Gemini 3.8 Flash, Qwen3.8-Max/Flash, DeepSeek-V4.1-Flash/V4-Pro, Kimi K3, GLM-5.3(-Flash) 등 12개 최신 모델을 동일 조건에서 비교.
  • 사람 대비 성능 분석: 1,000회의 독립적 사람 시도(50명 참가자)를 통해 사람의 실제 풀이 정확도(21.1%), 소요 시간, 체감 난이도를 함께 수집하여 모델-사람 간 난이도 캘리브레이션 데이터를 제공.
  • 실패/비용 분석: 툴 사용 패턴, 검색 비용(시간·호출 수·토큰), 종료 행동, 실패 복구 전략에 대한 심층 분석을 통해 "더 많은 자원 소모가 곧 더 높은 정확도를 의미하지 않는다"는 점을 실증.

방법론

OpenDS-World는 3단계 파이프라인으로 구축된다. 1. 실세계 앵커(Real-world Anchor) 선정: 8개 도메인에서 공개 영상 500개 후보를 수집하고, 전문 주석자가 연속된 프레임과 오디오를 분석해 시청각적으로만 식별 가능한 엔티티(앵커)를 지정한다. 앵커는 Wikidata 항목과 유일하게 대응되도록 하여, 단순 텍스트 검색만으로 풀리지 않게 만든다. 2. 공개 웹 증거 확장(Open-Web Evidence Expansion): 현재 노드를 기준으로 검색 질의를 만들고 구글 검색으로 후보 웹 소스를 수집, 검증 가능하고 의미적으로 관련된 소스를 선택해 다음 노드(새 엔티티)를 도출한다. 이 과정을 반복해 모달리티·포맷·접근 유형이 다양해지도록 증거 경로(evidence path)를 확장하며, 각 노드는 반드시 복수의 독립 소스로 교차 검증된다. 3. 질문 역변환(Question Inversion): 완성된 증거 경로의 중간 노드들은 직접 노출하지 않고, 각 노드를 앞선 증거에서 파생된 간접 서술(단서)로 변환하여 질문을 구성한다. 개별 단서만으로는 정답 엔티티가 드러나지 않고, 단서들이 결합되어야 후보 공간이 좁혀져 유일한 참조 답이 도출되도록 설계한다.

이후 10명의 독립 검토자가 증거 경로의 사실 정확성(evidence validity)과 질문의 명확성·제약 일관성·답 유일성(task validity)을 모두 검증하여 최종 200개 과제를 확정한다.

평가 단계에서는 모든 모델에 동일한 통합 에이전트 하네스(harness)를 제공한다: (1) 텍스트/이미지/영상 검색을 지원하는 Search Tool, (2) 웹 탐색·클릭·입력·스크롤·스크린샷을 지원하는 GUI Tool, (3) 입력 및 외부 영상의 프레임 검사와 자막 추출을 지원하는 Other Tools. 검색 단계는 샘플당 최대 3,600초, 툴 호출 총 100회로 제한되며, 한도 도달 시 툴이 비활성화된 상태에서 수집된 증거만으로 최종 답을 생성하게 한다. 정답 판정은 Qwen3.8-27B를 LLM judge로 사용해 참조 답과 모델 답의 의미적 동치 여부로 채점한다.

실험 설정 및 결과

  • 주요 결과: 200개 과제 전체에서 GPT-6 Astra가 39.0%로 최고 정확도를 기록했고, Claude Opus 5.5(38.0%), Gemini 3.8 Flash(36.5%), Claude Fable 5.1(33.5%)이 뒤를 이었다. GPT-5.6 Sol과 Qwen3.8-Max는 각각 28.0%, 25.5%였고, 나머지 4개 모델은 20% 미만(최저 GLM-5.3 13.5%)에 그쳤다. 최고 성능 모델도 200개 중 122개(61.0%) 과제에서 실패했다.
  • 난이도별 성능: 사람 풀이자 5명 중 정답자 수로 정의한 Low/Medium/High 난이도 구간에서, 전 모델 평균 정확도는 Low 39.66% → Medium 23.50% → High 16.76%로 하락했다. 다만 모델별로 단조 감소는 아니며, Gemini 3.8 Flash는 High 구간에서 오히려 가장 높은 28.24%를 기록했다.
  • 사람 평가: 1,000회 독립 시도 전체 정답률은 21.1%, 과제 단위로는 200개 중 115개(57.5%)가 5명 중 최소 1명에게는 풀렸고 85개(42.5%)는 전원 실패했다. 참가자는 과제당 평균 12.92시간(20문항 세트 기준), 체감 난이도는 평균 3.884/5로 매우 높게 평가됐다.
  • 비용/자원 분석: 툴 호출 수·소요 시간·토큰 소비가 정확도와 단순 비례하지 않았다. 예컨대 Gemini 3.8 Flash는 GPT-6 Astra의 약 5.22배 토큰을 쓰고도 정확도는 더 낮았고, DeepSeek-V4-Pro는 약 2.39배의 시간을 쓰고도 12.5%에 그쳤다.
  • 툴 사용 패턴: 모델마다 Search/GUI/Other 툴 비중이 크게 다르다(예: GPT-5.6 Sol은 Search 74.5% 집중, Claude Opus 5.5·Qwen3.8-Flash는 GUI 비중이 51~49%로 유사하지만 정확도는 38.0% vs 12.0%로 큰 차이). 같은 범주의 툴을 연속 호출하는 경향(Search→Search, GUI→GUI)이 대부분의 모델에서 지배적으로 나타났다.
  • 오류/종료 분석: GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5.5는 각각 69.0%, 65.0%, 60.5%의 과제에서 자연 종료(답을 스스로 생성)했지만, Qwen3.8-Flash는 6.5%만 자연 종료하고 80%가 툴 호출 한도에 도달했다. 툴 실패는 전체 호출의 일부(2.83~9.42%)에 불과하지만 실행 시간의 19~62%를 소모했으며, 실패 후 가장 흔한 대응은 툴 전환이었다.
  • 예산 소진 분석: 모델별로 1시간 시간 제한 또는 100회 호출 제한 중 하나 이상에 도달한 과제 비율이 16.5%(Claude Opus 5.5)에서 81.5%(Qwen3.8-Flash)까지 큰 편차를 보였다. GPT-6 Astra와 Claude Opus 5.5는 예산 소진이 적음에도 정확도가 40%를 넘지 못해, 소스 선택·증거 통합·종료 판단의 효율성이 핵심 병목임을 시사한다.

한계점

  • 최고 성능 모델도 과제의 61%를 풀지 못하는 등, 현재 프런티어 모델들은 실제 웹 환경의 복잡한 딥서치 과제를 안정적으로 수행하지 못한다.
  • 툴 호출 수나 시간, 토큰 소비를 늘리는 것이 정확도 향상으로 이어지지 않아, 정보원 선택과 툴 조정, 탐색 전략 조정, 장기(long-horizon) 탐색 관리 능력이 근본적으로 부족함을 보여준다.
  • 툴 실패가 실행 시간의 상당 부분(최대 약 62%)을 소모하며, 실패 후 효과적인 복구(인자 수정, 툴 전환 등) 전략이 모델별로 미흡하다.
  • 다수 모델이 100회 호출 혹은 1시간 제한과 같은 예산 한도에 쉽게 도달하여, 장기 실행에서의 효율적 예산 관리가 큰 과제로 남아 있다.
  • 자연 종료(스스로 답을 생성하며 종료)가 되었다고 해서 정답률이 높은 것은 아니며, 종료 판단(스스로 충분한 증거를 모았다고 판단하는 능력)과 실제 정답률 사이에 괴리가 있다.

시사점

  • 저자들은 OpenDS-World가 실제 웹에서의 장기 탐색(long-horizon search)과 에이전트의 재귀적 자기개선(recursive self-improvement) 연구를 위한 구체적인 평가 기반을 제공한다고 주장한다.
  • 벤치마크가 모달리티·포맷·접근 방식이라는 세 축을 체계적으로 조합함으로써, 향후 딥서치 에이전트가 정보원 선택, 크로스모달·크로스소스 증거 통합, 상호작용적 접근, 실행 예산 관리 능력을 균형 있게 갖추도록 설계·훈련하는 데 참고 지표로 활용될 수 있다.
  • 사람 대비 성능 격차(모델 39.0% vs 사람 21.1%)는 모델이 특정 측면(예: 대규모 정보 처리 속도)에서는 사람을 능가하지만, 신뢰할 수 있는 증거 통합과 전략적 탐색에서는 여전히 사람과 다른 양상의 한계를 지님을 시사한다.
