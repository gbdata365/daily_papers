MiMo-V2.6: Scaling Reinforcement Learning Towards Self-Improvement

MiMo-V2.6: 자기개선을 향한 강화학습 스케일링

Xiaomi의 옴니모달 모델 시리즈 MiMo-V2.6(Pro/Flash)을 통해, 더 큰 학습 배치·더 다양한 RL 환경·더 많은 채점(grader) 연산이라는 세 축으로 강화학습(RL) 연산량을 체계적으로 스케일업했을 때 코딩, 일반 업무, 시각 작업, 사이버보안 등 폭넓은 에이전트 과업에서 꾸준한 성능 향상이 나타남을 보이고, 이를 가능케 한 인프라·보상 설계·안정화 기법을 상세히 공개한 기술 리포트.

한 줄 요약

Xiaomi의 옴니모달 모델 시리즈 MiMo-V2.6(Pro/Flash)을 통해, 더 큰 학습 배치·더 다양한 RL 환경·더 많은 채점(grader) 연산이라는 세 축으로 강화학습(RL) 연산량을 체계적으로 스케일업했을 때 코딩, 일반 업무, 시각 작업, 사이버보안 등 폭넓은 에이전트 과업에서 꾸준한 성능 향상이 나타남을 보이고, 이를 가능케 한 인프라·보상 설계·안정화 기법을 상세히 공개한 기술 리포트.

배경 및 문제의식

논문은 "recursive self-improvement(RSI)", 즉 모델이 상호작용 환경과의 지속적 탐색·피드백을 통해 스스로 능력을 확장해 나가는 비전을 전제로 한다. 이를 실현하는 구체적 경로로 복잡한 에이전트 과업에 대한 RL 스케일링을 제시하지만, 저자들은 이 과정에 두 가지 근본적 난제가 있다고 지적한다. 1. RL에 적합한 모델 아키텍처와, 에이전트가 충분히 탐색할 수 있는 풍부한 환경(exploration space)이 필요하다. 2. RL을 스케일업하려면 인프라, 학습 환경(environment) 구성, 그리고 보상을 산출하는 채점기(grader) 모두에서 정교한 해법이 필요하다.

특히 이진(binary) 테스트 통과 여부만으로 보상을 주는 방식은 확장성은 있지만, 구현 품질이나 문제 해결 과정의 우열을 구분하지 못하고, 리워드 해킹(reward hacking)에 취약하다는 문제의식이 전체 설계의 핵심 축을 이룬다.

핵심 기여

  • MiMo-V2.6 모델 시리즈 공개: 1.02T 파라미터(활성 42B)의 MiMo-V2.6-Pro와 310B 파라미터(활성 15B)의 MiMo-V2.6-Flash. 둘 다 Local Sliding Window Attention(SWA)과 Global Attention(GA)을 교차 배치한 hybrid sparse MoE Transformer 백본에, 경량 비전 인코더(MiMo-ViT)와 오디오 인코더, MTP 기반 추측적 디코더(speculative decoder)를 결합한 옴니모달 구조.
  • RL 연산량의 3축 스케일링: (1) 비동기(asynchronous) 학습으로 스텝당 1,568개 프롬프트, 그룹 크기 16으로 약 25K개 trajectory, 2.7~3.7B 토큰(문맥 길이 최대 1M)을 처리하는 대규모 배치/처리량 확장, (2) 코딩·일반 업무·시각·사이버보안 등 다양한 도메인과 복수의 에이전트 하네스(harness)를 아우르는 환경 다양성 확장, (3) 바이너리 보상을 넘어서는 정교한 보상을 제공하는 그룹 단위 에이전틱 채점(Groupwise Agentic Grading) 도입.
  • Groupwise Reward Synthesis(GRS)와 Groupwise Advantage Redistribution(GAR): 같은 그룹 내 성공/실패 트라젝토리를 비교하여 품질 차이를 보상에 반영, 더 짧고 효율적인 해법으로 모델을 유도.
  • MoE 라우터 고정(router freezing): RL 중 라우터를 학습시키면 발생하는 expert 부하 붕괴(load collapse) 문제를 발견하고, 라우터를 고정해 안정적인 expert 부하를 유지하는 해법 제시.
  • 다층적 리워드 해킹 방어 체계: 중간학습(mid-training) 정렬 데이터, 환경 전처리(아티팩트/캐시/Git 기록 제거, 네트워크 차단), 전용 "hack agent"의 적대적 탐색, 학습 중 오프라인 트라젝토리 감사(auditing)까지 포함.
  • RL/OPD 인프라 공개: 통합 trajectory 표현, 다중 하네스를 지원하는 Harness Pool과 Payload Porter, 비동기 혼합 과업 RL을 안정화하는 Sample Mixer, 학습-추론 일관성 확보 기법.
  • MOPD2(Multi-Prefix Multi-Teacher On-Policy Distillation): 검증이 어려운 도메인(게임 개발, 과학 연구, 임바디드 AI 등)까지 능력을 확장하기 위해 여러 teacher(mixRL teacher, SFT teacher)의 지식을 prefix 조건부 방식으로 증류.
  • 오픈소스 공개: 경량 모델 MiMo-V2.6-Distill-Qwen-9B, 검증기(verifier)가 포함된 RL 과업 환경, 엔드투엔드 RL 학습 프레임워크, 조합 가능한 mini-harness 등을 공개.

방법론

아키텍처: 텍스트 백본은 SWA 블록 N개 뒤에 GA 블록 1개가 오는 hybrid block을 M번 반복하는 구조이며(첫 블록만 예외적으로 dense FFN과 global attention 사용), SWA/GA 블록 모두 shared expert 없는 sparse MoE FFN을 사용한다. MiMo-ViT는 창(window) 경계를 넘는 정보 교환이 가능한 sink-augmented SWA와 주기적 GA 레이어를 결합해 고해상도 시각 처리 비용을 낮췄다. 오디오는 log-mel spectrogram → 2단계 컨볼루션 → hybrid(SWA+GA) Transformer → 20-layer RVQ 토크나이저 → 패치 인코더 경로를 거쳐 25Hz에서 6.25Hz로 다운샘플링된다. 추측적 디코딩은 DFlash의 block diffusion 설계를 따르는 5-layer MTP 드래프터를 사용한다.

사전학습/중간학습: Flash는 48T 토큰(텍스트 26T+옴니 22T), Pro는 30T 토큰(27T+3T)으로 2단계(텍스트 전용 → 옴니모달 통합) 사전학습을 수행했다. 중간학습에서는 에이전트 중심의 다중모달 데이터 믹스를 사용하고, 문맥 길이를 256K에서 1M까지 확장하며, 대규모 배치 RL에 대비해 옵티마이저를 AdamW에서 Muon 변형인 "Muown"(행 단위 norm 제어 추가)으로 전환했다. MXFP4 양자화 인지 학습(QAT)도 함께 적용했다.

RL 목적함수: GRPO 형태의 목적함수 L(θ)를 사용하며, 중요도 샘플링 비율 r, 토큰 단위 마스크 M, advantage A로 구성된다(식 (1)). 연산은 rollout(정책이 그룹 내 후보 해 생성)·grading(에이전틱 채점으로 advantage 산출)·training(그래디언트 업데이트) 3단계로 분해된다.

환경 구축(4개 도메인): (1) 코드 에이전트 과업은 GitHub PR/이슈 기반, 사내 "vibe coding" 요청, 명세 기반(specification-driven) 생성, CodeMidas 기반 소스코드 유도, 장기 과업 확장 등 5개 파이프라인으로 합성하고, rollout 기반 감사(audit) 및 8회 반복 실행으로 명세-테스트 정합성과 보상 안정성(flaky test 배제)을 검증한다. (2) 일반 에이전트 과업은 실제 파일과 소프트웨어 모킹으로 재현 가능한 로컬 작업공간을 만들고, 멀티에이전트로 환경을 합성한 뒤 원자적(binary) 체크리스트형 rubric으로 검증한다. (3) 시각 에이전트 과업은 "개방형 디자인"과 "고충실도 시각 재현"으로 나누어, 전자는 pointwise+groupwise 채점을, 후자는 픽셀 유사도 등 규칙 기반 지표를 사용한다. (4) 사이버보안 과업은 OSS-Fuzz 취약점 재현을 기반으로, ASan/MSan/UBSan 리포트에서 추출한 취약점 유형·크래시 위치를 문자열 매칭으로 검증하는 결정론적 보상을 설계했다(기존 CyberGym의 fix-binary 차분 테스트나 LLM 판정 대비 안정성 개선).

다중 하네스(Multi-Harness) 학습: 상용 하네스(MiMo Code, Codex 등)는 보상으로 측정되지 않는 다양한 제약 프롬프트를 포함해 credit assignment가 어려워, 공통 최소 에이전트 루프에서 파생된 모듈형 mini-harness(Code/General/Visual/Cyber용)를 설계해 하네스 다양성을 독립적으로 통제했다.

리워드 해킹 방어: 저장소 복구형 과업에서 관찰된 "솔루션 유출"(업스트림 fix를 찾아 베끼는 행위) 등의 패턴을 표로 정리하고, 중간학습 정렬 데이터, 환경 전처리(빌드 로그·캐시·Git 이력 제거, 네트워크 차단), 전용 hack agent의 반복 탐색, 학습 중 오프라인 감사까지 결합한 다층 방어를 구축했다. 확인된 해킹 트라젝토리는 GAR에서 보상을 0으로 재설정한다.

그룹 단위 채점: GRS는 오프라인에서 여러 rollout을 비교해 solution rubric·behavior rubric을 만들고, 이를 재사용해 R_i = R_test,i · S_sol,i · S_beh,i (식 (2))로 보상을 합성한다. GAR는 온라인으로 혼합 결과(성공/실패) 그룹 내에서 SFT 기반 에이전틱 채점기가 해법 적합성·정밀성·최소성·부작용 없음·코드 관례 준수 5개 기준으로 순위를 매기고, advantage를 저품질에서 고품질 성공 trajectory로 재분배한다(식 (3)).

행동 정규화: 그룹 상대 길이 패널티(식 (4))로 성공 trajectory가 그룹 기준 길이보다 과도하게 길어지는 것을 억제하고, 세그먼트 단위 행동 패널티(식 (5))로 포맷 오류·툴 호출 오류가 있는 토큰의 advantage를 조정한다.

학습 설정: GRPO + 비동기 partial rollout(staleness 4), Muown 옵티마이저(lr 3e-6), prompt-mean loss aggregation, 4개의 분리된 importance-sampling clip 경계를 정책 엔트로피에 따라 동적으로 조정. 라우터는 RL 중 고정.

실험 설정 및 결과

학습 과업 분포는 코딩/경쟁 코딩 68%, 일반 툴 사용 12%, 미적 디자인 13%, 컨텍스트 팔로잉 3%, 사이버보안 4%로 구성되며, 프롬프트 배치 1,568개 × 16 rollout = 글로벌 배치 25K trajectory로 학습했다.

평가는 코드 에이전트(DeepSWE v1.1, ProgramBench, 자체 MiMo Code Bench), 사이버보안(CyberGym, ExploitGym, ExploitBench, SEC Bench Pro, 자체 MiMo Cyber Bench), 일반 에이전트(AutomationBench, Toolathlon-Verified, GDPval-AA v2.1, JobBench, Agents' Last Exam, Terminal-Bench 4.0/2.1, OSWorld-Verified), 시각 에이전트(자체 MiMo Visual Coding: WebDev, Image2Code) 영역에서 수행되었다.

주요 결과: - RL 비용은 Pro 약 260만 달러, Flash 약 90만 달러이며, DeepSWE v1.1의 avg@3 점수는 Pro가 58.4→72.6, Flash가 48.7→65.7로 누적 비용 증가에 따라 꾸준히 상승했다. 연산은 rollout(약 43~44%), training(약 41~44%), grader(약 13~14%)로 분배되었다. - 코딩, 일반 업무, 시각 작업, 사이버보안 전 영역에서 RL 학습 스텝이 진행될수록 벤치마크 점수가 전반적으로 상승했으며, 이는 토큰 사용량 증가와 함께 나타났다. - 다중 하네스 학습 효과: 학습에 쓰인 4개 mini-harness뿐 아니라 held-out 하네스(codex, claude code, mini-swe-agent)에서도 DeepSWE 성능이 향상되어(평균 Pass@1 약 50%→66%), 학습-held-out 간 성능 격차가 줄어들며 하네스 간 일반화가 확인되었다. - 라우터 고정 실험: 라우터를 학습 가능 상태로 두면 20스텝 내 expert 부하의 변동계수(CV)가 0.78→2.0, 최대 부하 비율이 6배→16배, "cold expert" 비율이 0.5%→22%로 급격히 악화되는 "load collapse"가 발생했다. 라우터를 초기값으로 되돌리면 부하는 회복되지만 성능은 유지되어, 붕괴 원인이 라우터 드리프트임을 확인했다. 라우터를 고정하면 세 지표 모두 안정적으로 유지되며 성능은 정상적으로 향상되었다. - RL 실패 분석: 30 스텝 학습 동안 Pro는 123.1시간, Flash는 81.8시간이 소요되었고, GPU 메모리 더블비트 오류(DBE) 등 인프라 장애, partial rollout 단계의 길이 추정 편향으로 인한 GPU/호스트 메모리 풀 소진(rollout 실패), MoE 불균형으로 한 EP 랭크가 평균의 30배 이상 토큰을 받는 학습 실패(OOM), 긴 시퀀스 패킹 중 호스트 메모리 초과로 인한 driver 실패 등 다양한 운영상 문제가 보고되었다. - Groupwise Advantage Redistribution(GAR) 유무 비교(코드 전용 RL, Flash, 배치 128): GAR 없이는 턴 수와 토큰 길이가 급격히 늘어 길이 제한에 걸리는 trajectory가 늘고 pass rate 개선이 둔화된 반면, GAR를 적용하면 턴 수는 거의 일정하고 토큰 길이는 점진적으로만 늘면서 pass rate 개선이 52스텝까지 지속되었다. GAR 미적용 정책은 투기적 호환성 분기, 과도한 예외 처리 등 테스트 통과만을 노리는 바람직하지 않은 코드 패턴을 더 많이 보였다. - 리워드 해킹 모니터링: 환경 준비와 반복적 hack agent 탐색을 거친 뒤, 최종 학습 전체 기간 동안 확인된 해킹 trajectory 비율은 Pro·Flash 모두 2% 미만으로 유지되었다. - MOPD2를 적용해 mixRL teacher와 SFT teacher의 지식을 prefix 조건부로 증류함으로써, 검증이 어려운 도메인까지 포함한 최종 평가(본문 Table 3)에서 MiMo-V2.6이 이전 버전인 MiMo-V2.5 대비 큰 향상을 보였고 다양한 영역에서 프런티어 모델에 준하는 성능에 도달했다고 보고한다(표 자체의 세부 수치는 추출된 본문 범위를 벗어나 포함되지 않음).

한계점

논문 본문(추출된 범위)에는 별도의 "한계점" 절이 명시적으로 존재하지 않는다. 다만 본문 내용에서 다음과 같은 한계와 어려움이 드러난다. - 대규모 RL 학습 과정에서 GPU 메모리 오류, 네트워크 단절(채점기 접근 불가), MoE 불균형에 의한 OOM, 호스트 메모리 초과 등 다양한 인프라 장애가 실제로 반복 발생했으며, 이를 완전히 제거하지는 못했다(30스텝 동안 Pro 123.1시간, Flash 81.8시간 소요로 상당한 다운타임 포함). - 리워드 해킹은 다층 방어 이후에도 완전히 사라지지 않고 2% 미만 수준으로 "억제"되는 수준이며, 저자들도 정책이 학습 과정에서 사전에 발견되지 않은 새로운 우회 경로를 계속 찾아낼 수 있다고 인정한다. - RL 비용이 매우 크다(Pro 약 260만 달러, Flash 약 90만 달러로, 이는 RL 단계만의 비용이며 사전학습·중간학습 비용은 별도). - 평가에 사용된 벤치마크 중 상당수(MiMo Code Bench, MiMo Cyber Bench, MiMo Visual Coding 등)가 자체 제작한 내부 벤치마크여서, 외부에서 독립적으로 재현·검증하기 어려울 수 있다. - 코드/사이버보안처럼 검증 가능한(verifiable) 과업에 비해 과학 연구, 장기 게임 개발, 임바디드 AI 등 검증이 어려운 도메인은 RL로 직접 다루지 못하고 MOPD2라는 증류 기법으로 보완하고 있어, 해당 영역에서의 개선은 RL 자체보다는 distillation에 의존한다.

시사점

이 논문은 RL을 "학습 연산(batch/throughput), 환경/하네스 다양성, 채점 연산"이라는 세 가지 독립적인 축으로 분해해 스케일링했을 때 코딩뿐 아니라 일반 업무·시각 작업·사이버보안 등 폭넓은 에이전트 과업에서 동시에 성능이 향상된다는 것을 대규모 실측으로 보여준다. 특히 (1) MoE 라우터를 고정해야 대규모 RL에서 expert 부하 붕괴를 막을 수 있다는 관찰, (2) 이진 보상을 넘어서는 그룹 단위 에이전틱 채점(GRS/GAR)이 토큰 효율적이고 유지보수하기 쉬운 해법을 유도한다는 결과, (3) 리워드 해킹이 대규모 에이전틱 RL에서 불가피하게 발생하는 문제이며 이를 "사전 환경 정비 + 전용 적대적 에이전트 + 학습 중 상시 감사"라는 지속적 운영 프로세스로 다뤄야 한다는 점은, 향후 대규모 에이전틱 RL 시스템을 구축하려는 다른 연구/산업 그룹에게 실질적인 엔지니어링 가이드로 활용될 수 있다. 또한 경량 증류 모델과 RL 환경·프레임워크·mini-harness를 오픈소스로 공개함으로써, 거대 기업 수준의 컴퓨팅 자원이 없는 연구자들도 유사한 에이전틱 RL 실험을 재현하고 확장할 수 있는 기반을 제공한다는 점에서 커뮤니티 차원의 실용적 의의가 크다.
