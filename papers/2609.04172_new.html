Rethinking On-Policy Distillation of Large Language Models II: One Training Example

대형 언어모델의 온폴리시 증류 재고하기 II: 단 하나의 학습 예제

온폴리시 증류(OPD)를 단 하나의 학습 쿼리로 수백 스텝 동안 학습해도 전체 데이터로 학습한 것과 비슷한 성능 향상을 얻을 수 있음을 보이고, 그 이유가 "데이터는 과잉 공급되지만 알고리즘의 흡수 속도가 느리기 때문"임을 상태(state) 커버리지와 흡수율 분석으로 규명한다.

한 줄 요약

온폴리시 증류(OPD)를 단 하나의 학습 쿼리로 수백 스텝 동안 학습해도 전체 데이터로 학습한 것과 비슷한 성능 향상을 얻을 수 있음을 보이고, 그 이유가 "데이터는 과잉 공급되지만 알고리즘의 흡수 속도가 느리기 때문"임을 상태(state) 커버리지와 흡수율 분석으로 규명한다.

배경 및 문제의식

온폴리시 증류는 학생 모델이 직접 생성한 롤아웃에 교사 모델이 토큰 단위의 조밀한 분포 감독을 제공하는 방식으로, Qwen3, GLM-5, DeepSeek-V4 등 최신 후속학습 파이프라인에서 널리 쓰이고 있다. 기존 연구는 주로 알고리즘 관점에서 OPD의 작동 원리를 분석했지만, 학습 데이터가 OPD에 어떤 역할을 하는지, 데이터와 알고리즘이 어떻게 상호작용하는지는 규명되지 않았다.

핵심 기여

  • 단 하나의 쿼리만으로 학습하는 "원샷 OPD"가 수백 스텝 동안 계속 성능을 개선하며, 수학·코드·지시 따르기·에이전틱 도구 사용 등 4개 도메인과 3개 모델 계열에 걸쳐 전체 데이터 학습 성과의 상당 부분을 회복함을 실증
  • "상태 커버리지(state coverage)" 지표를 도입해, 단일 쿼리가 전체 데이터 OPD가 방문하는 상태 공간의 71.5%를 커버하며, 의미적으로 다양한 16개 쿼리만으로 98.9% 커버리지와 전체 데이터 수준의 성능을 달성함을 보임
  • "흡수율(absorption rate)"이라는 지표로 학생이 교사와의 격차를 줄이는 속도가 쿼리 개수와 무관하게 비슷한 속도로 느려짐을 보여, OPD가 "데이터 과잉·알고리즘 기아" 상태임을 규명
  • 멀티 티처 OPD, 콘텐츠가 거의 없는 템플릿, 도메인 외 WildChat 쿼리로도 유사한 효과가 재현됨을 보여 일반화 가능성 제시

방법론

OPD는 상태 s=(x,y_<i)마다 학생과 교사의 로그 확률 차이를 어드밴티지로 사용해 학생을 교사에 정렬시킨다. 저자들은 전체 데이터 OPD가 방문한 상태들을 교사의 최종층 은닉벡터로 표현하고 PCA 후 K-평균으로 200개 클러스터로 나누어, 특정 설정의 롤아웃이 도달하는 클러스터 비율을 "상태 커버리지"로 정의했다. 또한 매 스텝 학생-교사 간 남은 거리(distance)와 한 번의 업데이트가 그 거리를 얼마나 줄이는지(흡수율)를 별도로 추적해, 데이터 측면(상태 커버리지)과 알고리즘 측면(흡수 속도)을 분리해 분석했다.

실험 설정 및 결과

수학 추론에서 원샷 OPD는 300스텝에서 전체 데이터 OPD의 87%에 해당하는 성능 향상을 회복했고, 1000스텝에서는 72%를 유지했다. 이 효과는 R1-Distill-1.5B, Llama-3B-It, OLMo-7B-It-DPO 등 세 모델 계열과 코드 생성(73%), 지시 따르기(66%), 에이전틱 도구 사용(64%) 등 다른 도메인에서도 재현되었으며, 쿼리 난이도·응답 길이·샘플링 온도에 대해서도 강건했다. 상태 커버리지 분석에서 단일 쿼리는 300스텝까지 71.5%의 클러스터를 커버했고(대부분 초기 100스텝 내), 16개의 의미적으로 다양한 쿼리는 98.9% 커버리지로 전체 데이터 성능과 일치했다. 반면 흡수율은 1개, 4개, 16개, 전체(약 17,000개) 쿼리 모두에서 비슷한 속도로 감소했으며, 상태를 고정한 오프폴리시 학습도 200스텝 이상 지속적인 성능 향상을 보여 "고정된 상태 집합조차 흡수하는 데 수백 스텝이 걸린다"는 것을 확인했다. 멀티 티처 OPD에서도 도메인당 16개의 다양한 쿼리가 전체 데이터 성능의 101%를 회복했다.

한계점

콘텐츠가 거의 없는 템플릿이나 도메인 외 쿼리도 효과가 있다는 결과가 과제 내용 자체가 일반적으로 불필요하다는 것을 의미하지는 않으며, 실험에서 명시적 도메인 콘텐츠는 여전히 약 1점의 성능 차이를 만들었다. 원샷 RLVR와의 비교는 동일한 쿼리에서 수행되었지만, 이 두 방법의 근본적으로 다른 신호 구조(검증 가능한 결과 대 조밀한 분포 신호) 때문에 직접적인 일반화에는 한계가 있다.

시사점

데이터 큐레이션의 핵심 질문이 "얼마나 많은 문제를 모을 것인가"에서 "이 입력이 어떤 상태를 유도하는가"로 바뀌어야 함을 시사하며, 향후 연구가 OPD의 스텝 효율성(알고리즘이 공급된 감독을 더 빠르게 흡수하는 방법)에 초점을 맞춰야 함을 제안한다.
