3DCodeVerse: Exploring 3D Worlds as Code

3D코드버스: 코드로 탐색하는 3D 세계

3DCodeVerse는 코딩 에이전트가 실행 가능하고 검증 가능한 3D 콘텐츠를 대규모로 생성할 수 있도록, 200만 쌍 규모의 실행 가능한 3D 코드 데이터셋과 멀티 에이전트 기반의 생성·검증 하네스를 함께 제공하는 오픈소스 연구 생태계이다.

한 줄 요약

3DCodeVerse는 코딩 에이전트가 실행 가능하고 검증 가능한 3D 콘텐츠를 대규모로 생성할 수 있도록, 200만 쌍 규모의 실행 가능한 3D 코드 데이터셋과 멀티 에이전트 기반의 생성·검증 하네스를 함께 제공하는 오픈소스 연구 생태계이다.

배경 및 문제의식

3D 코딩(코드를 통한 3D 콘텐츠 제작)은 기하 구조, 관절 운동, 장면 구성, 그래픽 효과 등을 실행 가능한 프로그램으로 표현함으로써 편집·재사용·검사가 쉬운 구조화된 3D 콘텐츠를 만들 수 있다는 장점이 있다. 그러나 기존 연구들은 이 분야를 단편적으로만 다뤄왔다. DeepCAD와 BlenderLLM은 CAD/Blender 스크립팅에 대한 데이터를 제공하고, SceneCraft와 VIGA는 시각적 피드백을 통한 콘텐츠 정제에 집중하며, Articraft는 관절형 에셋 생성을 위한 전용 SDK와 하네스를 결합하는 등, 각 자원이 서로 다른 작업(정적 객체, 관절형 객체, 장면, 그래픽)과 환경(Blender, CadQuery, OpenSCAD, Three.js 등)에 흩어져 있어 3D 코딩 시스템을 개발하고 평가할 공유 인프라가 부재했다. 저자들은 이러한 파편화를 해소하기 위해 대규모 실행 가능 코드 코퍼스와 3D 코드 생성 하네스를 결합한 통합 프레임워크가 필요하다고 보았다.

핵심 기여

  1. 3DCodeVerse-2M: 정적 객체, 관절형 객체, 장면, 그래픽(셰이더 등)을 포괄하며 Blender, CadQuery, OpenSCAD, Three.js, GLSL, URDF 등 6종의 실행 환경에 걸친 약 203만 쌍 규모의 실행 가능 3D 코드 데이터셋. 기존 공개 데이터를 표준화된 독립 실행 코드로 변환하고, 코딩 에이전트로 신규 프로그램을 생성하여 구축했다.
  2. 3DCodeVerse Harness: 멀티 에이전트 방향성 비순환 그래프(DAG) 기반의 3D 코드 생성·정제 프레임워크로, 실행 검사, 공간적 측정, 시각적(VLM) 피드백을 결합해 사람의 개입 없이 생성물을 자동으로 평가·수정한다.
  3. 실증적 가이드라인 및 오픈 모델: 하네스 구성요소별 분석을 통한 3D 코딩 실무 지침 제시, 그리고 데이터셋으로 파인튜닝한 오픈소스 모델(Qwen 계열) 베이스라인 공개.
  4. Claude Opus 5.5를 동일하게 사용했을 때, 자사 하네스가 Claude Design(3D Object) 대비 사람 평가에서 90%의 승률을 달성함을 입증.

방법론

3D 코딩의 과제 정의: 텍스트 요청(및 선택적 참조 이미지)로 주어진 조건 c를 만족하는 3D 콘텐츠를 생성하는 프로그램 f를 작성하는 것으로 정의한다. 프로그램은 선언된 환경 e(예: Blender의 bpy, CadQuery)에서 실행 가능한 독립적 코드이며, 실행 결과 (a, ℓ) = E_e(f)로 아티팩트 a(메쉬, 관절형 에셋, 장면, 애니메이션)와 실행 피드백 ℓ을 얻는다. 단발성 LLM 생성(T=0)과, 실행 결과와 렌더링을 참고해 반복적으로 코드를 수정하는 코딩 에이전트 방식(T회 반복) 모두를 포괄하는 수식으로 표현했다.

데이터 구축(3DCodeVerse-2M): Bioinspired3D, 3DCodeBench, Thingiverse, Shadertoy, CodePen 애니메이션, Three.js/React Three Fiber 프로젝트, ProcTHOR 등 다양한 공개 소스를 수집하고, DeepCAD의 CAD 구성 시퀀스를 CadQuery 코드로, Articraft의 관절형 에셋 기하 구조를 URDF를 유지하며 변환했다. 코딩 에이전트(Claude Code, Codex CLI 등)가 "스킬"(작성 규칙, 코드 예시, 수정 가이드 모음)을 활용해 특수 API에 의존하는 원시 프로그램을 독립 실행 가능한 표준 코드로 재작성한다. 각 프로그램은 실행(E_e), 3D IoU·충돌·거리 등의 검사 도구(M_e)를 통과해야 하며, DeepCAD 변환은 복셀 IoU로, Articraft 변환은 Chamfer distance로 변환 충실도를 측정했다. 최종적으로 각 레코드는 코드, 환경, 세 가지 조건(지시문·시각 묘사·구성 절차)에 대한 텍스트 설명, 렌더링 이미지, 메쉬/영상(가능한 경우), 출처·라이선스·검증 결과를 함께 저장한다.

생성 하네스(3DCodeVerse Harness): 조건 c와 목표 환경 e가 주어지면 LLM 플래너가 대상 구성요소, 치수, 재질, 공간 관계, 수용 기준을 담은 계획 P를 수립하고, 이를 코딩·조립 작업의 DAG로 변환해 여러 서브 에이전트가 파일 소유권을 나누어 병렬로 작업하도록 한다. 각 라운드마다 ① 실행/빌드 로그, ② 치수·접촉·충돌·운동학·배치 등을 점검하는 측정 피드백, ③ 멀티뷰 렌더링을 수용 기준과 대조해 결함과 점수를 산출하는 VLM 판정(시각 피드백)이라는 세 가지 피드백을 수집한다. 이 피드백은 우선순위가 매겨진 수정 작업으로 전환되어 수정 에이전트가 반영하며, 이 과정을 반복해 점수가 가장 높은 프로그램을 최종 결과로 선택한다. 또한 개발 단계에서 판정자(judge)의 평가 기준(θ_J)과 생성 워크플로(θ_H)를 교대로 개선하는 적대적 루프(사람이 직접 라운드마다 개입하지 않고, 저장된 아티팩트 뱅크에 대한 반복 평가로 판정 일관성을 높이고, 이후 동일 판정 기준으로 생성 워크플로의 품질과 실패율을 비교)를 거쳐 하네스를 최적화했다.

실험 설정 및 결과

하네스 평가: 100개의 텍스트-투-3D 객체 프롬프트(및 관절형 객체 50개, 장면 50개, 그래픽 50개 프롬프트)에 대해 여러 백본(Gemini 3.8 Flash, Claude Opus 5.5, GPT-6 Astra, GPT-6 Luna)의 네이티브 하네스와 3DCodeVerse Harness를 비교했다. 평가지표는 사람 선호도(Human Preference), VLM 판정 선호도(Gemini 3.1 Pro), 판정 점수(Judge Score, 0~100), SigLIP-2 텍스트-이미지 코사인 유사도이다. 결과적으로 3D 객체 생성에서 3DCodeVerse Harness의 사람 선호도는 69~89%, 판정 점수는 11~25점 향상되었으며, 특히 약한 모델(Gemini 3.8 Flash: 61→87, GPT-6 Luna: 64→86)에서 개선이 크게 나타났다. 동일하게 Claude Opus 5.5를 사용했을 때 Claude Design 대비 사람 선호도 90%, 판정 점수 88 대 37을 기록했다. 관절형 객체·장면·그래픽에서도 유사하게 사람 선호도 78~88%를 보였다.

오픈 모델 파인튜닝: Qwen3.5-9B, Qwen3.8-27B를 LoRA로 3DCodeVerse-2M 일부로 파인튜닝하여 805개 고정 과제(3DCodeBench 텍스트-투-Blender 212개 및 Blender/CadQuery/OpenSCAD/GLSL/Three.js 5개 테스트 스플릿)에서 평가했다. Qwen3.5-9B는 파인튜닝 전 3DCodeBench에서 실행률 0%였으나 파인튜닝 후 84.9%로 상승했고(Blender 90.3%, CadQuery 98.5%, OpenSCAD 86.0%, GLSL 56.0%), Qwen3.8-27B는 파인튜닝(SFT+DPO) 후 3DCodeBench에서 51.9%→92.9%로 상승했다. 참조 메쉬와의 충실도(F@0.05, DINOv2-L 유사도) 또한 파인튜닝 후 큰 개선을 보였다.

정성적 분석 및 응용: 동일 프롬프트/백본 비교에서 3DCodeVerse Harness가 더 완전한 구조와 세부 디테일(예: 피닉스의 다리와 둥지, 피아노 내부 구조)을 생성했으며, 다중 라운드 반복 정제가 특정 결함(얼굴 깃털, 의자 다리 부착, 네온 셰이더의 블록 아티팩트)을 교정함을 보였다. 응용 사례로, 관절형 로봇 에셋을 MuJoCo에 임포트해 렌더링 관측치를 비교했을 때 문-손잡이 기하 검사를 코드 렌더/VAE 재구성 모두 12/12로 통과했지만 UWM 예측은 7/36에 그쳤고, 생성된 3D 장면의 코드 렌더링을 Gemini Omni Flash와 Seedance 2.5 영상 생성 모델의 조건부 입력(레이아웃, 모션, 카메라 궤적 제어)으로 활용하는 사례도 제시했다.

한계점

논문에 '한계점'이라는 별도 절은 명시되어 있지 않다. 다만 본문 서술로부터 다음과 같은 제약을 유추할 수 있다. - 평가 환경이 Blender, CadQuery, OpenSCAD, GLSL, Three.js, URDF 등 특정 코딩 환경/언어에 한정되어 있으며, 전체 코퍼스 중 수집·변환된 프로그램과 하네스가 직접 생성한 프로그램 간에는 품질 검증 커버리지가 다르다(전자는 실행·렌더링 기반 검증, 후자는 게이트·판정 결과를 품질 등급으로 부여). - 자동 피드백과 평가가 VLM 판정자(Gemini 3.1 Pro 등)에 크게 의존하므로, 판정자의 신뢰도가 전체 시스템 품질에 영향을 미치며 이를 보완하기 위해 적대적 루프로 판정 기준을 반복 보정하는 과정이 필요했다. - 로보틱스·영상 생성 응용은 소규모(예: 12개 사례) 예비 평가로 제시되어 있어, 더 큰 규모의 검증이 필요하다. - DeepCAD/Articraft 등 변환 기반 데이터는 복셀 IoU, Chamfer distance 등으로 측정된 변환 충실도 손실이 존재할 수 있다.

시사점

3DCodeVerse는 3D 콘텐츠 생성을 "코드 작성"의 문제로 재구성하여, 기존에 단편화되어 있던 3D 코딩 데이터와 에이전트 하네스를 하나의 폐루프(데이터 구축-생성-검증-정제-모델 개선) 생태계로 통합했다는 의의가 있다. 실행 가능성과 공간적 정확성을 기계적으로 검증할 수 있는 코드 기반 표현을 활용함으로써, 사람의 피드백 없이도 대규모로 고품질 학습 데이터를 자동 생성하고 오픈소스 모델의 3D 코딩 능력을 크게 끌어올릴 수 있음을 보였다. 이는 로보틱스 시뮬레이션(관절형 에셋의 물리적 제약 인코딩)과 비디오 생성(명시적 장면 프로그램을 통한 공간·시간적 제어) 등 3D 코드가 다른 생성 모달리티의 조건 신호로 활용될 수 있는 가능성도 제시하며, 향후 데이터셋·하네스·모델·학습 레시피 공개를 통해 3D 코딩 연구의 공유 기반이 되는 것을 지향한다.
