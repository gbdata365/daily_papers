ShowNow: Fine-Grained Speculative Streaming for Responsive World Models

쇼나우(ShowNow): 반응형 월드 모델을 위한 세밀한 추측 스트리밍

사용자 입력이 들어오기 전에 재생(playback) 중 남는 연산 자원을 활용해 행동별로 분기된 "미래 영상 후보"들을 미리 준비해두고, 실제 입력이 들어오면 그중 하나만 선택·확정함으로써 인터랙티브 월드 모델의 입력-표시 지연(input-to-display latency)을 크게 줄이는 스트리밍 프레임워크 ShowNow를 제안한다.

한 줄 요약

사용자 입력이 들어오기 전에 재생(playback) 중 남는 연산 자원을 활용해 행동별로 분기된 "미래 영상 후보"들을 미리 준비해두고, 실제 입력이 들어오면 그중 하나만 선택·확정함으로써 인터랙티브 월드 모델의 입력-표시 지연(input-to-display latency)을 크게 줄이는 스트리밍 프레임워크 ShowNow를 제안한다.

배경 및 문제의식

인터랙티브 월드 모델(게임·시뮬레이션 영상을 실시간 생성하며 사용자 조작에 반응하는 모델)은 목표 프레임레이트로 영상을 계속 생성하면서 동시에 사용자의 입력(이동, 회전, 발사, 점프 등)에 즉각 반응해야 한다. 그러나 기존의 "반응형(reactive)" 생성 방식은 입력이 들어온 뒤에야 다음 영상을 생성하기 시작하므로, 생성에 걸리는 시간만큼 입력-표시 지연이 발생한다. 저자들은 재생이 진행되는 동안 GPU에 유휴 연산 여력(compute slack)이 상당히 남아있다는 점에 주목하고, 이 여유 자원으로 입력 전에 "가능한 다음 행동들에 대한 결과 영상(미래, future)"을 미리 생성해 두는 보완적 설계 축을 제안한다.

핵심 기여

  • 입력 선행 생성 프레임워크: 준비(prepare)-선택(select)-확정(commit)이라는 3단계 주기를 통해 재생 중 연산을 활용, 행동 조건부 미래를 입력 전에 미리 만들어두는 ShowNow 프레임워크를 제시.
  • 다중 미래 데이터셋과 학습 파이프라인: 동일한 과거 상태(shared history)에서 분기되는 8개의 행동 조건부 연속 영상을 포함하는 매칭된 멀티퓨처 데이터셋을 구축하고, 이를 학습하기 위한 교사-증류 파이프라인을 설계.
  • 단일 GPU 실시간 멀티퓨처 생성: 공유 히스토리 트리 실행과 결합된(fused) 확정 로직을 통해 5B 모델이 H100 1장에서 8개의 미래를 준비하면서도 480p·16fps 생성을 유지하도록 구현.

방법론

ShowNow는 공유된 과거 히스토리 h_n으로부터 지원되는 8개 행동(W/A/S/D 이동, L/R 회전, F 발사, J 점프) 각각에 대응하는 후보 미래들을 동시에 생성한다. 입력이 들어오면 해당 행동에 대응하는 후보를 즉시 선택해 디코딩·표시하고, 선택된 타임라인이 다음 라운드의 공통 히스토리가 된다(이 과정이 반복되는 prepare-select-commit 주기). 핵심 구성 요소는 다음과 같다. - 단일 레이턴트 커밋(single-latent commitment): 한 번에 한 타임스텝(레이턴트)만 생성·확정하여 결정 주기를 짧게 가져가, 행동이 바뀔 때 빠르게 반응. - 구성 가능한 커버리지: 준비하는 후보 수 K를 1개(지속되는 행동만 가정)부터 8개(모든 행동 전부 커버)까지 조절 가능. - 브랜치-트리 어텐션(branch-tree attention): 공유 히스토리는 한 번만 계산하고, 각 행동 분기는 서로 격리된 상태로 자신의 미래만 보도록 마스킹하여 중복 계산을 제거(공유 프리픽스 키-값 캐싱, FlashAttention류 효율화 기법 응용). - 학습: SolarWM/Wan2.2 5B 백본 교사 모델에 양방향 브랜치-트리 어텐션과 분기별 플로우 매칭(flow matching)을 적용해 학습한 뒤, AnyFlow 증류와 Self-Forcing 정제를 거쳐 적은 샘플링 스텝(3스텝)으로 동작하는 학생 모델을 얻음. - 추론 최적화: 정적 형태 고정을 통한 CUDA 그래프 활용, 윈도우 슬라이딩 방식의 키-값 캐시, 선택된 분기의 클린 상태를 다음 생성 패스에 바로 결합하는 fused commitment로 선택 이후 추가 작업을 최소화.

실험 설정 및 결과

ViZDoom 환경에서 단일 H100 GPU 기준으로 평가했다. 매칭된 정책(동일 체크포인트·런타임·입력 트레이스) 비교에서, 완전한 ShowNow 배포(8개 미래 준비, 최적화 실행)는 중앙값 입력-표시 지연을 기존 SolarWM-FT 자동 리드 배포의 620ms에서 208ms로 줄였으며(P90: 983→345ms, P99: 1385→374ms), 재시작 시 빈 프레임(empty tick) 비율도 1.56%에서 0.09%로 약 94% 감소시켰다. 또한 동일 선택 마감시간을 사용하는 "균일 위상 전환(uniform-phase switch)" 실험에서, 8개 미래를 준비하는 방식이 1개만 준비하는 방식보다 목표 시점 내 응답 달성률을 83.8%에서 96.8%로 13%p 향상시켰다. 공유 히스토리 실행은 8개 후보를 독립적으로 배치 생성하는 것보다 생성 시간을 약 10%, 최대 메모리를 약 48% 줄였다. 아울러 33B 규모 백본으로 확장한 ShowNow-33B도 다양한 실내외·게임 장면에서 입력-표시 지연을 862ms에서 232ms로(73% 감소) 단축함을 보였다.

한계점

준비 가능한 후보 수(K)와 모델 크기, 재생 프레임레이트 사이에는 연산 예산 트레이드오프가 존재하며, 더 넓은 행동 커버리지(K=8)는 GPU 활용률을 크게 높인다(논문에서는 약 80% GPU 사용률로 보고). 또한 단일 레이턴트 단위의 잦은 커밋은 긴 시간축에 걸친 생성 품질·일관성(fidelity, long-horizon consistency) 측면에서 다중 레이턴트 블록 방식보다 다소 낮은 지표(LPIPS, PSNR, SSIM 등)를 보이는 트레이드오프가 관찰되었다. 이 밖에 지원 행동 집합이 ViZDoom 기반의 8가지 이동/조작 행동으로 제한되어 있으며, 더 복잡하거나 연속적인 제어 공간으로의 일반화는 논문에 명시되지 않음.

시사점

ShowNow는 "재생 중 남는 연산을 입력 전에 선제적으로 활용한다"는 아이디어를 월드 모델 스트리밍에 체계적으로 적용하여, 생성 속도 자체를 높이지 않고도(즉 처리량을 유지한 채) 체감 반응 지연을 크게 줄일 수 있음을 보여준다. 이는 언어 모델의 스펙큘레이티브 디코딩 개념을 영상 기반 인터랙티브 월드 모델로 확장한 사례로 볼 수 있으며, 임베디드/원격조작 시스템이나 실시간 게임 엔진형 생성 모델 등 저지연이 중요한 인터랙티브 영상 생성 응용 전반에 적용 가능한 설계 원칙(세밀한 커밋 단위 + 구성 가능한 사전 준비 폭)을 제시한다.
