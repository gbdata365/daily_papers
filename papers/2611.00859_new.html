Wave Forcing: Towards Speed-of-Light Streaming Video Generation

웨이브 포싱: 빛의 속도에 준하는 스트리밍 비디오 생성을 향하여

생성·학습·실행을 함께 설계해 청크 단위 자기회귀 비디오 생성에서 한 번의 동시 순방향 라운드마다 하나의 완성된 비디오 청크를 내보내는 "1F1C" 파이프라인을 구현함으로써, 실시간 스트리밍 비디오 생성의 처리량을 최대 7배 이상 끌어올린 연구.

한 줄 요약

생성·학습·실행을 함께 설계해 청크 단위 자기회귀 비디오 생성에서 한 번의 동시 순방향 라운드마다 하나의 완성된 비디오 청크를 내보내는 "1F1C" 파이프라인을 구현함으로써, 실시간 스트리밍 비디오 생성의 처리량을 최대 7배 이상 끌어올린 연구.

배경 및 문제의식

Self Forcing, Causal Forcing 등 기존 청크 단위 자기회귀 스트리밍 비디오 생성 방법은 디노이징과 '청정 이력 캐시 갱신(store)'을 순차적으로 수행해야 해서, 한 단계 디노이징만 하더라도 청크당 두 번의 순방향 연산(N Forward Rounds, 1 Chunk Output, NF1C)이 필요하다. 또한 더 긴 롤아웃을 생성할수록 품질 저하와 카메라 드리프트(배경이 한쪽으로 밀리는 현상) 같은 장기 안정성 문제가 커진다. 즉, 생성 효율(지연시간)과 장기 영상 품질을 동시에 만족시키기 어렵다는 문제의식에서 출발한다.

핵심 기여

  • 더 늦게 생성되는(노이즈가 많은) 청크가 이미 더 깨끗해진 앞선 청크를 디노이징이 끝나기 전에도 참조할 수 있게 하는 '인과적 웨이브프런트(causal wavefront)' 생성 방식인 Wave Forcing(WF)을 제안.
  • 디노이징 단계마다 모델 복제본을 분산시켜 파이프라인을 채운 뒤로는 매 동시 순방향 라운드마다 완성된 청크 하나를 내보내는 1F1C 스케줄을 달성.
  • 혼합 노이즈 디노이징, 교사 모델 기반 모션 지도, 자기 생성 이력을 활용한 인과적 적응이라는 3단계 학습 절차로 모델을 이 연속 생성 방식에 맞게 적응시킴.
  • 조기 레이어별 K/V(키/값) 전달과 통신-연산 오버랩을 구현하는 'Wave Runtime(WaveRT)'과 'Wave Parallelism(WP)'을 설계해 위 스케줄을 실제 처리량 향상으로 전환.
  • Wan2.1-T2V-1.3B 모델 기준, 5단계 WF가 기존 Rolling Forcing과 동등하거나 더 나은 품질을 유지하면서 Dynamic Degree(동적 변화량)를 더 높이고, 8대의 H200 GPU에서 4단계 WF가 초당 147.6 DiT 프레임, 종단간(E2E) 134.8 FPS를 달성해 단일 GPU 대비 7.07배의 종단간 속도 향상을 보임.

방법론

비디오는 VAE로 디코딩되는 잠재 프레임 청크 단위로 생성되며, 각 청크는 S번의 이력 조건부 디노이징 업데이트를 거쳐 완성된다. WF는 청크별 인과적 어텐션 마스크를 사용해, 디노이징 단계 s에 있는 질의(query)가 자신보다 더 '깨끗한'(단계 번호가 작거나 같은) 모든 선행 청크의 K/V는 볼 수 있지만 그 반대는 금지하는 하삼각 마스크를 적용한다. 이렇게 하면 디노이징 단계마다 전용 GPU 복제본을 배정해 '이동하는 웨이브프런트' 형태로 여러 청크를 동시에 처리할 수 있다. 모델을 이 방식에 적응시키기 위해 (1) RF/SF 롤아웃을 혼합해 distribution matching distillation(DMD)으로 학습하는 혼합 노이즈 초기화, (2) 교사 비디오의 청크를 재노이즈화해 DMD와 LPIPS로 모션·구도를 지도하는 오프폴리시 DMD, (3) 자기 생성된 RF/WF/SF 롤아웃을 균등하게 섞어 온폴리시로 학습하는 인과적 적응, 세 단계를 순차 적용한다. 실행 단계에서는 Wave Runtime이 각 디노이징 단계와 store 단계를 소유한 GPU 복제본 간에 레이어 단위로 K/V를 조기에 발행(publish)하고 통신과 연산을 겹쳐 수행하며, VAE 디코딩도 여러 GPU에 걸쳐 부하 균형을 맞춰 파이프라인화한다.

실험 설정 및 결과

Wan2.1-T2V-1.3B를 기반으로 Rolling Forcing, Causal Forcing과 비교했으며, 짧은 영상은 VBench(총점·품질·의미·동적 변화량), 긴 영상(100초)은 MovieGen 프롬프트 200개 기준 VBench-Long 품질·동적 변화량과 함께 자체 정의한 Subject Preservation(피사체 보존도), Camera Drift(카메라 드리프트) 지표로 평가했다. 5단계 WF는 VBench 총점 81.64(기존 Rolling Forcing 81.15), VBench-Long 품질 81.26(Rolling Forcing 81.18)을 기록했고, 짧은 영상 Dynamic Degree는 51.39→94.44, 100초 영상은 36.63→91.45로 크게 상승했다. 동시에 Subject Preservation 97.10(Rolling Forcing 92.75)과 Camera Drift 0.37(Rolling Forcing 0.17과 유사한 수준)로 안정성도 유지했다. 시스템 효율 측면에서는 8×H200 GPU에서 4단계 WF가 BF16+FA3 백엔드 기준 147.6 DiT FPS, 134.8 종단간 FPS로 단일 GPU 대비 7.07배 속도 향상을 보였으며, 동일 조건의 DiT 전용 비교에서 Wave Parallelism은 Ulysses·Ring 같은 기존 컨텍스트 병렬 기법 대비 최대 2.53배의 처리량을 달성했다(1.3B~14B 모델 규모에서 측정).

한계점

저자들은 다음을 명시적 한계로 제시한다: (1) VBench 기반 점수만으로는 장기 스트리밍 품질을 완전히 특징짓지 못하며, 실제로 높은 품질·동적 변화량 점수가 피사체 소실이나 카메라 드리프트와 공존하는 사례가 있어 자체 보조 지표(Subject Preservation, Camera Drift)의 민감도·일반화 가능성은 추가 검증이 필요함. (2) VAE 디코딩 파이프라인을 오버랩해도 유한한 처리 용량 한계가 남아 있으며, 특히 1.3B 모델에서는 출력 경로 병목이 일부 성능 격차의 원인으로 추정됨. (3) 학습 절차가 3단계로 복잡하여 단순화 여지가 있음. (4) Wave Parallelism은 디노이징 단계 수(S)만큼의 GPU로 파이프라인 폭이 제한되며, 모델 규모가 커질수록 전통적 컨텍스트 병렬 대비 처리량 우위가 줄어듦. (5) 온라인 조건 변경, 프롬프트 전환, 폐루프(closed-loop) 작업, 멀티스트림 지연시간 보장 등 상호작용 시나리오는 이번 평가 범위에 포함되지 않음.

시사점

생성 모델의 추론 스케줄(웨이브프런트), 학습 절차, 실행 런타임을 함께 설계하면 단순히 더 빠른 커널을 적용하는 것보다 훨씬 큰 처리량 향상을 얻을 수 있음을 보여준다. 이는 실시간 상호작용이 필요한 비디오 생성·세계 모델링 응용에서, 알고리즘 차원의 의존성 구조 재설계와 시스템 차원의 병렬화를 분리하지 않고 공동 최적화하는 접근이 중요한 설계 방향이 될 수 있음을 시사한다.
