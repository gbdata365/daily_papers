Composable Soft-Prompt Distillation of RL Experts: Toward Continual Post-Training

RL 전문가의 합성 가능한 소프트 프롬프트 증류: 연속적 사후학습을 향하여

RL로 특화 학습된 각 "전문가" 모델을 고정된 pre-RL 백본 위의 독립적인 soft prompt로 증류한 뒤, 추론 시 단순히 프롬프트들을 이어붙이는 것만으로(joint training 없이) 여러 전문가의 능력을 조합하는 Composable Soft-Prompt Distillation(CSPD)을 제안한다.

한 줄 요약

RL로 특화 학습된 각 "전문가" 모델을 고정된 pre-RL 백본 위의 독립적인 soft prompt로 증류한 뒤, 추론 시 단순히 프롬프트들을 이어붙이는 것만으로(joint training 없이) 여러 전문가의 능력을 조합하는 Composable Soft-Prompt Distillation(CSPD)을 제안한다.

배경 및 문제의식

RL 사후학습은 보통 도메인별로 따로 진행되어 여러 전문가 모델이 생기는데, 이들을 하나의 모델로 합치는 작업(consolidation)은 새 전문가가 계속 추가되는 "지속적(continual)" 과정이 된다. 기존 방법인 weight merging이나 multi-teacher on-policy distillation(MOPD)은 전문가가 하나 추가될 때마다 전체 모델을 다시 합치거나 재학습해야 하고, 타깃 도메인 밖의 일반 능력을 훼손할 위험이 있다. 라우팅 기반 방법은 전문가 추가마다 라우터를 재학습해야 하고 요청 내에서 전문가를 결합하기 어렵다.

핵심 기여

  • 사전-RL 모델(backbone)을 동결한 채 각 RL 전문가를 256개 벡터의 soft prompt로 증류하는 CSPD 제안
  • 23개의 수학·코드·에이전트 설정에서 단일 soft prompt가 teacher 성능 향상분의 90% 이상을 22개 설정에서 회복함을 입증
  • 서로 다른 도메인에서 독립적으로 학습된 프롬프트들이 단순 연결(concatenation)만으로 잘 조합되며, 전문가를 하나씩 추가할 때마다 평균 성능이 계속 상승해 결국 MOPD와 동등한 수준(67.83 vs 67.79)에 도달함을 보임
  • 6개의 held-out 벤치마크에서 CSPD 조합이 비교 방법들보다 가장 우수한 out-of-domain 일반화 성능을 보임
  • 입력 공간에서의 적응(soft prompt)은 서빙 오버헤드가 거의 없어, 처리량이 미적응 백본의 1.5% 이내로 유지되고 rank-4 LoRA 대비 2.40배의 처리량을 달성

방법론

Pre-RL 모델 pθ0와 특정 도메인의 verifier를 가진 post-RL 전문가 pθj가 있을 때, CSPD는 backbone을 동결하고 시스템 메시지에 삽입되는 L×d 크기의 soft prompt Pj를 학습한다. 학습은 sequence-level distillation으로, teacher(전문가) 응답 중 verifier를 통과한 것만 모아 길이 정규화된 negative log-likelihood로 Pj만 최적화한다. 여러 전문가를 결합할 때는 각 soft prompt들을 그대로 이어붙여 P1:k = [P1;...;Pk]로 만들어 같은 템플릿에 삽입하며, 별도의 joint training이 없다. 새 전문가가 들어오면 그 프롬프트만 학습해 추가하고, 제거할 때는 해당 프롬프트만 빼면 된다. 추론 시 다른 프롬프트 뒤에 놓여도 잘 작동하도록, 학습 예시의 절반에는 같은 도메인의 다른 질문에서 샘플링한 128~256 토큰의 프리픽스를 soft prompt 앞에 배치하는 "prefix-robust training"을 적용한다.

실험 설정 및 결과

단일 전문가 증류 실험에서는 7B~35B 규모의 다양한 모델군(MiMo, GPT-OSS, Qwen3, OLMo-3 등) 23개 수학/코드/SWE-bench·Terminal-Bench 에이전트 설정에 대해 soft prompt가 teacher 성능 향상의 90% 이상을 22개 설정에서 회복했고, 15개 설정에서는 teacher를 능가했다. 다중 전문가 실험은 M2RL 세팅(Qwen3-4B-Base SFT 모델을 student로, 수학·코드·과학·instruction following 4개 도메인의 RL 전문가를 teacher로 사용)에서 수행됐으며, AIME24·LiveCodeBench v5·GPQA-Diamond·IFBench로 평가했다. CSPD 조합(MCSI 순서)은 평균 67.83점으로 TA(67.27), TIES(67.47), LoRA+TA/TIES(65.50/66.19)를 넘고 MOPD(67.79)와 동등했다. 전문가를 순차적으로 추가하는 지속학습 실험에서는 평균이 50.41→60.99→61.67→63.67→67.83으로 계속 상승했으며, 하나를 제거하면 자신의 도메인과 전체 평균이 대부분 하락함을 확인했다(수학 제거 시 평균 -4.16점). Progressive Prompts 방식(이전 프롬프트를 고정하고 새 프롬프트를 그 앞에서 학습)과 비교했을 때, 독립 학습이 모든 단계에서 더 높은 평균을 기록했다. Out-of-domain 6개 벤치마크(XSTest, TruthfulQA, BFCL, TriviaQA, BBEH, FinQA)에서는 CSPD가 평균 56.6점으로 MOPD(53.5), TIES(54.1), LoRA+TA(53.8)를 모두 앞섰다. 서빙 효율 실험(B200 GPU, SGLang)에서는 soft prompt가 백본 단독 대비 처리량 손실이 1.5% 이내였고, 32개의 서로 다른 어댑터를 동시에 사용하는 상황에서 rank-4 LoRA보다 2.40배 높은 처리량과 2.27배 낮은 TTFT(첫 토큰까지 시간)를 보였다. 추가로 soft prompt가 실제로 "무엇을 학습하는지" 분석한 결과, teacher-student KL gap의 86.8%를 해소했으며 주로 중간 결과를 재확인("?", "But", "Check" 토큰 강화)하는 행동을 학습했음을 보였다(같은 의도의 서면 지시문은 최대 2.1%만 해소).

한계점

논문에서 명시적으로 밝힌 한계는 다음과 같다: 조합 실험이 하나의 backbone, 네 개 도메인, 단일 학습 시드에만 기반해 전문가 수가 늘어날 때의 확장성이나 도메인 간 관계에 따른 영향은 미확인이며, 전문가 간에는 양(+)과 음(-)의 상호작용이 실제로 존재한다. 일부 보고 수치(단일 전문가 체크포인트, TA 계수 등)는 평가 벤치마크에서 선택된 값이고, teacher의 성능 향상이 작을 때는 회복율(recovery) 지표가 noisy해질 수 있다. 각 프롬프트가 컨텍스트에 256개 토큰을 추가하므로 조합하는 전문가 수가 늘수록 attention과 KV-cache 비용이 증가하며, 프롬프트는 특정 backbone에 종속되어 있어 backbone을 바꾸면 재증류가 필요하다.

시사점

CSPD는 능력 "획득"과 "결합"을 분리함으로써, backbone을 전혀 변경하지 않고도 여러 당사자가 병렬로 전문가를 학습·배포·제거할 수 있는 지속적 사후학습(continual post-training)의 실용적 틀을 제시한다. 저자들은 이를 "고정된 backbone + 커지는 소형 전문가 모듈 라이브러리"라는 사후학습의 새로운 형태로 보고, 후속 연구 방향으로 (1) 더 많은 backbone·도메인·시드로의 확장, (2) 요청별로 필요한 프롬프트를 자동 선택하는 방법, (3) 프롬프트 간 전이·공유 attention의 메커니즘 이해, (4) 대규모 라이브러리를 위한 더 짧은 프롬프트와 비용 비교를 제안한다.
