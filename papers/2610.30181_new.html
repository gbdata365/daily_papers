Deep Search in Real-World Web Environments

실제 웹 환경에서의 딥서치(Deep Search)

실제 오픈 웹 환경에서 멀티모달·멀티포맷·상호작용이 필요한 "딥서치(Deep Search)"를 수행하는 AI 에이전트의 능력을 평가하기 위해, 200개의 고난도 과제로 구성된 OpenDS-World 벤치마크를 구축하고 12개 최신 모델과 인간 참가자를 비교 평가했다.

한 줄 요약

실제 오픈 웹 환경에서 멀티모달·멀티포맷·상호작용이 필요한 "딥서치(Deep Search)"를 수행하는 AI 에이전트의 능력을 평가하기 위해, 200개의 고난도 과제로 구성된 OpenDS-World 벤치마크를 구축하고 12개 최신 모델과 인간 참가자를 비교 평가했다.

배경 및 문제의식

최근 거대언어모델과 도구 사용 에이전트는 다중 라운드 검색, 웹 브라우징, 다중 소스 추론 능력에서 큰 발전을 이루었지만, 이러한 능력을 "실제 오픈 웹" 환경에서 평가하는 연구는 여전히 부족하다. 저자들은 실제 웹의 복잡성이 크게 세 가지 측면에서 비롯된다고 지적한다. 첫째, 정보가 텍스트·이미지·오디오·비디오 등 다양한 모달리티로 존재하는 "다양한 모달리티(Diverse Modalities)" 문제. 둘째, HTML, PDF, XML, Parquet 등 서로 다른 구조와 처리 방식을 요구하는 "이질적 포맷(Heterogeneous Formats)" 문제. 셋째, 단순 검색으로는 얻을 수 없고 웹 내비게이션, 인터페이스 조작, 파라미터 변경, 파일 다운로드 등 상호작용이 필요한 "상호작용적 접근 요구(Interactive Access Requirements)" 문제다. 기존 벤치마크들은 이 세 가지 특성을 동시에, 그리고 서로 연결된 형태로 충분히 다루지 못해 에이전트의 실제 딥서치 능력을 체계적으로 평가하기 어려웠다.

핵심 기여

논문은 세 가지를 주요 기여로 제시한다. 1. OpenDS 과제 정의: 실제 오픈 웹에서 다양한 모달리티·포맷·접근 방식을 가진 정보를 자율적으로 탐색, 접근, 연결하여 하나의 고유한 사실적 정답을 도출하는 멀티스텝 검색 과제를 공식화했다. 2. OpenDS-World 벤치마크: 문화, 일상, 과학, 경제, 역사, 자연, 사회, 기술의 8개 도메인에 걸친 200개의 고난도 과제를 구축했다. 각 과제는 실제 동영상에서 시작하는 "앵커"를 기반으로 여러 독립적인 웹 소스를 연결해야 정답을 찾을 수 있도록 설계되었으며, 독립적인 인간 검증을 통해 증거의 유효성과 정답의 유일성을 확보했다. 3. 체계적 모델 평가: 12개의 최신 프런티어 모델을 동일한 도구 환경과 실행 프로토콜 하에서 평가하고, 정확도·검색 비용·도구 사용 패턴·종료 행동·오류 복구 등을 다각도로 분석하여 현재 에이전트들의 한계를 구체적으로 드러냈다.

방법론

과제 구축은 3단계로 진행된다. (1) 실세계 앵커 설정: 전문 주석자가 8개 도메인에 걸쳐 500개의 후보 동영상을 선정하고, 영상의 시청각 콘텐츠만으로 식별 가능한 초기 앵커 엔티티를 지정한다. 이 엔티티는 반드시 고유한 Wikidata 항목과 매칭되어야 하며, 단순 텍스트 검색으로 풀리지 않도록 설계된다. (2) 오픈 웹 증거 확장: 각 단계마다 주석자가 검색 질의를 만들어 구글 검색으로 후보 웹 소스를 얻고, 명확한 의미적 연결과 검증 가능성을 갖춘 소스를 선택해 다음 노드(엔티티)를 추출한다. 각 노드는 여러 독립적 웹 소스로 재확인되며, 이 과정을 반복해 고유하고 안정적인 최종 노드(정답)에 도달한다. (3) 질문 역변환(Question Inversion): 완성된 증거 경로를 거꾸로 변환하여, 중간 노드를 직접 드러내지 않는 간접적인 단서들의 집합으로 질문을 구성한다. 개별 단서만으로는 답을 알 수 없고, 단서들을 종합해야만 후보 공간이 좁혀져 유일한 정답에 도달하도록 설계했다.

이후 10명의 독립 검토자가 증거 경로의 사실적 정확성, 노드 간 관계의 논리적 일관성, 질문의 명확성과 정답 유일성을 검증해 최종 200개 과제를 확정했다. 또한 LLM 기반 시스템 사용이 금지된 50명의 인간 참가자(과제당 5명)를 대상으로 독립적인 풀이 테스트를 실시해 인간 기준 성능을 수집했다.

모델 평가를 위해 통합 에이전트 하네스를 구축했으며, 검색 도구(텍스트·이미지·비디오 검색), GUI 도구(웹 탐색, 클릭, 입력, 스크롤, 스크린샷), 기타 도구(비디오 프레임 분석, 자막 추출)의 세 가지 핵심 도구군을 모든 모델에 동일하게 제공했다. 검색 단계는 과제당 3,600초, 도구 호출은 최대 100회로 제한했으며, 제한에 도달하면 도구 없이 지금까지 수집한 증거만으로 최종 답을 생성하게 했다. 정답 판정은 Qwen3.8-27B를 LLM 심판으로 사용해 의미적 동등성을 기준으로 채점했다.

실험 설정 및 결과

GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5.5, Claude Fable 5.1, Gemini 3.8 Flash, Qwen3.8-Max/Flash, DeepSeek-V4-Pro/V4.1-Flash, Kimi K3, GLM-5.3/5.3-Flash 등 12개 모델을 평가했다.

  • 전체 200개 과제에서 최고 성능 모델인 GPT-6 Astra가 39.0% 정확도를 기록했고, Claude Opus 5.5(38.0%), Gemini 3.8 Flash(36.5%), Claude Fable 5.1(33.5%)이 뒤를 이었다. 하위권 모델들은 20% 미만의 정확도를 보였다.
  • 인간 참가자(1,000회 독립 시도)의 전체 정확도는 21.1%였으며, 전체 과제의 42.5%는 어떤 참가자도 풀지 못했다. 참가자들은 과제당 평균 약 38.8분, 20개 과제 묶음당 평균 12.92시간을 소요했고, 체감 난이도는 평균 3.88/5로 매우 높게 평가되었다.
  • 과제 난이도(인간 정답자 수 기준 Low/Medium/High)가 높아질수록 모델 정확도는 일관되게 하락했다(평균 약 39.7%→23.5%→16.8%).
  • 도구 호출 수나 소요 시간이 많다고 정확도가 높아지는 것은 아니었다. 예컨대 Gemini 3.8 Flash는 GPT-6 Astra보다 약 5.22배 많은 토큰을 쓰지만 정확도는 더 낮았고, DeepSeek-V4-Pro는 시간을 2.39배 더 쓰면서도 정확도는 12.5%에 불과했다.
  • 도구 사용 패턴도 모델마다 크게 달랐다. GPT-5.6 Sol은 검색 도구에 74.5%를 할애하는 반면 Claude Opus 5.5나 Qwen3.8-Flash는 GUI 조작에 절반 가까운 호출을 사용했지만, 두 모델의 정확도는 38.0%와 12.0%로 큰 차이를 보였다.
  • 오류 분석에서, 도구 실패는 전체 호출의 2.8~9.4%에 불과하지만 전체 실행 시간의 19.3~61.9%를 차지하는 등 불균형하게 큰 시간 비용을 초래했다. 실패 후에는 대부분 모델이 "다른 도구로 전환"하는 전략을 택했다(Claude Opus 5.5 약 83%).
  • 예산(시간 1시간, 호출 100회) 소진 여부도 모델별로 크게 갈렸다. Claude Opus 5.5(16.5%), GPT-6 Astra(25.5%)는 예산 소진이 적었지만 Qwen3.8-Flash(81.5%), DeepSeek-V4.1-Flash(78.0%)는 대다수 과제에서 예산을 모두 소진했다.

한계점

논문에서 명시적으로 짚은 한계 및 과제는 다음과 같다. 현재 최강 모델도 전체 과제의 61%를 해결하지 못하며, 인간 역시 거의 절반의 과제를 풀지 못하는 등 벤치마크 자체가 매우 도전적이다. 또한 자연 종료율(스스로 충분한 증거를 모았다고 판단해 답을 제출하는 비율)이 높은 모델(GPT-6 Astra 69%)조차 정답률은 39%에 그쳐, "언제 탐색을 멈출지" 판단하는 능력과 정답 정확성 사이에 지속적인 간극이 존재한다. 도구 호출 수·시간 소비와 정확도 사이의 비일관성은 현재 에이전트들이 정보원 선택, 도구 조율, 장기 호라이즌(long-horizon) 탐색 관리에서 근본적인 약점을 가지고 있음을 시사한다. 논문 자체의 한계로는, 과제 수(200개)가 상대적으로 제한적이고, 벤치마크가 특정 시점의 실제 웹 콘텐츠(동영상, 웹페이지, 데이터셋 등)에 의존하므로 웹 콘텐츠 변경이나 소실 시 재현성 문제가 발생할 수 있다는 점이 암묵적으로 내포되어 있다(논문에 명시되지 않음: 이에 대한 구체적 대응책은 상세히 기술되어 있지 않음).

시사점

OpenDS-World는 단순한 정적 검색·QA 평가를 넘어, 실제 웹의 멀티모달리티, 이질적 파일 포맷, 상호작용적 접근이라는 세 가지 복잡성을 통합적으로 반영한 평가 플랫폼을 제공한다. 이는 향후 딥서치 에이전트가 단순히 더 많은 도구를 호출하는 것이 아니라, 정보원을 효과적으로 선별하고, 증거를 통합하며, 적절한 시점에 탐색을 종료하는 능력을 길러야 함을 보여준다. 또한 도구 실패에 대한 견고한 복구 전략과 장기 호라이즌 작업에서의 예산 관리 능력이 실제 환경에서 에이전트 성능을 좌우하는 핵심 요인으로 부각되며, 저자들은 이 벤치마크가 장기 호라이즌 검색 및 에이전트의 자기 개선(recursive self-improvement) 연구를 위한 구체적인 토대가 될 것으로 기대한다.
