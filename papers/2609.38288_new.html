AREX-2: Advancing Self-Improving Agents through Long-Horizon Reflective Tasks

AREX-2: 장기 성찰 과제를 통한 자기개선 에이전트 고도화

테스트 시점에 라운드를 거듭할수록 스스로 해법을 개선하는 "자기개선(self-improving)" LLM 에이전트를 만들기 위해, 머신러닝 엔지니어링과 알고리즘 프로그래밍처럼 검증 가능한 도메인에서 장시간(수 시간, 수백 턴) 걸친 "성찰-개선" 궤적 데이터를 합성·학습시킨 AREX-2(Qwen3.8-27B 기반, 27B)가 MLE-bench Lite·Frontier-CS는 물론 딥리서치 벤치마크(BrowseComp, HLE, GAIA, DeepSearchQA)에서도 더 큰 모델들과 대등하거나 더 나은 성능을 보였다.

한 줄 요약

테스트 시점에 라운드를 거듭할수록 스스로 해법을 개선하는 "자기개선(self-improving)" LLM 에이전트를 만들기 위해, 머신러닝 엔지니어링과 알고리즘 프로그래밍처럼 검증 가능한 도메인에서 장시간(수 시간, 수백 턴) 걸친 "성찰-개선" 궤적 데이터를 합성·학습시킨 AREX-2(Qwen3.8-27B 기반, 27B)가 MLE-bench Lite·Frontier-CS는 물론 딥리서치 벤치마크(BrowseComp, HLE, GAIA, DeepSearchQA)에서도 더 큰 모델들과 대등하거나 더 나은 성능을 보였다.

배경 및 문제의식

어려운 문제는 한 번의 시도로 풀리지 않고, 시도-측정-수정을 반복하는 루프를 통해 해결된다. 그러나 기존 에이전트 시스템들은 이 루프를 모델이 아니라 외부 스캐폴드(언제 재시도할지, 무엇을 남길지를 결정하는 하네스)가 담당하고, 모델은 매번 한 번의 시도만 생성하도록 요청받는다. 저자들은 "자기개선"을 "더 많은 라운드가 주어졌을 때 에이전트가 스스로의 판단으로 더 나은 해를 만들어내는 능력"으로 정의하고, 이를 테스트 시점 스케일링(test-time scaling)의 한 형태로 본다.

자기개선을 가능하게 하는 두 요소는 (1) 현재 해와 피드백으로부터 더 나은 해를 만드는 "성찰(reflection)"과 (2) 여러 라운드에 걸쳐 유용한 발견을 유지하고 실패에서 회복하며 과정을 지속시키는 "장기 실행(long-horizon execution)"이다. 그러나 현재 에이전트 학습 데이터는 "하나의 과제 → 하나의 해 → 통과/실패 판정"식으로 수집되어, 중간 시도·피드백·수정 과정이 모두 버려진다. 특히 바로 통과하는 쉬운 해가 수집에 유리하기 때문에, 장시간에 걸친 개선 과정을 보여주는 궤적은 학습 데이터에 거의 존재하지 않는다.

핵심 기여

  1. 자기개선을 "성찰"과 "장기 실행"이라는 두 상보적 능력으로 공식화하고, 기대 개선량을 라운드별 기대 이득의 합으로 수식화하였다(Equation 1-5).
  2. 장기 성찰(long-horizon reflection)이 특정 도메인에 국한되지 않는 메타 스킬이라는 가설을 세우고, 검증 가능한 피드백이 명확하고 장시간 개선 여지가 크며 소스가 풍부한 두 도메인(머신러닝 엔지니어링, 알고리즘 프로그래밍)에서 학습 데이터를 합성하였다.
  3. 개별 라운드가 아니라 궤적 전체 단위로 데이터를 선별(최종 점수가 높고 과정이 요건을 만족하면 채택)함으로써, 실패·회귀·포기한 시도까지 학습 데이터에 남겨 모델이 "실패 후 회복하는 법"을 배우도록 설계하였다.
  4. 이렇게 학습된 AREX-2(27B)가 학습 도메인(MLE, 코딩)뿐 아니라 전혀 새로운 데이터를 추가하지 않은 딥리서치 도메인으로도 능력이 전이됨을 실증하였다.

방법론

환경 구성: GitHub 저장소(머신러닝 과제)와 온라인 저지(알고리즘 문제)라는 두 원천에서, 교사 모델(teacher model)이 과제 정의(σ)와 채점 함수(S)로 구성된 실행 가능 환경을 생성한다. GitHub 저장소의 경우 교사 모델이 코드를 읽고 측정 지표를 파악해 과제·채점 스크립트·샌드박스를 작성하며, 저지 문제의 경우 문제 자체가 과제가 되고 히든 테스트 통과율 등 점수화된(binary가 아닌 graded) 점수를 사용한다. 환경은 (1) 참조 해(레퍼런스 모델/정답 제출물)가 실제로 점수를 받는지, (2) 단순 베이스라인이 참조 해보다 충분히 낮은 점수를 받는지(=개선 여지가 있는지) 두 조건을 실행으로 검증해 통과한 것만 채택한다.

궤적 구성: 교사 에이전트가 한 과제당 통상적인 한 번의 시도보다 훨씬 큰 예산(수 시간, 수백 번의 툴 호출)을 부여받아 작업하며, 이 예산을 알고 있는 상태에서 베이스라인 확립→측정→수정의 패턴을 보이도록 유도한다. 에이전트는 작업 중 저장소 문서를 읽거나 관련 논문·라이브러리를 검색하고 소규모 실험을 돌리며 "운영 지식(operational knowledge)"을 습득하는데, 이 중 일부는 사전에 준비된 범용 스킬과 과제별 검색으로 만든 스킬 문서 형태로 에이전트 컨텍스트에 제공된다. 각 라운드는 제출→점수/피드백 수신→다음 가설 수립으로 이어지며, 점수가 떨어지는 라운드도 궤적에서 제거하지 않는다.

학습: 궤적은 (1) 최종 점수가 기준 이상이고 (2) 포맷·규칙을 준수하는지로 전체 단위 선별되며, 개별 라운드의 성공 여부는 선별 기준이 아니다. 손실(loss)은 궤적 전체를 컨텍스트로 유지한 채, "진전을 만드는 결정"(실패 진단, 복구, 전략 변경, 다음 실험 실행, 개선된 해 제출)에만 적용되고, 진전 없는 반복적 폴링이나 중복 턴, 시스템 메시지·환경 리포트 등에는 손실을 적용하지 않는다. 이렇게 선별된 궤적을 이전 AREX 레시피의 딥리서치 데이터(변경 없이 그대로 사용)와 결합해 Qwen3.8-27B를 파인튜닝하여 AREX-2를 얻는다.

실험 설정 및 결과

6개 벤치마크(Frontier-CS, MLE-bench Lite, BrowseComp, HLE, GAIA, DeepSearchQA)로 평가하였다.

  • 학습 도메인 성능: MLE-bench Lite에서 Any Medal 81.8점으로 비교 대상 중 최고(가장 강한 베이스라인 대비 +8.1, 최강 비공개 모델 대비 +9.1), Frontier-CS에서 70.7점으로 공개 가중치 모델 중 최고(+16.0), 비공개 최강 모델과는 5.7점 차이.
  • 도메인 전이(딥리서치): 새로운 검색 관련 학습 데이터를 전혀 추가하지 않았음에도 BrowseComp 84.0, HLE(텍스트 전용) 52.6, GAIA 92.2, DeepSearchQA 93.8을 기록하며, 40B 이하 소형 모델 중 BrowseComp·HLE·DeepSearchQA에서 선두, GAIA는 XYZ-Aquila-mini 등 일부 모델에만 뒤짐. 이전 레시피로 학습한 AREX(4B), AREX(122B) 대비 4개 벤치마크 전부에서 우위를 보여, 두 학습 도메인에서 익힌 "장기 성찰" 능력이 전혀 다른 도메인으로 전이됨을 시사.
  • 라운드(예산) 스케일링 — 피드백 있음: Frontier-CS 188문제에 5시간 예산을 주고 측정한 결과, AREX-2는 1시간 후 54.4점에서 5시간 후 70.7점까지 꾸준히 상승했고, 비교 모델(DeepSeek-V4-Pro, DeepSeek-V4-Flash 등)은 2~3시간 만에 성능이 정체됨.
  • 라운드 스케일링 — 피드백 없음: 정답 여부를 전혀 알려주지 않는 BrowseComp에서도, 평균 턴 수를 47→143으로 늘리자 정확도가 64.8→84.0으로 상승(체감 수익 존재). 같은 조건의 이전 모델 AREX(122B)보다 턴당 이득이 약 3배 크고, 파라미터 수는 4분의 1 이하(27B vs 122B).
  • 단계별 소거 실험(MLE-bench Lite): 베이스 모델(스킬 없음) 28.8 → 범용 스킬 추가 41.2 → 과제별 스킬+더 많은 라운드 68.2(이상은 학습 없이 스킬/예산만으로 달성) → 학습된 AREX-2는 동일 스킬·동일 라운드에서 75.8, 더 많은 라운드를 주면 81.8까지 상승. 즉 운영 지식(스킬), 학습(파인튜닝), 큰 예산이 각각 독립적으로 성능에 기여함을 확인.

한계점

  • BrowseComp와 HLE의 최상위(비공개) 모델들과는 여전히 격차가 존재한다고 논문이 직접 명시.
  • 학습 데이터 구성 도메인이 머신러닝 엔지니어링과 알고리즘 프로그래밍 두 가지로 한정되어 있어, 더 넓은 도메인으로 확장될 때의 일반화 가능성은 추가 검증이 필요.
  • 결론부에서 저자들은 향후 과제로 "학습 도메인 확장, 호라이즌(라운드 수) 연장, 모델이 생성한 궤적을 스스로의 다음 학습 데이터로 삼아 루프를 닫는 것"을 제시하고 있어, 현재 버전은 완전한 폐루프(closed-loop) 자기개선은 아님을 암시.
  • 환경 구성과 궤적 생성에 교사 모델(teacher model)이 필요하며, 이 교사 모델의 품질·편향이 결과 데이터 품질에 영향을 줄 수 있으나 이에 대한 구체적 분석은 논문에 명시되지 않음.

시사점

이 연구는 "에이전트의 자기개선 능력"을 스캐폴드(외부 제어 로직)가 아니라 모델 자체의 가중치에 내재화할 수 있음을 보여준다. 핵심은 검증 가능한 피드백이 있는 도메인(머신러닝 실험, 알고리즘 문제)에서 장시간의 "성찰-개선" 궤적을 합성하고, 실패와 회복까지 포함한 궤적 전체를 학습 신호로 사용하는 전략이 특정 도메인을 넘어 전혀 다른 과제(딥리서치)로도 전이된다는 점이다. 이는 향후 에이전트 학습 데이터 구축에서 "정답으로 가는 깨끗한 경로"보다 "실패를 포함한 장기 개선 과정" 자체를 보존하고 학습 대상으로 삼는 방향이 중요할 수 있음을 시사하며, 작은 모델(27B)로도 스킬 제공과 장기 학습을 결합하면 훨씬 큰 모델과 경쟁할 수 있다는 실용적 함의도 제공한다.
