Miles v0.1: Production-Level Post-Training

Miles v0.1: 프로덕션급 포스트트레이닝 시스템

Miles는 slime 프레임워크의 설계를 계승해 SGLang 기반 롤아웃, Megatron-LM/FSDP 학습 백엔드, 세 가지 가중치 동기화 전송 방식을 하나로 엮은 프로덕션급 강화학습(RL) 포스트트레이닝 시스템으로, 744B 파라미터급 GLM-5.2 모델의 에이전트형 코딩 RL을 64개 GB300 GPU에서 완전 비동기 방식으로 검증했다.

한 줄 요약

Miles는 slime 프레임워크의 설계를 계승해 SGLang 기반 롤아웃, Megatron-LM/FSDP 학습 백엔드, 세 가지 가중치 동기화 전송 방식을 하나로 엮은 프로덕션급 강화학습(RL) 포스트트레이닝 시스템으로, 744B 파라미터급 GLM-5.2 모델의 에이전트형 코딩 RL을 64개 GB300 GPU에서 완전 비동기 방식으로 검증했다.

배경 및 문제의식

최근 대형 언어모델의 포스트트레이닝은 단순한 "생성 후 업데이트" 루프를 넘어, 여러 턴에 걸쳐 도구를 사용하고 외부 환경과 상호작용하는 에이전트형 롤아웃으로 확장되었다. 이런 롤아웃은 대개 조 단위 파라미터의 MoE(Mixture-of-Experts) 모델에서 수행되는데, 지연에 민감한 롤아웃과 처리량 중심의 학습을 동시에 GPU에서 효율적으로 굴리기가 어렵고, 롤아웃 엔진과 트레이너 사이의 수치적 불일치(train-rollout mismatch)가 커지면 학습 목표 자체가 무의미해질 위험이 있다. 저자들은 이러한 문제를 해결하기 위해 "검증 가능하고(verified), 깔끔하고(clean), 커스터마이징 가능한(customizable)" 컴포넌트라는 하나의 원칙 아래 시스템을 설계했다.

핵심 기여

  • 완전 비동기 RL 루프: 롤아웃 생성과 학습을 분리된 GPU 풀에서 동시에 진행시켜, 동기식 루프에서 발생하는 유휴 시간을 제거하는 구조를 제시했다.
  • 토큰 인/토큰 아웃(TITO) 세션 서버: 하네스가 아닌 서버가 토큰화를 전담해, 여러 턴에 걸친 궤적에서도 정확히 정책이 샘플링한 토큰 ID를 트레이너에 전달하는 메커니즘을 제안했다.
  • 롤아웃 라우팅 재현(R3, Rollout Routing Replay): MoE 모델에서 롤아웃과 학습이 서로 다른 전문가(expert)를 선택하는 문제를 토큰별 라우팅 결과를 그대로 재생함으로써 해결했다.
  • 세 가지 가중치 동기화 전송 방식: NCCL 브로드캐스트, RDMA 기반 P2P 전송, 공유 스토리지 기반 디스크-델타 업데이트를 배치 토폴로지에 맞게 선택할 수 있도록 설계했다.
  • 저정밀도 학습 레시피와 메모리 오프로딩: FP8/MXFP8/NVFP4 등 저정밀 포맷을 롤아웃-학습 간 동일하게 적용하는 계약(contract)과, 옵티마이저 상태를 디스크로 스트리밍하는 메모리 절약 기법을 제공했다.
  • LoRA RL, 온폴리시 증류(OPD), 완전 온폴리시 정렬 등 코어 RL 루프를 확장하는 부가 레시피와, 이미지·비디오 디퓨전 모델까지 아우르는 Miles-Diffusion 아키텍처를 함께 제시했다.

방법론

Miles의 RL 루프는 세 단계로 구성된다. (1) SGLang 엔진이 궤적을 생성하는 롤아웃 단계에서는, 동일한 에이전트 세션의 요청을 같은 엔진(또는 데이터 병렬 랭크)에 고정하는 "어피니티(affinity)" 라우팅으로 KV 캐시 재사용률을 높인다. (2) 학습 단계에서는 Megatron-LM 또는 FSDP 백엔드가 완성된 궤적 그룹을 소비해 GRPO, GSPO, PPO 등의 손실 함수로 정책을 업데이트한다. (3) 가중치 갱신 단계에서는 업데이트된 파라미터를 롤아웃 엔진에 전달한다. 완전 비동기 모드에서는 데이터 버퍼가 두 단계 사이의 속도차를 흡수하며, 그룹의 신선도(staleness), 필터링 결과에 따라 궤적을 버리거나 재시도한다. TITO 세션 서버는 대화 이력을 저장·체크포인트하여 각 턴마다 새로 생성된 접미사만 토큰화함으로써 토큰 정확성을 보장하고, R3는 SGLang이 반환한 라우팅된 전문가 정보를 학습 단계에서 그대로 재생해 정합성을 높인다. 저정밀도 학습에서는 롤아웃과 학습이 동일한 양자화 로직을 공유하는 "계약(contract)" 방식을 사용하며, 예외적으로 일부 텐서는 BF16으로 유지한다. 가중치 동기화는 버킷 단위 파이프라인을 공유하며, 브로드캐스트/P2P/디스크-델타 세 가지 전송 방식 중 배치 환경(같은 패브릭 공유 여부, 노드 수 등)에 따라 선택한다.

실험 설정 및 결과

대표 사례 연구로 GLM-5.2(744B 총 파라미터, A40B 활성 파라미터) 모델을 터미널 사용 코딩 작업(terminal-bench-2)에 대해 64개의 NVIDIA GB300 GPU(32개 롤아웃 + 32개 학습)에서 완전 비동기 방식으로 100스텝 학습했다. 학습은 BF16, 롤아웃은 FP8 가중치·FP8 KV 캐시("BF16 학습, FP8 서빙" 조합)를 사용했고, 텐서×파이프라인×컨텍스트×전문가 병렬화(TP2/PP4/CP4/EP8)로 옵티마이저 상태(랭크당 약 279GB)를 디스크에 스트리밍했다. 측정 결과, 첫 30개 스텝의 중앙 학습 스텝 시간은 263초였고(스텝 0의 1042초 워밍업은 제외), 프리픽스 캐시 히트율은 96%를 유지했다. 학습-추론 간 로그확률 차이(KL 발산)는 평균 0.0369로 안정적이었고, 원시 과제 보상의 9스텝 이동평균은 0.438에서 0.556으로 상승했으나, 저자들은 단일 실행 결과이므로 이를 검증된 개선이 아니라 관찰(observation)로만 보고한다고 명시했다. 그 외에도 저정밀도(MXFP8, NVFP4) 레시피, P2P 전송(H100 클러스터에서 브로드캐스트 대비 최대 86% 시간 단축), 옵티마이저 상태 스트리밍(오프로드 시간 24초→5.2초) 등 개별 컴포넌트 수준의 측정치를 제시했다.

한계점

  • 논문에서 스스로 명시한 한계로: 비전-언어 모델은 TITO 세션 서버가 이미지/비디오 입력을 아직 지원하지 않아 별도 저수준 인터페이스로 처리해야 한다.
  • MXFP8, NVFP4 등 일부 저정밀 포맷은 아직 "베타" 단계이며 검증된 모델이 한정적이다.
  • P2P 가중치 전송은 통합 가중치 이름 매핑이 있는 일부 모델 계열(Qwen2/3, GLM4-MoE, DeepSeek-V3 계열 등)에만 적용 가능하고, 단일 노드 환경에서는 브로드캐스트보다 오히려 느리다.
  • 디스크-델타 업데이트는 Megatron 백엔드에서만 지원되며 콜로케이션·LoRA·프리필-디코드 분리 배치와는 함께 쓸 수 없다.
  • 완전 온폴리시 정렬(true-on-policy alignment)은 현재 Qwen3 0.6B/4B 등 일부 소형 모델에서만 검증되었다.
  • GLM-5.2 사례 연구는 단일 실행(100스텝)에 기반한 관찰로, 보상 상승을 통계적으로 유의미한 개선으로 주장하지 않는다.

시사점

이 연구는 초대형 MoE 모델의 에이전트형 RL 포스트트레이닝을 실제 프로덕션 규모(수십~수백 GPU, 조 단위 파라미터)에서 안정적으로 수행하기 위한 구체적인 시스템 설계 패턴 — 토큰 정확성 보장, 라우팅 재현, 저정밀도 계약, 다중 전송 방식 등 — 을 공개함으로써, 연구자와 기업이 프런티어 규모 RL을 오픈소스 도구로 재현·확장할 수 있는 실질적인 기반을 제공한다. 또한 모델 발표 당일(day-0) 대응, 다중 하드웨어(NVIDIA/AMD) 지원, 코드 품질 원칙 등을 통해 대규모 RL 인프라가 지녀야 할 신뢰성과 확장성의 기준을 제시한다.
