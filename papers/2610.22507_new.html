RealCLI: Toward a Unified Evaluation of Human-Agent Collaboration for CLI Agents

RealCLI: CLI 에이전트를 위한 인간-에이전트 협업 통합 평가

RealCLI는 CLI(명령줄 인터페이스) 에이전트의 작업 수행 능력뿐 아니라 사람과의 실시간 협업 품질까지 함께 측정하는 페어드(paired) 벤치마크로, 101개의 실전형 과제와 5차원 협업 평가 프레임워크를 통해 최상위 모델조차 과제 완수율에 비해 협업 품질(Joint Collaboration Score)이 크게 뒤처진다는 사실을 보여준다.

한 줄 요약

RealCLI는 CLI(명령줄 인터페이스) 에이전트의 작업 수행 능력뿐 아니라 사람과의 실시간 협업 품질까지 함께 측정하는 페어드(paired) 벤치마크로, 101개의 실전형 과제와 5차원 협업 평가 프레임워크를 통해 최상위 모델조차 과제 완수율에 비해 협업 품질(Joint Collaboration Score)이 크게 뒤처진다는 사실을 보여준다.

배경 및 문제의식

SWE-bench, Terminal-Bench 등 기존 CLI 에이전트 벤치마크는 사용자가 처음에 완전한 작업 명세를 제공하고 에이전트가 이를 자율적으로 끝까지 수행한 뒤 최종 코드나 환경 상태만을 채점하는 방식을 따른다. 그러나 실제 사용 환경에서는 사용자의 목표가 처음부터 완전히 정해져 있지 않고, 작업이 진행되는 동안 정보가 추가되거나 제약이 수정되며, 위험하거나 민감한 작업에 대해서는 사용자의 승인 여부를 판단해야 한다. 기존 벤치마크들은 이러한 실행 중 상호작용을 거의 다루지 않거나, 다루더라도 협업을 작업 완료의 부수 요소로만 취급할 뿐, 에이전트가 계획과 상태를 사용자에게 얼마나 이해하기 쉽게 전달하는지, 사용자의 개입과 수정 요구를 얼마나 잘 받아들이는지, 실패를 스스로 감지·복구하는지, 위험과 한계를 정직하게 공개하는지, 사용자의 통제권(승인 경계)을 지키는지를 체계적으로 평가하지 않는다. 이에 저자들은 동일한 과제와 실행 환경 위에서 "작업 성공"과 "협업 품질"을 동시에, 독립적인 축으로 측정할 수 있는 통합 평가 프레임워크의 부재를 핵심 문제로 제기한다.

핵심 기여

  • 동일한 과제·환경·채점 기준을 공유하면서 완전한 명세를 한 번에 주는 RealCLI-EXEC 모드와, 스크립트화된 가상 사용자가 정보를 점진적으로 공개하고 수정·제약 변경·승인 결정을 요구하는 RealCLI-COLLAB 모드를 모두 제공하는 101개 과제(10개 대분류, 52개 하위영역)의 페어드 벤치마크를 구축했다.
  • 사람-컴퓨터 상호작용(HCI) 이론에 기반해 이해 가능성(Understandability), 조종 가능성(Steerability), 관찰과 복구(Observation & Recovery), 신뢰 보정(Trust Calibration), 안전 및 위험 인식(Safety & Risk Awareness)의 5차원 협업 프레임워크를 설계하고, 이를 22개 하위 차원과 51~57개의 상호작용 시나리오 템플릿(총 1,658개의 평가 체크리스트 항목)으로 구체화했다.
  • 과제 성공률(R), 4단계 상향식 집계로 산출되는 종합 협업 점수(S_collab), 그리고 둘을 곱한 결합 협업 점수(Joint Collaboration Score, J_collab = R_collab × S_collab)라는 새로운 평가지표를 제안해, 협업 품질이 낮으면 과제 성공률이 높아도 종합 점수가 크게 깎이는 엄격한 벌점 구조를 도입했다.
  • 11개 최신 모델 × 3개 에이전트 하네스(Claude Code, Terminus-2, Codex), 총 33개 구성에 대한 대규모 평가를 수행하여, 과제 수행 능력과 협업 능력이 서로 괴리되어 있고 협업 5차원 간 능력 불균형이 심각함을 실증했다.

방법론

각 과제는 (실행 환경 E, 초기 상태 s0, 완전한 작업 명세 ω, 결과 검증기 V)의 튜플로 정식화되며, EXEC와 COLLAB 두 모드는 행동·관측 공간만 다를 뿐 동일한 검증기로 최종 환경 상태를 채점한다. COLLAB 모드의 가상 사용자는 과제 명세를 여러 "정보 조각(information slice)"으로 나누어 에이전트의 질문에 답하거나 상황에 맞게 먼저 제공하며, 5차원 프레임워크에서 정의된 "상호작용 프로브(probe)"(트리거 조건·기대 행동·증거 요건을 갖춘 시나리오)를 실행 흐름 속에 삽입한다.

벤치마크 구축은 두 단계 파이프라인으로 이루어진다. ① 실제 CLI 로그를 압축해 작업 목표·환경 상태·제약·실패 신호를 추출하고, 이를 재사용 가능한 "스킬"로 변환해 컨테이너화된 환경·참조 해법·검증기를 갖춘 과제로 합성한 뒤 품질 검사와 다중 에이전트 반복 실행, 난이도 분류를 거쳐 기본 과제(base instance)를 확정한다. ② 각 기본 과제에 시나리오를 배정하고, 오프닝 메시지·정보 조각·상호작용 프로브·체크리스트로 구성된 상호작용 스크립트를 작성한 뒤, 정적 검사·의미 검토·실제 에이전트와의 엔드투엔드 파일럿·전문가 검토를 거쳐 최종 과제로 확정한다.

협업 점수는 4단계 상향식으로 집계된다: (1) 시나리오 단위에서는 체크리스트 전 항목을 만족해야만 통과로 인정하는 전부-또는-전무(all-or-nothing) 채점, (2) 과제 전체에서 해당 시나리오의 통과율이 75% 이상이어야 최종 통과로 인정하는 교차-과제 일관성 기준, (3) 하위차원·차원 점수는 통과한 시나리오들의 단순 평균, (4) 5개 차원 점수의 동일 가중 평균이 종합 협업 점수 S_collab이다. 여기에 과제 성공률 R_collab을 곱해 J_collab을 산출함으로써, 협업이 부실하면 아무리 과제를 잘 끝내도 종합 점수가 크게 낮아지는 곱셈형 벌점 구조를 적용했다.

실험 설정 및 결과

Claude Opus 5·4.8, GPT-5.6 Sol, DeepSeek V4.1 Flash·V4 Flash, Qwen3.8 Max, Kimi K3, GLM 5.3·5.3 Flash, MiniMax M3, Hy3 등 11개 모델을 Claude Code, Terminus-2, Codex 세 하네스에 적용한 33개 구성을 101개 과제(컨테이너로 격리, EXEC 6시간/COLLAB 10시간, 최대 600턴, avg@3)로 평가했다.

  • 전체 평균 과제 점수는 Claude Opus 5가 49.2%로 최고치를 기록했고 DeepSeek V4.1 Flash가 45.6%로 근소하게 뒤를 이었다. 그러나 J_collab 기준으로는 최고치조차 37.6%(Claude Opus 5, Terminus-2 하네스)에 그쳤다. GPT-5.6 Sol은 Codex 하네스에서 자율 실행 성공률(R_exec) 58.5%를 기록했지만 J_collab은 8.5%로 추락해, 과제 완료 능력이 협업 품질을 전혀 보장하지 않음을 보여준다.
  • 사용자 개입이 성과를 일관되게 높이지는 않았다. Claude Code 기준 비대화형과 대화형 평균 통과율은 각각 47.4%, 46.8%로 거의 동일했지만, 실행별로는 17.9%가 실패에서 성공으로, 18.5%가 성공에서 실패로 뒤바뀌어 양방향 변동이 상쇄되었다. 성능 변화는 모델·과제 유형·하네스에 따라 크게 달랐다(예: Codex 하네스에서 평균 +3.4pp 개선).
  • 협업 능력은 차원별로 뚜렷이 불균형했다. 모델들은 이해 가능성과 관찰·복구에서는 상대적으로 양호했지만(표준 RLHF가 장려하는 장문 설명·자기수정 덕분으로 추정), 조종 가능성, 신뢰 보정, 안전·위험 인식에서는 지속적으로 취약했다. GPT-5.6 Sol은 Terminus-2에서 R_collab 47.5%를 달성하고도 S_collab은 19.1%, 특히 신뢰 보정 7%·안전 인식 0%에 그쳐 "작업은 밀어붙이면서 안전 경고와 승인 절차는 무시하는" 위험한 경향을 드러냈다.
  • 실패 양상 분석 결과, 기능적/경계조건 오류가 자율 실행 실패의 62.7%, 대화형 실패의 53.8%를 차지해 가장 흔한 실패 유형이었다. 성공한 대화형 실행 중에서도 91.0%가 적용 가능한 협업 체크리스트 항목을 하나 이상 위반했으며, 제약 유지 실패 사례의 91.3%는 대화에서는 제약을 지키겠다고 응답(53.3%는 대화 체크 전부 통과)했음에도 최종 산출물에는 그 제약이 반영되지 않는 "말과 행동의 불일치"였다.

한계점

논문에 별도의 "한계점" 절은 명시되어 있지 않다. 다만 본문에서 드러나는 설계상 제약으로는, 실제 사용자가 아닌 스크립트화된 시뮬레이션 사용자를 통해 상호작용을 재현한다는 점, 평가가 101개 과제·11개 모델·3개 하네스라는 특정 범위로 한정된다는 점, 시나리오 단위 채점이 항목 전부를 만족해야 통과로 인정하는 엄격한 전부-또는-전무 기준이라는 점, 그리고 실행에 턴 수·시간 예산 상한(600턴, EXEC 6시간/COLLAB 10시간)이 적용되어 더 긴 호라이즌에서의 행동은 다루지 못한다는 점을 들 수 있다. 저자들은 생성형 AI를 문헌 조사와 저자 작성 문장의 언어 교정에만 사용했고 연구 설계·분석·결과 생성에는 사용하지 않았다고 명시했다.

시사점

이 연구는 "과제를 잘 끝내는 능력"과 "사람과 잘 협업하는 능력"이 서로 다른 축이며, 결과 중심 평가만으로는 에이전트의 체계적인 협업 실패(조종 불가능성, 안전 경계 침범, 말과 행동의 불일치 등)를 포착할 수 없음을 보여준다. 이는 향후 CLI 에이전트 개발이 단순히 자율 실행 성능을 높이는 것을 넘어, 계획과 상태를 투명하게 전달하고, 사용자의 개입·수정 요구를 지속적으로 반영하며, 위험과 한계를 정직하게 공개하고, 승인 경계를 지키는 능력을 1급 설계 목표이자 측정 가능한 역량으로 다뤄야 함을 시사한다. RealCLI가 제공하는 재현 가능한 평가 체계는 이러한 "이해 가능하고 조종 가능하며 신뢰할 수 있는" 협업형 에이전트 개발의 기준점으로 활용될 수 있다.
