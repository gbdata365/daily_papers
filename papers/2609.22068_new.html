CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

CodeMidas: 코드 자체로부터 에이전틱 코딩 RL 환경을 확장하기

오픈소스 코드베이스에 이미 구현되어 있는 기능을 소스 코드만을 입력으로 삼아 실행 가능한 강화학습(RL) 환경으로 자동 변환하는 에이전틱 파이프라인 CodeMidas를 제안하고, 이를 통해 만든 5,545개 과제로 MiMo-V2.5를 학습시켜 다섯 개의 외부 코딩 벤치마크 전반에서 유의미한 성능 향상을 확인했다.

한 줄 요약

오픈소스 코드베이스에 이미 구현되어 있는 기능을 소스 코드만을 입력으로 삼아 실행 가능한 강화학습(RL) 환경으로 자동 변환하는 에이전틱 파이프라인 CodeMidas를 제안하고, 이를 통해 만든 5,545개 과제로 MiMo-V2.5를 학습시켜 다섯 개의 외부 코딩 벤치마크 전반에서 유의미한 성능 향상을 확인했다.

배경 및 문제의식

코딩 에이전트를 강화학습으로 훈련하려면 다양한 과제와 신뢰할 수 있는 채점(검증) 방식이 함께 필요하다. 기존 파이프라인들은 대부분 이슈, 풀 리퀘스트, 커밋 같은 개발 이력(development artifact)이나 기존 테스트·문서에 의존해 과제를 만들어 왔는데, 이는 결국 "기록으로 남은 변경 사항의 범위"에 과제 생성이 종속된다는 한계를 낳는다. 저자들은 오픈소스 코드베이스 자체가 수백 개 언어에 걸친 방대한 구현 기능의 원천이라는 점에 착안해, 이슈·PR·커밋·기존 테스트·문서 없이 소스 코드 하나만으로 과제 진술문, 개발 환경, 실행 기반 검증기를 함께 만들어내는 방법을 모색한다.

핵심 기여

  • 소스 코드만을 과제별 입력으로 사용해 실행 가능한 코딩 RL 환경을 자동 구성하는 에이전틱 파이프라인 CodeMidas를 제시했다. 기존 방법 대비 이슈·PR·커밋·기존 테스트·문서 요구 조건이 전혀 없는 유일한 방법으로 자리매김한다.
  • CodeMidas로 3,185개 오픈소스 코드베이스, 23개 프로그래밍 언어, 15개 기술 도메인에 걸쳐 5,545개의 검증된 학습 과제를 구축했다.
  • 이 데이터로 GRPO를 이용해 MiMo-V2.5를 학습시켜, 이슈 수리·전체 프로그램 구축·터미널 작업 등 성격이 서로 다른 다섯 개 외부 벤치마크 전부에서 성능이 개선됨을 보였다.
  • 과제 규모·품질과 성능의 관계, 그리고 RL 학습 중 에이전트의 행동(코드베이스 탐색, 코드 초안 작성, 자기검증)이 어떻게 변화하는지를 정량적으로 분석했다.

방법론

CodeMidas는 네 단계로 구성된 파이프라인이다. 1. 과제 설계 및 코드베이스 적응: 에이전트가 코드베이스 구조와 빌드 메타데이터를 살펴 공개 진입점과 관측 가능한 동작을 지닌 기능을 후보로 찾는다. 해당 기능의 핵심 구현부를 코드베이스에서 제거하고 주변 코드를 정합성 있게 조정해, 목표 기능이 "아직 구현되지 않은" 상태의 개발 시작점을 만든다. 원본 구현은 별도로 보관되어 참조 솔루션 역할을 한다. 2. 실행 기반 테스트 구성: 에이전트가 과제 진술문이 요구하는 동작 요구사항을 입력·경계 조건으로 매핑하고, 참조 코드 복사본에서 공개 진입점을 직접 실행해 그 결과를 테스트 기대값으로 기록한다. CLI 도구는 명령 실행, 순수 함수는 입출력 케이스, 상태를 갖는 API는 호출 시퀀스로 테스트를 구성하며, 진술문에 명시되지 않은 제약(정확한 문자열, 우연한 순서, 내부 구조 등)에 의존하는 검증은 제거하거나 행동 기반 검사로 대체한다. 3. 환경 준비 및 실행 일관성 검사: 표준 베이스 컨테이너에서 프로젝트 선언에 맞춰 의존성과 빌드/런타임 자원을 준비하고, 삭제된 구현을 유추할 수 있는 컴파일 산출물·캐시·구성 과정에서 남은 파일 등을 정리한다. 각 과제는 6개의 새 컨테이너(초기 코드베이스 2회, 참조 솔루션 4회)에서 실행해, 초기 상태는 반드시 실패하고 참조 솔루션은 반드시 통과하는지 확인한다. 4. 사후 롤아웃 필터링: 별도 에이전트가 컴파일 산출물·캐시·설치된 원본 프로젝트 복사본 등 잔존 정보(leakage)를 악용해 실제 구현 없이 정답을 얻을 수 있는지 탐색하고, 이런 우회가 가능한 과제는 제거한다. 또한 검증 에이전트가 여러 실제 에이전트 롤아웃 결과와 진술문·참조 솔루션을 대조해 검증기의 오탐(false positive)·누락(false negative)을 점검하며, 프런티어 모델이 여러 번 시도했을 때 전부 성공하거나 전부 실패하는(난이도나 잔존 결함을 시사하는) 과제도 걸러낸다.

RL 학습은 GRPO를 사용하며 이진 실행 성공/실패를 보상으로 사용한다(학습된 보상 모델이나 별도 검증기 없이 테스트 통과 여부만으로 보상 산출).

실험 설정 및 결과

MiMo-V2.5를 초기 정책으로 두고 5,545개 CodeMidas 과제에서 GRPO로 학습시켰다(배치 크기 32, 과제당 32회 롤아웃, 최대 응답 길이 약 51만 토큰, 최대 500턴). 평가는 SWE-bench Pro, DeepSWE v1.1, ProgramBench, RepoZero C2Rust, Terminal-Bench v2.1의 다섯 개 외부 벤치마크와, 학습셋과 겹치지 않는 200개 과제로 구성된 자체 검증셋 CodeMidas Val에서 수행했다.

주요 결과: - SWE-bench Pro: 50.3% → 54.4% (+4.1%p) - DeepSWE: 10.0% → 21.7% (+11.7%p) - ProgramBench(Almost Solved): 4.5 → 21.5 (+17.0점) - RepoZero C2Rust: 40.5% → 51.8% (+11.3%p) - Terminal-Bench v2.1: 63.7% → 72.2% (+8.5%p) - CodeMidas Val 학습 곡선: 학습 진행에 따라 통과율이 35.0%에서 44.7%로 상승하고, 응답 길이도 함께 길어짐(상호작용 예산을 더 적극적으로 활용).

추가 분석(과제 규모·품질 비교)에서는 고품질 필터링을 거친 1k/3k/5k 과제 풀과, 필터링을 거치지 않은 약 8k 과제(vanilla) 풀을 비교했다. 과제 수가 1k→3k→5k로 늘수록 DeepSWE(17.57→19.05→21.70), CodeMidas Val(41.30→43.22→44.73) 점수가 모두 꾸준히 상승했으며, 고품질 5k 풀은 물론 3k 부분집합조차 필터링을 거치지 않은 8k 풀보다 SWE-bench Pro·DeepSWE·CodeMidas Val 모든 평가에서 더 높은 점수를 기록했다. 즉 과제 수보다 정제·검증 품질이 더 중요함을 시사한다.

행동 변화 분석에서는 초기와 후기 롤아웃을 비교했을 때, 코드 수정 전 읽기/검색 호출 수(코드베이스 탐색)가 27.2회에서 40.1회로, 코드 초안-실제 작성 코드 간 중복 비율(드래프팅 비율)이 0.36에서 0.63으로, 수정 후 실행하는 서로 다른 검증 명령 수(자기검증 다양성)가 2.03에서 2.53으로 각각 증가했다. 같은 과제·체크포인트 내에서 자기검증을 수행한 롤아웃은 그렇지 않은 롤아웃보다 평균 통과율이 4.2%p 높았다(95% 신뢰구간 1.8~6.6). 이러한 행동 변화는 SWE-bench Pro, ProgramBench, Terminal-Bench v2.1 같은 외부(학습에 쓰이지 않은) 과제에서도 유사하게 관찰되어, 학습된 행동이 일반화됨을 뒷받침한다.

한계점

논문에 별도의 "한계점" 절은 명시되어 있지 않으나, 본문에서 확인되는 방법론적 제약은 다음과 같다. 첫째, 파이프라인의 각 단계(과제 설계, 테스트 구성, 누출 탐지, 검증기 오류 점검)가 모두 에이전트/모델의 판단에 의존하므로, 사용된 스크리닝 모델 자체의 편향이나 오류가 최종 데이터셋 품질에 영향을 줄 수 있다. 둘째, 방법이 전제하는 이진 실행 보상(테스트 통과 여부)만을 사용하기 때문에, 부분적으로 옳은 해법이나 코드 품질 같은 요소는 보상에 반영되지 않는다. 셋째, 환경 구축 대상이 되는 코드베이스는 기존 테스트·문서가 부실하더라도 최소한 빌드·실행이 가능해야 하므로, 이런 조건을 만족하지 못하는 코드베이스에는 적용하기 어렵다. 넷째, 언어·도메인 분포가 균등하지 않아 Python·TypeScript·Go 등 상위 언어와 시스템/웹/개발도구 도메인에 과제가 치우쳐 있다(상위 10개 언어가 전체 과제의 98.2%를 차지).

시사점

이슈·PR·커밋·문서 등 부가적인 개발 이력이 없어도 오픈소스 코드베이스의 "이미 구현된 기능" 자체만으로 대규모·다양한 영역의 검증 가능한 RL 환경을 만들 수 있음을 보여주었다는 점에서, 코딩 에이전트 훈련 데이터 확보의 병목을 크게 완화할 잠재력이 있다. 또한 과제 수를 단순히 늘리는 것보다 실행 일관성 검사와 사후 롤아웃 필터링을 통한 품질 관리가 더 중요하다는 실증 결과는, 향후 코딩 RL 데이터셋 구축에서 "양보다 질"을 우선해야 한다는 실무적 지침을 제공한다. 아울러 RL 학습이 진행될수록 에이전트가 코드베이스 탐색과 자기검증을 스스로 강화하는 방향으로 행동이 바뀌고, 이 경향이 학습에 쓰이지 않은 과제 유형에도 전이된다는 관찰은, 소스 코드 기반 과제가 단순 암기가 아닌 전이 가능한 문제 해결 역량을 길러줄 수 있음을 시사한다.
