Omni-IO Skills: Harnessing Your Agent Omni-Native

옴니-IO 스킬: 에이전트를 옴니 네이티브로 만들기

기존 범용 에이전트(예: Claude Code, Codex)의 추론 핵심은 그대로 둔 채, 계층적 Skill과 의존성 인식 오케스트레이션, 영속적 Asset Registry를 결합한 플러그앤플레이 하니스 "Omni-IO Skills"를 통해 텍스트·이미지·비디오·오디오·문서·3D·코드 등 7개 모달리티를 아우르는 옴니 네이티브 에이전트로 전환시키는 시스템을 제안한다.

한 줄 요약

기존 범용 에이전트(예: Claude Code, Codex)의 추론 핵심은 그대로 둔 채, 계층적 Skill과 의존성 인식 오케스트레이션, 영속적 Asset Registry를 결합한 플러그앤플레이 하니스 "Omni-IO Skills"를 통해 텍스트·이미지·비디오·오디오·문서·3D·코드 등 7개 모달리티를 아우르는 옴니 네이티브 에이전트로 전환시키는 시스템을 제안한다.

배경 및 문제의식

실제 업무는 단일 모달리티에 머물지 않고 텍스트, 이미지, 오디오, 비디오, 문서, 3D 자산, 코드가 뒤섞인 형태로 요청과 산출물이 오간다. 옴니 기반모델을 통합 아키텍처로 확장하는 방법은 새로운 모달리티가 추가될 때마다 비용이 큰 모델 재학습이 필요하다는 한계가 있고, 반대로 전문 모델·도구를 단순히 조합하는 방식은 절차, 의존관계, 중간 산출물, 턴 간 수정 사항을 어떻게 조율할지에 대한 해법이 없었다. Codex, Claude Code 같은 범용 에이전트는 강력한 계획·추론·코드 실행 능력을 갖췄지만 실제 production 범위는 여전히 소프트웨어·지식 작업에 집중되어 있어, 오디오·비디오·3D·전문 문서 등은 외부 역량과 명시적 오케스트레이션에 의존해야 한다. 이 논문은 "호스트 에이전트의 추론 핵심을 바꾸지 않으면서 플러그앤플레이 하니스만으로 옴니 네이티브화할 수 있는가"라는 질문에서 출발한다.

핵심 기여

  • 호스트 모델 재학습 없이 범용 에이전트를 옴니 네이티브 시스템으로 확장하는 "Omni-modal Agent Harness" 개념을 정식화
  • Atomic·Expert·Scenario 3단계 계층적 Skill, 표준화된 멀티모달 실행 인터페이스(MCP Tool Service), 공급자/설정 계층, 영속적 Asset Registry를 하나의 확장 가능한 아키텍처로 통합한 Omni-IO Skills 구현
  • 이해·생성·추론·검색 4개 역량군, 7개 아티팩트 모달리티, 27개 Skill, 38개 대표 과제를 아우르는 애플리케이션 지향 시스템 구축
  • 서로 다른 두 호스트 에이전트(GPT-5.6 Sol, Claude Sonnet 5)에서 모달리티 커버리지, 의미 품질, 인터리브 일관성, 구조적 완성도 전반에서 일관된 성능 향상을 실증

방법론

시스템은 4계층 아키텍처로 구성된다. (1) Skill Entry 계층은 사용자 요청을 해석해 Atomic(단일 실행 가능한 최소 단위, 예: 이미지 생성), Expert(포스터 디자인처럼 하나의 최종 산출물을 위한 완전한 전문 제작 워크플로우), Scenario(소셜미디어 게시물 등 특정 응용 맥락에서 여러 연관 산출물을 조율) 세 등급의 Skill을 선택·재귀적으로 전개한다. 각 Skill은 s = ⟨c_s, I_s, P_s, O_s, H_s⟩(적용조건, 입력, 절차, 출력, 관계) 형태의 선언적 표현을 공유한다. (2) MCP Tool Service 계층은 이해/생성/유틸리티 세 그룹의 외부 도구를 표준 계약으로 매핑하며, 코드·마크다운처럼 외부 서비스가 필요 없는 작업은 호스트 에이전트가 직접 수행한다. (3) Provider and Configuration 계층은 시맨틱 역량(예: '이미지 생성')을 OpenAI, Google Gemini, Alibaba, Tripo3D, ElevenLabs 등 구체적 공급자·모델·자격증명·기본 파라미터·폴백 정책에 바인딩한다. (4) Asset Registry 계층은 모든 산출물을 a = ⟨asset_id, type, subtype, path, description, params, turn_id, source_asset_id⟩로 기록하는 append-only JSON 레지스트리로, 물리적 경로와 독립적인 참조를 제공해 턴을 넘나드는 재사용과 버전 추적을 가능케 한다. 런타임에서는 선택된 Skill들이 전개되어 Declare Execution Graph(DEG)를 구성하고, 구조 검증 후 의존관계가 없는 노드들이 동일 Wave로 묶여 동시 실행되며(wave scheduling), 실패한 노드의 후속 노드만 취소되고 독립 브랜치는 계속 실행된다.

실험 설정 및 결과

UniM 벤치마크에서 텍스트·이미지·오디오·비디오·문서·코드·3D를 포괄하는 90개 인스턴스를 선별한 UniM-90 벤치마크로 평가했다. GPT-5.6 Sol과 Claude Sonnet 5를 Base Agent(내장 기능만 사용)와 Agent+Omni-IO Skills 두 조건으로 비교했다. 주요 지표는 입력 지원률(τ), Semantic–Quality Coupled Score(SQCS), Interleaved Coherence Score(ICS), Strict/Lenient Structure Score(StS/LeS)이다. 결과: 입력 지원률이 두 에이전트 모두 40.00%, 38.89%에서 100%로 상승했다. 전체 테스트셋 기준 상대 SQCS는 GPT-5.6 Sol에서 26.99→74.94(+47.95점), Claude Sonnet 5에서 27.82→77.78(+49.96점)로 증가했으며, Strict Structure Score는 각각 100.00, 99.78에 도달했다. 지원 가능한 부분집합만 놓고 본 절대 SQCS(Base Agent 67.49/71.53)보다도 Omni-IO Skills 적용 후 전체 셋 기준 절대 SQCS(74.94/77.78)가 더 높아, 모달리티 커버리지 확장과 동시에 품질도 향상됨을 보였다. 아트 튜토리얼 생성, 제품 프로모션(포스터·홍보영상·랜딩페이지 동시 제작) 등 사례 연구를 통해 Skill 간 협업과 아티팩트 일관성 유지를 정성적으로도 검증했다.

한계점

논문에 명시되지 않음 (본문에서 별도의 "한계점" 절을 찾지 못했으며, 저자들은 대신 현재 구현이 19개 Atomic, 2개 Expert, 6개 Scenario Skill로 구성된 초기 범위임을 밝히고 있어 확장성이 향후 과제로 남아있음을 암시한다).

시사점

이 연구는 기반모델 자체를 재학습하지 않고도 하니스 계층에서의 역량 조합(harness-level capability composition)만으로 실용적인 옴니 시스템을 구축할 수 있음을 보여준다. 이는 특정 모델·공급자에 종속되지 않고 절차·공급자·자산을 독립적으로 확장 가능하게 유지하면서, 멀티턴 프로덕션 워크플로우에서 이종 미디어를 조율하고 재사용 가능한 산출물을 다루는 에이전트를 위한 응용 지향적 토대를 제공한다. Skill 세트 확장, 더 많은 호스트 에이전트에 대한 적용, 실패 복구·품질 검증 메커니즘의 고도화 등이 자연스러운 후속 연구 방향이 될 수 있다.
