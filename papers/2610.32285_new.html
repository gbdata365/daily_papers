Trial by Trace: Benchmarking AI Agent Harnesses for Reliability and Failure Attribution

트라이얼 바이 트레이스: 신뢰성과 실패 원인 분석을 위한 AI 에이전트 하네스 벤치마킹

LLM 에이전트의 실제 성능은 모델 자체뿐 아니라 이를 감싸는 "하네스(harness)"에도 크게 좌우된다는 문제의식에서 출발해, 95개의 전문가 설계 과제와 4종 하네스·9종 모델 조합(총 3,420회 실행)에 걸쳐 에이전트 성과와 하네스 신뢰성을 분리 평가하고 실패 원인을 추적 가능한 증거로 귀속시키는 벤치마크 TraceTrial-Bench를 제안한다.

한 줄 요약

LLM 에이전트의 실제 성능은 모델 자체뿐 아니라 이를 감싸는 "하네스(harness)"에도 크게 좌우된다는 문제의식에서 출발해, 95개의 전문가 설계 과제와 4종 하네스·9종 모델 조합(총 3,420회 실행)에 걸쳐 에이전트 성과와 하네스 신뢰성을 분리 평가하고 실패 원인을 추적 가능한 증거로 귀속시키는 벤치마크 TraceTrial-Bench를 제안한다.

배경 및 문제의식

대부분의 기존 에이전트 벤치마크는 최종 답변, 테스트 통과 여부, 환경 최종 상태 같은 "결과"만으로 평가한다. 이런 지표는 모델과 하네스가 결합된 효과만 보여줄 뿐, 정보 손실·잘못된 도구 결과·생명주기(lifecycle) 위반 같은 하네스 내부의 결함이 성능에 어떤 영향을 미쳤는지는 구분하지 못한다. 논문은 과제가 성공해도 하네스가 맥락을 누락했을 수 있고(모델이 부족한 정보를 스스로 보완한 경우), 반대로 하네스가 충실하게 동작했음에도 모델의 잘못된 판단으로 과제가 실패할 수 있다고 지적한다. 즉 모델을 고정해도 결과 수준 비교만으로는 어떤 하네스 동작이 성능 차이를 만들었는지 알 수 없다는 것이 핵심 문제의식이다.

핵심 기여

  • TraceTrial-Bench: Context, Execution, Governance, Lifecycle, Observability, Tools, Verification 등 7개 하네스 신뢰성 컴포넌트를 다루는 95개의 전문가 수준 메커니즘 지향 과제 모음을 구축.
  • Trajectory Tracing(TT) 모듈: 서로 다른 하네스의 고유한 실행 기록을 공통 Trace 중간 표현(Trace IR)으로 정규화하여 재구성.
  • 2계층(two-layer) 평가 프레임워크: 에이전트의 과제 수행 성과(Agent layer)와 하네스의 의무 이행(Harness layer)을 별도의 채점표로 독립적으로 평가.
  • 다출처 증거 수집(MEA) 모듈: 에이전트 컨텍스트, 하네스 기록, 실행 환경(워크스페이스 변경 등) 세 가지 출처에서 기준(criterion)별 증거 패킷을 구성해 LLM 기반 채점의 근거로 제공.
  • 실패 귀속(FA) 모듈: 사전에 선언된 "메커니즘 체인(mechanism chain)"을 통해 하네스 실패와 에이전트 실패 사이의 인과적 연결 후보를 식별하고, 수동 증거 검토를 거쳐 실행(run) 수준에서 실패 전파 여부를 검증.

방법론

논문은 "Agent = Model + Harness"라는 추상화를 전제로, 하네스를 모델을 감싸는 투명한 래퍼가 아니라 독립적으로 검증해야 할 "피시험 시스템(system under test)"으로 취급한다. Claude Code, Codex, OpenClaw, DeepSeek Harness 네 가지 네이티브 하네스를 소스별 어댑터로 통합하여, 각 하네스 고유의 프롬프트 구성·도구 인터페이스·세션 동작을 그대로 유지하면서도 동일한 과제·모델 조합을 비교할 수 있도록 설계했다. 각 과제는 하네스가 지켜야 할 의무(harness obligation)와 에이전트가 산출해야 할 결과물(agent deliverable)을 쌍으로 두고, 결정론적 검증기 또는 상태 기반 ground truth라는 독립적인 '진실 기준'을 함께 정의한다. 실행은 Docker 컨테이너에서 이루어지며, 정규화된 실행 trace·워크스페이스 변경분·probe 증거를 수집해 기준별 증거 패킷을 만들고, 이를 바탕으로 LLM judge(deepseek-v4-flash)가 의미론적 채점을 수행한다. Agent layer와 Harness layer 점수는 50/50 비율로 결합되어 최종 점수를 이룬다. 실패 귀속 단계에서는 하네스 기준 실패와 에이전트 기준 실패를 연결하는 사전 선언된 메커니즘 후보 링크를 자동으로 활성화시키고, 이후 사건 순서·중간 왜곡 증거를 사람이 직접 검토해 실제로 실패가 전파되었는지 검증한다.

실험 설정 및 결과

4개 하네스 × 9개 모델(DeepSeek-V4-Pro, Gemini 3.7 Flash, GLM-5.3, GPT-5.6-Sol, Grok-4.6, HY3, Kimi K3, Opus 5, Qwen3.8-Max) × 95개 과제 조합으로 총 3,420회 실행을 평가했다. 하네스별 종합 점수(Overall)는 65.2~73.5%, Harness macro 점수는 59.8~72.0% 범위로 나타났다. Claude Code가 가장 높은 에이전트 과제 성공률(44.0%)과 종합 점수(73.5)를 기록했지만, 하네스 신뢰성 지표(macro 72.0%, clean rate 11.7%)는 OpenClaw가 가장 우수했다. 즉 과제 성공률이 가장 높은 하네스가 반드시 하네스 자체의 신뢰성도 가장 높은 것은 아님을 보여준다. 전체 실행의 31.1%는 적어도 하나의 Harness 기준을 위반했음에도 에이전트 과제는 성공했으며, 두 계층 기준을 모두 만족한 "완전 클린"한 실행은 전체의 8.4%에 불과했다. 신뢰성 차원별로는 Execution과 Lifecycle, Context 영역의 하네스 충족률이 상대적으로 낮았고, Observability와 Verification은 높았다. 실행당 평균 비용은 하네스별로 약 0.436~0.633달러였다.

한계점

과제 커버리지가 모든 메커니즘에 균등하지 않으며, 각 과제-모델-하네스 조합마다 단 한 번의 실행만 수집해 반복 실행 간 안정성(variance)은 검증하지 못했다. 또한 과제 개정, 런타임 설정, 채점 예산(judge token budget) 등이 조합마다 달라 하네스 설계 선택에 대한 엄밀한 인과적 결론을 내리기는 제한적이라고 저자들은 밝히고 있다.

시사점

이 연구는 AI 에이전트 평가에서 모델 성능과 하네스(실행 인프라) 신뢰성을 분리해서 측정해야 한다는 점을 실증적으로 보여준다. 결과 지표만으로는 숨겨진 하네스 결함이나 반대로 하네스가 충실해도 모델이 실패하는 상황을 구분할 수 없으며, trace 기반의 증거 중심 평가가 이런 한계를 보완할 수 있다. 저자들은 향후 이 벤치마크를 하네스 개선 루프(trace 기반으로 결함을 찾아 하네스를 수정하고 재평가)나, 모델과 하네스를 함께 발전시키는 재귀적 자기개선(Recursive Self-Improvement) 평가에 활용할 수 있다고 제안한다.
