RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

레크리에이션월드: 하이브리드 컴퓨터 사용 에이전트를 위한 확장 가능하고 검증 가능한 환경

실행 중인 참조 애플리케이션을 보고 그대로 재구현(recreation)하게 만드는 다섯 개 플랫폼(Ubuntu, macOS, Windows, Android, Web) 환경 프레임워크 RecreationWorld와, 이를 이용해 GUI 조작과 코드 작성을 넘나드는 "하이브리드 컴퓨터 사용 에이전트"의 능력을 측정하는 250개 과제 벤치마크 RecreationBench를 제안한 연구.

한 줄 요약

실행 중인 참조 애플리케이션을 보고 그대로 재구현(recreation)하게 만드는 다섯 개 플랫폼(Ubuntu, macOS, Windows, Android, Web) 환경 프레임워크 RecreationWorld와, 이를 이용해 GUI 조작과 코드 작성을 넘나드는 "하이브리드 컴퓨터 사용 에이전트"의 능력을 측정하는 250개 과제 벤치마크 RecreationBench를 제안한 연구.

배경 및 문제의식

기존 컴퓨터 사용 에이전트(CUA) 연구는 두 갈래로 나뉘어 발전해 왔다. 하나는 GUI를 보고 클릭·타이핑으로 화면을 조작하는 GUI 에이전트, 다른 하나는 터미널과 코드로 프로그램을 작성·실행하는 코딩 에이전트다. 문제는 GUI 에이전트는 인터페이스 뒤의 소프트웨어를 직접 만들거나 고칠 수 없고, 코딩 에이전트는 자신이 만든 결과물을 화면으로 확인할 시각적 수단이 없다는 점이다. 그러나 실제 소프트웨어 작업은 인터페이스를 관찰해 동작을 이해하는 것과, 그 이해를 바탕으로 구현을 고치는 것이 한 번에 끝나지 않고 끊임없이 오가며 진행된다. 저자들은 이렇게 탐색-구현-검증을 하나의 긴 흐름 속에서 자율적으로 오가는 에이전트를 "하이브리드 CUA"라 부르며, 이를 제대로 측정할 벤치마크가 부재하다는 점을 문제로 지적한다.

핵심 기여

  • RecreationWorld 프레임워크: 실행 중인 참조 애플리케이션(reference)이 주어졌을 때, 에이전트가 정해진 절차 없이 그 동작을 스스로 파악하고 빌드·실행 가능한 대응 구현체(candidate)를 만들어내는 "recreation" 과제를 다섯 플랫폼(Ubuntu, macOS, Windows, Android, Web)에서 공통 실행 규격으로 제공.
  • 검증 가능성(verifiability): 참조 앱 자체가 오라클 역할을 하여, 숨겨진 행동 기반 테스트(프로그램적 어서션 + 시각적 VLM 어서션)를 자동 생성하고 사람 검수 후 고정된 채점 스위트로 동결함으로써, 사람의 채점 없이도 구현-무관적으로 채점 가능.
  • 확장 가능한 학습 데이터 생성: 오픈소스 GitHub/F-Droid 애플리케이션을 참조로 삼아 Qwen3.8-Max 에이전트로 recreation 궤적을 대량 생성, 거부 샘플링으로 고득점 궤적만 선별해 플랫폼당 7,000개씩 총 35,000개의 SFT 학습 데이터 구축.
  • RecreationBench: 5개 플랫폼 × 50개 과제(총 250개)로 구성된 held-out 평가 벤치마크. 프로그램적 어서션(AT-SPI, AXUIElement, UI Automation, UiAutomator, DOM/ARIA 등 플랫폼 고유 접근성 API 기반)과 시각적 어서션(VLM 판정)을 함께 사용.

방법론

RecreationWorld는 각 플랫폼별로 격리된 워커(VM)에서 참조 앱을 실행하고, 에이전트에게 GUI 제어와 코딩 도구를 함께 제공한다. 에이전트는 탐색(explore)-구현(implement)-검증(verify) 루프를 스스로 반복하며 참조 앱의 동작을 관찰하고, 소스 코드를 작성·빌드하고, 결과물을 다시 실행해 참조와 비교하는 과정을 필요한 만큼 되풀이한다. 순서나 방식은 과제에서 지정하지 않으며, 최종 제출물은 플랫폼별 빌드/실행 계약(예: Android는 Gradle 프로젝트로 APK 생성, Web은 자체완결 index.html)을 만족하는 소스 코드다.

테스트 생성 파이프라인은 오케스트레이터가 소스 분석과 참조 앱 실행 탐색을 결합해 기능·화면·트리거·응답의 인벤토리를 만들고, 플랫폼별 생성기가 이를 바탕으로 단일 홉부터 다중 홉 상호작용, 지속성, 계산 결과까지 다양한 깊이의 테스트 케이스를 작성한다. 각 테스트는 참조 앱에 대해 리플레이해 검증하고 사람이 검수한 뒤에야 고정 스위트에 편입된다. 평가 시에는 격리된 워크스페이스만 노출하고 참조 소스, 인터넷 접근, 평가 자료 등은 차단하는 격리 프로토콜을 적용한다(데스크톱/안드로이드는 소스 블라인드, 웹은 서빙되는 정적 자원만 노출).

학습 실험에서는 완전 학습된 Qwen3.7-Plus와 지속 사전학습 체크포인트 Qwen-Flash-CPT 두 초기화 모델을 동일한 35,000개 recreation 궤적 혼합 데이터로 파인튜닝했다.

실험 설정 및 결과

  • OOD 전이 평가: ProgramBench, GameCraft-Bench, Vision2Web(코딩 계열), OSWorld 2.0, WeaveBench(하이브리드 컴퓨터 사용 계열) 5개 외부 벤치마크에서 두 학습 모델 모두 학습 진행에 따라 첫 체크포인트 대비 최대 17.9%p까지 점수가 상승, recreation 학습이 벤치마크 범위를 넘어 전이됨을 시사.
  • 행동 변화: 학습이 진행될수록 코드 검증(자체 결과 확인), 이미지(자신이 만든 화면) 점검, GUI 상호작용 비중이 모두 증가.
  • RecreationBench 본평가: Gemini 3.7 Flash, Kimi K3, GLM-5.3, Qwen3.7-Plus, Grok 4.6, Qwen3.8-Max-0902, Claude Opus 5, Claude Opus 4.8, GPT-5.6 Sol, GPT-6 Astra 등 10개 프런티어 모델을 평가. GPT-6 Astra가 평균 58.1%로 1위, Claude Opus 5(44.2%), GPT-5.6 Sol(42.1%)이 뒤를 이음. 다만 프로그램적 테스트를 100% 통과한 과제 비율은 최고 모델도 2.8%에 불과.
  • 분석 결과: 에이전트들은 정적인 인터페이스 구조(메뉴, 텍스트, 레이아웃)는 비교적 잘 재현하지만, 상태 전이나 계산된 출력 같은 동작 기반 요소는 상대적으로 취약. 생성된 애플리케이션은 참조 앱보다 코드량이 훨씬 적고(중간값 비율 약 16.9%) 파일 수도 적어 구조적으로 더 단순·집중된 형태를 보임.
  • 프로그래머블 상호작용 런타임 실험: GUI 조작을 지속형 JavaScript SDK로 구성해 매 행동마다 관찰을 반환받지 않도록 한 결과, 동일 수준의 과제 품질을 유지하면서 상호작용 오버헤드(도구 호출 수, 입력 토큰, 소요 시간, 비용)가 크게 감소.

한계점

  • RecreationBench는 고정(pinned)된 재현 가능 환경을 중시하므로, 라이브 서비스, 변화하는 외부 상태, 실사용자와의 상호작용이 관여하는 워크플로는 다루지 못함.
  • 숨겨진 테스트 스위트가 유한한 시각적·행동적 결과만을 표본화하므로, 테스트 통과가 모든 상태·상호작용 경로에서의 동등성을 보장하지는 않음.
  • 공개 참조 구현체가 사전학습 데이터에 이미 포함되어 있었을 가능성을 배제할 수 없고, 소스 중복 검사만으로는 사전 암기나 다른 형태의 소스 재사용을 완전히 걸러낼 수 없음. 따라서 점수는 어디까지나 지정된 환경과 고정 테스트 스위트 내에서의 충실도를 측정한 것.
  • 저자들은 향후 과제로 통제된 온라인/다중 사용자 워크플로 포함, 상태·상호작용 경로에 대한 숨겨진 테스트 커버리지 확장, 오염 위험을 줄이기 위한 새 참조 앱 구축 등을 제시.

시사점

GUI 조작과 코드 작성을 분리된 능력으로 다루던 기존 관행에서 벗어나, 동일한 에이전트가 두 modality를 자유롭게 오가며 스스로 관찰-구현-검증 루프를 돌리는 "하이브리드" 능력을 정면으로 측정·학습시킬 수 있는 프레임워크를 제시했다는 점에서 의미가 크다. 특히 실행 중인 참조 앱을 오라클로 삼아 사람의 채점 없이도 확장 가능한 검증 신호를 자동 생성할 수 있다는 점은, 대규모 자기개선(self-improvement) 학습 데이터 파이프라인으로 이어질 잠재력을 시사한다. 다만 현재 프런티어 모델들도 정적 구조는 잘 흉내 내지만 실제 동작·상태 전이 재현에는 크게 못 미친다는 결과는, 향후 에이전트가 "보이는 것"을 넘어 "작동하는 방식"까지 검증하도록 학습되어야 한다는 방향성을 제시한다.
