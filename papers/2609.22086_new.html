Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design

Designer-RSI: 사용자 트래픽으로부터 진화하는 절차적 메모리 기반 에이전틱 그래픽 디자인

전문가급 그래픽 디자인 에이전트가 실제 사용자 트래픽으로부터 자연어로 작성된 절차적 기억(스킬 뱅크)을 스스로 넓히고 다듬어, 모델 가중치를 전혀 바꾸지 않고도 실행 성공률과 디자인 품질을 크게 끌어올리는 프레임워크를 제안한다.

한 줄 요약

전문가급 그래픽 디자인 에이전트가 실제 사용자 트래픽으로부터 자연어로 작성된 절차적 기억(스킬 뱅크)을 스스로 넓히고 다듬어, 모델 가중치를 전혀 바꾸지 않고도 실행 성공률과 디자인 품질을 크게 끌어올리는 프레임워크를 제안한다.

배경 및 문제의식

전문 그래픽 디자인은 레이어, 텍스트, 자산 등 구조화되고 편집 가능한 산출물을 요구하는 장기 호라이즌(long-horizon) 에이전틱 작업이지만, 코드처럼 프로그램적으로 검증 가능한 정답(oracle)이 없다. 하나의 디자인이 수십 개의 상호의존적 도구 호출로 이루어지기 때문에 결과 하나에 대한 최종 보상만으로는 어느 단계가 성공이나 실패를 유발했는지 파악하기 어렵고(신용 할당 문제), 디자인 브리프 또한 텍스트·색상·배치처럼 구체적인 요구사항과 계층구조·구도·스타일처럼 주관적인 요구사항이 뒤섞여 있어 자동 평가자가 이를 온전히 포착하지 못한다. 이런 조건에서 지도학습식 접근은 값비싼 시연 데이터가 필요하고, 외부에 호스팅된 프론티어 모델은 파인튜닝 자체가 비현실적이라는 한계가 있다.

핵심 기여

  • 프론즌(고정) 프론티어 모델을 감싸는 외부 절차적 기억(자연어 스킬 뱅크)을 학습 대상으로 삼아, 파라미터 업데이트 없이 지속적으로 적응하는 프레임워크를 제시했다.
  • 스킬 뱅크를 "넓히기(widening)"와 "깊게 하기(deepening)"라는 두 축으로 진화시킨다. 넓히기는 반복적으로 나타나지만 기존 스킬이 다루지 못하는 하위작업을 새 스킬로 채굴하고, 깊게 하기는 실패 사례와 성공 사례를 대조하여 기존 스킬을 수정한다.
  • 노이즈가 섞인 LLM 채점자·롤아웃 피드백 아래에서도 안전하게 동작하도록, 기존 실적을 절대 후퇴시키지 않으면서 관찰된 실패를 복구하는 변경만 채택하는 보수적인 "매칭 리플레이 게이트"를 도입했다.
  • 5라운드에 걸친 실제 사용자 트래픽 기반 진화만으로 Claude-Opus-4.6, Claude-Sonnet-4, Qwen3.6-27B 등 여러 프론티어 백본에서 범용 텍스트-이미지(T2I) 벤치마크와 전문 그래픽 디자인 벤치마크 모두 성능이 향상됨을 입증했다.

방법론

시스템은 Adobe Photoshop·Illustrator·InDesign에 대응하는 230개 이상의 도구를 조작하는 프론즌 LLM 에이전트("Solver")와, 사람이 읽고 편집할 수 있는 자연어 플레이북(SKILL.md 파일)으로 구성된 외부 스킬 뱅크로 이루어진다. 전체 루프는 네 가지 역할로 조직된다: Prompter(실 사용자 데이터·LLM 기반으로 디자인 브리프 생성), Solver(검색된 스킬과 도구를 이용해 브리프를 실행해 이미지 산출), Grader(멀티모달로 결과를 채점하고 어떤 요구사항이 왜 미충족인지 설명), Reflector(실패 원인을 SKILL.md에 대한 구체적 수정으로 변환).

넓히기 단계에서는 각 트라젝토리마다 프론즌 LLM이 실제로 수행된 하위작업을 추출·정규화한다. 검색된 스킬이 전혀 없거나 다른 부분만 커버할 경우, 혹은 실패의 원인으로 지목된 스킬이 관련된 경우 해당 하위작업을 "미포착(uncovered)"으로 표시한다. 동일한 하위작업 레이블이 최소 임계치(k_min=3회) 이상 누적되면 프론즌 LLM이 이를 후보 스킬로 증류하고, 이 후보는 리플레이 게이트를 통과해야만 뱅크에 등재된다.

깊게 하기 단계는 오직 스킬 자체의 채점 이력만으로 기존 스킬을 개정한다. 성공 임계치(τ=0.6) 미만인 트라젝토리를 실패로 간주해 스킬별 실패 횟수를 집계하고, 임계치(기본 2회) 이상 실패한 스킬을 우선 수정 대상으로 선정한다. Reflector는 실패 사유와 유사 작업에서 성공했던 도구 호출 시퀀스를 대조하여 스킬의 특정 절(section)에 대한 타깃 수정을 제안하며, 반복된 타깃 수정이 게이트를 통과하지 못하면 스킬 전체를 다시 쓰는 방식으로 확대된다. 거부된 개정안은 선택적 탐색 사이클을 거쳐 최종적으로 업데이트·삭제·유지 중 하나로 처리된다.

두 축 모두의 변경 제안은 하나의 리플레이 게이트를 통과해야 채택된다. 채점자의 절대 점수는 라운드 간 드리프트가 있을 수 있어 신뢰하지 않고, 대신 동일한 자산·상류 상태(컨텍스트)를 동결한 채 후보(신규 또는 개정 스킬)와 기존 안(인큐먼트)을 제시 순서를 무작위화하여 쌍대 비교한다. 어떤 프롬프트에서도 후보가 패배하지 않으면서 최소 하나의 프롬프트에서는 승리해야만 변경이 채택되는 보수적 정책을 적용한다.

실험 설정 및 결과

실 사용자 트래픽에서 뽑은 1,406개의 비중복 디자인 브리프와 LLM 증강 변형을 5라운드에 걸쳐 재생하여 1,869개의 채점된 트라젝토리를 생성했으며, 사람 레이블이나 가중치 업데이트 없이 스킬 뱅크가 문서 기반 콜드스타트 76개에서 139개로 성장했다. 진화 브리프와 분리된 200개의 사람이 작성한 held-out 브리프로 평가한 결과, Claude-Sonnet-4의 GenEval2 실행 성공률이 72.7%에서 99.3%로(+11.99점) 상승했고, 4개의 전문 그래픽 디자인 벤치마크(OpenCOLE, GraphicBench, CreatiDesign, BannerRequest400)에서 무스킬 에이전트 대비 Claude-Sonnet-4는 61.8%, Claude-Opus-4.6은 67.6%의 승률을 기록했다. GenEval2·DPG-Bench·OneIG-EN·OneIG-ZH 등 범용 T2I 벤치마크에서도 Opus·Sonnet·Qwen 세 백본 전반에서 평균 생성 품질이 각각 +3.83, +7.70, +9.67 향상됐으며, 지연시간 오버헤드는 3.4~6.2% 수준으로 경미했다. Ablation 실험에서는 넓히기와 깊게 하기를 각각 단독으로 적용했을 때 콜드스타트 대비 개선 폭이 제한적이었지만(완성도 각각 69.02%/69.79%, 승률 48.6%/49.4%), 두 메커니즘을 결합하면 완성도 74.04%(+5.42), 승률 58.5%(p=0.025)로 초가산적(superadditive) 효과가 나타났다.

한계점

자연어 스킬이 선호하는 절차를 기술하더라도, 모델이 이미 강한 기본 전략을 가지고 있으면 검색만으로는 이를 실제로 따르게 강제하지 못할 수 있다. 정밀한 기하학적 조작은 모델의 지각 능력과 자동 검증 방식 자체의 한계로 여전히 제한적이며, 절차가 길어질수록 여러 실행 단계를 거치며 지시의 충실도가 저하된다. 또한 리플레이 게이트는 평가에 사용된 사례에 국한되어 있어, 리플레이 세트에서 관측된 성능 퇴행을 막는 것이 전체 사용자 트래픽 분포에 대한 단조적 개선을 보장하지는 않는다. 실제로 일부 라운드(R4)에서는 진화가 비단조적으로 진행되어 특정 완성도 구간에서 무스킬 기준선보다 낮은 성능을 보이기도 했다.

시사점

절차적 기억은 검증 불가능하고 노이즈가 섞인 피드백 아래에서 프론즌 에이전트를 지속적으로 적응시키는 실용적인 경로를 제공하며, 모델 자체의 파인튜닝이나 결정론적 실행 구조를 대체하기보다 이를 보완하는 메커니즘으로 자리매김한다. 저자들은 향후 선호를 인지하는 검색, 더 결정론적인 실행 프리미티브, 더 정교한 검증 방법이 이러한 한계를 완화하는 데 필요하다고 제안한다.
