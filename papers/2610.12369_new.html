Embodied Turing Machines: Stateful Code for Robot Recursive Self-Improvement

구현된 튜링 머신: 로봇의 재귀적 자기개선을 위한 상태 기반 코드

로봇과 환경을 "구현된 튜링 머신(Embodied Turing Machine)"으로 바라보고, 상태가 정확히 표현될 수 있다면 의사결정을 전적으로 코드로 작성할 수 있다는 관점에서, 실행 시점에 어떤 모델(VLA나 VLM)도 사용하지 않고 코드만으로 정책을 구성하는 Code-Only-as-Policy(COAP)를 제안한다.

한 줄 요약

로봇과 환경을 "구현된 튜링 머신(Embodied Turing Machine)"으로 바라보고, 상태가 정확히 표현될 수 있다면 의사결정을 전적으로 코드로 작성할 수 있다는 관점에서, 실행 시점에 어떤 모델(VLA나 VLM)도 사용하지 않고 코드만으로 정책을 구성하는 Code-Only-as-Policy(COAP)를 제안한다.

배경 및 문제의식

대부분의 로봇 정책은 제어 루프 안에 모델을 유지한다: VLA(Vision-Language-Action)는 관찰을 행동으로 직접 매핑하고, Agent-as-Policy나 Harness VLA 같은 에이전트 하네스는 실행 시점에 VLM을 호출해 의사결정을 내린다. 저자들은 다른 관점을 제시한다: 튜링 머신이 테이프(기호 저장소)와 고정된 규칙으로 임의의 계산 가능한 수열을 처리할 수 있듯, 로봇과 환경도 세계 상태(환경 상태, 로봇 상태)를 테이프로, 정책을 규칙으로 하는 "구현된 튜링 머신"으로 모델링할 수 있다. 이 두 종류의 상태가 정확히 관찰 가능하다면, 의사결정은 모델 없이 코드로 완전히 작성될 수 있다는 것이 핵심 가설이다.

핵심 기여

  • "구현된 튜링 머신"이라는 관점을 제시하고, 카메라 영상과 자기수용감각(proprioception)으로부터 로봇·환경·과업 상태를 측정·추적하며 모든 결정을 그로부터 내리는 코드만으로 구성된 정책 COAP 제안. 동일한 코드가 에피소드 전반에 적용되고, 서로 다른 과업이 VLM이나 VLA 없이 하나의 라이브러리를 공유.
  • VLA·에이전트 하네스와 비교해 COAP의 세 가지 강점 분석: (i) 명시적 상태(Explicit State) - 상태를 코드에 저장 가능, (ii) 실행(Execution) - 의사결정을 통제 가능하게 만들고 실패로부터 유연하게 복구하며 온라인에서 빠르고 저비용으로 실행, (iii) 확장성(Extensibility) - 새로운 과업이 공유 라이브러리를 재사용·상속·확장하여 역량이 과업에 걸쳐 축적됨.
  • 이러한 강점들이 재귀적 자기개선(RSI)에 적합한 매체임을 제시: 코딩 에이전트가 닫힌 루프에서 라이브러리를 발전시키고, 각 변경이 명시적이고 통제 가능.
  • RoboDojo의 42개 양손 조작(bimanual) 과업에서 테스트 시점에 모델 없이 70.24%의 성공률을 달성, 기존 최고 성능 방법보다 38.9%p 높고 5개 평가 차원 모두에서 선두.

방법론

COAP는 공유 라이브러리로서, Try Existing Code(기존 코드 시도) → Observe(관찰) → Debug(디버그) → Validate(검증) → Save·Reuse·Refactor(저장·재사용·리팩토링)의 반복 루프를 통해 새로운 과업마다 코드를 개발·축적한다(Figure 1 하단). 실행 시점에는 state_update(obs)로 상태를 갱신하고, action = plan(state, goal)로 행동을 계획하며, execute(action)으로 실행하고, check_and_recover(state)로 점검 및 복구하는 네 단계 루프가 상태 레지스터(state register)를 테이프처럼 사용해 동작한다. 정책은 project/tasks/, project/functions/ 형태로 구조화된 코드 저장소이며, 태스크별 코드(예: pick_block.py)가 공유 함수(예: perception.py, motion.py, contact.py)를 재사용한다.

실험 설정 및 결과

  • RoboDojo 42개 양손 조작 과업: COAP는 모델 없이 70.24% 성공률을 달성해 VLA(33.95%), 에이전트 하네스(27.96%~36.27% 수준) 등 비교 대상을 크게 상회.
  • 실패 원인 분석(Figure 11): 실패의 62%는 상태 측정의 한계(지각 오류 35%, 접촉 오류 27%)에서, 37%는 코드 로직의 한계(불완전한 로직 29%, 미흡한 코드 설계 8%)에서 발생. 예를 들어 RGB 전용 입력으로 다트보드를 헤드셋으로 오인식하거나, 옷의 부드러운 재질 때문에 잡았던 천이 미끄러지는 등의 사례가 제시됨.
  • 일반화 실험: 새로운 물체·방·방해물이 포함된 무작위화된 레이아웃(Generalization 과업)에서는 성공률이 54.1%로 표준 레이아웃(77.3%)보다 낮았으나, 표준 레이아웃에서는 검증 레이아웃(76.7%)과 테스트 레이아웃(74.9%) 간 성능 차이가 크지 않아, 코드가 특정 장면에 과적합되지 않고 과업 수준에서 일반화됨을 시사.
  • 데이터 엔진으로서의 활용: 한 번 작동하는 과업 프로그램은 모델 없이 CPU에서 실행되며 다양한 레이아웃에서 병렬로 실행 가능해, VLA나 에이전트 하네스를 학습시키기 위한 효율적인 데이터 엔진으로도 활용 가능함을 시연.

한계점

저자들이 명시한 한계는 다음과 같다: (1) 시뮬레이션 한정 - 모든 결과가 시뮬레이션에서 얻어졌으며, COAP의 지각은 시뮬레이션 벤치마크의 공개된 카메라 파라미터·로봇 메시·물체 크기 등에 의존하는데, 이는 실제 로봇에서는 직접 측정하고 그립 폭·이동 속도 등 접촉 관련 파라미터를 재조정해야 하는 주요 제약이다. (2) 오프라인 개발 비용 - 온라인 실행은 빠르지만, 코드를 반복적으로 평가·수정하는 오프라인 개발 과정에 시간이 소요되며, 바로 정책으로 쓸 수 있는 모델(GPT 등)과 달리 새 과업마다 개발 비용이 발생한다. (3) 일반화의 한계 - 코드의 상한은 높지만 현재 70.24%의 성공률에 그치며, 하드코딩된 값처럼 작성 당시의 특정 상황에만 작동하는 불완전한 로직이 그 원인 중 하나다.

시사점

실행 시점에 신경망 모델을 전혀 사용하지 않고도 복잡한 양손 조작 과업에서 기존 VLA·에이전트 하네스 기반 방법을 능가하는 성능을 보였다는 점은, 상태 표현의 정확성과 코드 로직의 견고함을 높이는 방향으로 로봇 정책을 발전시키는 완전히 새로운 패러다임을 제시한다. 정책이 화이트박스 코드이기 때문에 코딩 에이전트가 이를 직접 검사·디버깅·확장하며 재귀적 자기개선을 수행할 수 있다는 점, 그리고 성공한 프로그램이 다른 모델 기반 접근법을 위한 데이터 엔진으로 즉시 활용될 수 있다는 점은 임베디드 AI 연구 전반에 실용적인 시사점을 제공한다.
