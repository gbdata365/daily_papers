Iris: Climbing to the Search Frontier

아이리스: 검색 최전선을 향한 등반

한 줄 요약

웹 그래프의 하이퍼링크 구조로부터 어려운 다중 홉 검색 질문을 자동 생성하고, SFT와 RL을 반복적으로 교차시키는 "SFT-RL climbing" 기법으로 학습한 35B/397B 규모의 검색 에이전트 Iris-mini/Iris-pro가 여러 벤치마크에서 오픈소스 최고 성능을 달성했다는 기술 보고서.

배경 및 문제의식

검색 에이전트는 무엇을 검색할지, 증거를 어떻게 해석할지, 언제 탐색을 멈출지를 스스로 판단해야 하는 어려운 과제다. 기존 연구들은 툴 사용과 추론을 결합한 학습(ReAct 계열), 정적/실시간 웹 검색 기반 RL, 하이퍼링크·지식 그래프를 이용한 어려운 질문 합성 등으로 발전해왔지만, 자연 발생한 웹 질문은 학습에 너무 쉬운 경우가 많고, 벤치마크 간 성능 차이가 실제 정책(policy) 능력이 아니라 추론 시점의 컨텍스트 관리(context management, CM) 전략 차이에서 비롯되는 경우가 많다는 문제가 있었다. 이 논문은 이 두 문제(데이터 난이도, CM에 의한 성능 왜곡)를 동시에 다룬다.

핵심 기여

  • 웹 그래프 하이퍼링크 구조에서 다중 홉 질문을 역구성(reverse-construct)하고, 정답이 아닌 모든 개체명을 서술적 표현으로 재작성하여 문자열 매칭으로 답을 찾을 수 없게 만드는 완전 LLM 기반 데이터 파이프라인
  • 참조 모델이 폐쇄형(closed-book)에서는 실패하지만 증거가 주어지면 성공하는 질문만 채택하는 이중 기준(난이도·해결가능성) 검증
  • 궤적(trajectory) 수준 필터링(정확성, 퇴화, 검색 깊이)과 턴(turn) 수준 필터링(데이터로부터 유도한 루브릭을 사용하는 LLM 판정)의 2단계 필터링을 거친 SFT
  • 실시간 웹 검색에 대한 강화학습(RL)을 훈련 클러스터 내부에 보상 판정자와 관찰 요약기를 함께 배치하여 수행하고, 긴 롤아웃을 요청 단위로 중단·재개하는 부분 롤아웃(partial rollout) 기법 적용
  • SFT와 RL을 반복 교차시키는 "SFT-RL climbing": 각 RL 라운드에서 가장 어렵고 효율적인 성공 궤적을 다음 SFT 라운드에 되먹임하는 자기-페이스(self-paced) 커리큘럼
  • 컨텍스트 관리(CM) 유무를 모두 보고하는 평가 프로토콜을 도입해, 정책 자체의 능력과 추론 시점 하네스의 기여를 분리

방법론

데이터 파이프라인은 웹 페이지를 노드, 하이퍼링크를 엣지로 하는 방향 그래프를 구성한 뒤, 시드 페이지와 그 외부 링크로 이루어진 서브그래프에서 핵심 개체와 관계로 이루어진 압축된 "개체 그래프"를 추출한다. 이 그래프 위에서 최소 N개의 관계를 거쳐야 답에 도달하는 질문을 생성하고, 정답을 제외한 모든 개체명을 고유하게 식별 가능한 서술적 표현으로 치환(anchor abstraction)해 단순 검색으로 답을 찾을 수 없게 만든다. 이렇게 만든 질문은 참조 모델이 도구 없이는 못 풀지만 그래프가 주어지면 유일한 정답으로 풀 수 있는 경우에만 채택된다.

훈련은 두 단계로 진행된다. 먼저 강한 교사 모델이 ReAct 방식(추론-도구호출-관찰 반복)으로 각 질문을 풀어 궤적을 생성하면, 압축비 기반 퇴화 탐지(반복 루프 등)와 정확성 판정을 거친 뒤(coarse filtering), 데이터 유도 루브릭을 사용하는 LLM 판정자가 개별 턴 단위로 불필요하거나 잘못된 턴을 최대 10%까지 마스킹하는(fine filtering) 과정을 거쳐 SFT 데이터셋을 구성한다. 이후 실시간 검색에 대해 그룹 상대 정책 경사(group-relative policy gradient) 방식의 RL을 수행하며, 자체 In-house 모델(Qwen3.5-397B-A17B)을 훈련 클러스터 내부에서 보상 판정자 겸 관찰 요약기로 동시에 서빙한다. 긴 롤아웃의 긴 꼬리(long tail) 문제를 완화하기 위해 요청 단위로 미완료 세션을 중단하고 다음 스텝에서 이어받는 부분 롤아웃 방식을 사용하며, 서로 다른 정책 가중치에서 생성된 프리픽스가 섞이는 문제는 절단 중요도 샘플링(truncated importance sampling)으로 보정한다. 마지막으로 각 RL 라운드에서 통과율이 0~50% 사이인(풀 수는 있지만 아직 불안정한) 질문 중 성공한 궤적 가운데 가장 짧은 것을 골라 다음 SFT 라운드의 학습 데이터로 되먹이는 반복(climbing) 절차를 사용한다.

실험 설정 및 결과

Qwen3.6-35B-A3B, Qwen3.5-397B-A17B를 각각 기반으로 한 Iris-mini(35B), Iris-pro(397B)를 BrowseComp, BrowseComp-ZH, DeepSearchQA, HLE(텍스트 전용) 네 가지 벤치마크에서 평가했다. 모든 벤치마크는 동일한 도구셋, 컨텍스트 한도, 판정 절차 하에서 CM(discard-all 전략) 유무 두 가지 설정으로 보고된다. - CM 적용 시: 30~35B급에서 Iris-mini는 BrowseComp 82.2, BrowseComp-ZH 84.8, HLE 52.3으로 동급 최고 성능(XYZ-Aquila-mini 대비 BrowseComp +3.4점); DeepSearchQA(86.9)는 XYZ-Aquila-mini(89.5)보다 낮음 - ~400B급에서 Iris-pro는 BrowseComp 88.6, DeepSearchQA 92.9, HLE 56.4로 4개 중 3개 벤치마크 최고, BrowseComp-ZH는 XYZ-Aquila-pro와 85.1로 동률 - CM 미적용(w/o) 상태에서도 Iris-mini/pro가 FORT-Searcher, OpenSeeker-v2, REDSearcher 등 기존 공개 결과를 능가해, 성능 우위가 CM 전략만이 아니라 정책 자체의 검색 능력에서 비롯됨을 보임 - CM의 효과는 벤치마크·모델 크기에 따라 크게 달라짐(Iris-mini는 BrowseComp에서 최대 +21.2점, HLE에서는 +9.2점 수준); 이는 지식 위주인 HLE보다 장기 검색이 필요한 BrowseComp류 과제에서 컨텍스트 소진이 더 큰 병목이기 때문으로 분석 - 부록에서는 BrowseComp-ZH 문제의 정답 주석이 원작(왕좌의 게임)과 불일치하는 사례를 제시하며 벤치마크 품질 문제도 논의

한계점

논문은 최상위 프론티어 모델(Claude Fable 5, GPT-5.6 Sol, Kimi-K3 등) 대비 여전히 성능 격차가 있음을 인정하며, 이를 향후 과제로 남긴다고 명시했다. 또한 이 보고서를 "초기 탐색"으로 규정하고, 벤치마크 성능이 에이전트의 전체 능력 중 일부만을 포착한다는 점, retry와 같은 공격적인 추론 시점 전략은 추가 추론 비용을 수반한다는 점을 명시적으로 언급했다.

시사점

이 연구는 (1) 컨텍스트 관리가 검색 에이전트 벤치마크 점수에 크게 기여하지만 이를 분리해 보고하지 않으면 시스템 간 공정한 비교가 어렵다는 방법론적 문제를 제기하고, (2) 웹 그래프 기반 질문 합성과 SFT-RL 반복 교차 학습이 상대적으로 작은 모델(35B)도 1T급 모델에 근접한 검색 성능을 내도록 만들 수 있음을 보인다. 또한 검색으로 학습된 데이터와 모델이 일반 도구 사용(BFCL, τ-bench)이나 사무 작업(OfficeQA, APEX) 등 검색과 무관한 영역에도 전이된다는 관찰은, "검색"이 수직 특화 능력이 아니라 불완전한 정보 하에서 행동하는 에이전트의 원자적(atomic) 능력일 수 있다는 시사점을 제공한다.
