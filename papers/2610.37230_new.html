TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving

TAO: LLM 기반 에이전틱 서빙을 위한 도구 인식 공동 스케줄링

클러스터형 GPU와 분산 CPU(도구 실행)를 함께 사용하는 LLM 에이전트 서빙 환경에서, 도구 호출 지연(tool-return readiness)까지 고려한 세션 평가와 동적 계획법 기반의 공동 스케줄링(선택+배치)을 결합하여 지연시간과 디코드 처리량을 동시에 개선하는 프레임워크 TAO를 제안한다.

한 줄 요약

클러스터형 GPU와 분산 CPU(도구 실행)를 함께 사용하는 LLM 에이전트 서빙 환경에서, 도구 호출 지연(tool-return readiness)까지 고려한 세션 평가와 동적 계획법 기반의 공동 스케줄링(선택+배치)을 결합하여 지연시간과 디코드 처리량을 동시에 개선하는 프레임워크 TAO를 제안한다.

배경 및 문제의식

LLM 에이전트는 GPU에서의 모델 추론과, 컴파일러·검색기 등 외부 CPU 기반 도구 호출을 번갈아 수행하는 "에이전트 세션" 형태로 동작한다. 논문은 이러한 배포 환경을 Clustered-GPUs with Distributed-CPUs(CGDC)로 정의하는데, 도구 호출이 GPU 추론 사이에 간헐적인 공백을 만들어 지연시간의 주요 병목이 된다고 지적한다. 기존 서빙 시스템들은 "평가 후 결정(evaluate-then-decide)" 방식을 따르지만 두 가지 한계가 있다. 첫째, 세션 평가 단계에서 KV 캐시 재사용, CPU 자원, SLO 등은 고려하면서도 도구 호출이 언제 끝나 다시 추론이 필요해지는지(tool-return readiness)는 대체로 무시하거나, 휴리스틱한 규칙으로만 반영한다. 둘째, 의사결정 단계에서 세션별로 개별적인 점수·배치 규칙을 적용하기 때문에, 여러 세션이 동일한 노드 용량을 두고 경쟁할 때 전역적으로 최적이 아닌 근시안적 선택을 하게 된다.

핵심 기여

  • CGDC(Clustered GPUs with Distributed CPUs)라는 서빙 시나리오를 정의하고, 에이전트 시대에 지연시간 병목이 도구 호출로 이동했음을 규명함.
  • 세션 평가에 도구 반환 준비도(tool-return readiness)를 명시적으로 반영하고, 선택과 배치를 공동으로 모델링·최적화하는 TAO 프레임워크를 제안함.
  • TAO는 멀티 에이전트 오케스트레이션, Looped Agents 등 다양한 워크로드로 확장 가능하며, 일반 챗봇(비에이전트) 시나리오와도 호환됨.
  • 12가지 모델-워크로드-동시성 설정 전반에서 지연시간 최대 26.8%, 평균 TTFT 최대 36.3%, 디코드 처리량 최대 29.5% 개선.

방법론

TAO는 크게 두 단계로 구성된다.

1) 세션 평가(Session Evaluation): 대기 풀(waiting pool)에 있는 각 세션-노드 쌍에 대해 사전식(lexicographic) 가치 삼중항 v = (k, r, t)를 계산한다. - k(시간 가중 KV 캐시 크레딧): 관측된 캐시 토큰 수에 지수적 시간 감쇠(반감기 h=10초)를 적용해, 중단 이후 시간이 지날수록 캐시 재사용 가치를 할인한다(식 4). - r(도구 반환 준비도, 이진 신호): 도구 실행 완료 관측, 예측된 반환 시점, 과거 도구 소요시간 통계(평균·분산·범위 기반의 보수적 상한 추정, 부록 A) 등을 결합해 가까운 시간 내 추론 재개가 필요한 세션을 식별한다. 예측 없는 경우 5초 기본값을 사용한다. - t(토큰 수, footprint): 캐시/준비도가 동률일 때 더 큰 컨텍스트를 가진 세션의 용량 비용을 고려하기 위한 세 번째 기준. 삼중항의 우선순위는 캐시 크레딧 > 준비도 > 토큰 수 순으로 고정되며, 값 자체는 시간에 따라 갱신된다.

2) 의사결정(Decision Making): 다중 배낭(multiple-knapsack)/일반화 할당 구조의 동적 계획법을 설계하여, 대기 중인 모든 세션의 평가값 합을 사전식으로 최대화하도록 노드 용량 제약 하에서 세션을 동시에 선택·배치한다(식 7, 알고리즘 1). 계획은 격리된 비동기 워커에서 수립된 후 적용 전에 실시간 상태와 재검증(revalidation)되어, 선택된 세션의 상태가 변했으면 계획을 폐기하거나 실행 가능한 최장 접두사만 적용한다. 부록 C에서는 이러한 비동기 재검증으로 인한 손실(스냅샷 최적해 대비)에 대한 이론적 상한도 제시한다.

실험 설정 및 결과

DeepSeek-V4 Flash(2노드, 노드당 4×H100), Qwen3-32B(4노드, 노드당 2×H100), GLM-4.7(1노드, 8×H100) 세 모델을 SWE-bench Lite, Terminal-Bench, SWE-verified 등 워크로드(MiniSWE-agent, Claude Code 하네스 활용)에서 평가했다. 비교 대상 베이스라인은 vLLM Scheduler(라운드로빈/캐시인식), Dynamo(KV 인식 스케줄러), ThunderAgent(토큰 수 기반 스케줄링+best-fit-decreasing 배치) 등이다.

주요 결과(각 지표별 최상의 베이스라인 대비): DeepSeek-V4 Flash에서 지연시간 2.4~26.8%, TTFT 7.4~36.3%, 디코드 처리량 5.1~29.5% 개선. Qwen3-32B에서도 TTFT·디코드 처리량 전반적 우위, SWE-verified에서 TTFT 12.9~29.9%, 처리량 4.0~7.8% 개선. 더 큰 모델인 GLM-4.7(단일 노드 고동시성)에서도 지연 16.2~18.9%, TTFT 15.7~38.4%, 처리량 22.8~24.7% 개선. 또한 실행 추적(running-request trace)에서 TAO가 전체 워크로드를 더 빨리 완료하면서도 동시 실행 요청 수를 낮게 유지함을 보였다. 구성요소 제거 실험(ablation)에서는 캐시 크레딧, 준비도, 공동 스케줄링(DP) 각각이 성능에 기여함을 확인했으며, DP 배치가 best-fit-decreasing 대비 디코드 처리량을 크게 향상시켰다. 챗봇 혼합 워크로드(Terminal-Bench+SWE-Lite, AutomationBench)에서도 호환성과 개선 효과를 확인했다.

한계점

저자들은 비동기 재검증(asynchronous revalidation)으로 인한 손실에 대한 이론적 상한을 제시했지만, 이는 전역 최적 온라인 정책 대비 엔드투엔드 지연시간/후회(regret)를 보장하지는 않는다고 명시한다. 또한 이 손실 상한은 상태 변화, 적격성(eligibility) 변화, 폐기된 가치 등에 대한 특정 가정(예: 계획당 최대 K개 할당, 스칼라 값 변화 한도) 하에서만 성립하며, 이진 준비도 신호의 급격한 변화는 이러한 가정을 자동으로 만족하지 않는다고 지적한다. 또한 AutomationBench의 128 워커 설정에서는 TAO의 지연시간이 베스트 베이스라인 대비 오히려 소폭 악화(-7.0%)되는 등 모든 설정에서 일관되게 우위를 보이는 것은 아니었다.

시사점

TAO는 도구 호출 지연이라는 에이전틱 서빙 고유의 신호를 세션 평가에 명시적으로 통합하고, 개별 세션 단위의 휴리스틱 결정 대신 전역적인 공동 최적화(DP)를 통해 결정을 내리는 것이 지연시간과 처리량을 동시에 개선할 수 있음을 보여준다. 세션 평가와 의사결정을 분리한 설계는 평가 인터페이스(예: 캐시 신뢰도 추정, 도구 완료 예측 모델)를 독립적으로 발전시키면서도 스케줄링 절차 자체는 유지할 수 있게 해, 멀티 에이전트 오케스트레이션이나 비에이전트 챗봇 등 다양한 워크로드로 확장 가능한 범용적 서빙 아키텍처의 방향을 제시한다.
