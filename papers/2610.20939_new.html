MAI-Gym: An Open All-in-One Platform for GUI Agent Evaluation and RL Training across Mobile and Computer Environments

MAI-Gym: 모바일·컴퓨터 환경 전반의 GUI 에이전트 평가 및 강화학습 훈련을 위한 올인원 오픈 플랫폼

모바일·컴퓨터·웹 환경을 하나의 롤아웃(rollout) 경로로 통합해 GUI 에이전트의 평가, 데이터 수집, 온라인 강화학습(RL) 훈련을 한 플랫폼에서 수행하고, 애플리케이션과 과제까지 자동으로 합성하는 오픈소스 시스템 MAI-Gym을 제시한다.

한 줄 요약

모바일·컴퓨터·웹 환경을 하나의 롤아웃(rollout) 경로로 통합해 GUI 에이전트의 평가, 데이터 수집, 온라인 강화학습(RL) 훈련을 한 플랫폼에서 수행하고, 애플리케이션과 과제까지 자동으로 합성하는 오픈소스 시스템 MAI-Gym을 제시한다.

배경 및 문제의식

검증 가능한 보상을 활용하는 온라인 RL은 수학, 코딩, 툴 사용 분야에서 빠른 발전을 이끌었지만, 이를 GUI 에이전트로 확장하는 데는 두 가지 근본적인 어려움이 있다. 첫째, GUI 환경은 코드 샌드박스와 달리 동시 시도 간 공유가 불가능해 각 시도마다 독립적인 폰·컴퓨터·브라우저 인스턴스가 필요하고, 평가와 훈련에 서로 다른 에이전트 구현을 쓰면 하네스(harness) 차이만으로도 성능이 달라지는 문제가 생긴다. 둘째, 실제 업무 흐름은 여러 앱과 파일에 걸쳐 정보가 분산되어 있는데, 기존 과제 합성 방식은 고립된 입력 파일이나 공유 샘플 데이터에 의존해 다양성과 현실성이 떨어진다. 또한 실제 거래형 앱은 훈련에 쓰기에는 위험하거나 비현실적이다. 기존 GUI 짐(gym)들은 인프라 중심(한 플랫폼만 지원, 수백 개 환경 규모) 또는 데이터 중심(훈련 코드 미공개) 중 하나에 치우쳐 있어, 확장 가능한 실행 인프라와 자동화된 환경·과제 합성을 결합한 통합 플랫폼이 필요했다.

핵심 기여

  1. 통합·확장 가능한 평가·온라인 RL 플랫폼: 모바일, 컴퓨터, 웹에서 공유 환경 인터페이스와 에이전트 하네스를 통해 평가, 데이터 수집, 온라인 RL 훈련을 하나로 묶었으며, 10개 벤치마크를 지원하고 2만 개 병렬 환경까지 확장성을 입증했다.
  2. 자동화된 애플리케이션·과제 합성: 리셋 가능한 모킹(mocked) 애플리케이션과, 상호 연결된 환경 상태에 기반한 어려운 크로스앱 과제를 자동 합성하는 파이프라인을 도입했다. 실행 검증된 태스크 검증기(verifier)와 실패 기반(failure-driven) 과제 생성을 포함한다.
  3. 10B 미만 최강 오픈소스 GUI 에이전트: 통합 9B 모델 MAI-Gym-9B를 공개했으며 MobileWorld 78.4%, OSWorld-Verified 76.2%로 동급 모델 중 최고 성능을 달성했다.
  4. 재현 가능한 연구를 위한 자원 공개: 평가·훈련 프레임워크, 합성 스킬, 49개의 모킹 앱(실제 앱 클론 7개 + 신규 앱 42개), 실행 검증된 2,000개 과제, 모델 체크포인트를 공개했다.

방법론

실행 가능한 과제는 환경 E, 초기 상태 s₀, 자연어 지시 g, 검증기 V로 구성된 튜플 x = (E, s₀, g, V)로 정의되며, 보상은 검증기 기준의 가중 이진 조건들의 가중 평균으로, 성공 여부는 필수 조건들의 곱으로 계산된다. 아키텍처의 핵심 설계는 두 가지다. 첫째, 평가·데이터 수집·훈련이 동일한 하네스와 단일 롤아웃 경로를 공유하도록 하여 세 작업이 항상 같은 에이전트를 보게 한다. 둘째, 에이전트는 환경 매니저(environment manager)를 통해서만 환경에 접근하며, 환경 매니저는 인스턴스 프로비저닝·세션 생애주기 관리·과제 등록·보상 계산·대시보드 보고를 담당한다. 확장성을 위해 모바일은 중첩 가상화 없이 컨테이너에서 바로 구동되는 ReDroid를 사용하고, 비동기 프로비저닝과 워밍풀(warm pool), 객체 스토리지를 통한 스크린샷 전송으로 2만 개 인스턴스 동시 운용을 지원한다. 멀티턴 추론 효율화를 위해 K개 스텝 단위, O개 스텝 중첩의 윈도우로 히스토리를 묶어 KV 캐시 재사용률을 높였다. 환경·과제 합성은 (1) 실제 앱을 참고해 코딩 에이전트가 처음부터 구축하는 '리얼 월드 클론'과 완전히 새로운 인터페이스의 '노벨 앱' 생성, (2) 페르소나와 시나리오로부터 여러 앱에 걸친 일관된 파일·기록을 만드는 크로스앱 월드 구성, (3) 요구사항을 먼저 명세한 뒤 독립적으로 골든 코드와 검증기 코드를 생성하고 초기-완료-리셋 시퀀스로 실행 검증하는 과제·검증기 합성 3단계로 이뤄진다. 훈련은 GRPO를 기본으로 하며, 정책이 가끔 성공/실패하는 과제에 롤아웃을 집중시키는 정책 적응형 과제 샘플링, 윈도우 단위 패킹, 트레이너-롤아웃 간 로그확률 일치성 검사(KL 기반)를 적용한다.

실험 설정 및 결과

Qwen3.5-9B를 베이스로 지도 미세조정(SFT) 워밍업 후 모바일·컴퓨터 과제를 하나의 RL 런에서 조인트로 학습시켜 MAI-Gym-9B를 만들었다(512 GPU, 최대 2만 동시 환경, 약 96시간). 7개 벤치마크(모바일 3개, 컴퓨터 4개) 평가에서 훈련 환경은 같지만 과제는 겹치지 않는 Task-OOD 벤치마크(MobileWorld, OSWorld-Verified)에서 각각 78.4%, 76.2%를 기록해 동급(10B 이하) 오픈 GUI 에이전트 중 최고 성능을 보였으며, UI-Venus-2-9B·GUI-Owl-1.5-32B 등 더 크거나 비슷한 모델들을 능가했다. 훈련 환경이 전혀 다른 Env-OOD 벤치마크(AndroidWorld, MobileGym, MacAgentBench, MyPCBench, OSWorld 2.0)에서도 경쟁력 있는 성능을 보여 일반화를 확인했다. SFT 워밍업이 성능 향상의 대부분을 제공했고, 조인트 RL은 모바일·컴퓨터 양쪽 평균을 모두 끌어올렸다(전문가 모델을 따로 학습해 합치는 방식보다 우수). 특히 12306(중국 기차표 예매 앱) 클론에서의 RL 학습이 실제 물리적 스마트폰에서의 실제 앱 성공률을 28.8%에서 48.1%로 끌어올렸으며, 완전히 새로운 앱에서의 학습도 미지 과제 성공률을 25.8%에서 45.2%로 높여 시뮬레이션-실제 전이 가능성을 입증했다.

한계점

논문은 에이전트 주도 진단(실패 분석 → 과제 합성 → 재훈련)의 반복 루프를 지원한다고 언급하지만, 이 논문에서는 반복 라운드에 대한 평가를 수행하지 않았다고 명시한다. 또한 모킹 앱은 실제 앱을 참고해 구축되지만 완벽히 동일하지 않을 수 있어 실제 전이 효과는 검증된 일부 사례(12306 등)에 한정되어 보고된다. 그 외 세부적인 실패 사례나 일반화 한계에 대한 구체적 논의는 논문에 명시되지 않음.

시사점

MAI-Gym은 플랫폼별로 흩어져 있던 GUI 에이전트 평가·훈련 인프라를 하나의 공유 롤아웃 경로로 통합함으로써, 하네스 불일치로 인한 성능 왜곡 문제를 해결하고 모바일과 컴퓨터를 동시에 학습하는 조인트 RL의 이점을 보여준다. 또한 자동화된 모킹 앱·크로스앱 월드·검증기 합성 파이프라인은 위험하거나 비용이 큰 실제 앱 환경 대신 안전하게 대규모 RL 과제를 생성할 수 있음을 보이며, 시뮬레이션에서 학습한 능력이 실제 앱으로 전이된다는 실증 결과는 GUI 에이전트 연구에서 합성 환경의 실용적 가치를 뒷받침한다.
