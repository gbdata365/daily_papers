IQuest-Q1: Advancing Foundation Capabilities for Agentic CLI Systems

아이퀘스트Q1: 에이전틱 CLI 시스템을 위한 파운데이션 역량 강화

한 줄 요약

명령줄 인터페이스(CLI) 기반 에이전트 작업에 특화된 3200억 파라미터(150억 활성화) 규모의 희소 MoE 파운데이션 모델 IQuest-Q1을, 사전학습-중간학습-다단계 사후학습(SFT·RL·멀티티처 온폴리시 증류·모델 병합)으로 이어지는 파이프라인으로 구축하고 오픈소스로 공개한 연구.

배경 및 문제의식

LLM 기반 에이전트가 CLI를 통해 파일 접근, 도구 사용, 코드 실행 등 외부 시스템과 상호작용하는 것이 가장 일반적인 방식으로 자리잡으면서, 더 강력한 에이전트 모델을 만들려면 CLI 환경에서의 견고한 상호작용 능력이 필수적이라는 문제의식에서 출발한다. 기존 모델들은 코딩, 범용 에이전트 작업, 장기 호라이즌 추론·실행, 사이버보안 등 CLI 기반 작업 전반에서 균형 잡힌 역량과, 실제 사용 환경에서의 신뢰성 있는 도구 호출을 동시에 만족시키기 어려웠다는 점을 과제로 제시한다.

핵심 기여

  • 320B 총파라미터/15B 활성 파라미터 규모의 오픈 가중치 희소 MoE 에이전틱 모델을 공개
  • CLI 중심의 3단계(사전학습 → 중간학습 → 다중 스캐폴드 사후학습) 학습 파이프라인 설계
  • Stable SplitNorm, Muon 옵티마이저, μP 파라미터화를 결합해 동일 데이터 기준 Qwen3-MoE 스타일 베이스라인 대비 약 1.93배의 스케일링 효율을 달성
  • "임계 모델 크기(Critical Model Size)" 개념을 도입해 학습 안정성 여유(stability headroom)를 정량화하는 프레임워크 제안
  • SFT, 도메인별 RL, 멀티티처 온폴리시 증류(MOPD), 모델 병합을 결합한 사후학습 체계와, 리워드 해킹을 막기 위한 환경 준비·실행 시점 점검·궤적 감사의 3중 방어 체계 구축
  • 인간 감독 하에 모델이 스스로 CLI 상호작용의 결함을 진단·수정하는 "human-on-the-loop" 반복 개발 루프의 실제 사례 제시

방법론

IQuest-Q1은 Transformer 기반 희소 MoE 구조(88개 레이어, 은닉 차원 3,072, 쿼리/키-밸류 헤드 48/8, 전문가 256개 중 8개 활성화)를 사용하며, 슬라이딩 윈도우 어텐션(3개 레이어)과 전체 어텐션(1개 레이어)을 3:1 비율로 교차 배치하는 하이브리드 어텐션을 채택한다. QK 정규화, Query-Aware Sink Attention, Partial RoPE, Stable SplitNorm(어텐션 경로만 정규화하고 FFN 경로는 비정규화 유지) 등을 결합해 깊은 네트워크의 안정성과 표현력을 동시에 확보했다. 최적화는 대부분의 파라미터에 Muon을, 임베딩·LM 헤드·정규화·MoE 라우터에는 Adam을 사용하고, μP로 폭·깊이 방향 학습률 전이를 지원해 소형 프록시 모델(히든 폭 896, 18개 레이어)에서 탐색한 학습률을 추가 튜닝 없이 타깃 규모로 전이한다.

학습은 (1) 사전학습(2단계 커리큘럼으로 코드/STEM 데이터 비중을 40%→70%까지 점진 확대), (2) 중간학습(자연어·QA·에이전틱 궤적 데이터 혼합, 32K→128K→512K 토큰으로 점진적 컨텍스트 확장, 토큰 단위 손실 마스킹 적용), (3) 사후학습(SFT 2단계 → 도메인 특화 RL → 멀티티처 온폴리시 증류(MOPD) → 모델 병합)의 순서로 진행되며, 사전·중간학습 합산 29조 토큰을 사용했다. 사후학습에서는 Claude Code, Codex 등 다양한 스캐폴드·버전에서 수집한 궤적으로 GRPO 기반 RL을 수행하고, 에이전틱 사용자 경험·멀티하니스·장기호라이즌·범용 에이전트의 4개 전문가 모델로부터 역KL 기반 길이정규화 증류(MOPD)를 통해 학생 모델에 지식을 통합한다. 리워드 해킹 방지를 위해 솔루션 유출 차단(환경 준비), 실행 시점 네트워크/파일 접근 제한, 궤적 사후 감사를 포함한 3중 보호 체계를 적용했다.

실험 설정 및 결과

코딩 에이전트 벤치마크(DeepSWE v1.1, SWE-bench Multilingual/Pro, NL2Repo-Bench, ProgramBench, CyberGym, SkillsBench, Terminal-Bench 2.1/3.0/4.0, PaperBench, LiveCodeBench v6, 자체 구축한 IQuest-CLIBench)와 범용 역량 벤치마크(GPQA Diamond, Humanity's Last Exam, GDPval, APEX-Agents, Toolathlon-Verified, MCP-Atlas, Claw-Eval, AutomationBench, JobBench, Agents' Last Exam, τ³-Banking, BrowseComp, WideSearch, HealthBench Professional 등)에서 Claude Opus 5, GPT-5.6 Sol, GLM-5.3-Flash, DeepSeek-V4-Flash, Hy3, MiniMax M3 등과 비교 평가했다.

주요 결과로 DeepSWE v1.1 64.6점, SWE-Bench Pro 57.5점, NL2Repo-Bench 63.0점, CyberGym 84.5점, PaperBench 86.0점을 기록했고, GPQA Diamond 93.3점, IMOAnswerBench-Verified 93.0점으로 강한 과학·수학 추론 성능을 보였다. 반면 Humanity's Last Exam은 도구 미사용 시 39.2점에 그쳐 전문가 수준 추론에는 한계를 보였다(도구 사용 시 55.7점). 스케일링 효율 실험에서는 동일 학습 데이터로 Qwen3-MoE 스타일 설계 대비 약 1.93배 높은 효율(동일 손실 도달에 필요한 연산량이 약 52%)을 보였고, 외삽 결과 활성 파라미터 기준 임계 모델 크기(CMS)가 약 572B, 총파라미터 기준 약 12T로 추정되어 추가 스케일링 여력이 있음을 시사했다. 사이버보안 실사용 평가에서는 3일간 인간 전문가와의 협업으로 30건의 취약점 보고서를 생성했으며 모두 동료 전문가의 독립 검증을 통과했다고 보고했다.

한계점

논문이 명시한 한계는 다음과 같다. (1) 텍스트 입력만 지원하며 이미지·음성·영상 입력 능력이 없음. (2) 생성된 설명과 코드가 부정확할 수 있어 과제에 적합한 검증이 필요함. (3) 도구 호출이 IQuest 전용 포맷을 사용해 호환 가능한 서빙 파서·에이전트 하니스가 필요함. (4) 실제 CLI 작업에서는 반복 디버깅·검증이 필요한데 모델이 제약을 간과하거나 실패한 시도를 반복하거나 문제를 미해결 상태로 남길 수 있어 사람의 검토·감독이 필요함. (5) 모델이 아직 역량과 신뢰성 면에서 지속적인 개선이 필요한 개발 중인 상태임.

시사점

IQuest-Q1은 CLI 기반 에이전트 상호작용을 중심에 둔 학습 파이프라인 설계가 코딩·보안·범용 에이전트 작업 전반의 성능 향상으로 이어질 수 있음을 보여주며, 스케일링 효율·안정성 프레임워크(CMS)는 대규모 MoE 모델 설계에 참고할 수 있는 정량적 기준을 제공한다. 또한 모델이 스스로 자신의 실패 사례를 진단하고 개선안을 제시해 다음 버전 개발에 반영하는 human-on-the-loop 반복 개발 프로세스는, 재귀적 자기개선(RSI) 연구와 맞닿아 있는 실용적 사례로서 향후 에이전틱 모델 개발 방법론에 영향을 줄 수 있다.
