WorkFactory: Turning Professional Intents into Executable Work for Scalable Agent Training

워크팩토리: 전문 업무 의도를 실행 가능한 작업으로 변환하여 확장 가능한 에이전트 학습 지원하기

한 줄 요약

전문직 업무 의도(intent)로부터 정보 의존 관계를 명시적으로 설계하고 실행 기반 점검·수리를 거쳐 실행 가능한 업무 환경을 대규모로 생성함으로써, 업무 에이전트(working agent) 지도학습용 교사 궤적(teacher trajectory)의 품질과 규모를 동시에 확보하는 프레임워크 WorkFactory를 제안한다.

배경 및 문제의식

언어 에이전트를 실제 전문 업무(문서 작성, 데이터 분석, 소싱 의사결정 등)에 투입하려면 다양한 직무를 아우르는 실행 가능한 과제와 그에 대한 전문가 수준의 시연(demonstration)이 필요하다. 기존 접근은 관련 자료를 검색·재활용·합성해 과제를 자동 구성하지만, 생성된 과제 환경이 "교사 에이전트가 의도된 산출물을 만들어내는 데 필요하고 일관된 정보(sufficient and consistent information)"를 실제로 포함하는지는 보장하지 못한다. 예를 들어 공급업체 선정 과제에서 수요 예측과 견적서는 각각 다른 파일에 분산되어 있는데, 한쪽 견적에 운임 포함 여부가 빠지면 생애주기 비용을 일관되게 계산할 수 없다. 반대로 계산 결과를 미리 제공해버리면 에이전트가 수행해야 할 핵심 작업 자체가 사라진다. 즉 과제 환경 구축은 "모든 필요한 전제는 해결자(solver)에게 노출되어야 하지만, 중간·최종 결과는 해결자가 직접 도출하도록 남겨두어야 한다"는 미묘한 경계를 지켜야 하는데, 기존 프레임워크들은 이 경계를 명시적으로 다루지 않아 교사 궤적의 신뢰성이 떨어지는 문제가 있었다.

핵심 기여

  • WorkFactory 프레임워크 제안: 의도된 산출물(output)로부터 거꾸로 계획하여, 재사용 자료와 합성 자료 전반에 걸친 정보 의존 관계를 "정보 지원 그래프(information support graph)"로 조직화하고, 환경을 실체화(materialize)한 뒤 실행 기반 수리(execution-based repair)로 과제 실행 가능성을 보존하는 방법을 제시.
  • 대규모 실증 스케일링 연구: 최대 11만 개 과제까지 업무 에이전트 학습 데이터를 체계적으로 늘려가며 모델 규모별 성능 추이, 실행 길이(execution length) 변화, 도구 사용 신뢰도 변화를 분석.
  • WorkPilot 모델 패밀리 학습: Qwen3.5-4B, Qwen3.6-27B, Qwen3.6-35B-A3B 세 규모에서 파인튜닝을 수행해 각각의 베이스 모델 대비 성능을 크게 향상시켰고, WorkPilot-27B는 GDPval-AA에서 프런티어 모델 수준(로컬 추정 1612 Elo)에 도달. 데이터 일부와 모델 가중치를 공개.

방법론

WorkFactory는 크게 세 단계로 구성된다.

  1. 다중 소스 전문 의도 합성(Multi-source Professional Intent Synthesis): 직무 계층(occupational hierarchy), 문서화된 스킬(skill documentation), 실제 전문 산출물(professional artifact)이라는 세 경로에서 업무 의도를 도출한다. 직무를 역할·상황으로 확장하고, 한 작업의 산출물이 다른 작업의 입력이 되도록 스킬을 조합하며, 실제 산출물로부터 역번역(instruction backtranslation)으로 그럴듯한 목표를 추론한다. LLM 기반 검토를 거쳐 내적 일관성과 직무 적합성, 실현 가능성을 갖춘 의도만 공유 라이브러리에 추가한다.

  2. 그래프 기반 환경 구축(Graph-guided Environment Construction): 각 의도에 대해 플래너가 최종 산출물에서 거꾸로 출발해 그 산출물을 뒷받침하는 계산·판단을 식별하고 필요한 정보로 역추적한다. 이렇게 구성된 정보 지원 그래프 G_info = (V_info, V_carrier, E_info, E_loc)는 정보 단위(V_info), 정보 보유 매체(V_carrier), 정보 간 지원 관계(E_info, 연관·변환·근거·제약 등), 그리고 정보가 위치할 매체를 지정하는 결합 관계(E_loc)로 구성된다. 이 그래프는 사용자 요청, 참조 자료, 외부 자원, 미래 산출물, 내부 구축 요건 등 어디에 어떤 정보가 있어야 하는지를 명시하되, 파생 결과(계산·추천 등)는 해결자가 직접 수행하도록 미지정 상태로 남긴다. 이후 환경 작업자(environment worker)가 이 그래프를 구체적인 산출물 구성 계획 P = (u, A, D)로 번역해 실제 사용자 요청, 산출물 명세, 구축 의존성을 만들고, 프로그래매틱 검사와 LLM 기반 검사로 계획과의 정합성을 확인한다.

  3. 실행 기반 환경 수리(Execution-based Environment Repair): "클린 프로브(clean probe)" 솔버가 그래프나 구축 계획, 이전 실행 기록 없이 해결자에게 노출되는 요청과 자원만으로 과제를 시도하여 누락되거나 모순된 정보를 진단한다. 진단 결과 중 과제 완료를 실제로 막는 "차단 이슈(blocker)"만 수리 대상이 되며, 리파이너(refiner)는 파일 개수·유형·의존 구조를 유지한 채 요청이나 참조 파일을 수정한다(예: 특정 공급업체의 운임 조건 USD 0.15/카턴을 누락분으로 추가). 수정본은 다시 구축 검사와 "핵심 목표 보존" LLM 검토를 통과해야 하며, 통과한 과제는 재프로브를 거친다. 차단 이슈가 모두 해소되거나 수리 예산이 소진될 때까지 이 루프를 반복하고, 끝내 해소되지 않은 과제는 폐기한다.

이렇게 통과된 과제 풀에 대해 독립된 교사 모델 GLM-5.3이 정보 지원 그래프나 구축 계획, 이전 진단 없이 깨끗한 샌드박스에서 과제를 수행하여 교사 궤적을 수집하고, 반복적 추론·도구 호출·누락된 산출물 등을 걸러내는 경량 필터링과 긴 궤적에 대한 선택적 거부 샘플링(rejection sampling)을 거쳐 최종 지도학습 데이터를 구성한다.

실험 설정 및 결과

데이터 규모: 최종 학습 코퍼스는 612개 세분화 직무, 23개 대분류에 걸친 112,686개 과제로 구성되며, 평균 과제당 참조 파일 4.15개(평균 1.56 MiB), 교사 궤적당 평균 57.36턴·62.95회 도구 호출·136.18K 토큰 규모다. 목표 산출물 형식은 XLSX(30.7%), PDF(28.0%), DOCX(22.9%) 등이 큰 비중을 차지한다.

벤치마크 및 베이스라인: GDPval-AA(Elo), JobBench, Workspace-Bench, OmegaUse-OfficeVal 네 가지 전문 업무 벤치마크로 평가하며, GLM-5.3·DeepSeek-V4.1-Flash·Qwen3.8-Max·GPT-5.6·Kimi-K3 등 프런티어 모델과 300B 이상/약 30B 규모의 오픈 웨이트 모델들을 비교 대상으로 삼는다.

주요 결과: WorkPilot-35B-A3B는 GDPval-AA에서 879→1565 Elo, JobBench 28.91→62.35, Workspace-Bench 47.12→56.53, OmegaUse-OfficeVal 7.14→21.18로 전 지표에서 베이스 모델 대비 큰 폭으로 향상되었다. WorkPilot-27B는 GDPval-AA에서 1612 Elo를 기록해 DeepSeek-V4.1-Flash보다 12점 높고 GLM-5.3보다 34점 낮은, 프런티어 모델군에 근접한 수준에 도달했다. WorkPilot-4B 역시 베이스 대비 전 지표 개선을 보이며 약 30B급 오픈 웨이트 모델 Apodex-1.1-mini를 GDPval과 OmegaUse-OfficeVal에서 능가했다.

스케일링 분석: 학습 과제 수를 2K에서 110K까지 늘리는 실험에서 Qwen3.6-35B-A3B는 Elo가 879→1565로 상승하되 수익 체감이 뚜렷했다(첫 5K 과제가 447점 기여, 75K→110K 구간은 13점 기여에 불과). 27B·35B-A3B 모델은 각각 3만 개 과제 시점에 110K 시점 대비 성능 향상분의 94%·88%를 이미 확보했다. 실행 길이(평균 턴 수)는 데이터가 늘수록 처음에는 증가(2K 과제에서 최대)했다가 이후 감소하는 비단조적 패턴을 보였고, 코드 실행 실패율은 데이터 증가에 따라 꾸준히 감소(16.0%→6.3%)한 반면 웹 페치 실패율은 40~48%대에서 크게 개선되지 않았다.

구성요소 분석: 직접적인 산출물 수준 계획, 정보 수준 계획(그래프 활용), 정보 수준 계획+실행 기반 수리 세 조건을 비교한 결과, 정보 지원 그래프 도입만으로도 손상된 추론 경로(broken derivation) 결함이 24.86%→6.86%, 불충분하게 명시된 요청이 7.22%→0.62%로 크게 줄었으나 정보 누설(leakage)·자기모순(self-inconsistency) 결함은 오히려 소폭 증가했다. 여기에 실행 기반 수리를 추가하면 8개 결함 범주 전부에서 추가 개선이 나타났고(교차 파일 불일치 25.74%→4.84% 등), 다운스트림 GDPval-AA Elo도 1245→1293→1326으로 누적 81점 상승해, 과제 환경의 일관성이 실제 학습 효용으로 이어짐을 보였다.

비용 대비 성능: 추정 작업당 추론 비용은 WorkPilot-4B 약 $0.012, WorkPilot-35B-A3B 약 $0.031, WorkPilot-27B 약 $0.396이며, 세 모델 모두 비교 대상 모델들 사이에서 비용-성능 비지배 프런티어(non-dominated frontier) 위에 위치했다.

한계점

논문이 명시한 한계는 두 가지다. 첫째, 교사 모델 GLM-5.3이 텍스트 입력만 지원하기 때문에, Qwen 백본이 가진 네이티브 비전·정렬 구성요소를 활용하지 못하고 텍스트 전용 인터페이스로만 학습·평가를 진행했으며, 따라서 시각적 증거로부터 학습하는 능력은 다루지 않는다. 둘째, 학습 방식이 교사 궤적에 대한 지도 파인튜닝(SFT)에 국한되어 있어, 고품질 과제와 실행 피드백을 활용한 강화학습 기반 학습은 향후 과제로 남겨두었다.

시사점

본 연구는 업무 에이전트 학습 데이터의 "양"보다 "환경의 일관성(coherence)"이 교사 궤적 품질과 다운스트림 성능에 직접적으로 영향을 미친다는 것을 정량적으로 보여준다. 정보 의존 관계를 명시적 그래프로 설계하고 실행 기반 진단·수리로 사후 검증하는 2단계 구조는, 단순히 과제 생성량을 늘리는 기존 접근과 달리 "해결해야 할 것"과 "이미 주어져야 할 것"의 경계를 체계적으로 관리할 수 있는 일반적 설계 원칙을 제공한다. 또한 스케일링 실험에서 드러난 모델별 수익 체감과 실행 길이의 비단조적 변화는, 향후 에이전트 학습 데이터 구축 시 단순 데이터량 확대보다 과제 다양성·난이도 분포와 모델 규모에 맞춘 데이터 설계가 더 중요할 수 있음을 시사한다.
