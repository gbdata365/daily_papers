Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

터미널 유니버스: 에이전트 궤적을 확장 가능한 터미널 환경으로 전환하기

한 줄 요약

이미 존재하는 터미널 에이전트 궤적(trajectory) 속 파일 조작 기록을 재생하여 실행 가능한 작업 환경으로 역복원하고, 이를 단일/교차 워크스페이스 및 다회차 질의로 확장해 에이전트 후속학습용 데이터를 대규모로 생성하는 프레임워크를 제안한다.

배경 및 문제의식

터미널 기반 코드 에이전트의 궤적 데이터는 대량으로 쌓여 있지만, 실제로 후속학습에 필요한 것은 재검증·재질의가 가능한 "환경"이지 고정된 궤적 하나가 아니다. Terminal-Bench처럼 수작업으로 만든 환경은 신뢰도가 높지만 규모 확장이 어렵고, 기존 저장소 기반·변형 기반·조건부 생성 기반 방법들은 각각 리포지토리 의존성, 버그 유형 제한, 비현실적인 워크스페이스 등의 한계를 갖는다.

핵심 기여

  • 궤적에 기록된 파일 read/write/edit 연산을 재생해 실행 가능한 환경을 복원하는 2단계(결정론적 재생 + 에이전틱 보완) 방법 제안
  • 단일 워크스페이스(Single-WS), 교차 워크스페이스(Cross-WS), 다회차(Multi-Round) 세 가지 재질의 방식으로 태스크의 폭과 깊이를 확장
  • 공개 궤적으로부터 37.3k개의 작업 충분(task-sufficient) 환경을 생성했고, 이를 활용한 SFT로 Terminal-Bench 2.1에서 11.9점, EvoCode-Bench v2 MT@4에서 13.8점의 성능 향상을 달성

방법론

1단계 결정론적 재생에서는 궤적 속 파일 연산을 시간순으로 재생해 에이전트가 수정하기 이전 상태의 부분 워크스페이스를 복원한다. 2단계 에이전틱 보완에서는 보완 에이전트가 부족한 파일과 의존성을 채워 넣어(해답은 노출하지 않으면서) 실행 가능한 워크스페이스를 만든다. 이후 판정 에이전트가 워크스페이스의 충분성을 평가해 필터링한다. 재질의 단계에서는 원 의도 복원(Intent Recovery), 단일 워크스페이스 내 신규 태스크 합성(Single-WS), TF-IDF 기반 관련 워크스페이스 탐색 후 의존관계를 활용한 교차 워크스페이스 합성(Cross-WS), 사용자 에이전트가 요구사항을 갱신해가며 라운드별 검증하는 다회차 확장(Multi-Round)을 수행한다. 모든 태스크는 컨테이너 내 에이전트가 작성한 pytest 검증기로 필터링된다.

실험 설정 및 결과

공개 터미널/SWE 궤적 풀에서 68,263개 환경을 복원했고, 충분성 필터링 후 37,273개를 확보했다. Qwen3.5-27B를 이 데이터(31,977개 SFT 예시)로 파인튜닝한 결과, Terminal-Bench 2.0/2.1에서 각각 52.8%/58.1%(기존 대비 +11.2/+11.9)를, EvoCode-Bench v2에서 MT@4 20.1(기존 6.3 대비 대폭 향상)을 기록했다. 어블레이션 결과, 원 궤적을 모방하는 것보다 복원된 환경에서 강한 교사 모델로 재해결(re-solving)하는 것이 훨씬 효과적이었고(52.1 대 36.7), 에이전틱 보완과 검증기 필터링, 교차 워크스페이스·다회차 확장 모두 성능에 유의미하게 기여했다. 고정 예산 하에서는 질의나 해답 수를 늘리기보다 환경 수 자체를 늘리는 것이 가장 효과적이었다.

한계점

모든 워크스페이스에 표준 Ubuntu 24.04 컨테이너를 사용해 특수 시스템 의존성이나 복잡한 빌드 단계가 필요한 경우 충실도가 떨어질 수 있다. 복원된 워크스페이스의 도메인·언어·툴체인 분포는 원본 궤적 소스의 커버리지에 근본적으로 제한되며, 단일 교사 모델이 태스크·해답·검증기를 모두 생성하므로 교사 모델의 한계가 그대로 반영될 수 있다.

시사점

새 환경을 처음부터 만드는 대신 이미 존재하는 에이전트 궤적을 재활용해 검증 가능한 학습 환경으로 전환할 수 있음을 보여주며, 에이전트 능력이 향상될수록 더 복잡한 궤적이 확보되어 이 파이프라인이 자연스럽게 함께 확장될 수 있는 잠재력을 시사한다.
