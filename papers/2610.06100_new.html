From Traces to Agentic Worlds: Agentic Language World Models for Interactive Environment Simulation

흔적에서 에이전틱 월드로: 상호작용 환경 시뮬레이션을 위한 에이전틱 언어 월드 모델

원본 환경을 재구축할 수 없을 때, 과거 상호작용 기록(trace)만으로 "월드북(worldbook)"을 만들고 이를 능동적으로 참조하는 에이전트가 직접 환경 역할을 수행하게 함으로써, 단순 프롬프팅 기반 언어 월드 모델보다 훨씬 충실하고 장기적으로 일관된 시뮬레이션 환경을 만드는 학습 없는(learning-free) 프레임워크 Trace2Env를 제안한다.

한 줄 요약

원본 환경을 재구축할 수 없을 때, 과거 상호작용 기록(trace)만으로 "월드북(worldbook)"을 만들고 이를 능동적으로 참조하는 에이전트가 직접 환경 역할을 수행하게 함으로써, 단순 프롬프팅 기반 언어 월드 모델보다 훨씬 충실하고 장기적으로 일관된 시뮬레이션 환경을 만드는 학습 없는(learning-free) 프레임워크 Trace2Env를 제안한다.

배경 및 문제의식

LLM 에이전트를 학습·평가하려면 실제와 유사하게 반응하는 환경 복제본이 필요하지만, 터미널, 소프트웨어 작업 공간, 사내 시스템 등 원본 환경은 코드·데이터·인프라가 없어 재구축이 불가능하거나 비현실적인 경우가 많다. 반면 과거 상호작용 기록(행동·관찰·실패 로그)은 비교적 쉽게 구할 수 있다.

기존의 언어 월드 모델(Language World Model, LWM)은 환경 설명, 상호작용 히스토리, 에이전트의 행동을 하나의 프롬프트로 합쳐 다음 관찰을 예측하는 방식(단순 프롬프팅)을 쓴다. 그러나 이런 방식은 장기적 상태 지속성(long-horizon state continuity) 문제에 취약하다. 예를 들어 report.txt를 삭제하는 행동은 그 즉시는 별다른 출력을 만들지 않지만, 한참 뒤 cat report.txt를 실행하면 "파일 없음" 오류가 떠야 한다. 단순 프롬프팅은 이렇게 지연되어 나타나는 상태 변화를 안정적으로 추론·보존하지 못해 멀티턴 시뮬레이션에 부적합하다.

또한 관련 연구인 Terminal-Universe는 트레이스로부터 실행 가능한(executable) 터미널 작업공간을 재구성하지만, 이는 트레이스에 없는 구현 세부사항·의존성까지 요구하는 경우가 많다. 저자들은 원본 시스템을 역공학으로 재구축하는 대신, 트레이스로부터 "행동 명세(behavioral specification)"만 복원하고 언어 월드 모델이 이를 바탕으로 새로운 행동에 대한 반응을 시뮬레이션하는 대안을 제안한다.

핵심 기여

  1. 에이전틱 언어 월드 모델링(agentic language world modeling)이라는 새로운 패러다임 제안: 환경 시뮬레이션 자체를 하나의 에이전틱 과제로 취급하여, 고정된 프롬프트에서 다음 관찰을 추론하는 대신, 외부화된 환경 지식을 스스로 조회할 수 있는 전담 "월드 모델 에이전트"를 둔다. 과제 수행 에이전트(task agent)는 행동을 결정하고, 월드 모델 에이전트는 그 행동에 대한 환경의 반응을 결정한다.
  2. Trace2Env 프레임워크: 원본 환경이 없어도 과거 트레이스만으로 재사용 가능한 "월드북(worldbook)"을 구성하는 학습 없는(learning-free) 방법. 월드북은 스키마(schemas), 근거 증거(grounded evidence), 유도된 행동 지식(induced abstractions), 출처 정보(provenance) 네 요소로 구성된다.
  3. 영속적 에피소드 작업공간(persistent episode workspace): 여러 에피소드에 걸쳐 재사용되는 고정된 월드북(KE)과, 에피소드별로 변화하는 상태(ŝt) 및 에피소드 메모리(Mt)를 명확히 분리하여, 트레이스에서 온 지식과 현재 에피소드에서만 성립하는 사실을 혼동하지 않도록 한다.
  4. 적용 가능성 게이트와 검증 게이트를 갖춘 에이전틱 시뮬레이션 절차: 검색된 월드북 항목이 현재 맥락에 실제로 적용 가능한지(supporting/uncertain/format-only) 판별하고, 월드 모델 에이전트가 제안한 상태 변화(Δt)와 관찰(õt+1)을 공유 하네스(harness)가 검증(accept/reject)한 뒤에만 커밋하는 구조.
  5. 9개의 서로 다른 환경(터미널, 소프트웨어 엔지니어링, 안드로이드, 웹, 식단·쇼핑·복지 등 업무용 플랫폼, 텍스트 게임 ALFWorld·SciWorld)에 대한 폭넓은 실증 평가.

방법론

Trace2Env는 오프라인(월드북 재구성)과 온라인(에이전틱 시뮬레이션) 두 단계로 구성된다.

1) 월드북 재구성 (오프라인) 빌드 트레이스 집합 Dbuild로부터 구성 모델 φ를 이용해 월드북 KE = Construct_φ(Dbuild)를 만든다. - 스키마(Schemas): 행동 인터페이스와 시뮬레이터가 유지할 상태 변수들을 정의. - 근거 증거(Grounded evidence): 실제로 관찰된 행동-결과 쌍, 선택된 데모와 원본 관찰을 그대로 보존 (귀속이 불확실한 효과는 보류). - 유도된 추상 지식(Induced abstractions): 여러 트레이스에 걸쳐 반복되는 규칙, 조건부 효과, 상태 제약, 관찰 형식 등을 성공/실패 사례의 대조를 통해 귀납적으로 도출. - 출처(Provenance): 각 지식 조각이 어떤 트레이스·턴에서 비롯되었는지 추적.

2) 영속적 에피소드 작업공간 각 시점 t의 작업공간은 Wt = (KE, ŝt, Mt)로 정의된다. KE는 환경이 "어떻게" 동작하는지, ŝt는 "현재 무엇이 참인지", Mt는 "이전에 무슨 일이 있었는지"를 각각 담당하며, 상태가 명시되지 않은 항목은 "존재하지 않음"이 아니라 "알 수 없음"으로 취급된다.

3) 에이전틱 시뮬레이션 (온라인) 행동 at이 주어지면, 월드 모델 에이전트는 현재 에피소드와 관련 월드북 지식을 조회하며 작업공간을 능동적으로 탐색한다. 검색된 각 월드북 항목 e에 대해 적용 가능성 게이트 G_app가 supporting/uncertain/format-only로 분류한다. 에이전트는 이 과정을 거쳐 전이 제안 qt = (Δt, õt+1)을 만들고(직접 상태를 수정하지 않음), 공유 하네스가 검증 게이트 G_val을 통해 스키마·규칙·상태 제약과 대조해 수용/거부를 결정한다. 수용된 제안만 상태에 커밋되고(ŝt+1, ôt+1) = H(Wt, at, qt), 이어지는 턴에 반영되어 하나의 에이전트 루프가 매번 새로 시작되더라도 상태 연속성이 유지된다.

실험 설정 및 결과

평가 환경: 단일 스텝 다음-관찰 예측에는 AgentWorldBench(Zuo et al., 2026)의 Terminal/SWE/Android/Web 분할과 EnvScaler(Song et al., 2026)의 Food/Shopping/Benefits 3개 환경을 사용했고, 멀티턴 상호작용 평가에는 ALFWorld와 SciWorld(텍스트 게임)를 사용했다. 월드 모델 백본은 gpt-5.6-sol과 deepseek-v4.1-flash 두 종류로 테스트했다.

비교 대상: Direct Prompting(공식 프로토콜의 단순 프롬프팅), Trace RAG Prompting(원시 트레이스 5개를 검색해 제공), Worldbook Prompting(재구성된 월드북을 정적 프롬프트로만 제공), Harness only(월드북 없이 Trace2Env 런타임 하네스만 사용), 그리고 전체 시스템인 Trace2Env.

다음-관찰 예측 결과(표 1): Trace2Env는 두 백본 모두에서 평균 최고점(gpt 백본 75.94점, deepseek 백본 75.75점)을 기록했으며, Direct Prompting 대비 각각 +6.43점, +7.04점 향상되었다. 14개 환경-백본 조합 중 11개에서 최고 성능을 보였고 어떤 경우에도 Direct Prompting보다 나쁘지 않았다. Factuality와 Consistency 지표는 모든 조합에서 개선되었다.

멀티턴 일관성 결과(표 2): ALFWorld에서 Direct Prompting은 시뮬레이션 내 성공률(WM)이 97%로 높았지만, 그 행동을 실제 환경에 재생(W2R)했을 때 성공률은 단 3%(CR=0.032)에 그쳤다. 반면 Trace2Env는 WM 성공률이 88%로 다소 낮아도 W2R 성공률이 85%(CR=0.914)로 매우 높았다. SciWorld에서도 Direct Prompting의 CR은 0.529, Trace2Env는 0.706으로 Trace2Env가 더 신뢰할 수 있는 전이를 만들었다. 이는 단순 프롬프팅 모델이 잘못된 전이를 "환각(hallucination)"하고도 내적으로는 일관되게 이어갈 수 있어, 가상의 상태에서 과제를 "성공"시키는 반면, Trace2Env는 지원되지 않는 행동을 올바르게 무효(no-op) 처리하고 상태를 보존함을 보여준다.

구성요소 소거 실험(표 3, Terminal 환경): 근거 증거(evidence)는 단독으로도 스키마 전용 대비 +2.45점의 유의미한 향상을 주지만, 추상 규칙(abstraction)만으로는 도움이 되지 않았다. 다만 증거와 결합하면 추상 규칙 추가가 +0.69점, 증거 추가가 +4.26점의 보완적 이득을 주어, 완전한 월드북이 최고 성능을 냈다.

트레이스 수에 따른 스케일링(그림 3): 구성 트레이스 수를 5~36개로 늘릴수록 Terminal 환경 점수가 꾸준히 상승(20개일 때 64.89점 → 36개일 때 66.42점)했으며, 36개에서도 아직 상승 곡선이 꺾이지 않아 더 많은 트레이스로 추가 향상 가능성이 있음을 시사했다. 다만 구성 비용도 트레이스 양에 거의 비례해 증가했다.

한계점

저자들이 직접 명시한 한계는 다음과 같다. - Trace2Env의 충실도는 결국 트레이스가 드러내는 정보의 범위에 묶여 있다(트레이스에 없는 행동·상태는 재구성할 수 없음). - 일부 백본 모델은 재구성된 증거를 다른 모델보다 덜 일관되게 활용한다(백본에 따른 신뢰도 차이). - 월드북에 대한 능동적 탐색·추론(active inspection and inference)은 더 강화될 여지가 있다. - 현재 재구성은 관찰된 행동 범위를 넘어서지 못하며, 이를 확장하는 것은 향후 과제로 남겨졌다. - 논문은 또한 Trace2Env가 에이전트 "훈련"에 활용되는 효과는 본 연구에서 직접 검증하지 않았고, 향후 연구 방향으로 제시했다.

시사점

이 연구는 "원본 실행 가능한 시스템을 재구축하지 않고도" 신뢰할 수 있는 환경 시뮬레이터를 만들 수 있다는 가능성을 보여준다. 핵심 통찰은, 시뮬레이션의 품질을 가르는 기준이 "시뮬레이션 내부에서의 성공률"이 아니라 "시뮬레이션에서 유도된 행동이 실제 환경에서도 유효한가(월드-투-리얼 일관성)"라는 점이다. 이는 평가 보안이나 사내 시스템처럼 원본 환경에 직접 접근하기 어려운 다양한 상황에서, 과거 로그만으로도 에이전트 학습·평가용 환경 복제본을 만들 수 있는 실용적 경로를 제시한다. 또한 지식을 "스키마-증거-추상 규칙"으로 계층화하고, 에이전트가 이를 능동적으로 조회·검증하게 하는 설계는, 향후 메모리 기반 에이전트나 다른 월드 모델 연구에도 일반적으로 적용 가능한 아키텍처 패턴으로 볼 수 있다.
