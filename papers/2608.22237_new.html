Read Less, Solve More: Token-Efficient Sparse Reading of External Content for AI Agents

Read Less, Solve More: AI 에이전트를 위한 토큰 효율적 외부 콘텐츠 선택적 읽기

한 줄 요약

웹 기반 AI 에이전트가 외부 문서·테이블·코드 저장소를 읽을 때 꼭 필요한 증거만 선택적으로 노출시키는 읽기 제어 계층 SparseRead를 제안해, 토큰 사용량을 최대 92.9%, 처리 시간을 최대 89.0% 줄이면서도 작업 품질을 유지하거나 개선했다.

배경 및 문제의식

LLM 에이전트는 웹페이지, 문서, 코드 저장소, 도구 응답 등 외부 콘텐츠에 반복적으로 접근하는데, 실제로 필요한 증거는 전체 내용의 일부(문서당 중앙값 약 3.17%)에 불과함에도 기존 에이전트는 객체 전체를 읽어들이는 경우가 많다. 이런 "과잉 읽기(over-reading)"는 토큰·지연시간·비용을 급격히 늘릴 뿐 아니라, 관련 없는 내용이 맥락에 섞여 들어가 오히려 도구 오용이나 혼란, 중단을 유발할 수 있다. 장문맥 아키텍처나 KV 캐시 압축은 노출된 콘텐츠를 얼마나 효율적으로 처리할지만 다룰 뿐, 애초에 어떤 콘텐츠를 모델에 노출할지는 결정하지 못한다는 것이 문제의식이다.

핵심 기여

논문은 세 가지 설계 요소로 구성된 SparseRead 프레임워크를 제시한다. (1) Read Intent Protocol: 에이전트가 매 접근 시 현재 필요한 정보 요구를 구조화된 "Read Intent"로 명시하고, 세션 단위 의도와 결합해 증거 상태(무엇이 확인되었고 무엇이 미해결인지)를 추적한다. (2) Adaptive Reader Backends: 텍스트/PDF, 구조화 데이터(테이블·JSON), 코드 저장소 등 아티팩트 유형별로 교체 가능한 Reader가 "어떻게 증거를 찾을지"와 "무엇을 노출할지"를 분리해 처리한다. (3) Budgeted Read Gate: 에피소드 단위로 누적 노출량에 예산 상한을 두고, 필요하면 신뢰 가능한 전체 보기(full-view) 폴백으로 전환하는 추론 시점 컨트롤러다. 저자들은 네이티브 상대 노출 상한(최대 2L)에 대한 수학적 증명도 제공한다.

방법론

SparseRead는 에이전트 모델 자체는 수정하지 않고, 에이전트와 외부 아티팩트 사이에 재사용 가능한 제어 계층으로 삽입된다. 각 Reader는 아티팩트 유형, 지원하는 행동, 실행 비용 프로필을 선언하며, Read Intent에 대해 추정 비용과 예상 증거 신뢰도를 기준으로 최적의 Reader 설정을 선택한다(수식 기반의 비용-신뢰도 최적화). 읽기는 scout·focus·collect·refine·verify의 5가지 안정된 행동으로 구성되며, SHA-256 지문으로 아티팩트 버전과 증거의 유효성을 관리한다. Budgeted Read Gate는 배치 전송 전에 예상 크기를 남은 예산과 비교해, 예산 초과 시 희소 읽기 대신 전체 보기로 폴백한다.

실험 설정 및 결과

Claude Opus 5, DeepSeek-V4-Pro/Flash, Qwen3.6-Plus, GLM-5.1, Kimi-K2.5 등 6개 모델과 장문맥 독해·다중 파일 감사·구조화 분석·웹 심층 검색·과학 연구(AI for Science) 등 5개 시나리오에서 평가했다. SparseRead는 Naive, RAG Static, RAG Agent, ACON, 관측 마스킹과 비교해 15개 설정 전반에서 작업 품질을 유지·개선하면서 토큰을 27.0~92.9%, 시간을 23.0~88.9% 절감했다. NanoBot·OpenCode·OpenClaw 등 세 에이전트 프레임워크에 재학습 없이 이식 가능함도 확인했으며, 소거(ablation) 실험을 통해 세 가지 설계 요소 각각의 기여도(반복 읽기 감소, 증거 추적 가능성 향상, 유효 검증 비율 증가 등)를 검증했다.

한계점

일부 설정(예: GLM-5.1의 AI for Science 시나리오)에서는 점수가 소폭 하락하는 경우가 있었다. 또한 전역 통계 계산이나 규칙 기반 코딩처럼 거의 모든 콘텐츠가 필요한 작업에서는 강제 희소 읽기가 오히려 토큰 사용을 209~309% 증가시켜, 모든 작업에 획일적으로 적용할 수는 없다고 저자들 스스로 명시한다. 가드 메커니즘(Budgeted Read Gate)에 대한 의존도가 높아 전체 성능이 비용 추정의 정확도에 좌우될 수 있다.

시사점

에이전트 인프라 설계에서 "무엇을 모델에 노출시킬지"를 압축이나 검색과는 별도의 명시적 제어 지점으로 다뤄야 한다는 점을 보여준다. 기존 LLM과 프레임워크를 그대로 사용하면서도 읽기 비용을 크게 낮출 수 있어, 실제 프로덕션 에이전트 시스템에 비교적 쉽게 통합될 수 있는 실용적 방향을 제시한다.
