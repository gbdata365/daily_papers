GraphForge: Training Working Agents with Graph-Anchored Workspace Synthesis

그래프포지: 그래프 기반 워크스페이스 합성을 통한 작업 에이전트 학습

한 줄 요약

실제 업무 파일을 바탕으로 증거 그래프를 구축해 작업(task)과 검증 루브릭을 동시에 생성함으로써, "일하는 에이전트(working agent)"를 위한 신뢰할 수 있는 학습 데이터를 자동으로 합성하는 프레임워크 GraphForge를 제안한다.

배경 및 문제의식

업무용 에이전트는 다양한 파일을 읽고, 도구를 조율하고, 산출물을 만들어내야 하는데, 이를 학습시키려면 검증 가능한 결과를 가진 다수의 실제 파일 기반 과제가 필요하다. 그러나 기존 파이프라인은 두 갈래로 나뉘어 한계가 있다. 모델이 파일을 직접 생성하는 방식(EnvCraft 등)은 현실성과 다양성이 떨어지고, 산출물 내용을 검증하지 못하는 파이썬 스크립트에 의존한다. 반대로 실제 파일 위에 과제를 쌓는 방식(NexForge 등)은 과제별 루브릭이나 검증기를 제공하지 않아 결과 품질을 체계적으로 확인할 수 없다. 즉, 실제 파일 기반으로 다양한 과제를 만들면서 동시에 신뢰할 수 있는 검증 루브릭을 갖추는 것이 어려운 과제였다.

핵심 기여

논문은 세 가지를 기여한다. 첫째, 과제와 그 검증을 모두 실제 파일에 근거시키는 프레임워크 GraphForge를 제안한다. 직업(occupation) 기반 시드에서 출발하여 과제문과 루브릭을 증거 그래프로부터 생성하고, 각 과제는 수집 과정에서 한 차례 실행을 통해 사전 검증된다. 둘째, Qwen3.6-27B와 Qwen3.6-35B-A3B를 GraphForge 데이터로 학습시켜 GDPVal, Workspace-Bench-Lite, SpreadsheetBench II에서 큰 성능 향상을 확인했다. 셋째, 합성된 데이터와 학습된 모델 체크포인트를 공개하여 후속 연구를 지원한다.

방법론

GraphForge는 시드 구성부터 궤적(trajectory) 승인까지 5단계로 구성된다. 1. O*NET 기반 과제 시드: ONET 직업 데이터베이스에서 직업, 공식 작업 활동(DWA), 작업-DWA 매핑을 가져와 디지털로 수행 가능한 작업만 남긴다. 각 시드는 직업, DWA 유형, 직업 특이적 업무 요구, 실행 패턴, 입력 파일군 등으로 구성된 튜플이며, 희소성 기반 점수(marginal coverage gain)로 다양성을 담보하도록 탐욕적으로 선택한다. 2. 실제 파일 워크스페이스 구축: 시드는 "케이스 중립적"으로 설계되어, 검색 에이전트가 실제 공개 사례를 찾아 그 수행에 필요한 파일들을 내려받아 워크스페이스를 구성한다. 각 파일은 핵심(core), 보조(supporting), 혼란(confuser), 배경(ambient)이라는 숨겨진 역할을 부여받는다. 3. 증거 그래프와 검증 가능한 루브릭: 워크스페이스로부터 증거 그래프(노드=파일 출처의 사실/필드, 엣지=파일 간 의존관계)를 구축하고, 이를 압축해 자연어 과제문, 산출물 요구사항, 양(+)/음(-)의 채점 기준으로 변환한다. 각 양의 기준은 목표 산출물, 요구사항, 기대값, 가중치, 증거 앵커(원본 파일 노드), 검증 절차로 구성되어 채점이 근거 파일에 "고정(anchored)"된다. 4. 실행 조건부 1단계 수정: 강한 교사 모델로 초안 과제를 한 번 실행해본 뒤, 수정 에이전트가 실행 결과를 보고 과제의 실행 가능성, 요구 수량의 뒷받침 여부, 기준의 정확한 앵커링 여부 등을 점검하여 명세를 보정한다. 5. 산출물 수준 승인 및 궤적 정제*: 산출물이 실제로 만들어졌는지 결정론적으로 검사하고, 에이전트 심판(judge)이 각 기준을 참조 파일과 대조해 채점한다. 점수가 임계값(Q>0.90)을 넘는 궤적만 학습 데이터로 채택되며, 반복 호출이나 과도한 도구 사용 등 퇴화된 행동을 보이는 궤적은 제외한다.

이렇게 수집된 2,169개의 고품질 궤적으로 지도 미세조정(SFT)을 수행하고, 이후 루브릭 기반 거절 미세조정(RFT)으로 추가 개선을 시도한다. RFT는 SFT 모델이 생성한 새 질의-후보군에서 증거 앵커 루브릭으로 점수가 가장 높은 궤적을 선택해 재학습한다.

실험 설정 및 결과

Qwen3.6-27B와 Qwen3.6-35B-A3B를 GraphForge 데이터로 학습시켜 GDPVal-AA(Elo 점수, OpenHands/Codex 스캐폴드), Workspace-Bench-Lite, SpreadsheetBench II(실행 정확도, Claude Code/Codex 스캐폴드)에서 평가했다. 27B 모델은 SFT 후 GDPVal에서 OpenHands 기준 1445.7(+65.7), Codex 기준 1427.4(+63.4)의 Elo를 기록했고, Workspace-Bench-Lite에서 63.7(+7.7), SpreadsheetBench II에서 24.0(+13.7)로 개선되었다. 35B-A3B 모델도 GDPVal에서 101점 이상의 큰 폭으로 향상되는 등 두 기반 모델 모두에서 일관된 이득이 나타나 GraphForge 궤적의 일반화 가능성을 시사했다. 평가는 생성에 쓰이지 않은 서로 다른 스캐폴드(OpenHands, Codex, Claude Code)에서도 이루어져 스캐폴드에 국한되지 않는 업무 능력 향상임을 뒷받침했다.

루브릭 기반 RFT 비교 실험에서는 증거 앵커를 활용한 선택(anchored)이 앵커 정보 없이 루브릭 텍스트만 본 선택(unanchored)이나 무작위 선택(random-of-4)보다 Workspace-Bench-Lite와 SpreadsheetBench II에서 더 큰 개선을 보였다. 또한 학습 코퍼스와 평가 벤치마크(GDPVal) 간 오염 여부를 감사한 결과, 파일·텍스트·직업 수준에서 실질적인 중복이 거의 없었으며, 평가 과제가 학습에서 다룬 직업과 겹치지 않는 경우에도 성능 향상이 유지되어 벤치마크 암기가 아닌 전이 가능한 업무 능력 학습임을 뒷받침했다.

한계점

저자들은 세 가지 한계를 명시한다. 첫째, 현재 코퍼스는 2,169개 궤적에 불과해 더 큰 데이터 규모로 확장했을 때의 이득은 연구되지 않았다. 둘째, 에이전트 심판과 합성 파이프라인 전체가 GLM-5.2로 구동되는데, 더 강력한 프론티어 모델을 사용하면 데이터 품질과 채점 신뢰도가 개선될 여지가 있으며 이는 향후 과제로 남는다. 셋째, 실험은 동일 계열(Qwen)의 두 기반 모델만을 다루어 다른 모델 패밀리로의 전이 여부는 검증되지 않았다.

시사점

GraphForge는 과제 생성과 그 검증(루브릭)을 같은 증거 그래프에서 함께 도출함으로써, 업무용 에이전트 학습 데이터의 현실성과 검증 가능성을 동시에 확보하는 설계 원칙을 제시한다. 특히 증거 앵커가 단순히 채점 보조 도구가 아니라 거절 미세조정에서 유용한 선택 신호로 작동한다는 점은, 합성 데이터 파이프라인에서 "검증 가능성"이 생성 품질뿐 아니라 이후 강화/선택 학습 단계에도 기여할 수 있음을 보여준다. 이는 향후 더 큰 규모·더 다양한 도메인으로 확장되는 업무 에이전트 학습 데이터 구축에 참고할 수 있는 방법론적 틀을 제공한다.
