Language Models Can Control Their Own Attention

언어 모델은 스스로 자신의 어텐션을 제어할 수 있다

긴 문맥을 다룰 때 모델이 매 디코딩 단계마다 전체 KV 캐시를 다시 훑는 대신, 스스로 "지금 어디에 주의를 기울여야 하는지"를 사고 과정(chain-of-thought) 속에서 직접 선언하게 함으로써, 추가 학습 없이도 어텐션 비용을 크게 줄이는 zero-shot 프로토콜을 제안한다.

한 줄 요약

긴 문맥을 다룰 때 모델이 매 디코딩 단계마다 전체 KV 캐시를 다시 훑는 대신, 스스로 "지금 어디에 주의를 기울여야 하는지"를 사고 과정(chain-of-thought) 속에서 직접 선언하게 함으로써, 추가 학습 없이도 어텐션 비용을 크게 줄이는 zero-shot 프로토콜을 제안한다.

배경 및 문제의식

트랜스포머는 디코딩 각 단계마다 이전의 모든 토큰에 대해 어텐션을 계산해야 하므로, 긴 문맥(예: 100만 토큰)에서는 KV 캐시를 메모리에서 읽어오는 비용이 디코딩 지연 시간을 지배하게 된다. 그런데 실제로 어텐션 가중치는 문맥의 극히 일부에 집중되는 경향이 있음이 여러 선행 연구에서 밝혀졌다. 문제는 "어떤 토큰이 중요한지"가 전체 어텐션을 계산해 봐야 알 수 있다는 점이다. 기존 방법들은 recency나 과거 어텐션 크기 같은 고정 휴리스틱을 쓰거나(StreamingLLM, H2O 등), 매 디코딩 단계마다 경량 스코어러로 KV 캐시를 훑어 중요 토큰을 근사적으로 골라내는 방식(Quest, DeepSeek Sparse Attention 등)을 사용해왔다. 그러나 후자도 여전히 매 스텝마다 문맥 길이에 비례하는 O(N) 비용이 든다. 저자들은 "모델이 이미 어느 부분이 관련 있는지 알고 있지 않을까?"라는 질문에서 출발해, 모델 스스로 자신의 주의 범위를 명시적으로 선언하게 하는 내재적(intrinsic) 접근을 제안한다.

핵심 기여

  1. 선언적 어텐션(Declarative Attention, DA) 프로토콜 제안: 모델의 생성 과정을 <global>(전체 문맥 탐색), <focus>(특정 영역에 집중), <local>(자신이 생성한 응답만 참조) 세 가지 모드로 나누고, 추론 엔진이 이 태그를 도구 호출처럼 파싱해 KV 캐시 마스크를 실시간으로 구성한다.
  2. 학습 없이 zero-shot으로 작동: 별도의 파인튜닝이나 파라미터 업데이트 없이, 기성 모델(off-the-shelf)에 하나의 고정된 프롬프트만 적용해 15개의 다양한 장문맥 과제에서 작동함을 보였다. 이는 선행 연구(SSAS)가 과제별로 별도 학습을 필요로 했던 것과 대비된다.
  3. 비용-정확도의 유리한 트레이드오프 입증: Gemma-4-31B에서는 디코딩 중 어텐션 대상 토큰 수를 평균 52.0% 줄이면서 정확도 하락은 1.27%p, Qwen-3.6-27B에서는 31.1% 감소에 정확도 하락 2.75%p에 그쳤다.
  4. vLLM에 실제 통합: FlashAttention과 호환되는 블록 단위 KV 캐시 마스킹을 vLLM에 구현하여, 실제 서빙 환경에서의 이론적 벽시계 시간(wall-clock time) 절감 효과까지 분석했다.

방법론

DA는 프롬프트를 "스캐폴드"(시스템 지시문, 질문, 사용 지침)와 "문맥"(긴 입력) 두 영역으로 나눈다. 문맥은 약 2048토큰 단위의 "매직 청크(magic chunk)"로 분할되며, 이는 모델이 실제 도구 호출로 문서를 하나씩 가져온 것처럼 보이는 시뮬레이션된 대화 형식으로 제공된다(문단, 문장, 절 경계 등 자연스러운 지점에서 분할). 모델은 응답을 생성하며 세 모드를 자유롭게 오간다: <global>은 어느 청크가 관련 있는지 살피는 탐색 모드로 전체 청크에 접근 가능하고, <focus magic_chunks="K">는 특정 청크(들)만 보며 값을 원문 그대로 추출하는 모드, <local>은 문맥 청크를 전혀 보지 않고 이미 추출한 값들만으로 최종 답을 종합하는 모드다. 이 세 모드 전환은 태그의 닫는 ">" 문자에서 파싱되어, 상태 머신이 vLLM의 KV 캐시 블록 테이블을 매 디코딩 스텝마다 다시 써서 마스킹을 실질적으로 적용한다. 마스킹은 vLLM의 고정 크기 블록(16~32토큰) 단위로 이루어지므로 기존 FlashAttention 커널을 변형 없이 그대로 사용할 수 있다. 단, 슬라이딩 윈도우 어텐션(SWA)이나 Gated DeltaNet(GDN) 같은 효율적 레이어는 애초에 문맥 길이에 비례하지 않으므로 DA의 마스킹 대상에서 제외된다. 저자들은 또한 대규모 배치·디스어그리게이션 서빙 환경을 가정한 루프라인(roofline) 모델을 통해, 어텐션의 메모리 대역폭 비용과 FFN의 연산 비용을 하드웨어 상한선 기준으로 분해하여 DA의 실질적 이득을 추정했다.

실험 설정 및 결과

Gemma-4(31B/12B/E4B)와 Qwen-3.5/3.6(27B/9B/4B) 두 계열, 총 6개 모델을 대상으로 RULER, LongBench v1/v2, LooGLE, ZeroSCROLLS에서 가져온 15개 장문맥 과제(단일 구간 검색·추론 및 다중 구간 추론 두 범주)에서 평가했다. 평가에는 정답 기준으로 엄격한 채점 기준(rubric)을 만들고 이를 로컬 LLM 판정자(Qwen-3.5-4B)로 채점하는 방식을 사용했으며, 이 판정자는 프론티어 모델(Gemini-3.1-Pro)과 98.5%의 일치율을 보여 신뢰성을 검증했다. 주요 결과로, DA는 Gemma-4-31B에서 어텐션 대상 토큰을 52.0%, Qwen-3.6-27B에서 31.1% 줄이면서 정확도 하락은 각각 1.27%p, 2.75%p에 불과했다. 청크된 프롬프트 형식 자체(마스킹 없이, DA-no-mask 조건)는 정확도에 거의 영향이 없었으므로, 정확도 하락과 토큰 절감 모두 마스킹 자체에서 비롯됨을 확인했다. 모델 규모가 커질수록 DA의 상대 정확도가 바닐라 대비 29%(가장 작은 모델)에서 99%(가장 큰 모델)까지 향상되는 긍정적 스케일링 경향을 보였고, 문맥이 길어질수록 절대적인 토큰 절감량도 커져(응답당 최대 약 2100만 토큰 절감) 장문맥일수록 이득이 커지는 특성을 보였다. 루프라인 기반 추정에 따르면, 최적화된 B200 GPU 서빙 환경에서 DA는 디코딩 벽시계 시간을 바닐라 대비 Gemma에서 0.71배, Qwen에서 0.77배로 줄일 수 있는 것으로 나타났다.

한계점

DA는 순수 프롬프팅만으로 유도된 zero-shot 행동이기 때문에 여러 구조적 한계가 있다. 첫째, 사고 모드(thinking mode)에서는 모델이 DA 프로토콜을 제대로 따르지 못해 non-thinking 모드에서만 실험을 진행했다. 둘째, 답을 찾기 위해 전체 문맥에 걸친 집계(예: 특정 단어의 전체 등장 횟수)가 필요하거나 표가 청크 경계에서 잘리는 경우처럼, 인위적인 문맥 분할이 정보를 파괴하는 과제에서는 정확도가 크게 떨어진다(최대 30%p 하락). 셋째, 출력 길이가 문서 크기에 비례해 늘어나는 과제(예: 문서 전체 요약, 단어 빈도 나열)에서는 디코딩 스텝 수 자체가 늘어나 절감 효과가 상쇄되기도 한다. 넷째, <global> 모드는 여전히 전체 문맥에 완전한 어텐션을 적용하므로 DA가 절감하지 못하는 잔여 비용으로 남으며, 문맥이 길어질수록 이 비중이 커진다. 다섯째, 가장 작은 모델(Gemma-4-E4B)은 태그 파싱 성공률이 58%에 불과해 프로토콜 준수 자체가 병목이 된다. 마지막으로, 이 모든 결과는 학습 없이 프롬프팅만으로 얻은 하한선(floor)이며, 저자들도 이를 명시적으로 인정한다.

시사점

저자들은 DA가 단순한 프롬프팅 기법을 넘어, 학습된 활성화 기반의 "시스템 1"적 희소 어텐션(경량 스캔 방식)과 대비되는 "시스템 2"적 희소 어텐션의 한 형태라고 주장한다. 즉 모델이 명시적 언어로 자신의 선택 전략을 표현하기 때문에 지시만으로 전략을 바꿀 수 있고, 모델 규모가 커질수록 별도의 프로토콜 수정 없이도 성능이 개선된다. 또한 이 선택 과정이 텍스트로 감사 가능(auditable)하다는 점에서 해석 가능성과 안전성 감독(oversight) 측면에서도 이점이 있다. 향후 방향으로는 (1) 강화학습 등 후속 학습을 통해 더 최적화된 DA 사용 전략을 학습시키는 것, (2) 에이전트 시스템처럼 도구 호출·대화 턴 등 자연스러운 경계가 이미 존재하는 환경에서 인위적 청크 분할 없이 적용하는 것, (3) 사고 모드 내에서도 DA가 작동하도록 확장하는 것, (4) <global> 모드 자체의 비용을 줄이기 위해 각 청크의 축약된 색인(index)을 모델이 참조하게 하는 것, (5) KV 캐시를 완전히 폐기하지 않고 호스트 메모리로 오프로드했다가 필요할 때만 다시 불러오는 "가역적 문맥 압축(reversible context compaction)"으로 확장하는 것 등을 제시한다.
