Evolving Infra: Agent-Adaptive LLM Serving at Scale

한 줄 요약

프리필(prefill)과 디코드(decode)의 연산 자원 할당을 KV 캐시 관리와 분리하고, 에이전트의 실시간 작업 구성과 컨텍스트 관리 신호에 맞춰 이 둘을 온라인으로 함께 조정하는 서빙 프레임워크 Evolving Infra를 제안한다.

배경 및 문제의식

에이전트형 워크로드는 LLM 추론 수요의 큰 비중을 차지하며, 과제·하네스·모델에 따라 프리필 위주 또는 디코드 위주로 성격이 크게 달라지고 시간에 따라 그 구성 비율도 계속 변한다. 기존 프리필-디코드 분리(PD disaggregation) 서빙 시스템은 런타임에 연산 할당과 KV 캐시 관리를 유연하게 조정하기 어렵고, 큐 깊이나 입력 길이 같은 거친 신호에 의존해 실제 에이전트 워크로드의 다양성과 동적 변화를 충분히 반영하지 못해 프리필-디코드 노드 간 부하 불균형과 KV 캐시의 불필요한 축출이 발생한다.

핵심 기여

  • 노드가 재시작 없이 프리필과 디코드 역할을 전환할 수 있는 대칭형(symmetric) 엔진과, 모든 노드가 공유하는 호스트 메모리 KV 풀을 도입해 연산 할당과 KV 캐시 관리를 분리.
  • 오프라인 프로파일링 없이 반복 시간 기반 모델을 온라인으로 학습해 프리필-디코드 분할 비율을 워크로드 구성에 맞게 정밀하게 산정하는 에이전트 적응형 연산 할당 기법 제안.
  • 포크·서브에이전트 생성·컨텍스트 압축 등 에이전트 컨텍스트 관리 신호를 활용해 어떤 KV를 먼저 축출할지 판단하는 클러스터 단위 KV 디렉터리 기반 에이전트 인지형 KV 캐시 관리 기법 제안.

방법론

Evolving Infra는 SGLang 엔진을 확장해 하나의 스케줄링 루프로 프리필과 디코드를 모두 처리할 수 있는 대칭 엔진을 만들고, Mooncake의 RDMA 전송을 재사용하는 KV 전송 프로토콜로 노드 간 어느 방향으로든 KV를 이동할 수 있게 한다. 모든 노드의 호스트 메모리(L2)를 하나의 공유 KV 풀로 묶고, 클러스터 전역 KV 디렉터리가 각 KV 블록을 참조하는 활성 브랜치 수를 추적해 포크·압축·서브에이전트 종료 등에 따라 더 이상 필요 없는 KV를 식별한다. 온라인 플래너는 각 계획 윈도우 동안의 평균 프리필·디코드 작업량을 추정하는 모델을 실시간으로 학습해, 서브에이전트 동시 생성 등으로 인한 순간적인 부하 폭증에 흔들리지 않으면서 예측된 처리량 개선이 지속될 때만 프리필-디코드 분할을 전환한다. 라우터는 큐에 들어온 요청에 대해 비동기로 원격 KV를 미리 가져오면서, 예측된 첫 토큰 생성 시간이 가장 짧은 노드로 프리필 요청을 보낸다.

실험 설정 및 결과

코딩, 수학, 컴퓨터 사용 에이전트 과제에서 GLM-5.2와 Kimi K2.6 모델을 최대 256개의 GB300 GPU 환경에서 서빙하며 NVIDIA의 프로덕션 프레임워크 Dynamo와 비교했다. 단일 워크로드를 정상 부하로 서빙할 때 Evolving Infra는 Dynamo 대비 평균 종단 간 요청 지연과 P95 TTFT(첫 토큰까지 시간)를 각각 최대 4.1배, 14배 줄였으며, 처리량은 Dynamo 대비 최대 2.7배, 최적 정적 분할 대비 최대 38% 더 높았다. 수학 에이전트에서 컴퓨터 사용 에이전트로 워크로드 구성이 바뀌는 상황에서도 온라인으로 프리필-디코드 분할을 적응시켜 Dynamo 대비 2.1배, 최적 정적 분할 대비 28% 더 높은 처리량을 달성했다. 기존 Dynamo 플래너는 노드 전환마다 평균 681초가 걸리고 KV 재사용 손실이 발생했으나, Evolving Infra의 대칭 엔진은 0.7초 만에 전환하면서 KV 재사용 손실을 0.3%로 낮췄다.

한계점

본 평가는 코딩·수학·컴퓨터 사용이라는 특정 에이전트 과제 유형과 GLM-5.2, Kimi K2.6 두 모델, GB300 GPU 환경에 한정되어 수행되었으며, 다른 모델 아키텍처나 이종 GPU 클러스터, 훨씬 더 큰 규모의 멀티테넌트 환경에서의 일반화 가능성은 논문에 명시되지 않음.

시사점

연산 할당과 KV 캐시 관리를 분리하고 에이전트의 실제 컨텍스트 관리 동작을 서빙 시스템의 의사결정에 직접 반영함으로써, 점점 더 동적이고 다양해지는 에이전트형 LLM 워크로드를 대규모로 효율적으로 서비스하기 위한 실용적인 인프라 설계 방향을 제시한다.
