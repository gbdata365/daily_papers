ToolSpace: Scaling Tool-Centric Environment Synthesis for Long-Horizon Agents

툴스페이스: 장기 수행 에이전트를 위한 툴 중심 환경 합성 확장

실제 MCP(Model Context Protocol) 서비스와 공개 에이전트 데이터에서 수집한 실행 트레이스로부터 툴(도구) 간 의존 관계 그래프를 먼저 구축하고, 이 그래프 위에서 상태 인지형 랜덤 워크로 장기 과업을 합성하는 "툴 중심" 접근법으로, 7개 장기 수행 벤치마크에서 Qwen3.6-35B-A3B를 23.0점에서 41.0점(RL 적용 시 43.2점)으로, GLM-5.2급 744B 모델을 44.6점에서 56.6점으로 끌어올려 Claude Opus 5와 동등한 수준을 달성한 연구.

한 줄 요약

실제 MCP(Model Context Protocol) 서비스와 공개 에이전트 데이터에서 수집한 실행 트레이스로부터 툴(도구) 간 의존 관계 그래프를 먼저 구축하고, 이 그래프 위에서 상태 인지형 랜덤 워크로 장기 과업을 합성하는 "툴 중심" 접근법으로, 7개 장기 수행 벤치마크에서 Qwen3.6-35B-A3B를 23.0점에서 41.0점(RL 적용 시 43.2점)으로, GLM-5.2급 744B 모델을 44.6점에서 56.6점으로 끌어올려 Claude Opus 5와 동등한 수준을 달성한 연구.

배경 및 문제의식

기존 MCP 환경 확장 기법들은 "데이터 중심" 방식으로, 먼저 가상의 데이터베이스·시나리오를 합성한 뒤 거기서 툴과 과업(task)을 역으로 도출한다. 저자들은 이 순서가 세 가지 근본적 한계를 낳는다고 지적한다: (1) 합성된 툴의 파라미터 로직이 실제 툴 인터페이스와 어긋나는 툴-기능 불일치, (2) 툴 간 연결 관계가 무작위 연결이나 얕은 LLM 판단에 의존해 신뢰성이 낮은 비authentic한 툴 조합, (3) 과업이 단일 환경 데이터에 묶여 여러 환경을 가로지르는 실제 업무 흐름을 반영하지 못하는 교차 환경 과업 합성의 부재. 즉 에이전트 실행에서 진짜 원자 단위는 정적 환경 데이터가 아니라 '툴'이라는 인식에서, 툴 중심으로 접근 순서를 뒤집을 필요성이 제기된다.

핵심 기여

  • 데이터 중심 합성의 한계를 규명하고, 이를 뒤집은 "툴 중심 환경 합성(Tool-Centric Environment Synthesis)" 패러다임을 제안.
  • 실제 MCP 서비스 및 공개 에이전트 말뭉치의 실행 트레이스에서 결정론적 규칙(LLM 판단 없음)으로 데이터·상태·재시도 의존 관계를 채굴해 가중 툴-조합 그래프를 구축하고, 이를 클러스터링해 환경을 재구성하는 ToolSpace 프레임워크를 제시.
  • 상태를 변화시키는(operation) 환경에만 선택적으로 데이터베이스를 합성하고, 조회형·무상태 툴은 기록된 응답을 재생(replay)함으로써 합성 비용을 절감.
  • 상태 인지형 랜덤 워크(State-Aware Random Walk)와 롤백 샘플링으로 교차 환경 툴 체인을 탐색하고, 이를 자연어 과업과 검증 스크립트로 역변환(decompile)하는 교차 환경 검증 가능 과업 합성 기법을 제안.
  • 기존 벤치마크(AutomationBench, τ³-Bench Banking)보다 난이도를 끌어올린 Pro 버전을 만들어, 7개 프론티어 모델이 최대 38.2점까지 성능이 하락함을 보임으로써 파이프라인의 난이도 확장 유연성을 입증.

방법론

ToolSpace는 2단계로 구성된다. 1단계(Tool Space Exploration)에서는 MCP 생태계 트레이스와 웹에서 수집한 다양한 신뢰도의 에이전트 트레이스를 결합해 통합 말뭉치를 구성하고, 연속된 두 호출 사이에서 (a) 출력값이 다음 입력으로 쓰이는 데이터 의존, (b) 같은 환경 객체를 공유하는 상태 의존, (c) 실패 후 재시도로 이어지는 재시도 의존이라는 세 가지 엣지를 규칙 기반으로 추출해 가중 그래프 G_TS를 만든다. 엣지 가중치는 관찰된 전이 빈도(N_ij/N_i)로 정의된다. 이 그래프를 연결 밀도로 클러스터링해 804개의 환경을 얻고, 상태를 변경하는 운영형 환경에는 연구 에이전트로 데이터베이스를 합성하고, 상태 조회형 환경은 실제 응답을 상태 스냅샷의 앵커로 활용하며, 무상태 환경은 기록된 출력을 그대로 재사용한다. 2단계(Cross-Environment Task Synthesis)에서는 그래프 위에서 엣지 가중치에 비례해 다음 노드를 샘플링하는 상태 인지형 랜덤 워크를 수행하고, 실행이 실패하거나 상태가 어긋나면 이전 스냅샷으로 되돌려 재샘플링(롤백)한다. 목표 길이(L)와 교차 환경 수(K)에 도달한 체인은 툴 이름이나 호출 순서를 노출하지 않는 자연어 과업과, 최종 상태·중간 상태·출력 필드를 검사하는 어서션 기반 검증 스크립트(V_state, V_trace, V_out)로 역변환되며, 초기 상태에서 재실행했을 때 모든 검증을 통과한 샘플만 최종 데이터셋에 남긴다.

실험 설정 및 결과

Qwen3-8B, Qwen3.6-35B-A3B, GLM-5.2-744B-A40B(결과 모델명 ToolSpace-744B-A40B) 세 백본에 대해 SFT 및 GRPO 기반 강화학습(Agent RL)으로 학습했으며, AutomationBench, SkillsBench, JobBench, τ³-Bench Banking, BFCL V4, Harvey LAB, OfficeQA Pro 등 7개 장기 수행 툴 사용 벤치마크로 평가했다. ToolSpace-35B-A3B는 평균 점수를 23.0에서 41.0(RL 적용 시 43.2)으로, ToolSpace-744B-A40B는 GLM 5.2(44.6)보다 높은 56.6점을 기록해 GPT 5.6 Sol(48.9)을 넘어서고 Claude Opus 5(56.6)와 동등한 수준에 도달했다. 환경·데이터 스케일링 분석에서는 환경 수나 데이터량이 늘어날수록 성능이 꾸준히 개선되는 경향을 확인했으며, 관련성 분석에서는 상위 50% 관련 환경과 무작위 50% 환경 간 성능 차이가 최대 1.7점에 불과해 성능 향상이 벤치마크에 특화된 과적합이 아니라 전이 가능한 툴 조합 구조에서 온다는 것을 보였다. 또한 자체 구성한 AutomationBench Pro(300개 과업)와 τ³-Bench Banking Pro(98개 과업)에서는 Claude Opus 5.5, GPT 6.1 Sol 등 7개 프론티어 모델이 표준판보다 최대 38.2점 하락했다. 컴포넌트 제거 실험(ablation)에서는 상태 의존 엣지와 데이터 의존 엣지가 서로 다른 벤치마크에서 핵심적인 역할을 하며, 실행으로 검증된 엣지가 LLM이 판단한 엣지보다 모든 벤치마크에서 더 나은 성능을 보였다.

한계점

논문은 별도의 '한계점' 절을 두지 않았으나, 본문에서 다음을 명시한다: (1) 환경 합성 비용 절감 효과는 합성 파일 수(JSON·CSV 등)를 대리 지표로 추정했을 뿐, 실제 토큰·시간·연산 비용 절감은 측정되지 않음. (2) 표준 벤치마크와의 성능 비교 중 일부 결과는 공식적으로 보고되지 않아("–" 표기) 비교가 제한적임. 그 외 구체적인 한계(예: 그래프 구축이 커버하지 못하는 툴 유형, 재시도 엣지의 비중이 작아 노이즈가 많은 서비스에서의 안정성 등)는 논문에 명시되지 않음.

시사점

에이전트의 실행 능력을 키우는 핵심은 가상의 환경 데이터를 얼마나 정교하게 합성하느냐가 아니라, 실제 실행에서 관찰된 툴 간 연결 구조(조합 공간)를 얼마나 폭넓게 복원하고 확장하느냐에 있음을 보여준다. 이는 향후 에이전트 학습 데이터 합성 연구가 '환경을 얼마나 사실적으로 만들 것인가'에서 '실제로 검증된 툴 조합을 어떻게 더 넓게, 더 신뢰성 있게 그래프화할 것인가'로 설계 방향을 옮겨갈 수 있음을 시사한다.
