Embodied First Exam

코딩 에이전트를 위한 임바디드 퍼스트 이그잼 (로봇 제어 첫 시험 벤치마크)

코딩 에이전트(코드 작성형 LLM 에이전트)가 직접 제어, 코드를 통한 제어, 정책 학습이라는 세 가지 방식 중 스스로 선택해 로봇을 조작하도록 하고, 시뮬레이터 접근 권한과 리셋 가능 여부를 달리한 세 가지 평가 설정(Privileged, Standard, Realtime)에서 47종 로봇·35개 스위트·1,156개 과제를 통일된 방식으로 평가하는 대규모 로봇공학 벤치마크 Embodied First Exam을 제안한다.

한 줄 요약

코딩 에이전트(코드 작성형 LLM 에이전트)가 직접 제어, 코드를 통한 제어, 정책 학습이라는 세 가지 방식 중 스스로 선택해 로봇을 조작하도록 하고, 시뮬레이터 접근 권한과 리셋 가능 여부를 달리한 세 가지 평가 설정(Privileged, Standard, Realtime)에서 47종 로봇·35개 스위트·1,156개 과제를 통일된 방식으로 평가하는 대규모 로봇공학 벤치마크 Embodied First Exam을 제안한다.

배경 및 문제의식

최근 코딩 에이전트가 소프트웨어 공학 과제를 자동으로 수행하는 데 성공을 거두면서, 이를 로봇 제어에도 적용하려는 시도들이 늘고 있다. 그러나 기존 로봇공학 벤치마크는 대부분 비전-언어-행동(VLA) 모델 같은 시각운동 정책 학습을 평가하기 위해 입출력 인터페이스가 고정되어 있어, 자유롭게 코드를 작성하고 실험을 반복하며 계획을 수정할 수 있는 코딩 에이전트의 능력을 평가하기에는 적합하지 않다. 저자들은 "범용 코딩 에이전트가 어떤 로봇 과제를, 어떤 물리적 제약 아래에서, 어디서 실패하는가"라는 질문에 답하기 위해, 과제의 다양성, 현실적 제약의 반영, 다양한 모델·하니스(harness)에 대한 통일 인프라라는 세 가지 설계 원칙에 따라 새로운 평가 체계를 구축했다.

핵심 기여

(1) 집기-놓기 중심의 기존 과제를 넘어 공간 퍼즐, 변형 가능한 물체의 정교한 조작, 다중 로봇 협동, 동적 전신 제어, 시뮬레이터 간 엔지니어링 등을 포함하는 9개의 신규 스위트(411개 과제)를 직접 설계하고, 기존 26개 로봇공학 벤치마크(745개 과제)를 가져와 총 1,156개 과제·35개 스위트·47종 로봇으로 구성된 대규모 평가체계를 구축했다. (2) 시뮬레이터 전체 상태와 무제한 리셋을 주는 Privileged(상한선 측정용), 센서 관측만 주고 리셋을 제한하며 에이전트가 사고하는 동안 시간이 멈추는 Standard(실제 로봇과 유사), 시뮬레이션이 실시간으로 계속 흐르는 Realtime이라는 세 가지 평가 설정을 정의해, 동일 과제에서 물리적 제약의 영향을 분리해 측정할 수 있게 했다. (3) 직접 제어·코드를 통한 제어·정책 학습이라는 세 가지 제어 방식을 에이전트가 자유롭게 선택할 수 있도록 하는 통일 인프라(Harbor 기반 컨테이너 환경)를 제공해 Codex, Claude Code, Antigravity CLI 등 어떤 하니스·모델 조합도 한 번의 명령으로 실행할 수 있게 했다. (4) 과제를 단계(stage)로 나눈 과제 그래프를 만들어 실패가 발생한 지점과 양상을 자동으로 라벨링함으로써, 에이전트가 왜, 어디서 실패하는지 세밀하게 분석할 수 있는 체계를 마련했다.

방법론

EFE는 Terminal-Bench의 평가 프레임워크인 Harbor를 기반으로 모든 과제를 컨테이너 형태로 패키징한다. 각 과제는 고정된 초기 상태에서 시작하며, 에이전트 컨테이너 밖의 별도 검증기(verifier)가 성공 여부를 판정한다. Privileged 설정에서는 에이전트와 시뮬레이터가 같은 컨테이너를 공유해 전체 상태 열람과 무제한 리셋이 가능하며, 에이전트가 제출한 저수준 궤적이나 컨트롤러 프로그램을 별도 컨테이너에서 재생해 평가한다. Standard 설정에서는 시뮬레이터가 별도 서비스 컨테이너로 분리되어, 에이전트는 사전 정의된 API(관측치 조회, 행동 묶음 전송)로만 접근할 수 있고 기본적으로 리셋이 불가능하며, API 호출 사이에는 시뮬레이션이 멈춰 실시간 압박이 없다. Realtime은 Standard와 같으나 에이전트의 행동 사이에도 시뮬레이션이 (계산 부담이 큰 과제의 경우 실제 시간의 일정 비율로) 계속 진행된다. 각 과제에는 시간 제한, 토큰 예산, 리셋 예산, CPU/메모리/GPU/디스크 상한 등 자원 제약이 부여된다. 전체 1,156개 과제 중 평가가 쉽거나 선별 에이전트(GPT-6 Luna)가 이미 푼 과제를 제외한 456개의 어려운 "core" 과제를 대표 평가 대상으로 삼았으며, 이 중 427개 과제는 완료해야 하는 순서가 있는 "단계(stage)"들로 이루어진 과제 그래프로 쪼개 각 실패 시도가 어느 단계에서, 어떤 현상(예: 균형 상실, 접촉 실패)으로 실패했는지 다른 코딩 에이전트(GPT-6.1 Sol, Claude Sonnet 5.5)가 라벨링하도록 했다.

실험 설정 및 결과

GPT-6 Astra(Codex), Claude Opus 5.5(Claude Code), Gemini 4 Argon(Antigravity CLI) 등 8개 에이전트·하니스 조합을 456개 core 과제에서 평가한 결과, 가장 강력한 GPT-6 Astra가 Standard 설정에서 33.6%(153개), Privileged 설정에서 77.5%(303개)의 성공률을 보였으며, 나머지 에이전트들은 이보다 크게 낮았다. 세 최상위 에이전트(GPT-6 Astra, Claude Opus 5.5, Gemini 4 Argon)가 함께 Standard 테스트의 48%를 풀었고, Standard에서는 서로 다른 테스트 집합을 풀어 상호 보완적인 경향을 보였다. Realtime 설정은 Standard보다 더 어려워 54개 공통 과제 중 어떤 에이전트도 풀지 못한 비율이 63%로, Standard의 50%보다 높았다. 통제 실험에서는 무제한 리셋을 주는 것이 정확한 물체 상태를 주는 것보다 GPT-6 Astra의 성능 향상에 더 크게 기여했으며, 두 요소를 함께 제공하면 Privileged 설정과의 성능 격차가 대부분 해소되었다. 정밀함을 요구하는 단계일수록 Standard 설정에서 훨씬 어려워졌고, 이런 단계에서는 리셋이 도움이 되지만 정확한 상태 정보만으로는 부족했다. 실패는 한 과제 내에서 대개 동일한 단계(주로 첫 단계)에서 반복적으로 발생했으며, 물성 변화나 신체 이동이 필요한 단계의 실패율이 가장 높았다. 약한 에이전트는 강한 에이전트보다 필요한 접촉조차 만들지 못하고 실패하는 경우가 훨씬 많았고, 동일 모델이라도 하니스를 바꾸면 성공률이 최대 12%p까지 달라졌다. 축구 과제의 Standard·Realtime 설정에서는 GPU와 학습 라이브러리가 제공되면 에이전트가 정책을 학습하는 방식을 택했고, 학습된 정책만이 승리했다.

한계점

각 결과는 하나의 모델-하니스 조합에 대한 것이며, 각 에이전트가 테스트당 단 한 번만 시도하므로 능력과 시행 간 변동을 구분할 수 없다. core 과제 집합은 GPT-6 Luna의 사전 선별로 쉬운 과제를 제외했는데, 이 모델이 GPT-6 Astra와 같은 계열이라 해당 계열이 잘 푸는 과제에 편향되었을 수 있다. 스위트별 성공률 다수가 소수의 테스트에 기반해 통계적 변동이 크고, 단계 및 제어방식 라벨도 에이전트가 생성한 것이라(라벨 작성 모델 GPT-6.1 Sol 역시 GPT-6 Astra와 동일 계열) 에이전트 간 비교에 편향을 줄 수 있다. 1,156개 과제 중 392개는 참조 해법이 없어 모든 설정에서 풀릴 수 있음이 검증되지 않았고, 스위트 간 시간 제한이 다르며, 일부 과제는 공개된 벤치마크에서 가져와 에이전트가 기존 공개 해법을 기억(memorization)해 풀었을 가능성도 있다. 또한 Section I의 실제 로봇 실험은 단 하나의 과제에 대한 시범 수준이라, 시뮬레이션 결과가 실제 하드웨어에서도 그대로 유지되는지는 아직 확인되지 않았다.

시사점

이 연구는 코딩 에이전트가 시각운동 정책 학습 모델과는 다른 경로로 로봇 제어에 접근할 수 있음을 보이는 동시에, 시뮬레이터 특권 접근과 실제 로봇과 유사한 제약 조건 사이에 성능 격차가 크다는 사실을 체계적으로 드러낸다. 이는 단순히 "에이전트가 로봇을 얼마나 잘 다루는가"를 넘어, 리셋 가능성·상태 접근 수준·실시간성이라는 현실적 제약이 성능에 어떤 방식으로 영향을 미치는지 분리해 측정할 수 있는 표준 틀을 제공한다는 데 의의가 있다. 또한 과제를 단계별로 나누어 실패 지점을 자동 라벨링하는 방법론은 앞으로 에이전트의 실패 원인을 정량적으로 추적하고 개선하는 데 유용한 도구가 될 수 있으며, 에이전트가 제어 방식(직접 제어·코드 작성·정책 학습)을 상황에 맞게 스스로 선택하게 하는 설계는 향후 범용 로봇 에이전트 설계에도 참고가 될 수 있다. 저자들은 이 Standard 설정의 인터페이스를 그대로 실제 로봇에 적용할 수 있다고 보고, 향후 물리적 하드웨어에서의 체계적 평가로 확장할 계획을 밝혔다.
