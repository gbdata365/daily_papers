Raven: The Harness of Harnesses for Composable Agentic Intelligence

레이븐: 조합 가능한 에이전틱 지능을 위한 하니스들의 하니스

Raven은 Claude Code, Codex 등 서로 다른 모델-하니스(harness) 쌍을 조합 가능한 실행 단위로 취급해 Host Agent가 과제를 분해·조율하고 하니스를 스스로 진화시키며 경험을 재사용하는 오픈소스 멀티에이전트 생태계로, 조합의 신뢰성에 대한 이론적 충분조건을 제시하고 기존 최고 시스템 대비 큰 폭의 성능 향상을 실증한다.

한 줄 요약

Raven은 Claude Code, Codex 등 서로 다른 모델-하니스(harness) 쌍을 조합 가능한 실행 단위로 취급해 Host Agent가 과제를 분해·조율하고 하니스를 스스로 진화시키며 경험을 재사용하는 오픈소스 멀티에이전트 생태계로, 조합의 신뢰성에 대한 이론적 충분조건을 제시하고 기존 최고 시스템 대비 큰 폭의 성능 향상을 실증한다.

배경 및 문제의식

LLM 에이전트는 단일 도메인 과제를 넘어 장기적이고 교차 도메인적인 워크플로우로 이동하고 있다. 이 과정에서 두 가지 문제가 드러난다. 첫째, 에이전트의 실질적 능력을 좌우하는 하니스(도구 인터페이스, 컨텍스트 관리, 스킬, 실행 정책, 복구 메커니즘)가 복잡해질수록 수작업 설계가 여러 모델·도메인에 걸쳐 확장되기 어렵다. 둘째, 특정 도메인에 특화된 하니스는 그 가정(도구, 작업 맥락, 기대 출력)에 강하게 결합되어 있어, 여러 하니스의 능력을 결합하려면 하위 과제를 적합한 실행자에 매칭하고 호환 가능한 핸드오프를 구성해야 한다. AutoGen, MetaGPT 같은 기존 멀티에이전트 프레임워크는 하나의 공통 하니스 아키텍처 안에서 역할을 구성하는 데 그치며, 조합의 이득은 과제 구조·개별 능력·조정 비용에 따라 달라진다는 것이 저자들의 문제의식이다.

핵심 기여

  • 개방형 하니스 조합 생태계: 자체 전문 에이전트(Raven-Research/Code/Design/Oncall)와 Claude Code, Codex, Hermes Agent, OpenClaw 등 서드파티 에이전트를 실행 어댑터로 결합하는 아키텍처를 제시하고, 모듈형 하니스 진화·영속 메모리·스킬 재사용을 통합
  • 조합적 에이전틱 지능 이론: 공유 자원 예산 하에서 과제 상대적 능력(task-relative capability)을 정식화하고, 조합이 개별 에이전트보다 신뢰성 있게 과제 범위를 확장할 수 있는 충분조건을 증명(결정론적 합성 건전성, 확률적 신뢰성 하한, 개별 능력을 넘어서는 조합 능력 정리)
  • Multi-Agent Orchestration Benchmark(MAOB): 전문가 선택 및 의존성 예측 능력을 워커 실행 이전 단계에서 측정하는 벤치마크 신규 도입
  • Host 기반 명시적 DAG 협업: 단계적 오케스트레이션 가이드 공개, 5단계 승인 검증(형식/그래프구조/에이전트능력/상태/환경), 준비노드 스케줄링, 독립 judge 모델을 통한 완료 판정, 예외 발생 시 host의 continue/abandon/replan 결정
  • EverOS 메모리와 Skill Forge: 호스트 아카이브와 EverOS 백엔드로 과제 간 경험을 보존하고, Skill Forge가 로컬/메모리 유래 스킬 및 SkillHub 코퍼스에서 과제 관련 절차를 검색·재활용

방법론

모델과 하니스의 결합은 Agent(Mi, hi)로 정의되며, 여러 에이전트가 하나의 Host H에 의해 오케스트레이션된다. Host는 계획 π=(G,σ,Φ,Γ,λ,b)를 유향비순환그래프(DAG)로 구성한다. 여기서 G는 노드(워커 호출)와 엣지(핸드오프)로 이루어지고, σ는 각 노드에 실행자(native loop, CLI, ACP, model API 백엔드 중 하나)를 배정한다. 제출된 그래프는 디스패치 전에 형식·그래프구조·에이전트능력·에이전트상태·환경 조건을 검사하는 5단계 승인(admission) 절차를 통과해야 하며, 검증 실패 시 워커 실행 없이 첫 오류와 가이드 포인터만 반환한다.

노드는 pending → running → completed/exception/failed/skipped/cancelled의 생애주기를 가지며, 모든 선행 의존성이 settle된 노드만 실행 가능(Ready 집합)하다. 워커의 반환 결과는 독립적인 judge 모델이 프롬프트·출력·트랜스크립트를 검토해 "달성/미달성"을 판정하며, 이는 객관적 정답성과는 별개의 개념이다. 미달성 판정은 exception report로 Host에 전달되고, Host는 계속(continue), 포기(abandon), 재계획(replan) 중 하나를 선택한다. 완료된 노드는 append-only 아티팩트 원장(ledger)에 기록되며, 세션 전역에서 노드 ID가 유일하므로 이후 그래프나 단일 위임이 과거 완료 노드를 참조로 재사용할 수 있다(cross-graph reuse). Shared Group Memory는 한 라운드(그래프 실행 또는 단일 위임) 종료 후 각 에이전트에 대한 Host의 평가(verdict)를 EverOS에 기록해 이후 오케스트레이션에 반영한다.

이론적으로는 Hoare 스타일의 상태-원장 불변식을 이용해 "호환 가능한 계획(compatible plan)"의 결정론적 합성 건전성(Lemma 1)을 증명하고, 각 연산이 국소적으로 계약을 실현할 확률적 오차 상한을 합산해 전체 조합 성공 확률의 하한(Theorem 1, Proposition 1)을 도출한다. 또한 서로 다른 읽기 인터페이스만 가진 세 에이전트가 협력해 개별적으로는 불가능한 패리티 비트 계산 과제를 해결하는 명시적 구성을 통해, 조합이 개별 에이전트의 능력 집합을 초과할 수 있는 충분조건(Corollary 1)을 예시로 증명한다.

실험 설정 및 결과

  • MAOB: 두 backbone 모델 모두에서 Node F1·Edge F1·Partial Order Accuracy·Exact Match Rate 4개 그래프 지표에서 전부 1위, Exact Match는 최고 baseline 대비 각각 +10.4pp, +10.5pp
  • Raven-Research (DeepResearch Mixed): Qwen3.6-35B-A3B +6.6pp, Qwen3.5-397B-A17B +3.3pp, DeepSeek-V4-Flash +7.6pp (최고 baseline 대비)
  • Raven-Code: SWE-bench Pro +2.0pp, SWE-bench Verified +0.6pp, WorkBuddy-Code(Reward) +1.4pp, SWE-Refactor(평균점수) +9.5
  • Raven-Design (Claude Opus 5 백본): PresentBench +1.9, ArtifactsBench-Dashboard +1.9, ArtifactsBench-SVG +2.8, GDPval +2.7
  • Raven-Oncall (AI4S 내부평가, Claude Opus 5): 성공률 82.35% (최고 baseline 64.71% 대비 +17.6pp) 달성과 동시에 케이스당 비용 $5.10으로 baseline($13.60) 대비 62.5% 절감

한계점

발췌된 본문(논문 약 20쪽 분량, 전체 86쪽 중 결론/한계 절은 포함되지 않음)에는 별도의 "한계" 절이 없다. 다만 저자들은 이론 부분에서 스스로 제약을 명시한다: 제시된 신뢰성 하한은 어디까지나 "충분조건"이며, 실제로 구현된 에이전트와 Host가 계약 실현·호환적 핸드오프·유계 오차 조건을 실제로 만족하는지는 별도로 검증되어야 한다고 밝힌다. 또한 평균 성공률 수치만으로는 조건부 신뢰성 전제가 성립함을 보장할 수 없다고 경고한다.

시사점

이질적인 모델-하니스 쌍을 조합하면서도 이론적으로 신뢰성을 보장할 수 있는 충분조건을 제시함으로써, 단일 초강력 에이전트보다 "조합 가능한 다수의 전문화 에이전트 + 적절한 Host 오케스트레이션"이 실용적인 확장 경로가 될 수 있음을 시사한다. Claude Code, Codex 등 서드파티 에이전트를 실행 어댑터로 흡수하는 개방형 생태계 설계는 향후 에이전트 생태계 상호운용성 표준화 논의에도 영향을 줄 수 있다.
