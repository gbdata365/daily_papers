Playfulness as Feedback for Agentic Game Development

놀이성을 피드백으로 활용한 에이전틱 게임 개발

코딩 에이전트가 만든 게임이 '실행은 되지만 재미는 없는' 문제를 해결하기 위해, 에이전트가 직접 플레이테스트를 하고 그 '놀이성(playfulness)' 피드백을 근거로 기능 수정과 비주얼·게임플레이 개선을 반복하는 재귀적 게임 개발 프레임워크 Play2Evolve를 제안한다.

한 줄 요약

코딩 에이전트가 만든 게임이 '실행은 되지만 재미는 없는' 문제를 해결하기 위해, 에이전트가 직접 플레이테스트를 하고 그 '놀이성(playfulness)' 피드백을 근거로 기능 수정과 비주얼·게임플레이 개선을 반복하는 재귀적 게임 개발 프레임워크 Play2Evolve를 제안한다.

배경 및 문제의식

자연어 설명만으로 실행 가능한 게임을 생성하는 코딩 에이전트(GameGPT, AutoUE, OpenGame 등)가 빠르게 발전했지만, 실행 가능하다는 것과 플레이어가 즐길 만한 게임이라는 것은 다른 문제다. 기존 연구는 주로 핵심 기능의 정상 동작에만 초점을 맞추었고, 매력적인 비주얼 에셋이나 탐험·진행을 지원하는 풍부한 게임플레이는 충분히 다루지 않았다. 저자들은 좋은 게임이 1) 신뢰할 수 있는 핵심 기능, 2) 매력적인 시각 디자인·에셋, 3) 탐험과 진행을 지원하는 풍부한 게임플레이를 갖춰야 한다고 정의하고, 이를 에이전트가 스스로 개선하도록 만드는 방법이 부족하다는 점을 문제로 제기한다.

핵심 기여

  1. 놀이성(신뢰성·비주얼·게임플레이 풍부함)을 축으로 게임 개발을 재귀적으로 구조화한 Play2Evolve 프레임워크를 제안.
  2. 플레이 증거를 기반으로 결함을 수정하고 새로운 게임플레이·미적 목표를 제안하는 플레이 기반 방법과, 버전 간 개선을 검증하는 A/B Judge(심판 에이전트)를 개발.
  3. 비디오 생성 모델과 코드를 결합해 정적·동적 비주얼 에셋을 적응적으로 관리, 생성하고 실제 게임플레이에 통합.
  4. GameCraft-Bench에서 기존 대비 최고 성능(Overall 60.05, 비교 대상 Play2Code 52.46) 및 인간 평가에서 종합 품질 3.67점(Play2Code 2.43점, 초기화 단계 2.38점) 달성.

방법론

Play2Evolve는 세 단계로 구성된다. ① 게임 초기화(Initialization): Builder 에이전트가 공개 명세를 읽고 코드 편집과 비디오 생성 요청을 번갈아 수행해 실행 가능한 게임(V0), 자산 계획, 재현 가능한 수용 트레이스를 생성한다. 비주얼 자산은 정적 소재, 단일 동적 소재, 상호작용 소재(커플드 오브젝트), 전체 장면(풀씬) 소재의 4단계 생성 수준 중 하나로 할당되며, 비디오는 외형·동작을 담당하고 코드는 입력·충돌·진행 상태 등 상호작용 제어를 담당한다. ② 게임 정제(Refinement): Player 에이전트가 목표 지향적 플레이테스트 그룹을 계획해 플레이하고, Judge가 품질을 평가해 문제를 진단하며, Planner가 수정 대상(에셋·코드 또는 둘 다)과 생성 범위를 결정해 후보를 재생성·검증한다. ③ 게임 진화(Evolution): 이전 버전의 플레이 기록을 바탕으로 에이전트가 새로운 게임플레이·미적 개선 목표를 제안하고, 후보 버전을 다시 플레이·평가한 뒤 A/B 비교로 더 나은 버전을 채택한다. 또한 이전 플레이 결과를 요약한 'Behavior Skill'을 다음 플레이 스크립트에 반영하여 탐험 효율을 높인다.

실험 설정 및 결과

구현은 Codex 기반 GPT-6 Sol(중간 추론 노력)을 빌드·플래닝·코드 편집·Player·Judge에 사용하고, 비디오 자산 생성에는 MiniMax H3(H200 GPU 8장)를 사용했다. Godot 및 브라우저 기반 HTML 게임을 지원한다. 평가는 GameCraft-Bench(15개 범주 140개 과제, 역학·깊이·시각적 기능·아트·종합 점수)와 GameASG-Bench(12개 범주 47개 과제, 정적 준수·런타임 동작·엄격한 과제 성공률)에서 수행되었으며, 비교 기준은 적응된 Play2Code(동일한 개발 토큰 예산 사용)이다. 결과적으로 GameCraft-Bench Overall은 초기화 50.81 → 정제 54.45 → 진화 60.05로 상승하며 Play2Code(52.46)를 능가했다. GameASG-Bench 엄격 성공률도 35.7%(V0)에서 57.4%(V1, V2)로 상승했다. 12명이 참여한 인간 평가(5점 척도)에서도 Play2Evolve의 최종 버전(V2)이 시각적 매력, 동작 품질, 아티팩트 부재, 플레이 의향, 종합 품질 등 5개 항목 모두에서 가장 높은 점수를 받았다(종합 품질 3.67 대 Play2Code 2.43). 10개 게임에 대한 3회 연속 진화 실험에서도 반복할수록 점수가 지속적으로 상승함을 확인했다.

한계점

플레이어 에이전트가 특정 이벤트에는 도달하지만 이후 게임플레이를 놓치는 등 탐험이 불완전할 수 있어, 탐험되지 않은 콘텐츠는 신뢰성 있게 진단되지 않는다. 레코딩·플레이 오류(텍스처 미반영, 잘못된 키 입력 등)로 평가 증거 자체가 부정확할 수 있다. 진화가 항상 더 나은 결과를 보장하지는 않으며(일부 사례에서 이전 버전이 유지됨), 서로 다른 플레이 정책 때문에 개선 효과를 명확히 귀속하기 어렵다. 인간 평가는 직접 플레이가 아닌 클립 시청을 기반으로 하여 지속적 몰입 경험을 측정하지는 못했고, 비디오 재생성에는 추가 연산 비용이 들며, 테스트된 엔진·생성기를 벗어난 환경으로의 일반화는 추가 검증이 필요하다.

시사점

이 연구는 '실행 가능함'과 '재미있음' 사이의 간극을 플레이 증거 기반의 재귀적 자기개선 루프로 좁히려는 시도로, 코딩 에이전트와 비디오 생성 모델을 결합해 콘텐츠(에셋)와 로직(코드)을 분리된 책임으로 관리하는 설계가 향후 자율적 콘텐츠 제작 에이전트 일반에 적용될 수 있는 패턴을 제시한다. 다만 에이전트 플레이의 탐험 커버리지와 평가 신뢰성이 전체 품질 개선의 상한을 좌우한다는 점은, 유사한 '에이전트 자가 플레이테스트' 접근이 다른 상호작용 콘텐츠(예: 교육 시뮬레이션, UI 프로토타입)로 확장될 때도 핵심 과제로 남을 것이다.
