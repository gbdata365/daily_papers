Memory Tax: Dissecting the Net Value of Agent Memory

한 줄 요약

장기 기억(long-term memory)을 갖춘 에이전트 다수가 실제로는 단순한 naive RAG보다 성능이 떨어지며, 이 저자들은 그 손익을 "memory benefit(기억 이득)"과 "memory tax(기억 비용)"로 분해해 분석한다.

배경 및 문제의식

개인화 에이전트나 장기 상호작용 에이전트에는 다양한 memory 시스템(요약, 사실 추출, 구조화 기록 등)이 빠르게 도입되고 있지만, 대부분의 선행 연구는 다른 memory 시스템끼리 비교할 뿐 raw history를 그대로 검색하는 naive RAG를 기준선으로 충분히 검증하지 않았다. 그 결과 memory를 구축하는 것이 direct retrieval 대비 실제로 얼마나 더 나은지(순가치, net value)가 불분명한 상태로 남아 있었다.

핵심 기여

(1) 여러 벤치마크와 백본에서 memory 시스템의 순가치를 naive RAG 대비 체계적으로 재평가했고, (2) 이 순가치를 memory benefit과 memory tax로 분해해 tax가 어디서 발생하는지 분석했으며, (3) 이 benefit-tax 관점을 personal-agent memory 외에 experiential memory, world-model memory 등 더 넓은 응용으로 일반화하고 설계 시사점을 도출했다.

방법론

저자들은 raw interaction history H를 memory ingestion 과정 I를 통해 memory M으로 변환하고, 질의 시 M에서 관련 유닛을 retrieve하여 답을 생성하는 공통 틀을 정의한다. Naive chunk 기반 RAG(1-round/2-round)를 기준 비교 대상으로 삼아, 질의 단위(per-query)로 memory 시스템이 RAG가 놓친 질문을 맞히는 경우(memory benefit)와 RAG가 맞힌 질문을 놓치는 경우(memory tax)를 Venn 비교로 나눈다. 또한 memory tax를 체계적으로 뜯어보기 위해 (i) faithfulness(정보가 얼마나 손실 없이 보존되는지), (ii) accessibility(보존된 정보가 얼마나 쉽게 검색되는지), (iii) robustness(백본이 바뀌어도 memory가 안정적인지) 세 축으로 분석하고, retrieval 예산을 Retrieval Scope(RS)라는 지표로 토큰 단위로 맞춰 공정하게 비교한다.

실험 설정 및 결과

LongMemEval-s, PersonaMem-v2, MINT-Eval 세 개 벤치마크에서 Qwen3.5-4B, Qwen3.6-27B, GPT-5.6-luna(low) 세 백본으로 A-Mem, MemOS, SimpleMem, MemoryOS, LightMem, OpenViking, HippoRAG2, MAGMA, PlugMem, Mem-T, Memory-R2 등 11개의 대표적인 memory 시스템을 평가했다. 결과적으로 naive RAG(2-round)가 매우 강력한 기준선이었고, 대부분의 memory 시스템이 여러 설정에서 RAG보다 낮은 점수를 받아 순가치가 음수였다. 세부 분석에서는 정보 손실(faithfulness) 정도가 시스템마다 크게 달랐고, 정보가 보존되어도 조각화·희석·재서술 등으로 접근성(accessibility)이 떨어지는 경우가 있었으며, memory 구성 시 사용한 백본과 질의응답 시 사용한 백본이 다르면 RAG보다 성능 변동(robustness 저하)이 더 크게 나타났다. 또한 experiential memory(ALFWorld, WebShop, AppWorld 등)와 world-model memory(Context-as-Memory, MemoBench) 실험에서도 유사한 benefit-tax 패턴이 재현되었다. 개선 방향으로 raw history로 돌아갈 수 있는 "recoverable deviation"을 만들거나(src-aug), 과거 질의·검색 경로를 memory에 재투입하는 recursive 검색을 적용했을 때 memory tax가 감소하고 정확도가 개선됨을 보였다.

한계점

사용된 벤치마크는 대부분 정적(static)·오프라인·영어 중심이어서 실제 장기 배포 환경에서의 interleaved 질의나 다국어 상황은 다루지 못했다. 계산 및 API 비용 제약으로 PersonaMem-v2는 20%, MINT-Eval은 10% 등 일부를 서브샘플링했고, GPT-5.6-luna보다 더 강력한 최신 프론티어 모델은 포함하지 않았다. 또한 omni-modal, latent, parametric 형태의 memory로의 확장은 향후 과제로 남겨두었다.

시사점

이 연구는 memory 시스템 평가 시 naive RAG를 반드시 기준선으로 포함해야 하며, 단순히 standalone 성능이 아니라 RAG 대비 순가치(memory benefit과 memory tax의 균형)를 함께 보고해야 한다는 점을 시사한다. 특히 벤치마크 자체가 retrieval에 유리한(headroom이 적은) 경우 memory의 tax가 더 쉽게 드러나므로, 더 어려운 평가 설정 설계와 함께 memory 구성 시 "복구 가능한 편차"를 남기는 설계(src-aug, recursive retrieval)가 실용적 개선책이 될 수 있다.
