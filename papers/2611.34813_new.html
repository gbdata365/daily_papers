Solve Vision with Code: Coding Agents Are Stronger Visual Reasoners Than Video Models

코드로 푸는 비전: 코딩 에이전트는 비디오 모델보다 강력한 시각 추론자다

비디오 생성 모델에게 "첫 프레임 + 프롬프트"를 주고 정답 비디오를 직접 생성하게 하는 대신, 코딩 에이전트(Codex, Claude Code, Gemini CLI 등)가 동일한 입력으로 정답 비디오를 렌더링하는 프로그램을 작성하게 했더니, 동일한 평가 기준(VBVR-Pro-Bench)에서 코딩 에이전트가 최고 성능의 비디오 생성 모델보다 훨씬 높은 점수를 기록했다.

한 줄 요약

비디오 생성 모델에게 "첫 프레임 + 프롬프트"를 주고 정답 비디오를 직접 생성하게 하는 대신, 코딩 에이전트(Codex, Claude Code, Gemini CLI 등)가 동일한 입력으로 정답 비디오를 렌더링하는 프로그램을 작성하게 했더니, 동일한 평가 기준(VBVR-Pro-Bench)에서 코딩 에이전트가 최고 성능의 비디오 생성 모델보다 훨씬 높은 점수를 기록했다.

배경 및 문제의식

최근 비디오 생성 모델은 사실적이고 시간적으로 일관된 영상을 만들어내면서, 단순히 설명을 영상화하는 것을 넘어 구조화된 과제를 "시각적으로 추론"해 풀 수 있는지에 대한 관심이 커지고 있다. VBVR-Pro-Bench는 첫 프레임과 자연어 프롬프트가 주어지면 모델이 과제를 수행하는 비디오를 만들어야 하고, 그 결과를 classical computer vision 기반의 규칙 평가기(rule-based evaluator)가 symbolic ground truth와 비교해 채점하는 대규모 벤치마크다. 그러나 "영상 매체 안에서 네이티브하게 추론하는 것"이 실제로 더 신뢰할 만한 경로인지, 언어나 코드를 매개로 한 대안과 동일 조건에서 비교된 적은 없었다. 저자들은 대부분의 과제에서 정답이 첫 프레임과 프롬프트로부터 결정론적으로 계산 가능한 함수라는 점에 주목해, 픽셀을 디노이즈하는 모델 대신 코드를 작성해 그 함수를 명시적으로 풀고 렌더링은 인터프리터에 위임하는 방식을 제안한다.

핵심 기여

  1. 통제된 비교: 동일한 입력, 출력 컨테이너 규격, 공식 평가기를 사용해 코딩 에이전트(폐쇄형 3종 + 오픈웨이트 23종)와 발표된 비디오 생성 모델들을 VBVR-Pro-Bench 500개 인스턴스에서 직접 비교했다.
  2. 효율성 분석: 생성 실패(delivery failure)와 내용 실패(content failure)를 구분하고, 툴 호출 수·토큰·실행 시간 기준으로 에이전트 간 비용 차이를 분석했다.
  3. 추론 전략 분류: 에이전트가 작성한 프로그램을 이미지를 실제로 탐색해 일반화 가능한 절차를 복원하는 "묘사적(depictive)" 프로그램과, 세션 중에 구한 정답 값을 하드코딩해 그리기만 하는 "명제적(propositional)" 프로그램으로 분류해, 과제 범주별로 두 전략의 비중이 어떻게 달라지는지 밝혔다.

방법론

코딩 에이전트는 비디오 모델과 동일하게 1024×1024 첫 프레임, 자연어 프롬프트, 그리고 프레임 크기·프레임율·프레임 수 등 출력 규격을 입력받는다. 단, 이미지/비디오 생성 모델 호출은 금지되며, CPU 전용 샌드박스에서 표준 Python 이미지 처리 라이브러리만 사용해 30분의 시간 예산 안에 정답 비디오를 렌더링하는 프로그램을 작성·실행해야 한다. 각 인스턴스는 재시도 없이 단 한 번의 시도만 허용되며, 비디오를 끝내 산출하지 못하면 비디오 생성 모델이 실패했을 때와 동일하게 0점 처리된다. 실험에는 Codex CLI(gpt-6-astra), Claude Code(Claude Fable 5.1), Gemini CLI(Gemini 3.1 Pro)의 폐쇄형 에이전트 3종과, OpenCode 하네스로 구동한 GLM, Kimi, MiniMax, DeepSeek, Qwen, gpt-oss, Nemotron, Mistral, Llama, Gemma 계열의 오픈웨이트 모델 23종(DeepSeek R1은 툴 호출 미지원으로 제외)이 사용됐다. 모든 결과는 VBVR-Pro의 공식 평가 키트를 수정 없이 그대로 사용해 채점했으며, 비디오 모델 점수는 기존 발표된 리더보드 수치를 그대로 인용했다.

실험 설정 및 결과

VBVR-Pro-Bench는 abstraction, perception, spatiality, transformation, knowledge의 5개 인지 범주, 100개 과제 패밀리(각 5개 인스턴스, 총 500개)로 구성된다. 결과적으로 Codex(0.923), Claude Code(0.894), Gemini CLI(0.893)의 세 폐쇄형 코딩 에이전트가 전체 37개 시스템 중 1~3위를 차지했으며, 모든 과제 범주에서 1위를 기록했다. 벤치마크 과제군으로 강화학습된 최고 성능 비디오 모델(VBVR-Pro-Wan2.2-I2V-A14B, RL)조차 0.670에 그쳐 Codex 대비 0.253 뒤처졌다. 오픈웨이트 중 최고인 GLM-5는 0.572로, RL 학습 모델을 제외한 모든 비디오 모델을 능가했다. 오픈웨이트 모델들의 낮은 점수는 주로 툴을 아예 호출하지 않거나, 코드를 실행 전에 조기 종료하거나, 시간 제한에 걸리는 등 "생성 실패"에서 비롯됐으며, 비디오를 만들어낸 에이전트들 사이에서는 툴 호출 횟수가 점수를 예측하지 못했다. 폐쇄형 에이전트 3종은 점수 차이는 0.03 이내로 작았지만, 비용(툴 호출 수·토큰 수)은 Claude Code가 Codex 대비 약 3~4배, Gemini CLI가 약 8~12배에 달해 거의 한 자릿수 차이로 벌어졌다. 또한 1,385개의 해결 프로그램을 분석한 결과, 묘사적 전략은 perception(67%)과 transformation(45%) 과제에서 비중이 높았고, 명제적 전략은 abstraction(26~33%)과 knowledge(27~28%) 과제에서 비중이 높았다.

한계점

VBVR-Pro-Bench는 원래 비디오 모델을 평가하기 위해 설계된 벤치마크로, 과제가 코드로 생성·렌더링되고 색상이 단순하며 기하학이 정확하고 평가기가 결정론적이어서, 프로그램적 해법에 특히 유리한 환경이다. 실제 텍스처·가림·조명이 다양한 실세계 영상에는 이러한 이점이 그대로 적용되지 않을 수 있으며, symbolic ground truth가 없고 픽셀 일부를 수정하는 것만으로 답을 낼 수 없는 상황에서는 이 비교가 성립하지 않는다. 비교 자체도 비대칭적이다. 에이전트는 툴, 샌드박스, 최대 30분의 반복 시간을 활용하지만 비디오 모델은 단일 샘플만 생성하며, 에이전트 간 비용 차이도 한 자릿수 이상 벌어진다.

시사점

첫 프레임과 프롬프트로부터 해답이 계산 가능한 과제에 대해서는, 현재 시점에서 프로그램 합성(코드 작성)이 비디오 생성보다 훨씬 신뢰도 높은 시각 추론 경로임을 보여준다. 다만 이는 영상 생성 모델이 원리적으로 시각 추론을 할 수 없다는 뜻이 아니라, 묘사적 프로그램(이미지를 탐색해 일반화 가능한 절차를 복원)과 명제적 프로그램(세션 중 얻은 값을 하드코딩)이라는 두 가지 양상이 과제 성격에 따라 달리 나타난다는 점에서, 코드와 결합된 시각 정보 처리가 언어모델의 사고사슬(chain-of-thought)과는 다른, 구조화된 시각 표현을 다루는 대안적 추론 매체가 될 수 있음을 시사한다. 저자들은 향후 결정론적 평가기를 보상으로 활용한 코드 작성 정책의 강화학습 훈련, 그리고 단일 프레임이 아닌 비디오-투-비디오 설정으로의 확장을 향후 과제로 제시한다.
