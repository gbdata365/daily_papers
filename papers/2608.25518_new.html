Agentic Game Development as a Verifiable Trajectory Data Engine for Scaling World Models

에이전트형 게임 개발: 월드 모델 확장을 위한 검증 가능한 궤적 데이터 엔진

코드 에이전트가 컴파일러·테스트로부터 검증 가능한 보상을 받아 급성장한 것처럼, 게임 엔진이 제공하는 물리·충돌·내비게이션 체크와 개발자의 수용/거부 판단을 결합한 "인간-엔진 이중 검증" 신호를 활용하면 월드 모델도 재귀적으로 자기 개선할 수 있다는 주장과 이를 검증하는 파일럿 실험을 제시한 논문이다.

한 줄 요약

코드 에이전트가 컴파일러·테스트로부터 검증 가능한 보상을 받아 급성장한 것처럼, 게임 엔진이 제공하는 물리·충돌·내비게이션 체크와 개발자의 수용/거부 판단을 결합한 "인간-엔진 이중 검증" 신호를 활용하면 월드 모델도 재귀적으로 자기 개선할 수 있다는 주장과 이를 검증하는 파일럿 실험을 제시한 논문이다.

배경 및 문제의식

저자들은 최근 월드 모델 연구가 "더 많은 크롤링 비디오와 더 많은 연산"으로 스케일을 키우는 데 집중하지만, 이는 비효율적이라고 주장한다. 코드 에이전트가 성공한 이유는 코드가 실행 가능해서 컴파일러/런타임이 저렴하고 밀도 높은 보상을 주고, 동시에 개발자가 유지보수성·제품 목표 등 상위 판단을 더해 "인간-컴파일러 이중 검증"을 형성하기 때문이다. 반면 비디오 생성이나 3D 생성 같은 공간 지능 분야는 CLIP 유사도, FVD, MLLM-as-judge 같은 모호하고 편향되기 쉬운(fuzzy) 대리 지표에 의존할 수밖에 없어, 강화학습 후속 훈련(RL post-training)에 적합한 신뢰 가능한 보상 채널이 없다. 저자들은 이를 "검증 가능성 병목(verifiability bottleneck)"이라 명명하고, 데이터·연산량 부족이 아니라 저비용·확장 가능한 피드백 채널의 부재가 공간 지능 발전을 막고 있다는 "데이터 중심판 The Bitter Lesson" 논지를 편다.

핵심 기여

  1. 검증 가능성 병목을 공식화하고, 공간 생성(비디오 생성, 3D 생성, 월드 시뮬레이터)이 왜 저비용 검증 신호를 얻지 못하는지 사례로 설명.
  2. AWoMo (Agentic World Model): 의도(intent)·행동(action)·검증(verification)·리뷰(review) 4개 인터페이스로 구성된 개발자 중심 에이전트형 월드 모델을 제안. 게임 엔진(Unity/Unreal/Godot)을 실행 가능한 "월드 명세서"이자 부분 검증기로 삼아, 씬을 제안·렌더링·검증·수정·리뷰하는 루프를 돌리고 이 전체 과정을 학습 데이터로 저장한다.
  3. RLHEV (Reinforcement Learning with Human-Engine Verification): 엔진이 주는 조밀한 구조적 체크(충돌, 물리 안정성, 내비메시 도달성 등)와 개발자의 수용/거부라는 희소하지만 정합성 높은 신호를 결합한 보상 함수 및 후속 훈련 프레임워크를 제안. 수식적으로는 인간 리뷰 유틸리티에서 엔진 진단 페널티를 빼고 필수 게이트(하드 제약)를 만족시키는 제약 최적화 형태로 정식화된다.
  4. UWDP (Unified World-Development Protocol): 프롬프트, 씬 프로그램, 렌더링 결과, 실패 로그, 수정 행동, 엔진 체크, 리뷰어 판단을 하나의 상태-행동-체크-리뷰 궤적으로 묶는 다중모달 데이터 프로토콜을 제안하여, 최종 산출물이 아니라 "왜 그 결과가 받아들여졌는가"라는 과정 정보까지 학습에 활용 가능하게 함.
  5. UnitySceneBench라는 200개 예제 규모의 Unity 자산 편집 평가 벤치마크를 구축하고, 통제된 실험을 통해 RLHEV, 도메인 전이, 임바디드 정책 성능 개선을 검증.

방법론

AWoMo의 핵심 신경망은 UnifiedGameAssetModel로, Mixture-of-Transformers 기반 옴니모달 모델인 Cosmos 3를 온-폴리시 증류(on-policy distillation) 후 지속 사전학습(continued pretraining)한 버전이다(공개된 체크포인트는 약 28.9억 파라미터, hidden width 3584, 8개 트랜스포머 레이어, 4개 어텐션 헤드, 4개의 게이트형 전문가 모듈로 구성). 이 모델은 텍스트, 이미지, 3D 가우시안, 메시, Unity/Unreal/Godot/MuJoCo 표현 등 게임 자산에 특화된 헤드를 갖는다.

실행 루프는 "제안(propose)-렌더링(render)-검증(verify)-수정(repair)-리뷰(review)"의 5단계로 구성된다. 모델이 씬 편집을 제안하면 엔진이 이를 실행하고 실패 지점을 국소화하며, 에이전트가 수정 행동을 내놓고, 최종적으로 인간 리뷰어가 수용/거부를 결정한다. 이 전체 루프가 UWDP 형식의 궤적(브리프, 객체 식별자, 씬 상태, 행동, 엔진 출력, 렌더링 증거, 리뷰 결정, 수정 이력 등 8개 필드)으로 저장되고, 이 저장된 궤적은 (1) 수용된 최종 상태 → 지도학습 생성 타깃, (2) 실패-수정 쌍 → 다음 편집/수정 예측 데이터, (3) 엔진 출력+리뷰 결정 → RLHEV의 융합 보상으로 각각 변환된다.

RLHEV의 보상은 인간 리뷰 보상(h)과 정규화된 엔진 보상(e)을 엔진 게이트(필수 통과 조건) 지시함수와 결합한 형태이며, UnitySceneBench 주 실험에서는 인간 가중치 0.65, 엔진 가중치 0.35로 설정된다(Offline RLHF는 인간 보상만, Engine-based RLVR은 엔진 보상만 사용하는 어블레이션). 학습은 오프라인 보상 가중 후보 학습과 KL 정규화가 포함된 정책 최적화 형태로 구현된다.

실험 설정 및 결과

UnitySceneBench (자산 분류/생성): 텍스트 편집 프롬프트, Unity 자산/컨텍스트 특징, 참조 이미지 특징 등을 입력으로 편집 후보의 수용/거부를 예측하는 이진 분류 과제(720 학습/80 검증/200 테스트, 8개 시드). Full RLHEV가 최고 성능(best-of-eight primary score 0.681, accuracy 0.665, F1 0.733, AUC 0.690)을 기록했고, 가장 강력한 비-Full 베이스라인 대비 +0.098(primary score), +0.120(accuracy/balanced accuracy) 향상. 생성 과제에서도 720개 학습 예산에서 Full RLHEV가 생성 품질 0.8197로 Engine-based RLVR(0.7934)을 능가.

OOD 일반화 및 교차 엔진 전이: Unity 분포 전이에서는 사전학습 후 타깃 적응이 스크래치 학습 대비 MLLM-as-judge 점수를 0.25에서 0.75로 크게 향상시켰다. Unity→Unreal은 0.25→0.35, Unity→Godot은 0.15→0.35로 더 작지만 유의미한 양의 전이 신호를 보였다. 부록 실험(Protocol Trace Analysis)에서는 최종 스냅샷만 사용하는 특징(Spearman 0.159)보다 전체 개발 궤적(프로토콜 트레이스) 특징(Spearman 0.719)이 타깃 엔진 순위 예측에 훨씬 강력함을 보였다.

임바디드 일반화 진단: R2R(비전-언어 내비게이션), Gymnasium MuJoCo, D4RL Gym-MuJoCo에서 AWoMo가 생성한 환경 데이터로 증강 학습한 정책이 원본 베이스라인 대비 각각 +0.79%, +9.96%, +48.43% 개선되어, 나이브 데이터 증강보다도 우수한 성능을 보였다.

한계점

저자들은 스스로 다섯 가지 강한 반론을 제시하고 답한다. (1) 게임은 현실이 아니므로 sim-to-real 격차가 검증되지 않았다는 점(실제 스캔·로봇 데이터 없이 게임 엔진 보상이 물리 세계로 전이된다는 증거는 아직 없음), (2) 비디오 생성이 이미 빠르게 발전 중이지만 이는 모방/연산 기반 진전이지 정확성 검증에 기반한 진전은 아니라는 점, (3) 엔진 보상 자체도 부분 검증기일 뿐이라 리워드 해킹이 가능하다는 점(검증기 앙상블·무작위 프로브·인간 리뷰 병행 필요), (4) 실세계 3D 데이터가 저렴해져도 그 자체로는 검증기가 되지 못한다는 점, (5) 소스 엔진 궤적이 특정 엔진에 과적합될 위험(교차 엔진 실험으로 완화 증거 제시). 전반적으로 저자들은 현재 실험이 "완결된 증거"가 아니라 "진단적 파일럿 결과"이며, 재현 가능한 대규모 스케일링 연구, 플레이 가능한 아티팩트, 동의 기반 인간 연구 등 추가 검증이 필요하다고 명시한다. 또한 실제 개발 궤적에는 창작자 의도, 독점 자산, IP가 포함될 수 있어 배포 시 접근 통제·데이터 거버넌스가 필요하다는 점도 한계로 언급된다.

시사점

이 논문은 특정 모델의 성능 우위를 주장하기보다, "게임 개발 과정 자체를 재귀적 데이터 엔진으로 취급하자"는 연구 의제(research agenda)를 제안하는 포지션 논문에 가깝다. 코드 에이전트의 성공 공식(실행 가능성 + 인간 검증)을 공간 지능 영역에 이식하려는 시도로서, 최종 산출물이 아니라 "개발 궤적(trajectory)" 자체를 훈련 데이터로 삼는다는 아이디어는 게임 엔진 외에도 CAD, 로보틱스 시뮬레이션, 건축 설계 등 "엔진이 검증 가능한 다른 창작 도메인"으로 확장될 잠재력이 있다. 장기적으로는 한 에이전트가 월드를 만들고 다른 게임 에이전트가 플레이테스트하며 실패를 다음 세대 모델의 학습 신호로 전환하는 완전 재귀적 자기개선 루프를 지향점으로 제시한다.
