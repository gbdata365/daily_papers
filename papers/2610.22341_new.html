3DCodeVerse: Exploring 3D Worlds as Code

3DCodeVerse: 코드로서의 3D 세계 탐구

한 줄 요약

코딩 에이전트가 Blender, Three.js, CadQuery, URDF, GLSL 등 다양한 언어/엔진으로 편집·검증 가능한 3D 콘텐츠(물체, 관절체, 씬, 그래픽스)를 대규모로 생성할 수 있도록, 200만 개 이상의 실행 가능 3D 코드 데이터셋(3DCodeVerse-2M)과 실행·시각 피드백 기반 자동 검증·수정 하네스(3DCodeVerse Harness)를 함께 제공하는 연구 생태계.

배경 및 문제의식

3D 콘텐츠를 코드로 생성하면(예: Blender 스크립트) 결과물을 편집·재사용·조합·검사할 수 있어 2D 생성 방식보다 구조적이고 확장 가능하다. 그러나 기존 자원들(DeepCAD, BlenderLLM, SceneCraft, Articraft 등)은 정적 물체·관절체·씬 중 일부에만 초점을 맞추거나, 시각적 피드백·자동 검증 지원이 제각각이어서 3D 코딩 시스템을 개발·평가할 공유 인프라가 부족했다. 이로 인해 3D 코딩 연구가 과제·환경별로 파편화되어 있었다.

핵심 기여

  1. 3DCodeVerse-2M 데이터셋: 공개 데이터 수집, 특수 표현(DeepCAD 시퀀스 등)의 코드 변환, 코딩 에이전트를 이용한 신규 프로그램 생성을 결합해 정적 물체·관절체·씬·그래픽스를 포괄하는 203만 개 규모의 실행 가능 3D 코드-설명 쌍 코퍼스를 구축했다(기존 최대 데이터셋 대비 규모와 다양성에서 우위).
  2. 3DCodeVerse Harness: LLM 플래너가 작업을 방향성 비순환 그래프(DAG)로 분해해 여러 하위 에이전트가 동시에 코드를 작성·조립하게 하고, 실행 로그·공간 측정(충돌·접촉·배치 검사)·VLM 기반 다각도 렌더 평가의 3단계 피드백으로 사람 개입 없이 반복적으로 프로그램을 수정하는 멀티에이전트 프레임워크를 제시했다.
  3. 체계적 실증 분석: 오픈 모델 파인튜닝 베이스라인 구축과 하네스 구성요소별(judge/harness) 분석을 통해, 데이터셋 파인튜닝이 3D 코딩 능력을 크게 향상시키고, 하네스가 Claude Opus 5.5 기반 비교에서 Claude Design(3D Object)을 상대로 사람 평가 90% 승률을 기록함을 보였다.

방법론

3D 코딩은 텍스트 요청과 선택적 참조 이미지로 구성된 조건 c를 만족하는 3D 콘텐츠를 생성하는 프로그램 f를 작성하는 작업으로 정의된다. 프로그램을 선언된 실행 환경(Blender, CadQuery 등)에서 실행하면 아티팩트(메시, 관절체, 씬, 애니메이션)와 실행 피드백을 얻는다. 데이터셋 구축 시에는 raw 프로그램을 코딩 에이전트의 "스킬(skill)"을 이용해 특수 API 의존성을 제거한 독립 실행형 프로그램으로 변환하고, 3D IoU·충돌 검사 등 검사 도구(inspection tools)로 측정한 뒤 VLM이 코드와 렌더링 결과로부터 설명을 생성해 각 레코드에 원본·라이선스·검증 결과를 함께 저장한다. 하네스는 입력 프롬프트에서 LLM 플래너가 대상 구성요소·치수·재질·공간관계·수용 기준을 담은 계획 P를 만들고, 이를 코딩/조립 작업의 DAG로 변환해 하위 에이전트들이 병렬로 파일을 작성하게 한다. 각 라운드마다 ①실행 피드백, ②측정 피드백(치수·접촉·충돌·배치), ③VLM 판정 피드백(다각도 렌더링을 수용 기준과 대조)을 결합한 점수를 산출하고, 이를 국소적 수정 과제로 변환해 수정 에이전트가 반복적으로 코드를 고친다. 또한 judge(평가자)와 harness(생성 워크플로우)를 개발 단계에서 교대로 개선하는 적대적 루프(adversarial loop)를 통해 평가 일관성과 생성 품질을 함께 높였다.

실험 설정 및 결과

3DCodeBench에서 파인튜닝 결과, 9B 모델은 실행률 84.9%, 27B 모델은 92.9%를 달성해 데이터셋의 효과를 입증했다. 하네스는 원샷 생성 대비 15.5~29.1점의 품질 향상을 여러 코딴 에이전트에서 일관되게 보였다. 텍스트-투-3D 물체 생성(100개 프롬프트), 관절체·씬(50개)·그래픽스(50개) 프롬프트에 대해 사람 선호도(Human Preference), VLM 선호도(Gemini 3.1 Pro), Judge Score(0~100점 루브릭) 세 지표로 평가했으며, 3DCodeVerse 하네스는 네이티브 하네스 및 Claude Design과의 비교에서 각각 우위를 보였고, 특히 Claude Opus 5.5로 양쪽을 구동했을 때 Claude Design(3D Object) 대비 90%의 사람 평가 승률을 기록했다.

한계점

논문에 명시된 세부 수치는 100개 텍스트-투-3D 물체 프롬프트, 50개 씬/그래픽스 프롬프트 등 상대적으로 제한된 평가셋 규모에 기반한다. VLM 판정(Gemini 3.1 Pro)에 의존하는 평가 방식은 사람 평가와 상관성이 높다고 주장되지만, 자동 판정 자체의 편향 가능성은 논문에 구체적으로 정량화되어 있지 않다. 데이터 변환 과정(예: DeepCAD→CadQuery)의 정확도는 voxel IoU·Chamfer distance로 측정되나 모든 소스 유형에 대해 동일한 정밀도로 검증되지는 않는다(소스별로 검증 커버리지가 다름).

시사점

3D 콘텐츠 생성을 코드 작성·실행·검증의 반복 루프로 공식화하고, 대규모 실행 가능 코드 데이터와 자동화된 멀티에이전트 하네스를 결합하면 사람 개입 없이도 상업적 3D 디자인 도구에 근접하거나 능가하는 품질을 달성할 수 있음을 보여준다. 이는 게임·영화·제품 디자인 등에서 코드 기반 3D 생성 파이프라인을 자동화·확장하는 기반 인프라로 활용될 수 있다.
