NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness

네오호스-1: 라우팅 하네스를 통한 에이전트 후처리 학습 기반 재귀적 자기개선을 향하여

한 줄 요약

실제 서비스 중인 "라우팅 하네스(routing harness)"가 남기는 실행 기록과 역량 예측 신호를 학습 데이터와 커리큘럼으로 재활용하여, 에이전트형 언어모델이 스스로의 부족한 부분을 찾아 다음 학습에 반영하는 재귀적 자기개선(RSI) 루프의 초기 프로토타입인 NeoHorse-1을 제시한다.

배경 및 문제의식

재귀적 자기개선(Recursive Self-Improvement, RSI)은 AI 시스템이 자신의 개선 과정에 점점 더 많이 참여하는 방향을 가리키지만, 이를 실현하려면 시스템이 "자신의 현재 역량을 관찰하고, 그 증거를 다음 학습 라운드로 전환하는" 구체적인 메커니즘이 필요하다. 저자들은 에이전트가 코드를 작성하거나 도구를 사용할 때 남기는 실행 궤적(trajectory)이 그 자체로 학습 데이터가 될 뿐 아니라, 모델이 무엇을 할 수 있고 무엇을 못하는지에 대한 관찰 가능한 증거도 함께 남긴다는 점에 주목한다. 특히 여러 모델을 요청에 따라 적절히 배정하는 "라우팅 하네스"는 각 턴마다 예측된 역량 수요, 실제 선택된 서비스 등급, 이후의 상호작용 결과를 이미 기록하고 있으므로, 이 데이터를 다음 학습 라운드의 원천으로 삼을 수 있다는 것이 이 논문의 핵심 문제의식이다.

핵심 기여

  1. 하네스 데이터의 체계적 정제: 실제 배포 하네스에서 나온 실행 궤적을 트라젝토리-유저턴-서브신(subscene)의 세 단위로 구조화하고, 규칙 기반 구조 검증과 6개 차원(목표 달성, 지시 준수, 도구 사용, 근거 일관성, 오류 복구, 종료 처리)의 의미 평가를 거쳐 학습에 사용할 유저턴 예제를 선별한다.
  2. 라우팅 신호 기반 3단계 커리큘럼 학습: 하네스 라우터가 각 턴에 부여하는 4단계 역량 등급(C0~C3) 및 정규화 점수를 난이도 대용치로 사용해, SFT 학습을 저난이도에서 고난이도로 점진적으로 전환하는 3단계 커리큘럼으로 구성한다.
  3. 라우팅 유도 온폴리시 증류(Routing-Guided On-Policy Distillation, R-OPD): 동일한 3단계 커리큘럼을 학생 모델이 스스로 생성한 응답에 대한 교사 모델의 감독(역-KL 발산 기반)으로 확장하여, SFT가 다루지 못하는 배포시 생성 분포 차이를 보완한다.
  4. 역량 기반 데이터 재배분(evaluation-selection-update 루프): 매 학습 반복마다 현재 체크포인트를 평가해 취약 영역을 파악하고, 다음 학습 데이터 구성을 취약 영역 쪽으로 재조정함으로써 "무엇을 잘하게 되었는지가 다음에 무엇을 배울지를 결정"하는 피드백 루프를 닫는다.

방법론

데이터 측면에서는, 대화의 최소 학습 단위를 "유저턴"으로 정의하고, 현재 턴의 추론·도구 호출·응답에만 예측 손실을 부여하며 이전 턴의 추론 과정은 생략하되 가시적 응답과 도구 상호작용은 컨텍스트로 유지한다(토큰 단위 마스크를 적용한 SFT 손실). 학습 방법 측면에서는, 라우터가 산출한 역량 점수(경등급 인덱스 또는 등급별 정규화 점수의 가중 평균)를 예제 순서를 정하는 커리큘럼 신호로만 사용하고, SFT 손실 자체를 재가중하지는 않는다. 3단계 커리큘럼은 각 단계가 전체의 약 1/3씩을 차지하며, 뒤쪽 단계일수록 고난이도 예제 비중이 높아지되 일부 저난이도 예제도 마지막까지 남겨 둔다. R-OPD 단계에서는 동일한 커리큘럼으로 선택된 컨텍스트에서 학생이 응답을 직접 생성하고, 고정된 교사 모델이 학생이 방문한 상태에 대해 토큰 단위 분포를 제공하여 reverse-KL 손실로 학생을 갱신한다(상위 K개 후보 토큰 + 나머지 확률 질량을 하나의 빈으로 압축해 계산 비용을 줄임). 마지막으로, 평가에서 드러난 모델의 취약 영역(장면·목표·결과 축과 라우팅 등급으로 계층화된 성과 프로파일)에 따라 다음 반복의 학습 데이터 비중을 조정한다.

실험 설정 및 결과

NeoHorse-1은 Qwen3.5 계열을 기반으로 4B와 9B 두 규모로 학습되었으며, 에이전트형 벤치마크(BFCL v4, VitaBench, τ²-Bench, PinchBench, WorkBuddy Bench, QwenClawBench), 코딩(HumanEval, LiveCodeBench v6), 지시 순응(IFEval, IFBench) 등 총 10개 벤치마크로 평가되었다. 그 결과 4B 모델의 매크로 평균 점수는 58.94에서 64.87로, 9B 모델은 65.60에서 69.04로 상승했으며, 특히 하네스 기반 에이전트 실행 및 실행 집약적 과제에서 향상이 두드러졌다. 학습을 거친 4B 모델은 여러 벤치마크에서 기반 모델인 Qwen3.5-9B와 동등하거나 이를 상회하는 성능을 보여, 학습이 모델 규모 차이 일부를 상쇄할 수 있음을 시사했다. 추가 분석에서는 (1) 동일한 커리큘럼 알고리즘을 사용하더라도 공개 합성 에이전트 데이터(Toucan)보다 라우팅 하네스에서 수집한 실제 데이터로 학습했을 때 5개 벤치마크 평균이 6.26점 더 높았고, (2) 고유 학습 토큰 수를 로그 스케일로 늘릴수록 5개 벤치마크 평균 점수가 69.31에서 71.45까지 꾸준히 상승함을 보였다. 사례 분석(코드 저장소의 시간 지연 검증 구현, 티켓 리포트 생성, Gomoku 게임 인터페이스 구현 등)에서는 NeoHorse-1-9B가 Qwen3.5-9B에 비해 요구사항 문서를 더 충실히 참조하고, 실행 결과를 검증해 반복적으로 오류를 복구하는 경향이 뚜렷했다.

한계점

저자들은 본 연구가 결정적 증명이 아니라 "초기 시도"임을 명확히 밝힌다. 현재 검증은 에이전트/코딩/도구사용/지시 순응 영역에 한정되어 있고, 하네스가 다루는 더 넓은 범위의 과제나 모델에 대해서는 아직 평가되지 않았다. 또한 이번 결과는 평가-선택-갱신 루프를 단 한 차례만 거친 것이므로, 여러 반복(iteration)에 걸쳐 자기개선 효과가 실제로 누적되는지는 검증되지 않았다. 아울러 라우팅 신호 자체는 아직 정교하게 보정(calibration)되어 있지 않으며, 라우터를 직접 학습시켜 난이도·결핍 추정을 개선하는 방향은 향후 과제로 남아 있다.

시사점

이 연구는 별도의 오프라인 데이터 파이프라인을 새로 구축하지 않고도, 이미 운영 중인 서비스형 라우팅 하네스 자체가 재귀적 자기개선에 필요한 실행 경험과 역량 진단 신호를 동시에 제공할 수 있음을 보여준다. 즉, 서비스 운영과 모델 학습이 분리된 별개 활동이 아니라 하나의 순환 루프로 통합될 수 있다는 실용적 청사진을 제시하며, 향후 여러 세대에 걸쳐 이 루프를 반복 적용했을 때 개선이 실제로 누적되는지를 검증하는 것이 다음 단계의 핵심 과제로 제시된다.
