Deep Search in Real-World Web Environments

딥서치: 실세계 웹 환경을 탐색하는 에이전트 평가 벤치마크

한 줄 요약

실세계의 살아있는 웹에서 다양한 정보 양식(modality)·이질적 파일 형식·상호작용적 접근이 뒤섞인 증거를 자율적으로 찾아 연결해야 하는 "오픈웹 딥서치(OpenDS)" 과제를 정의하고, 이를 평가하기 위한 200개 과제 벤치마크 OpenDS-World를 구축해 12개 최신 모델과 인간 참가자를 비교 평가한 연구이다.

배경 및 문제의식

딥서치(Deep Search) 에이전트는 복잡한 정보 탐색·연구 과제를 자율적으로 수행하는 것을 목표로 발전해 왔고, 멀티라운드 검색·웹 브라우징·교차 출처 추론 능력이 빠르게 향상되고 있다. 그러나 기존 평가들은 정적인 검색 환경이나 제한된 과제 설정에 머물러 있어, 실세계 웹의 복잡성을 충분히 반영하지 못한다. 저자들은 실세계 웹의 복잡성을 세 가지 속성으로 규정한다. (1) 다양한 양식(Diverse Modalities): 정보가 텍스트, 이미지, 오디오, 비디오 등 여러 형태로 존재. (2) 이질적 형식(Heterogeneous Formats): HTML, PDF, XML, Parquet 등 서로 다른 구조와 처리 방식을 요구하는 자원들에 정보가 분산. (3) 상호작용적 접근 요구(Interactive Access Requirements): 일부 증거는 단순 조회가 아니라 웹 내비게이션, 인터페이스 조작, 파라미터 변경, 자료 다운로드 같은 상호작용을 거쳐야만 얻을 수 있음. 기존 벤치마크들은 이 세 속성이 상호 연결되어 나타나는 증거 획득 과정을 체계적으로 다루지 못했다는 것이 문제의식이다.

핵심 기여

  1. 실세계 웹 환경에서 이질적 정보 출처에 걸친 딥서치 수행 능력을 평가하기 위한 과제 정의 OpenDS(Open-Web Deep Search)를 제안. 에이전트가 사전에 위치나 접근 방법이 주어지지 않은 상태에서 여러 출처의 증거를 자율적으로 탐색·접근·처리·연결해 고유한 사실적 답을 도출해야 한다.
  2. 문화·일상·과학·경제·역사·자연·사회·기술 8개 도메인에 걸쳐 4개 양식, 42개 파일 형식, 7가지 접근 유형을 포괄하는 OpenDS-World 벤치마크(200개 과제)를 구축. 모든 과제는 공개 비디오에서 시작하는 실제 증거 경로(evidence path)를 기반으로 하며, 독립적인 인간 검증을 통해 증거 유효성과 답의 유일성을 보장.
  3. 통일된 도구 환경과 실행 프로토콜 하에서 12개 최신 모델(GPT-6 Astra, Claude Opus 5.5, Gemini 3.8 Flash 등)을 체계적으로 평가하고, 1,000회의 독립적 인간 풀이 시도와 비교하여 도구 사용, 검색 비용, 종료 행태, 실패 복구 등을 다각도로 분석.

방법론

과제 정의(OpenDS). 사실적 질문과 초기 단서가 주어지면, 에이전트는 개방형 웹을 지속적으로 탐색하면서 다양한 양식·형식·접근 방식의 증거를 찾아 접근·처리·연결하여 고유하고 검증 가능한 사실적 답을 도출해야 한다. 증거의 정확한 위치와 접근 방법은 사전에 제공되지 않는다.

OpenDS-World 구축(3단계). - 1단계: 실세계 앵커(Real-world Anchor). 공개 비디오 500개 후보 중, 전문 주석자가 시청각 내용을 함께 분석해 "오디오·비주얼 동시 식별이 필요한" 검증 가능한 초기 앵커(엔티티)를 선정하고, 이를 고유한 Wikidata 항목과 연결한다. 단순 텍스트 검색만으로 식별되지 않도록 제약을 둔다. - 2단계: 오픈웹 증거 확장(Evidence Expansion). 각 확장 단계에서 현재 노드 기반 검색 질의를 만들고 Google Search로 후보 출처를 얻은 뒤, 출처가 명확한 의미적 관련성과 검증 가능성을 갖도록 검토하여 새로운 엔티티(다음 노드)를 추출한다. 양식·형식·접근 유형의 다양성을 고려해 출처를 선택하며, 각 노드는 다중 출처로 독립 교차검증된다. 이를 반복해 고유하고 안정적인 종단 노드(참조 답)에 도달한다. - 3단계: 질문 역변환(Question Inversion). 완성된 증거 경로를 상호의존적 제약 조건들의 집합으로 역변환해 질문을 구성한다. 중간 노드는 직접 드러나지 않고 간접적인 참조 설명으로 변환되어, 단서를 조합해야만 후보 공간이 점차 좁혀져 유일한 답에 도달하도록 설계된다.

인간 검증. 10명의 독립 검토자가 증거 경로의 모든 노드·관계·최종 답을 원 출처 외 복수의 독립 웹 출처와 교차검증하여 증거 유효성(evidence validity)과 과제 유효성(task validity, 질문의 명확성·제약 일관성·답의 유일성)을 확인하고, 기준 미달 과제는 제외했다.

인간 테스트. 필터링 후 200개 문항을 20문항씩 10개 세트로 나누고, 세트당 5명씩 총 50명이 독립적으로(LLM 도구 사용 금지, 일반 브라우저만 허용) 풀도록 하여 실제 난이도와 인간 성능을 별도로 측정했다.

평가 설정. 12개 최신 모델(GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5.5, Claude Fable 5.1, Gemini 3.8 Flash, Qwen3.8-Max/Flash, DeepSeek-V4.1-Flash/V4-Pro, Kimi K3, GLM-5.3-Flash/GLM-5.3 등)을 동일한 도구 하네스(검색 도구, GUI 웹 조작 도구, 비디오 프레임·자막 추출 도구)와 실행 예산(검색 단계 3,600초, 도구 호출 최대 100회) 하에서 평가했으며, Qwen3.8-27B를 LLM 심판으로 사용해 정답 여부를 판정했다.

실험 설정 및 결과

전체 200개 과제에서 최고 성능 모델인 GPT-6 Astra가 39.0%의 정확도를 기록했으며, Claude Opus 5.5(38.0%), Gemini 3.8 Flash(36.5%), Claude Fable 5.1(33.5%)이 뒤를 이었다. GPT-5.6 Sol과 Qwen3.8-Max는 각각 28.0%, 25.5%였고, 나머지 4개 모델은 20% 미만에 그쳤다(최저 GLM-5.3 12.0%). 반면 1,000회 독립 인간 풀이 시도의 전체 정확도는 21.1%였으며, 과제 단위로는 200개 중 85개(42.5%)가 5명의 인간 참가자 중 누구에게도 풀리지 않았고, 다수(3명 이상)가 성공한 과제는 14.5%에 불과해 인간에게도 상당히 어려운 벤치마크임을 보였다(참가자 평균 풀이 시간 12.92시간/20문항, 주관적 난이도 평균 3.884/5).

인간 검증 과정에서 사람조차 평균 2시간 이상 투입했고, 어려운(High) 난이도 그룹에서는 모델 정확도가 평균 16.76%까지 하락했다(GPT-6 Astra도 Low 59.26%→High 24.71%로 급감). 비용 분석에서는 도구 호출 수·소요 시간과 정확도가 단순 비례하지 않음을 확인했다(예: Gemini 3.8 Flash는 GPT-6 Astra 대비 약 5.22배의 토큰을 쓰고도 더 낮은 정확도를 기록; DeepSeek-V4-Pro는 약 2.39배의 소요시간에도 정확도는 12.50%에 그침). 도구 사용 패턴 분석에서는 모델별로 검색(Search) 중심형과 GUI 조작 중심형이 뚜렷이 갈렸으며(GPT-5.6 Sol은 호출의 74.50%가 Search, Claude Opus 5.5와 Qwen3.8-Flash는 각각 51.52%/49.42%가 GUI), 도구 구성의 유사성이 곧 성능 유사성을 의미하지는 않았다. 종료 행태 분석에서는 GPT-6 Astra·GPT-5.6 Sol·Claude Opus 5.5가 각각 69.0%/65.0%/60.5%의 과제에서 자연 종료한 반면 Qwen3.8-Flash는 자연 종료율 6.5%에 그치고 80.0%가 도구 호출 한도에 도달했으며, 도구 실패가 전체 호출의 2.83~9.42%에 불과하면서도 실행 시간의 19.27~61.90%를 소모하는 등 실패 비용이 불균형적으로 컸다. 예산 소진 분석에서는 모델별로 시간 한도 또는 호출 한도 중 하나 이상에 도달하는 비율이 16.5%(Claude Opus 5.5)에서 81.5%(Qwen3.8-Flash)까지 다양했다.

한계점

논문 본문에 별도의 "한계점" 절은 제시되지 않았다. 다만 결론 및 논의(Appendix E)에서 저자들은 현재 최고 모델조차 39.0%의 정확도에 그쳐, 실세계 웹에서의 정보원 선택, 도구 조율, 검색 전략 조정, 장기 호라이즌 검색 관리에 지속적인 어려움이 있음을 스스로 지적한다. 또한 자연 종료와 정답 정확성이 서로 무관하게 나타나는 점, 비용(도구 호출·시간)이 늘어도 정확도가 비례해 개선되지 않는 점을 모델들의 공통적 한계로 명시하고 있다.

시사점

이 연구는 딥서치 에이전트 평가를 정적 검색/단일 양식 설정에서 다중 양식·이질적 형식·상호작용적 접근이 뒤섞인 실제 웹 환경으로 확장해야 할 필요성을 제기한다. 또한 도구 호출량이나 시간 소모가 성능과 직결되지 않는다는 결과는, 향후 에이전트 설계가 단순히 더 많은 검색을 수행하는 방향이 아니라 효과적인 출처 선택·증거 통합·적절한 중단(stopping) 판단 능력을 강화하는 방향으로 나아가야 함을 시사한다. 저자들은 OpenDS-World가 장기 호라이즌 검색과 에이전트의 재귀적 자기개선(recursive self-improvement) 연구를 위한 구체적 토대를 제공한다고 밝힌다.
