MAI-Gym: An Open All-in-One Platform for GUI Agent Evaluation and RL Training across Mobile and Computer Environments

MAI-Gym: 모바일 및 컴퓨터 환경에서의 GUI 에이전트 평가와 RL 훈련을 위한 올인원 오픈 플랫폼

MAI-Gym은 모바일·컴퓨터·웹 환경을 아우르는 GUI 에이전트의 평가, 데이터 수집, 온라인 강화학습(RL) 훈련을 하나의 롤아웃 파이프라인으로 통합하고, 모의(mocked) 앱과 과제를 자동 합성하는 오픈소스 올인원 플랫폼으로, 이를 통해 학습한 9B 모델이 10B 이하 오픈 GUI 에이전트 중 최고 성능을 달성했다.

한 줄 요약

MAI-Gym은 모바일·컴퓨터·웹 환경을 아우르는 GUI 에이전트의 평가, 데이터 수집, 온라인 강화학습(RL) 훈련을 하나의 롤아웃 파이프라인으로 통합하고, 모의(mocked) 앱과 과제를 자동 합성하는 오픈소스 올인원 플랫폼으로, 이를 통해 학습한 9B 모델이 10B 이하 오픈 GUI 에이전트 중 최고 성능을 달성했다.

배경 및 문제의식

검증 가능한 보상을 활용한 온라인 RL은 수학·코딩·툴 사용 분야에서 빠른 발전을 이끌었지만, 이를 GUI 에이전트로 확장하는 데는 두 가지 근본적 난제가 있다. 첫째, GUI 환경은 코드 샌드박스처럼 동시 공유가 불가능해 각 시도마다 독립된 휴대폰·컴퓨터·브라우저 인스턴스를 초기 상태로 준비해야 하고, 대규모 훈련에는 수천 개의 인스턴스를 동시에 유지해야 하므로 비용과 유지 부담이 크다. 또한 평가용 에이전트 구현과 훈련용 구현이 서로 달라지면("harness drift") 측정된 성능이 모델이 아니라 하네스 차이에서 비롯될 수 있다. 둘째, 현실적인 GUI 과제는 여러 앱과 파일에 걸쳐 분산된 정보에 의존하는데, 기존 과제 합성 방법들은 독립된 입력 파일이나 공유 샘플 데이터에 의존해 과제의 다양성과 현실성이 제한적이었다. 또한 실제 거래가 발생하는 앱(결제, 송금 등)은 훈련에 안전하지 않고, 낯선 인터페이스 적응력을 평가하려면 완전히 새로운 앱이 필요하다. 기존 GUI 짐(gym)들은 인프라 중심(한 플랫폼만 지원, 수백 개 수준의 병렬 환경)이거나 데이터 중심(훈련 코드나 기존 벤치마크 실행 수단 미공개) 중 하나에 그쳐, 확장 가능한 실행 인프라와 자동화된 환경·과제 합성을 모두 갖춘 통합 플랫폼의 필요성이 제기되었다.

핵심 기여

  1. 통합·확장형 GUI 에이전트 평가 및 온라인 RL 플랫폼: 모바일, 컴퓨터, 웹 전반에서 공유 환경 인터페이스와 에이전트 하네스를 통해 평가·데이터 수집·온라인 RL 훈련을 통합하고, 10개 벤치마크를 지원하며 최대 20,000개 병렬 환경 인스턴스로 확장 가능함을 입증.
  2. 자동화된 애플리케이션·과제 합성: 리셋 가능한 모의 앱과 일관된 환경 상태에 기반한 어려운 크로스앱(cross-app) 과제를 자동 생성하는 파이프라인을 도입하여, 상호 연결된 애플리케이션 데이터 구축, 실행 검증된 과제 검증기(verifier) 생성, 실패 기반(failure-driven) 과제 생성을 지원.
  3. 10B 이하 최강 오픈소스 GUI 에이전트: MAI-Gym-9B를 공개하여 MobileWorld 78.4%, OSWorld-Verified 76.2%를 달성, 동급 규모 오픈 GUI 에이전트 중 최고 성능 기록(UI-Venus-2-9B, SCALECUA-Qwen3.5-9B, 심지어 더 큰 GUI-Owl-1.5-32B보다 우수).
  4. 재현 가능한 연구를 위한 자원 공개: 평가 하네스와 온라인 RL 훈련 코드를 포함한 프레임워크, 합성 스킬(skill), 49개 모의 앱, 실행 테스트를 거친 2,000개 과제(MobileWorld·OSWorld 각 1,000개), 모델 체크포인트를 공개.

방법론

실행 가능한 과제의 정의: 과제는 환경 E, 초기 상태 s0, 자연어 지시 g, 검증기 V로 구성되며(x = (E, s0, g, V)), 검증기는 최종 상태와 궤적을 바이너리 기준으로 채점해 부분 보상(가중 평균)과 전체 성공(필수 기준 모두 만족)을 함께 산출한다.

시스템 아키텍처: 모든 워크로드(평가, 데이터 수집, RL 훈련)가 하나의 에이전트 하네스와 하나의 롤아웃 경로를 공유해, 하네스를 수정하면 세 워크로드 모두에 즉시 반영된다. 환경 매니저가 인스턴스 요청·관찰·리셋·스텝·평가의 공통 인터페이스를 제공하고, 환경 어댑터가 각 벤치마크의 고유 API에 연결하며, Kubernetes/Docker 등 배포 백엔드가 실제 인스턴스를 호스팅한다. 에이전트 하네스 추가, 과제 추가, 환경 통합, 환경 커스터마이즈라는 네 가지 확장 지점을 제공한다.

확장 가능하고 효율적인 롤아웃: 모바일에서는 중첩 가상화 없이 ReDroid로 휴대폰을 컨테이너화하고 골든 스냅샷으로 리셋하며, 컴퓨터에서는 엄격한 준비 상태 점검과 실패 복구로 안정성을 높인다. 비동기 프로비저닝, 워밍 풀(warm pool), 객체 스토리지를 통한 스크린샷 전송으로 20,000개 인스턴스까지 확장했다. 추론 효율을 위해 윈도우 단위(window-wise) 히스토리 관리 기법을 도입했는데, K스텝 단위 윈도우(겹침 O스텝) 내에서만 프롬프트를 누적해 KV 캐시 재사용률을 높이고, 윈도우 경계에서 오래된 스크린샷을 텍스트 placeholder로 축소한다.

평가와 진단: 단일 명령으로 로컬 체크포인트나 API 모델을 다수 벤치마크에서 평가할 수 있으며, 대시보드는 각 시도의 스크린샷·행동·검증 결과를 단계별로 추적한다. Claude Code, Codex 같은 코딩 에이전트가 성공/실패 궤적을 비교 분석해 모델의 약점을 진단 보고서로 산출하고, 이 보고서가 과제 생성기의 입력이 된다.

환경 및 과제 합성: (1) 환경 합성 — 실제 서비스를 참조한 "실제 앱 클론"(12306, 중국건설은행, 디디, 메이투안, 디엔핑, 도우인, 샤오훙수 등 7개)과, 전혀 새로운 "노블 앱"(42개, HTML5 템플릿 기반 결정론적 상태 머신)을 코딩 에이전트가 생성. (2) 크로스앱 월드 구성 — 페르소나와 시나리오로부터 여러 앱·파일에 걸쳐 사람·사건·사실이 일관되게 공유되는 초기 상태를 먼저 구축한 뒤 과제를 생성. (3) 과제·검증기 합성 — 과제 명세(지시, 필요 자산, 성공 기준, 정답 컨텍스트)를 먼저 확정한 후, 독립적으로 골든 코드(정답 상태 직접 설정)와 검증기 코드를 생성하고, 초기-완료-리셋 상태에서 검증기를 실행 테스트하며 여러 모델의 실제 에이전트 시도로 실행 가능성과 난이도를 재검증한다.

온라인 RL 훈련: GRPO를 주요 알고리즘으로 사용(DAPO, GSPO, REINFORCE++, SAO, PPO도 지원)하며, slime(Megatron-LM + SGLang 기반) 위에 구축. 정책의 과거 성공률에 따라 롤아웃 예산을 동적으로 배분하는 정책 적응형 과제 샘플링(policy-adaptive task sampling), 윈도우 단위 패킹으로 학습 토큰 비용을 절감, 트레이너와 추론 엔진 간 로그 확률 차이(k3 KL 추정량)를 모니터링하는 훈련-롤아웃 일관성 검사를 적용한다.

실험 설정 및 결과

Qwen3.5-9B를 기반으로 SFT 웜업 후 모바일·컴퓨터 과제를 하나의 RL 런으로 공동 훈련(512 GPU, 최대 20,000개 동시 환경, 약 96시간)하여 MAI-Gym-9B를 만들었다. 7개 벤치마크(MobileWorld, AndroidWorld, MobileGym, OSWorld-Verified, OSWorld 2.0, MacAgentBench, MyPCBench)에서 평가한 결과: - 훈련 환경과 동일하지만 과제는 겹치지 않는 Task-OOD 벤치마크에서 MobileWorld 78.4%, OSWorld-Verified 76.2%를 기록, 동급(9B급) 오픈 모델 중 최고 성능이며 Claude Opus 4.8, GPT-5.5 등 프런티어 모델을 상당 부분 상회하거나 근접. - 훈련에 쓰이지 않은 환경인 Env-OOD 벤치마크(AndroidWorld, MobileGym, MacAgentBench, MyPCBench, OSWorld 2.0)에서도 동급 모델 중 선두권 성능을 유지. - SFT 웜업이 성능 향상의 대부분을 기여했으나(Task-OOD 평균 29.9→66.4), 공동 RL이 추가로 Cross Avg를 44.1→50.5로 끌어올리며 모바일·컴퓨터 두 도메인 모두에서 개선. - 모바일·컴퓨터를 각각 훈련한 전문가 모델을 파라미터 평균으로 병합하는 방식보다 공동 RL이 두 벤치마크 모두에서 더 우수(78.4%/76.2% vs. 최선 병합 76.4%/74.8%). - 합성 훈련 과제를 500개→5,000개로 늘릴수록 MobileWorld 69.2%→78.4%, OSWorld-Verified 69.7%→76.2%로 일반화 성능이 향상. - 12306 실제 앱 클론에서만 RL한 모델을 실제 휴대폰의 실제 앱에서 평가했을 때 성공률이 28.8%→48.1%로 상승(클론-실앱 전이 확인), 다만 클론 내부 성능(36.5%→73.1%)과의 격차는 오히려 커짐(7.7pp→25.0pp). - 완전히 새로운(novel) 앱 252개로 훈련 후 held-out 62개 과제에서 성공률 25.8%→45.2%로 향상, 평균 궤적 길이도 33.3→16.4 스텝으로 단축. - 환경 인프라는 1,000개 환경을 모바일 328.4초, 컴퓨터 88.9초, 브라우저 94.2초 내에 기동시켰으며, 윈도우 단위 히스토리가 스텝 단위 대비 학습 업데이트 시간을 2166.4초→810.9초로 단축. - GRPO와 SAO(비동기 단일 롤아웃 + 학습된 가치모델)를 비교한 결과, SAO는 샘플링 대기 시간을 줄이지만 크리틱 연산 비용이 이를 상쇄해 전체 훈련 시간 측면에서 뚜렷한 우위를 보이지 못함.

한계점

논문이 명시적으로 밝힌 한계로는, 클론 환경에서의 RL 성능 향상이 실제 앱으로 완전히 전이되지 않는다는 점(클론-실앱 성능 격차가 RL 이후 오히려 확대됨)이 있다. 또한 실패 기반 진단-합성-재훈련 루프를 반복적으로 수행할 수 있도록 설계했지만, 본 논문에서는 이러한 반복 라운드에 대한 평가를 수행하지 않았다고 명시한다. 그 외 구체적인 한계점 섹션은 논문에 별도로 명시되지 않음.

시사점

MAI-Gym은 GUI 에이전트 연구에서 평가·데이터 수집·훈련이 서로 다른 코드베이스로 분리되어 발생하는 "하네스 드리프트" 문제를 하나의 공유 롤아웃 경로로 해결하고, 모바일과 컴퓨터 도메인을 분리 훈련 후 병합하는 기존 관행보다 공동 RL이 더 효과적임을 보였다. 실제 앱의 안전한 모의 복제본에서 학습한 능력이 실제 환경으로 전이된다는 결과는, 위험하거나 비가역적인 실제 거래형 애플리케이션에 대한 RL 훈련을 안전하게 수행할 수 있는 길을 제시한다. 아울러 완전히 새로운 인터페이스에 대해서도 보상만으로 적응 능력을 학습할 수 있음을 보여, 합성 환경과 과제가 GUI 에이전트의 일반화 가능한 능력 습득에 실질적으로 기여할 수 있음을 시사한다. 프레임워크, 합성 스킬, 모의 앱, 검증된 과제, 모델 체크포인트의 공개는 후속 연구의 재현성과 확장성을 크게 높일 것으로 기대된다.
