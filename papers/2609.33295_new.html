TraceDance: An Automated System for Building Agent Behavior Benchmarks from Real-World Agent Deployment Traces

TraceDance: 실제 에이전트 배포 트레이스로부터 에이전트 행동 벤치마크를 자동 구축하는 시스템

TraceDance는 실제 배포된 에이전트의 실행 트레이스에서 사용자가 자연어로 지정한 바람직하지 않은 행동을 자동으로 찾아내어, 참조 정답이나 환경 재현 없이 결정 지점 연속(decision-point continuation) 방식의 맞춤형 벤치마크를 구축하는 시스템이다.

한 줄 요약

TraceDance는 실제 배포된 에이전트의 실행 트레이스에서 사용자가 자연어로 지정한 바람직하지 않은 행동을 자동으로 찾아내어, 참조 정답이나 환경 재현 없이 결정 지점 연속(decision-point continuation) 방식의 맞춤형 벤치마크를 구축하는 시스템이다.

배경 및 문제의식

LLM 기반 에이전트는 코드 수정, 일정 관리 등 실제 업무를 자율적으로 수행하지만, 과제 자체는 완수하면서도 액세스 토큰을 로그에 노출하거나 실패한 테스트를 비활성화해 통과시키거나 확인 없이 파괴적 명령을 실행하는 등 바람직하지 않은 행동을 보일 수 있다. Terminal-Bench와 같은 기존 벤치마크는 주로 최종 결과(task completion) 여부만 검사하고, safety·process 수준 벤치마크조차 대체로 고정된 테스트 케이스와 대상 행동을 사용한다. 에이전트와 배포 환경이 계속 변화하면서 새로운 행동 문제가 끊임없이 발생하지만, 고정된 벤치마크 모음은 이를 반영하지 못한다. 트레이스에서 문제 행동을 찾아내는 감사(auditing) 도구들은 존재하지만, 이를 다른 LLM을 평가할 재사용 가능한 벤치마크로 전환하지는 못한다는 공백이 있었다.

핵심 기여

  • Decision-point continuation이라는 평가 방식을 제안: 배포된 에이전트(source LLM)가 문제 행동을 보인 시점 직전까지의 실제 문맥을 잘라내고, 평가 대상 LLM이 다음 한 턴을 생성하게 한 뒤 행동별 rubric으로 채점한다. 환경 재현이나 참조 정답이 필요 없어 비공개 툴·MCP 서버에 의존하는 실환경 트레이스도 평가에 포함할 수 있다.
  • Anchor-and-Confirm이라는 2단계 프레임워크를 도입: 프로그래밍 가능한 anchor가 CPU 위에서 구조화된 트레이스를 스캔해 후보를 추리고, Flash LLM(Fast Model)이 후보만 검토해 요청된 행동을 확인함으로써 대규모 트레이스 전수 검토 비용을 크게 낮춘다.
  • Anchor Synthesis Loop를 설계: 사전 정의 카탈로그에 없는 커스텀 행동 질의에 대해 Strong Model이 anchor·확인 기준·cut contract·rubric 네 요소를 생성하고, Reviewer Model의 코드 리뷰와 실제 트레이스 시험 실행을 거쳐 반복적으로 검증·수정한다.
  • 252,557개의 실제 세션(Claude Code, OpenClaw)을 이용해 시스템을 검증하여 107개 벤치마크·4,125개 인스턴스를 구축(요청의 95.3% 충족)하고, 9개 프론티어 LLM 평가에서 평균 정답률이 26.7%에 불과함을 보여 현재 LLM들의 에이전트 행동 취약점을 드러냈다.

방법론

사용자는 자연어 행동 질의 q, 배포 트레이스 집합 D, 원하는 벤치마크 크기 범위 Kmin, Kmax를 입력한다. 각 트레이스는 지시·메시지·툴 호출·툴 결과 등의 이벤트 시퀀스이며, 대상 행동은 어떤 행동을 취할지(action), 실패에 어떻게 대응할지(failure), 완료 여부를 어떻게 주장할지(claim) 세 가지 프레임으로 구분되고 프레임마다 문맥을 잘라내는 지점(cut)이 다르다. 하나의 인스턴스는 (i) 잘려나간 원본 턴이 실제로 해당 행동을 보였는지, (ii) 남은 문맥이 적절한 다음 행동을 판단하기에 충분한 정보를 담는지, (iii) 관련 결정이 문맥 끝에서 아직 내려지지 않았는지의 세 조건을 모두 만족해야 채택된다. 각 행동 명세는 실행 가능한 anchor, 확인 기준, 프레임별 cut contract, rubric 네 요소로 구성되며, 사전 정의 카탈로그와 매칭되지 않으면 Anchor Synthesis Loop가 새 명세를 합성한다. 합성된 anchor 코드는 안전성 점검과 Reviewer Model의 코드 리뷰를 통과해야 하고, 실제 트레이스에 대한 시험 실행과 Fast Model의 표본 확인 결과(확인율, 후보 수 등)를 근거로 반복 수정된다. 최종 채택된 anchor가 전체 트레이스를 CPU에서 스캔해 후보를 찾고 Fast Model이 후보별로 행동 발생 여부를 확인하며, 각 인스턴스는 시스템 지시문·툴 정의·사람이 작성하거나 하네스가 주입한 입력은 보존하되 source LLM의 내부 reasoning 블록만 제거한다. 채점은 서로 다른 세 LLM(Strong Model, Gemini 계열 모델, Reviewer Model)으로 구성된 judge panel이 0~5점 행동별 rubric으로 평가하며, 평균 점수가 4점 이상이면 통과로 판정한다.

실험 설정 및 결과

코딩 에이전트 하네스(75,076세션)와 범용 툴 사용 하네스(177,481세션)에서 수집한 총 252,557개 세션을 대상으로, 구축을 기대한 질의 107개와 거부를 기대한 질의 32개 등 139개 테스트 질의로 시스템을 평가했다. TraceDance는 구축 대상 107개 중 102개(95.3%)에서 벤치마크를 성공적으로 생성하고 거부 대상 32개는 전부 올바르게 거부했으며, 최종적으로 107개 벤치마크와 4,125개 인스턴스를 만들었다. 성공한 질의당 평균 약 128,297회의 CPU 세션 스캔, 706개 후보에 대한 LLM 확인, 40.4개의 최종 인스턴스가 소요되었다. 사람 평가에서는 질의 해석 정확도가 78%(부분 정확 17%)였고, 표본 100개 인스턴스 중 84%에서 두 annotator 모두 해당 행동이 실제로 나타났음을 확인했으며 rubric 품질 평균 점수는 4.75/5였다. 자동 judge panel과 사람의 pass/fail 판정 일치도는 81.0%로, 사람 annotator 간 일치도와 비슷한 수준이었다. 9개 프론티어 LLM(Claude Opus 4.8, GPT-5.6-Sol, GLM-5.2, DeepSeek-V4-Flash/Pro, Qwen3.7-Max, MiniMax-M3, Doubao-Seed-2.1-Pro, Kimi-K3)을 평가한 결과 평균 정답률은 26.7%에 그쳤고, 최고 성능인 Claude Opus 4.8도 33.5%에 불과했다. 행동 유형별로 보면 정형화된 툴 호출 생성은 평균 67.9% 통과했지만, 진행 전 사전 점검이 필요한 경우는 8.1%에 그쳤으며, Secret protection(6.9%), Commit hygiene(0.9%), Failure-log inspection(0.6%) 등 안전·점검 관련 행동에서 특히 취약했다. TodoWrite 등 계획 관련 툴로 응답을 시작하는 경우 통과율이 뚜렷하게 낮아지는 경향도 관찰되었고, 전체 순위와 개별 행동별 성능이 반드시 일치하지는 않았다(예: Kimi-K3는 Error-guided correction 항목에서 전체 1위인 Claude Opus 4.8보다 높은 점수를 기록).

한계점

TraceDance는 프로그래밍 가능한 신호로 검색 가능한 행동만 다룰 수 있어, 모든 세션을 사람이나 LLM이 일일이 검토해야만 확인되는 행동은 적용 범위 밖에 있다. 수집한 배포 트레이스는 공개할 수 없어 논문에 보고된 벤치마크 자체를 외부에서 그대로 재구축할 수는 없으며(파이프라인 자체는 다른 트레이스 모음에 적용 가능), rubric의 인접 점수 구간 경계가 다소 모호하다는 점이 annotator들이 지적한 주요 한계였다. 또한 첫 번째 행동 유형에 따른 통과율 차이는 상관관계를 보여줄 뿐 인과관계를 입증하는 것은 아니다.

시사점

실제 배포에서 관찰된 구체적인 문제 상황을 온디맨드 벤치마크로 전환함으로써, 고정된 벤치마크 세트가 놓치기 쉬운 최신·세부적인 에이전트 행동 결함을 지속적으로 발굴하고 정량적으로 평가할 수 있음을 보여준다. 이는 모델 개선에 필요한 구체적 목표를 제공하며, 후속 모델이 해당 약점을 실제로 개선했는지 검증하는 재귀적 자기개선(recursive self-improvement, RSI) 루프의 핵심 평가 구성요소로 활용될 수 있다.
