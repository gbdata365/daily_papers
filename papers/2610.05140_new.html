AutoSciBench: Autonomous Benchmark Generation for Evaluating Scientific Agents

오토사이벤치: 과학 에이전트 평가를 위한 자율적 벤치마크 생성

과학 분야 에이전트를 평가하기 위한 벤치마크 자체를 LLM 에이전트가 자동으로 생성·반복 개선하는 프레임워크 AutoSciBench를 제안하고, 전산생물학·재료과학·임상영상 세 분야에서 인간이 직접 제작한 기존 벤치마크보다 더 어렵고 품질 평가도 높은 과제를 생성할 수 있음을 보였다.

한 줄 요약

과학 분야 에이전트를 평가하기 위한 벤치마크 자체를 LLM 에이전트가 자동으로 생성·반복 개선하는 프레임워크 AutoSciBench를 제안하고, 전산생물학·재료과학·임상영상 세 분야에서 인간이 직접 제작한 기존 벤치마크보다 더 어렵고 품질 평가도 높은 과제를 생성할 수 있음을 보였다.

배경 및 문제의식

에이전트의 능력이 빠르게 발전하면서 기존 벤치마크는 쉽게 포화(saturate)되어 능력 차이나 실패 모드를 변별하지 못하게 된다. 특히 과학 분야 벤치마크는 구축과 갱신에 상당한 시간, 인력, 전문 지식이 필요해 에이전트 발전 속도를 따라가기 어렵다. 저자들은 과학 에이전트 평가가 가져야 할 두 가지 요건을 제시한다. 첫째, 일반 LLM과 달리 에이전트는 계획 수립, 도구 실행, 관찰, 분석 등 환경과의 상호작용을 통해 정보를 추가로 획득해야 한다(LLM vs Agent). 둘째, 일반적인 에이전트 과제(코드/웹 환경)에서는 실행 오류나 상태 변화로 명시적 피드백을 받을 수 있지만, 과학 분석 과제에서는 중간 결과물이 정답 여부를 직접 알려주지 않고 수치나 가설에 대한 간접적 증거만 제공하므로, 원자료 재검토·중간 결과 해석·여러 증거의 통합이 요구된다(일반 에이전트 vs 과학 에이전트). 이러한 요구사항을 반영해 과학-에이전트 벤치마크를 자동으로 생성하고 에이전트 능력 변화에 맞춰 반복적으로 적응시킬 수 있는지가 핵심 연구 질문이다.

핵심 기여

  • 과제를 고수준 계획인 concept(과학 도메인, 데이터 양식, 요구되는 분석 연산)과 저수준 계획인 recipe(질문·데이터·정답 구성 및 검증 방법)의 이중 구조로 표현하는 프레임워크 AutoSciBench를 제안.
  • 솔버(에이전트)의 풀이 궤적과 판정(judge) 피드백을 바탕으로 recipe 또는 concept를 수정하는 피드백 기반 반복 개선(feedback-guided iterative refinement) 절차를 도입해, 지름길(shortcut) 풀이를 차단하고 원자료 재검토·중간결과 해석·증거 통합을 요구하는 방향으로 과제를 진화시킴.
  • 완료된 개선 이력을 요약한 경험 카드(experience card)를 축적하여 이후 concept 생성에 재사용하는 경험 기반 개념 생성(experience-guided concept generation)을 제안, 과거의 성공적 수정과 미해결 실패 사례를 새로운 과제 설계에 반영.
  • 전산생물학, 재료과학, 임상영상 세 분야에서 실제로 벤치마크를 자동 생성하여, 인간 제작 벤치마크 대비 평균 솔버 정확도를 각각 22.4%p, 25.5%p 낮추면서도(즉 더 어려우면서도) 품질 평가 점수는 세 분야 모두에서 더 높음을 실증.

방법론

AutoSciBench는 콘셉트 생성 → 레시피 설계 → 과제 구현 → 솔버 기반 평가 → 개선의 순환 과정으로 작동한다. 1. Concept(고수준 계획): 각 concept는 (도메인 d, 데이터 양식 m, 요구 연산 집합 O)의 튜플로 표현된다. 초기 concept는 기존 벤치마크의 시드 질문에서 추출한 concept와, 최근 5년 내 관련 문헌에서 추출한 분석 워크플로 및 이를 일반화한 패턴을 함께 참고하여 생성된다. 2. Recipe(저수준 계획): 주어진 concept에 대해 에이전트가 데이터 전략, 데이터 계획, 정답 구성 메커니즘, 답 형식, 필요 도구, 질문 은닉 전략 등 7개 필드로 구성된 recipe를 설계한다. 질문에 직접 제시할 정보와 상호작용을 통해 얻어야 할 정보를 구분하는 것이 핵심이다. 3. 과제 구현: recipe에 따라 질문, 관련 데이터 파일, 정답(ground truth)으로 구성된 과제 인스턴스를 구성하고 코드 실행으로 정답을 계산·검증한다. 4. 솔빙 및 판정: 각 과제에 대해 독립적인 솔버 시행(K회)을 수행하고, 판정자(judge, LLM)가 질문·데이터가 명확한 정답을 갖는지(verifiability)와 난이도(경험적 해결률 기반 easy/moderate/hard)를 평가한다. 5. 피드백 기반 개선: 과제가 검증 가능하면서 동시에 어렵지 않으면, recipe 수정(동일 concept 유지, 데이터·질문 설계만 변경) 또는 concept 수정(분석 요구사항 자체를 변경)을 수행한다. 최대 10라운드까지 반복한다. 6. 경험 기반 개념 생성: 완료된 개선 이력을 경험 요약, 유효한 설계 패턴, 피해야 할 패턴(anti-pattern), 선택 지침, 생성 지침의 5개 필드로 정리한 경험 카드로 압축하고, 이후 새로운 concept 생성 시 소스 레퍼런스와 함께 활용한다.

실험에는 생성기 겸 솔버로 Claude Opus 4.8(Claude Code CLI) 및 GPT-5.6 Sol(Codex CLI)을 사용했고, 각 도메인에서 100개의 시드 질문으로부터 콘셉트를 추론한 뒤 5회의 경험 기반 생성 반복(각 10개 콘셉트)을 통해 도메인당 50개 과제를 구성했다.

실험 설정 및 결과

시드 벤치마크로 전산생물학은 CompBioBench, 재료과학은 MatTools, 임상영상은 MedCTA를 사용했다. 생성된 벤치마크에서 다양한 솔버 모델(Claude Opus 5/4.8/4.7, Sonnet 5, Haiku 4.5, GPT-6 Astra, GPT-5.6 계열 등)의 정확도를 측정한 결과: - 생성된 벤치마크는 전산생물학과 재료과학에서 인간 제작 벤치마크 대비 평균 정확도를 각각 22.4%p, 25.5%p 낮추었으며, 이 난이도 상승은 생성에 쓰인 모델뿐 아니라 다른 솔버 모델에도 일반화되었다(즉 특정 생성기-솔버 쌍에 국한되지 않음). - 재료과학 인간 벤치마크에서는 솔버 정확도가 천장 효과(ceiling)에 몰려 있었지만, 생성된 벤치마크에서는 모델 간 성능 차이가 뚜렷하게 드러났다. - 생성기(생성에 사용한 모델)별로 난이도 경향이 달랐다(Claude Opus 4.8 생성 벤치마크가 GPT-5.6 Sol 생성 벤치마크보다 평균적으로 더 어려움). 반면 솔버로서는 GPT-5.6 Sol이 대체로 Claude Opus 4.8보다 우수해, 풀이 성능이 뛰어난 모델이 반드시 더 어려운 과제를 잘 생성하는 것은 아님을 시사. - 벤치마크 생성 후 출시된 상위 모델(Opus 5.0, GPT-6 Astra)은 해당 생성 벤치마크에서 이전 버전 대비 각각 19.5%p, 15.1%p 높은 정확도를 보여, 고정된 벤치마크가 에이전트 발전에 따라 빠르게 낡을 수 있음과 지속적 갱신의 필요성을 보여줌. - 품질 평가(검증가능성 Verifiability, 유용성 Usefulness, 적합성 Fitness, 1~5점, Claude Opus 4.8과 GPT-5.6 Sol 두 심사자 사용)에서 생성된 벤치마크는 세 도메인 모두에서 인간 제작 벤치마크보다 평균 점수가 높았으며, 특히 GPT-5.6 Sol 생성 과제는 적합성 점수가 높아 계획 수립·도구 사용·다단계 적응 요구가 강함을 시사. - 반복 개선 라운드가 진행될수록 어려운(hard) 과제의 비율이 지속적으로 증가했으며, 질문 유형도 중간결과를 직접 활용하는 형태에서 원자료 재검토 및 오류 인지(error-aware) 해석이 필요한 형태로 전환되었다(예: 실제 시퀀싱 오류를 반영한 UMI 서열 과제 사례). - 경험 기반 개념 생성을 제거한 ablation에서는 솔버 성공률이 35.0%에서 66.7%로 크게 올라가고 hard 과제 비율이 50.0%에서 15.0%로 감소해, 경험 재사용이 더 도전적인 과제 생성에 기여함을 확인. - concept/recipe 중 하나 또는 둘 다를 제거한 변형과 비교했을 때, 두 구조화된 계획을 모두 유지하며 개선하는 전체 프레임워크가 반복 라운드에 걸쳐 솔버 성공률을 가장 크게 낮추어, 구조화된 중간 표현(concept, recipe)을 직접 수정하는 것이 과제 자체를 직접 수정하는 것보다 난이도 상승에 효과적임을 보임.

한계점

논문 본문에 별도의 "한계점" 절은 없으나, 본문 및 실험 결과에서 드러나는 한계로는 다음이 있다. (1) 평가에 사용된 생성기 겸 솔버가 Claude Opus 4.8과 GPT-5.6 Sol 두 모델 계열로 제한되어 있어 다른 아키텍처 조합에 대한 일반화는 추가 검증이 필요하다. (2) 품질 평가 및 난이도 판정이 LLM 심사자(judge)에 의존하므로 심사자 자체의 편향이나 한계가 벤치마크 품질 평가에 영향을 줄 수 있다. (3) 반복 개선은 최대 10라운드로 제한되어 있으며, 각 concept당 하나의 과제만 최종 벤치마크에 포함되어 다양성보다는 난이도에 초점이 맞춰져 있다. (4) 임상영상 분야는 정답이 개방형(open-ended)이라 정확한 일치(exact match) 기반 비교가 불가능해 인간 벤치마크와의 정량 비교에서 제외되었다. 논문에 명시되지 않은 그 외 한계는 "논문에 명시되지 않음"으로 남긴다.

시사점

이 연구는 과학 에이전트 평가 역시 에이전트 능력 향상에 발맞춰 자동으로, 지속적으로 갱신될 수 있음을 보여준다. 고수준 concept와 저수준 recipe로 평가 요구사항을 구조화하고, 솔버의 실제 풀이 행동에서 얻은 피드백으로 이를 반복 개선하며, 개선 이력을 경험으로 압축해 재사용하는 접근은 특정 과학 도메인에 국한되지 않고 다른 전문 분야 벤치마크 구축에도 적용 가능한 일반적 틀을 제공한다. 특히 고정된 벤치마크가 신규 모델 출시로 빠르게 포화되는 문제에 대해, 벤치마크 생성-개선 루프에 최신 에이전트를 투입함으로써 벤치마크 자체가 에이전트와 함께 "진화"하도록 하는 실용적 방향을 제시한다.
