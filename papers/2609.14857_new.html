ModularRSI: Modular and Generalizable Recursive Harness Self-Improvement

모듈러RSI: 모듈형이며 일반화 가능한 재귀적 하네스 자기개선

ModularRSI는 성공·실패 실행 궤적을 대조 분석하고 에이전트 하네스(harness)를 다섯 개의 기능 모듈로 분해해 독립적으로 진화시킴으로써, 평가 벤치마크와 완전히 분리된 데이터만으로도 일반화 가능한 하네스 자기개선을 달성하는 프레임워크이다.

한 줄 요약

ModularRSI는 성공·실패 실행 궤적을 대조 분석하고 에이전트 하네스(harness)를 다섯 개의 기능 모듈로 분해해 독립적으로 진화시킴으로써, 평가 벤치마크와 완전히 분리된 데이터만으로도 일반화 가능한 하네스 자기개선을 달성하는 프레임워크이다.

배경 및 문제의식

터미널 기반 코딩·소프트웨어 엔지니어링 작업을 수행하는 CLI 에이전트의 성능은 기반 모델뿐 아니라 실행 흐름, 도구 사용, 컨텍스트 관리 등을 제어하는 "하네스"에 크게 좌우된다. 최근 연구들은 재귀적 자기개선(Recursive Self-Improvement, RSI)을 하네스에도 적용해 실행 경험으로부터 하네스를 스스로 개선하려 했으나, 저자들은 이를 어렵게 만드는 세 가지 문제를 지적한다. 첫째, 기존 방법들은 평가 벤치마크 자체나 그 하위집합으로 하네스를 진화시켜, 개선이 실제로 일반화 가능한지 벤치마크에 대한 과적합인지 구분하기 어렵다(데이터 수준 문제). 둘째, 개별 궤적 단위로 분석하면 하네스의 구조적 결함과 특정 과제에 한정된 추론·해법 세부사항이 뒤섞여, 새로운 과제로 전이되지 않는 과제 특화적 수정이 발생한다(궤적 수준 모호성). 셋째, 반복적으로 나타나는 결함을 발견해도 하나로 뭉친(monolithic) 하네스 안에서 어느 구성요소를 수정해야 하는지 특정하기 어렵고, 하네스 전체를 최적화하면 서로 무관한 메커니즘이 얽혀 원인 규명과 검증이 힘들어진다(메커니즘 수준 신용 할당 문제).

핵심 기여

  1. 성공/실패 궤적 대조, 과제 간 증거 집계, 모듈 단위 제한적 수정을 결합해 하네스 자기진화의 신용 할당(credit-assignment) 문제를 해결하는 대조적·모듈형 프레임워크 ModularRSI를 제안했다.
  2. 다운스트림 평가 벤치마크와 완전히 분리된 2,000개의 실행 가능한 진화(evolution) 과제를 GitHub, Hugging Face, Kaggle, 리눅스 커널 문서 등 외부 소스에서 독립적으로 구축하고, 인스턴스 단위 유사도 필터링과 세부 도메인 분석으로 벤치마크와의 중복을 최소화한 "벤치마크-분리 진화 프로토콜"을 확립했다.
  3. TerminalBench 2.0과 SWE-Bench Verified에서 광범위한 실험을 수행해, 진화된 하네스가 미지의 인도메인·아웃오브도메인 과제에서 일관되게 성능을 향상시키고, 서로 다른 기반 모델 간에도 전이됨을 입증했다.

방법론

ModularRSI는 세 단계로 구성된다. 1. 대조적 궤적 샘플링 및 분석(Contrastive Trajectory Sampling and Analysis): 각 진화 과제를 K회 롤아웃하여 얻은 궤적들을 성공률에 따라 Positive(전부 성공), Contrastive(일부만 성공), Negative(전부 실패) 그룹으로 나눈다. Contrastive 그룹은 같은 과제의 성공·실패 궤적을 짝지어 비교하고, Negative 그룹은 과거 성공 사례를 저장하는 Trajectory Memory에서 유사 궤적을 찾아 대조하거나 단독으로 반복 루프·잘못된 도구 사용·조기 종료 등 결함을 진단하며, Positive 그룹은 불필요한 행동이나 비효율적 탐색 등 효율성 개선 여지를 분석한다. 이 분석은 "Code-Modify Agent"라 불리는 에이전트 자신이 수행하며 결과는 구조화된 JSON 형태의 findings로 정리된다. 2. 모듈별 하네스 수정(Module-wise Harness Modification): 하네스의 행동 메커니즘을 Agent Loop(추론-행동-관찰 흐름 및 복구), Observation Management(환경 피드백 압축·정제), Tool Use(도구 선택·호출·검증), Context Management(상호작용 이력 관리), Task Completion Detection(과제 완료 판단) 5개 기능 모듈로 나누고, 각 모듈을 독립적으로 제한된 범위 내에서만 수정한다. 초기 하네스는 Harbor 프레임워크의 Terminus-2를 기반으로 재구성했다. 비슷한 진단은 득표수 기반으로 후보를 통합하고, Evolution History를 유지해 반복적이거나 모순된 수정을 방지한다. 3. 검증 게이트(Validation Gates): 수정마다 (a) AST 검증·임포트 확인 등 정적 Program Check, (b) 과제 특화적 수정 여부를 점검하는 Diff Review, (c) 실제 샘플 과제 실행으로 검증하는 Execution Validation을 거쳐 통과한 수정만 반영하고 실패 시 이전 버전으로 롤백한다. 5개 모듈이 각각 진화된 뒤에는 Cross-Module Integration 단계에서 통합 하네스를 재실행해 모듈 간 충돌(중복 메커니즘, 상충 행동)을 해소한다. 또한 Function Merge로 유사 기능을 병합해 함수 라이브러리의 비대화를 막고, Task-Aware Function Composer가 과제별로 관련 함수만 선택 활성화한다.

실험 설정 및 결과

TerminalBench 2.0(89개 장기 호라이즌 터미널 과제)과 SWE-Bench Verified(500개 실제 저장소 기반 과제)에서 Accuracy, Pass@3, StepNum(평균 상호작용 스텝 수), Pass³(3회 모두 성공) 지표로 평가했다. 진화는 DeepSeek-V4-Flash 계열 모델로 3 epoch 수행했으며, 2,000개 진화 과제 중 TB·SWE 관련 각 120개를 사용했다. - 일반화: TB 관련 데이터로 진화한 하네스는 SWE-Bench Verified 정확도를 73.40 → 75.80(아웃오브도메인)으로, SWE 관련 데이터로 진화한 하네스는 SWE-Bench Verified를 73.40 → 76.45(인도메인)로 향상시켰다. TerminalBench 2.0에서도 47.57 → 52.43(인도메인), 47.57 → 49.40(아웃오브도메인)으로 개선되어 벤치마크 도메인을 넘어서는 전이가 확인됐다. 특히 Pass³는 30.34 → 35.96으로 크게 올라 실행 신뢰성 향상이 두드러졌다. - 모델 간 전이: TB 데이터로 DeepSeek-V4-Flash 기반으로 진화한 하네스를 GLM-5.2, MiniMax-2.5 등 다른 기반 모델에 적용해도 정확도가 각각 59.55→61.80, 41.57→44.94로 향상되어 모델에 국한되지 않는 개선임을 보였다. - 모듈형 진화 효과: 모듈을 독립적으로 진화 후 통합한 방식(Acc 52.43)이 비모듈(Non-modular, 46.44) 및 전체 모듈 공동 진화(Joint All-Module, 44.19)보다 우수했다. 개별 모듈 평가에서는 Agent Loop이 가장 큰 단일 모듈 정확도 향상을, Observation Management가 평균 스텝 수 감소에 가장 크게 기여했다. - 기존 방법 비교: 동일한 조건에서 Meta-Harness(62.92)와 AHE(62.54)는 baseline(61.79) 대비 약 1%p 개선에 그친 반면, ModularRSI는 67.42로 5%p 이상 향상되어 벤치마크-분리 프로토콜 하에서 더 강한 일반화 성능을 보였다. - 진화 데이터 난이도: 너무 쉽거나 너무 어려운 과제보다 중간 난이도(Medium-centered) 과제 분포로 진화했을 때 대조 신호가 더 풍부해져 SWE-Bench Verified 정확도가 76.45%로, Hard&Easy 설정(74.25%)보다 높았다.

한계점

저자들은 대조적 궤적 분석(contrastive trajectory analysis) 자체의 기여도를 독립적으로 분리하는 전용 ablation을 수행하지 못했다고 밝혔다(궤적 분석과 사례 연구를 통한 정성적 근거만 제시). 또한 계산 비용 제약으로 2,000개로 구축한 전체 진화 데이터셋 중 일부만 실제 진화 실험에 사용했으며, 더 큰 규모의 비교 연구는 향후 과제로 남겼다.

시사점

ModularRSI는 하네스 자기개선 연구에서 "벤치마크 데이터로 직접 진화시키지 않고도" 일반화 가능한 개선을 끌어낼 수 있음을 보여주며, 하네스를 기능별 모듈로 분해하고 대조적 증거로 국소적인 신용 할당을 수행하는 접근이 전체 하네스를 한 번에 최적화하는 방식보다 효과적이고 안정적임을 시사한다. 이는 향후 에이전트 하네스 RSI 연구에서 재현 가능하고 신뢰할 수 있는 평가 프로토콜(벤치마크-분리 진화 데이터셋)과 모듈형 설계 원칙이 중요한 표준으로 자리잡을 수 있음을 시사한다.
