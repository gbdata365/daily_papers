CyberFactory: Scaling Cyber Security Capabilities with Instances from the Wild

사이버팩토리: 야생의 인스턴스로 사이버보안 역량 확장하기

실제 CVE(공개된 취약점 사례)를 실행 가능하고 검증 가능한 학습 과제로 자동 변환하는 오픈소스 파이프라인 "CyberFactory"를 제안하고, 이를 통해 합성한 에이전틱 궤적으로 학습시킨 사이버보안 특화 모델 "OpenAegis"가 CyberGym 벤치마크에서 훨씬 큰 범용 모델들을 능가함을 보인 연구.

한 줄 요약

실제 CVE(공개된 취약점 사례)를 실행 가능하고 검증 가능한 학습 과제로 자동 변환하는 오픈소스 파이프라인 "CyberFactory"를 제안하고, 이를 통해 합성한 에이전틱 궤적으로 학습시킨 사이버보안 특화 모델 "OpenAegis"가 CyberGym 벤치마크에서 훨씬 큰 범용 모델들을 능가함을 보인 연구.

배경 및 문제의식

  • 폐쇄형(closed-source) LLM들은 이미 뛰어난 사이버보안 능력을 보여주고 있지만, 개방형(open-weight) 모델 진영은 여러 한계에 부딪혀 있다.
  • 프론티어 오픈웨이트 모델들은 강력한 사이버보안 성능을 내더라도 그 학습 방법과 데이터를 재현 가능한 형태로 공개하지 않는다.
  • 기존 오픈소스 노력들은 CTF(캡처 더 플래그) 등 개별적이고 파편화된 과제에 머물러 있으며, 서로 다른 세팅에서 고립적으로 이루어져 왔다.
  • 사이버보안 모델을 제대로 학습시키려면 단순한 프롬프트 기반 롤아웃이 아니라, 확장 가능한 에이전틱(agentic) 데이터가 필요한데, 이는 강한 도메인 사전지식(domain prior)을 요구하여 스케일링이 어렵다.
  • 이에 따라 저자들은 "실세계의 흩어진 취약점 아티팩트를 실행 가능하고 검증 가능한 학습 감독 신호로 바꾸는, 통합되고 재현 가능한 오픈소스 프레임워크를 어떻게 만들 것인가?"라는 연구 질문을 제기한다.

핵심 기여

  1. CyberFactory: 데이터 구성 → 궤적 합성 → 모델 학습을 하나의 파이프라인으로 연결한, 사이버보안 모델 학습을 위한 통합 오픈소스 레시피를 제시. 취약점 탐지(PoC 생성), 패치 생성, 사이버보안 질의응답(CyberQA) 세 과제를 아우른다.
  2. 확장 가능한 에이전틱 데이터 파이프라인: ARVO, OSS-Fuzz, 그리고 "야생의(from-the-wild)" CVE들을 실행 가능하고 검증 가능한 과제 인스턴스로 변환하고, 재사용 가능한 "취약점 분석 스킬(vulnerability-analysis skill)"로 교사(teacher) 모델의 도구 상호작용 궤적 합성을 유도한다. 이는 무제약적인 모델 롤아웃 대신 실제 취약점 근거와 실행 피드백에 기반한 감독을 가능하게 한다.
  3. OpenAegis 공개: 위 궤적으로 학습된 멀티태스크 사이버보안 모델을 공개. 학습 시에는 스킬(도메인 절차)의 안내를 받지만, 추론 시에는 스킬 없이도 학습된 워크플로우를 내재화하여 재현한다는 점을 궤적 분석으로 입증.

방법론

  • 인스턴스 구축(PoC 생성용): PoC(개념 증명, Proof-of-Concept)는 취약한 pre-patch 빌드에서는 크래시를 일으키고 patch가 적용된 post-patch 빌드에서는 일으키지 않아야 한다는 "차분 오라클(differential oracle)"로 정의된다. ARVO/OSS-Fuzz는 이미 pre/post-patch 쌍이 존재하지만, 난이도가 가장 높은 "야생의 CVE"는 영향받는 소프트웨어 버전 범위와 CWE(공통 취약점 유형) 메타데이터만 주어지므로, (1) CWE 유형 확인 → (2) 영향 버전 범위에서 수정 커밋 위치 확인(pre/post-patch 버전 결정) → (3) 추론 모델이 이미 쉽게 푸는 인스턴스를 걸러내는 난이도 검증의 3단계 파이프라인으로 인스턴스를 만든다.
  • 설명(description) 생성: 취약점 수정 커밋 메시지 품질을 LLM으로 분류하고, 메시지 품질이 낮으면 취약점 관련 근거와 수정 커밋을 활용해 설명을 새로 생성하며, 품질이 높으면 원문 커밋 메시지를 그대로 사용한다.
  • 패치 생성 및 QA: 기존 CVE 기반 취약점-수정 데이터(코퍼스)를 활용해 패치 생성 인스턴스를 구축한다. QA 데이터는 "정답 우선(answer-first)" 전략을 쓴다 — 실행 결과(크래시 위치, 테스트 결과), 구조적 사실(변경된 함수, 콜그래프 관계), 신뢰할 수 있는 보고서에서 추출한 텍스트 등 신뢰 가능한 소스에서 먼저 정답을 확정한 뒤, LLM이 이를 질문으로 재구성한다. 이후 LLM 판정자가 답이 근거로 역추적되는지, 질문에 답이 유출되지 않았는지, 질문이 유일한 답을 특정하는지를 자동 검증한다.
  • 스킬 기반 궤적 합성: 인스턴스는 "무엇을" 풀어야 하는지만 규정할 뿐 "어떻게" 접근할지는 정하지 않으므로, 재사용 가능한 "취약점 분석 스킬"을 제공해 대상 코드/환경 조사, 적절한 분석·테스트 기법 사용, 검증 실패 시 접근법 수정 등 과제에 무관한(task-independent) 절차를 안내한다. 이 스킬은 데이터 합성 단계에서만 사용되며, 최종 모델(OpenAegis)에는 추론 시 제공되지 않고, 지도 미세조정(SFT)을 통해 절차 자체가 모델 파라미터로 내재화된다.
  • 장기 문맥 압축(long-horizon context compaction): 256K 토큰 문맥 한계에 근접할 수 있는 긴 롤아웃 문제를 해결하기 위해, 문맥 사용량이 90%에 도달하면 검증된 근거, 실패한 시도, 열린 가설, 생성된 아티팩트, 빌드 상태, 대기 중인 행동 등을 유지한 채 연속 상태(continuation state)로 압축하는 학습-추론 공용 프로토콜을 적용한다.
  • 평가 프로토콜(CyberGym): 코드베이스와 자연어 설명만 주어진 상태에서 목표 취약점을 재현하는 PoC 입력을 합성하는 과제. pre-patch 빌드에서는 크래시가 나고 post-patch 빌드에서는 나지 않아야 성공으로 판정하는 "차분 오라클" 수식을 프로그램적/결정적(machine-checkable) 신호로 사용한다.

실험 설정 및 결과

  • 모델 및 베이스라인: OpenAegis는 Qwen 3.5-397B-A17B 체크포인트에서 초기화되어 최대 131,072 토큰, 3 에폭 전체 파라미터 SFT로 학습되었다(256 GPU, BF16, 코사인 학습률 스케줄 등). 비교 대상은 초기화 체크포인트인 Qwen 3.5(397B-A17B), 그리고 더 크고 강력한 범용 에이전트 백본인 Kimi K2.7(1T-A17B/A32B급)과 GLM 5.2(744B-A40B)이며, 모든 모델은 동일한 스캐폴드·도구 인터페이스·제출 로직·차분 오라클·1시간 예산으로 평가된다(스킬은 어떤 모델에도 추론 시 제공되지 않음).
  • 주 결과(Table 1): 1시간 예산 하 CyberGym Pass@1 기준, OpenAegis 58.1%로 Qwen 3.5(29.6%) 대비 28.5점 향상, GLM 5.2(43.3%) 대비 14.8점, Kimi K2.7(51.7%) 대비 6.4점 높은 성능을 기록해 훨씬 적은 파라미터로도 더 큰 범용 모델들을 능가했다.
  • 문맥 관리 비교(Table 2): 90% 임계값에서 압축하는 전략이 전체 Pass@1 58.1%로, 전체 히스토리 유지(52.1%)나 단순 절단(45.6%)보다 우수했으며, 특히 40회 이상 도구 상호작용이 필요한 장기 과제에서 8.5점 향상 및 문맥 소진 실패율 11.7점 감소 효과가 있었다.
  • 스킬의 데이터 합성 효과(Table 3, 4): GLM 5.2에 취약점 분석 스킬을 부여하면 60분/1회 시도 대비 15분/5회 시도(4분의 1의 실행 시간)로도 Pass@1이 43.3%에서 46.5%로 향상 — 처리량(throughput) 관점에서 스킬이 유익함을 보여준다. 스킬 부여 시 탐색(exploration) 사용률이 3.78%→99.85%, 검증(validation) 사용률이 0.13%→98.41%로 급증한다.
  • 스킬 내재화 분석(Figure 3, Table 5, Figure 4, Table 6): OpenAegis는 스킬을 추론 시 제공받지 않았음에도, Qwen3.5 대비 궤적당 탐색/검증 호출 수가 늘고(예: 검증 호출 0.01→1.05), 도구 호출을 셸 호출로 통합하며(70.1%→89.9%), 단일 연산 호출 비율이 낮아지고(31.4%→13.5%) 다중 연산 호출이 늘어나는 등 GLM 5.2+스킬에서 관찰된 것과 동일한 방향의 행동 변화를 보인다. 또한 ASAN(AddressSanitizer) 컴파일·출력 확인 빈도가 늘고, 정확히 한 번만 제출하는 비율이 증가(37.9%→48.2%)하는 등 더 증거 기반적이고 신중한 워크플로우로 변화했다.

한계점

  • 평가는 현재 확보 가능한 CVE 아티팩트 범위, 벤치마크 커버리지, 고정된 1시간 실행 예산에 제한되어 있다.
  • 일부 타겟은 퍼징(fuzzing) 우선 접근보다 수작업 입력 구성이 더 유리할 수 있어, 현재 파이프라인이 모든 취약점 유형에 최적은 아니다.
  • 패치 생성과 CyberQA에 대해서는 PoC 생성만큼 엄밀한 평가가 아직 완비되지 않았다(향후 과제로 명시).
  • OpenAegis가 학습에 사용한 합성 인스턴스 자체에도 위험 요소가 있어, 공개 시 사용자가 의도된 용도로만 사용하도록 검증이 필요하다고 저자들이 명시하고 있다.
  • 복수의 상호보완적 분석 전략 중에서 상황에 맞게 선택하는 "적응형 에이전트"는 아직 구현되지 않았다(향후 과제로 제시).

시사점

  • 폐쇄형 모델에 의존하지 않고도, 실세계 CVE라는 "야생의" 데이터를 실행·검증 가능한 학습 신호로 변환하는 재현 가능한 파이프라인만으로 오픈웨이트 모델의 사이버보안 역량을 크게 끌어올릴 수 있음을 보여준다.
  • 도메인 절차(스킬)를 교사 모델의 데이터 합성 단계에서만 활용하고 학생 모델에는 노출하지 않는 "스킬 유도 후 내재화" 방식은, 절차적 지식을 모델 파라미터로 전이시키는 일반적 학습 전략으로 다른 에이전틱 도메인에도 적용 가능성이 있다.
  • 차분 오라클과 같은 프로그램적·자동 검증 신호를 활용하면 사람 개입 없이 제안-검증-수정(propose-verify-refine) 루프를 통해 에이전틱 학습 데이터를 대규모로 확보할 수 있음을 시사한다.
  • 장기 호라이즌 에이전트 작업에서 문맥 압축 전략이 단순 절단이나 전체 히스토리 유지보다 성능과 효율 면에서 우월할 수 있음을 실증적으로 보여, 향후 장기 툴 사용 에이전트 설계에 참고가 된다.
