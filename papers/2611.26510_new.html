AutoMaster: Autonomous Post-Training by Making the Same Model a Better Teacher

오토마스터: 같은 모델을 더 나은 교사로 만드는 자율 사후훈련

한 줄 요약

과제 성공 여부만으로는 어떤 행동(reasoning/behavior)을 강화해야 할지 알 수 없다는 문제의식에서 출발해, 자연어로 된 "스킬(skill)"을 교사(teacher) 모델의 시스템 프롬프트에 주입해 바람직한 행동을 유도하고(Skill-FT) 그 결과 trajectory를 선별해 학생 모델을 SFT시키는 과정을, LLM 에이전트가 자율적으로 설계·실행·개선하는 프레임워크 AutoMaster를 제안한다.

배경 및 문제의식

에이전트 후속학습(post-training)에서 흔히 쓰이는 방법은 성공한 trajectory에 대해 지도 미세조정(SFT)을 수행하는 것이지만, 저자들은 "과제 성공 자체가 어떤 행동을 강화해야 하는지 알려주지 않는다"는 점을 지적한다. 근거 없는 가정, 비생산적 반복, 형식적인(피상적인) 검증 같은 바람직하지 않은 습관도 결과적으로 성공한 trajectory 안에 섞여 있을 수 있고, 이런 trajectory로 SFT하면 그 나쁜 습관까지 함께 강화된다. 반대로 바람직한 행동은 지도 없는(unguided) rollout에서는 애초에 드물게 나타나 학습 데이터에 거의 포함되지 않는 문제도 있다.

핵심 기여

  1. Skill-FT (Skill-Guided Fine-Tuning): 자연어로 작성된 "스킬"(어떻게 추론하거나 행동해야 하는지를 기술한 지침)을 교사 모델의 시스템 프롬프트에 덧붙여 rollout을 생성하게 함으로써, 교사가 이미 풀 수 있는 과제에서도 행동 패턴을 바꿀 수 있게 했다. 학생 모델은 이렇게 생성된 trajectory로 SFT되는데, 이때 교사에게 준 스킬 지시문을 학습 입력에서 제거하지 않고 그대로 유지한다.
  2. AutoMaster 프레임워크: LLM 에이전트가 이중 루프(inner loop/outer loop) 구조로 스킬을 설계·테스트·정제하고, 학습용 trajectory를 선별하며, 학생 모델의 평가 결과와 trajectory를 다시 피드백으로 받아 다음 라운드의 개입을 조정한다.
  3. 스킬 맥락 보존이 행동 내재화에 도움이 된다는 실증: 평가 시에는 스킬 없이 테스트하는 동일 조건에서, SFT 때 스킬 지시문을 학습 입력에 남겨둔 경우(Keep)가 제거한 경우(Remove)보다 6개 설정 전부에서 평균 성능이 높았다(2.15~4.01%p 차이).

방법론

AutoMaster의 inner loop에서는 에이전트가 먼저 지도되지 않은 교사와 초기 학생의 trajectory를 분석해 "억제해야 할 나쁜 패턴"과 "장려해야 할 좋은 패턴"을 찾는다. 이를 바탕으로 스킬을 설계해 일부 과제 부분집합에 시범 적용(pilot rollout)하고, 효과가 있으면 더 큰 배치로 확장해 rollout을 수행한 뒤, 과제 성과와 보여준 행동을 모두 고려해 학습에 쓸 trajectory를 선별한다. Outer loop에서는 매 라운드마다 동일한 초기 체크포인트에서 시작해 선택된 trajectory로 전체 파라미터 SFT를 수행하고, 평가 점수와 trajectory를 다시 inner loop에 피드백해 스킬을 개정하거나 데이터 선택을 바꾼다. 인프라 측면에서는 Model Context Protocol(MCP)을 통해 에이전트가 Docker 컨테이너 안에서 rollout·SFT 작업을 제출하고, 학습과 평가 GPU 클러스터가 체크포인트 저장소를 공유해 평가를 자동으로 스케줄링하도록 구성했다.

실험 설정 및 결과

Terminal-Bench 2.1, BrowseComp(Lite-185 부분집합), Doc2Repo(소프트웨어 엔지니어링) 세 영역에서 Qwen3.5-4B와 Qwen3.5-9B를 학생 모델로, DeepSeek-V4-Pro-Preview를 교사로, Codex(GPT-6 Astra 기반)를 에이전트로 사용해 평가했다. 각 영역에서 고정된 1,000개 과제 풀 중 512개 trajectory로 3 epoch SFT한 결과, AutoMaster는 Base 대비는 물론, 지도되지 않은 성공 trajectory로 SFT한 Vanilla SFT 대비 6개 벤치마크-모델 조합 전부에서 평균 1.42~8.99%p 더 높은 성능을 보였다(예: Terminal-Bench 2.1에서 9B 모델은 Vanilla SFT 26.59% → AutoMaster 35.58%). 스킬 유도와 데이터 선택을 각각 제거하는 ablation에서는 두 요소 모두 제거 시 성능이 떨어졌지만 영역별로 상대적 기여도가 달랐다(예: Terminal-Bench 2.1에서는 스킬 유도가, BrowseComp에서는 데이터 선택이 상대적으로 더 중요). 또한 과제 구성(어떤 과제를 몇 개씩 썼는지)을 AutoMaster의 최종 학습셋과 동일하게 맞춘 "Task-Matched SFT"와 비교해도 AutoMaster가 1.08~10.11%p 더 높아, 단순히 과제 선택만으로는 설명되지 않는 이득이 있음을 보였다. 5회의 자율 실험 라운드에 걸쳐 2~4라운드에서 최고 성능이 나타나는 경향을 보였다.

한계점

저자들은 9B 모델이 4B 모델보다 더 일관되게 Vanilla SFT를 능가한다고 보고해, 더 큰 모델 용량이 AutoMaster가 제공하는 개입으로부터 더 안정적으로 이득을 얻는다는 점을 시사한다고 언급했다(즉 작은 모델에서는 이득의 일관성이 떨어짐). 또한 실험은 특정 교사(DeepSeek-V4), 특정 에이전트(Codex/GPT-6 Astra), 세 가지 영역(터미널, 검색, SWE)에 한정되어 있으며, 논문 본문에서는 다른 교사·에이전트·영역으로의 일반화에 대한 구체적 한계는 명시되지 않음.

시사점

"성공한 trajectory를 모으는 것"과 "그 trajectory가 어떤 행동을 보여주는지를 적극적으로 설계하는 것"은 서로 다른 문제라는 점을 분명히 보여준다. 같은 교사 모델이라도 행동을 유도하는 프롬프트 개입만으로 더 나은 학습 데이터를 생산하는 "더 나은 교사"가 될 수 있다는 결과는, 별도의 더 큰/더 좋은 교사 모델 없이도 데이터 품질을 개선할 수 있는 길을 제시한다. 또한 스킬 지시문을 평가 시 사용하지 않더라도 학습 입력에는 남겨두는 것이 더 나은 내재화로 이어진다는 발견은, SFT 데이터 구성 시 "지도와 평가 프롬프트의 일치"를 맹목적으로 추구하기보다 학습에 필요한 맥락을 의도적으로 유지하는 것이 유리할 수 있음을 시사한다.
