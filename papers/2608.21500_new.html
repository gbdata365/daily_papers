SecOPD: Mitigating Adaptive Prompt Injections by On-Policy Distillation

SecOPD: 온폴리시 증류를 통한 적응형 프롬프트 인젝션 완화

LLM 에이전트가 외부 데이터에 섞여 들어온 악성 지시(프롬프트 인젝션)를 따르지 않도록, 토큰 단위로 "정상 지시를 따르는 부분은 강화하고 주입된 지시를 따르는 부분은 억제"하는 온폴리시 증류(On-Policy Distillation, OPD) 기반 방어 기법 SecOPD를 제안하여, 최신 적응형 공격(PISmith) 대비 공격 성공률을 기존 최고 방어(Meta-SecAlign) 대비 약 10분의 1 수준으로 낮췄다.

한 줄 요약

LLM 에이전트가 외부 데이터에 섞여 들어온 악성 지시(프롬프트 인젝션)를 따르지 않도록, 토큰 단위로 "정상 지시를 따르는 부분은 강화하고 주입된 지시를 따르는 부분은 억제"하는 온폴리시 증류(On-Policy Distillation, OPD) 기반 방어 기법 SecOPD를 제안하여, 최신 적응형 공격(PISmith) 대비 공격 성공률을 기존 최고 방어(Meta-SecAlign) 대비 약 10분의 1 수준으로 낮췄다.

배경 및 문제의식

  • 프롬프트 인젝션은 AI 에이전트에 대한 위협 1순위로 꼽힌다(OWASP GenAI Security Project). 에이전트가 웹페이지, 파일, 이메일 등 외부(신뢰할 수 없는) 데이터를 읽는 과정에서, 그 데이터 안에 공격자가 심어둔 지시문이 섞여 있으면 에이전트가 사용자의 원래 지시 대신 공격자의 목표를 수행해버릴 수 있다. 실제로 이런 공격은 코드 에이전트가 취약한 패치를 만들게 하거나, 웹 탐색 에이전트가 악성코드를 내려받게 하거나, Slack/Google Docs 등에서 개인 정보를 유출시키는 등의 사례로 이어졌다.
  • 방어 방식은 크게 (1) 백엔드 모델은 그대로 두고 탐지기·입력 필터·프롬프트 실드 등을 외부에 두는 시스템 수준 방어와, (2) 신뢰 프롬프트와 비신뢰 데이터를 별도 메시지 타입으로 구분하도록 모델 자체를 파인튜닝하는 모델 수준 방어로 나뉜다. 그러나 기존 모델 수준 방어(Meta-SecAlign 등)는 정적 공격 템플릿에서는 잘 작동하는 것처럼 보이지만, 방어된 모델에 맞춰 공격 프롬프트를 최적화하는 "적응형 공격"(예: PISmith, 강화학습으로 공격자 LLM을 학습시켜 특정 타깃 모델을 뚫는 방식) 앞에서는 공격 성공률(ASR)이 거의 100%에 가깝게 치솟는다.
  • 저자들은 이 취약성의 근본 원인을, 기존 방어 학습법(DPO, GRPO 등)이 모델의 응답 "전체"에 대해 하나의 시퀀스 수준 피드백(보상/선호도)만 주기 때문이라고 진단한다. 실제 응답은 정상 지시에 답하는 부분과 주입된 지시를 따르는 부분이 한 응답 안에 섞여 있는 "혼합 응답"인 경우가 많은데, 시퀀스 수준 피드백은 이 혼합 응답을 전부 좋다/나쁘다로만 평가해 어느 토큰이 문제인지 구분하지 못한다(신용 할당 문제).

핵심 기여

  • 프롬프트 인젝션 방어에 온폴리시 증류(OPD)를 최초로 적용한 SecOPD를 제안: 응답의 각 토큰 단위로 "정상 지시를 따르는 토큰은 장려, 주입된 지시를 따르는 토큰은 억제"하는 세밀한(token-level) 학습 신호를 제공한다.
  • 별도의 보안 판정기(judge)나 태스크 전용 보상 모델 없이, 초기화 모델(=학생 모델의 파인튜닝 이전 버전) 자체를 교사로 활용하는 방법을 고안했다. 학생이 공격이 포함된 입력에서 만들어낸 롤아웃(생성 토큰열)을, 동일한 초기화 모델이 "주입이 제거된 깨끗한 입력"을 조건으로 각 토큰에 확률을 매기게 하여 토큰별 이득(advantage) 신호로 삼는다. 교사는 학습 시에만 필요하며 추론(테스트) 시에는 필요 없다.
  • Qwen3.6-27B 모델을 기준으로, SoTA 적응형 공격(PISmith)에 대한 ASR을 기존 최고 방어인 Meta-SecAlign의 94.0%에서 9.0%로(약 1자리수 개선) 낮췄고, 학습 시 전혀 보지 못한 에이전트 툴콜 도메인(AgentDojo)에서도 4.7% ASR(Meta-SecAlign 5.5%)로 방어가 일반화됨을 보였다.
  • 일반 유용성(utility)도 undefended 모델 대비 크게 훼손되지 않음을 여러 벤치마크(AlpacaEval2, SEP, AgentDojo, MMLU-Pro, GPQA-Diamond, GSM8K, Minerva-Math)로 검증했다.

방법론

  • 문제 정식화: 신뢰 가능한 사용자 지시 I와 비신뢰 외부 데이터 c가 있을 때, 정상 입력은 이 둘을 결합해 만들고, 공격 입력은 공격자가 c 안에 목표 g를 자신의 표현 방식으로 삽입해 만든다. 모델은 채팅 템플릿에서 신뢰 지시("user")와 비신뢰 데이터("input")를 별도 메시지로 분리해 받는다(Meta-SecAlign과 동일한 형식).
  • 시퀀스 수준 피드백의 한계: Meta-SecAlign은 DPO로 (정상 응답=선호, 주입 추종 응답=비선호) 쌍을 학습하지만 선호 레이블이 응답 전체에 하나만 부여되어, 정상 답변과 주입 추종 문장이 섞인 혼합 응답을 제대로 다루지 못한다. GRPO 방식도 응답 전체에 하나의 스칼라 보상(LLM judge가 매김)만 주어 마찬가지 한계가 있다.
  • SecOPD의 핵심 아이디어(토큰 단위 크로스컨텍스트 스코어링):
  • 학생 모델이 "공격 입력"(신뢰 지시 + 주입이 섞인 데이터)을 받아 롤아웃(응답 토큰열)을 생성한다.
  • 동일한 초기화 모델(교사, 파라미터 고정)이 "대응되는 깨끗한 입력"(같은 신뢰 지시 + 주입이 제거된 데이터)을 조건으로, 학생이 생성한 각 토큰에 로그확률을 매긴다. 교사는 애초에 주입을 본 적이 없으므로 자동으로 안전하다.
  • 각 토큰에서 "교사 로그확률 - 학생 로그확률"을 역-KL 기반 토큰별 이득(advantage)으로 사용한다. 정상 지시에 맞는 토큰은 교사도 높은 확률을 주므로 이득이 양(장려)이 되고, 주입을 따른 토큰은 교사가 낮은 확률을 주므로 이득이 음(억제)이 된다.
  • 이 토큰별 이득으로 정책(학생) 파라미터를 업데이트한다(정책 그라디언트류 업데이트, advantage에는 stop-gradient 적용).
  • 학습 데이터 구성: 깨끗한 지시-응답 예제(Cleaned-Alpaca 기반 1.9만 건)에서, 각 예제에 대해 공격 목표를 인젝션 풀에서 샘플링하고 이를 비신뢰 데이터에 삽입해 공격 입력을 만든다. 삽입 방식은 주로 직접적인 지시 무시/전복 시도(비신뢰 데이터의 시작 또는 끝에 배치)이며, 일부는 완료(delimiter) 스타일의 역할 경계 공격도 포함해 다양한 공격 패턴에 노출시킨다(구체적 공격 문구는 본 요약에서 재현하지 않음).
  • 별도의 외부 보안 판정기나 태스크 전용 보상 모델 없이, 오직 "초기화 LLM이 정상 버전 입력에서 평가한 값"만으로 전체 지도 신호를 구성한다는 점이 특징이다.

실험 설정 및 결과

  • 모델/베이스라인: Qwen3.6-27B를 기준으로 (1) 무방어(undefended), (2) Meta-SecAlign(DPO 기반, 기존 최고 모델 수준 방어), (3) GRPO(시퀀스 수준 온폴리시 학습 베이스라인), (4) SecOPD 네 가지를 비교. 학습은 Tinker, 평가는 lm-eval 사용.
  • 보안 벤치마크: SEP(9.1K개 인젝션 샘플, instruction-following 도메인)에서 정적 공격(6종 결합) 및 적응형 공격(Basic, PISmith)을 평가하고, AgentDojo(에이전트 툴콜 도메인, 949개 태스크-인젝션 쌍)로 도메인 전이를 평가. PISmith는 각 방어 모델별로 전용 공격자 LLM을 새로 학습시키는 강력한 적응형 공격.
  • 핵심 결과(ASR, 낮을수록 좋음):
  • SEP 정적: 무방어 99.4% / Meta-SecAlign 28.9% / GRPO 15.0% / SecOPD 1.3%
  • SEP Basic 적응형: 무방어 99.0% / Meta-SecAlign 5.5% / GRPO 2.3% / SecOPD 0.2%
  • SEP PISmith 적응형(가장 강력한 공격): 무방어 97.9% / Meta-SecAlign 94.0% / GRPO 61.2% / SecOPD 9.0% — 기존 최고 방어 대비 약 10배 개선
  • AgentDojo 정적(미학습 도메인): 무방어 26.7% / Meta-SecAlign 5.5% / GRPO 0.7%(가장 낮음이나 유용성 저하 동반) / SecOPD 4.7%
  • 유용성 벤치마크: AlpacaEval2, SEP-utility, AgentDojo, MMLU-Pro, GPQA-Diamond, GSM8K, Minerva-Math 7개 평균에서 무방어 88.1% 대비 Meta-SecAlign 88.5%, GRPO는 큰 폭 하락(예: SEP 79.5%, AgentDojo 82.5%, Minerva-Math 85.1%), SecOPD는 평균 88.1% 수준으로 무방어와 대등하면서 GRPO보다 뚜렷이 높은 유용성을 유지. 즉 SecOPD가 유일하게 "낮은 PISmith ASR"과 "높은 유용성"을 동시에 달성.
  • 사례 분석: 정의를 요구하는 정상 질문에 "특정 문장을 덧붙이라"는 주입이 섞인 입력에서, Meta-SecAlign과 GRPO는 정상 답변 뒤에 주입된 문장을 그대로 덧붙였지만 SecOPD는 주입 문장을 덧붙이지 않고 정상 질문에만 답했다.
  • 오류 분석: Minerva-Math에서 무방어 모델은 맞혔지만 SecOPD가 틀린 46개 사례를 수작업 분석한 결과, 실제 수학적 추론 오류는 4건뿐이었고, 나머지는 무관한 문제로 전환/손상된 답, 채점(추출/포맷) 문제로 오분류된 정답, 또는 </think> 마커와 함께 조기 종료된 미완성 응답(생성 한도 도달이 아님) 등으로 나타났다.

한계점

  • 이 연구는 사용자 프롬프트는 정상(benign)이고 외부 데이터만 악성인 (간접) 프롬프트 인젝션 방어에 초점을 맞춘다. 따라서 사용자 자신이 악의적인 직접 프롬프트 인젝션이나 탈옥(jailbreak) 공격을 막는 데는 적용되지 않는다.
  • 시스템이 입력 중 어느 부분이 신뢰 가능하고 어느 부분이 아닌지에 대한 명확한 신호를 이미 알고 있다고 가정한다. 즉 입력 파트 중 어느 것이 신뢰 가능한지 스스로 판단해야 하는 에이전트에 대한 보안은 다루지 않는다(논문 말미에서 언급되는 한계로, 이어지는 문장이 다음 페이지로 이어져 상세 내용은 논문에 명시되지 않음).
  • PISmith 등 특정 적응형 공격 프레임워크로 평가했으며, 아직 시도되지 않은 새로운 유형의 적응형 공격에 대한 견고성은 논문에 명시되지 않음.

시사점

  • "모델을 안전하게 만들 수 없다"는 통념에 도전하며, 잘 설계된 학습 신호(토큰 단위 크레딧 할당)만으로 토이 수준의 학습 샘플에서도 상당한 보안 향상이 가능함을 보였다.
  • 별도의 보안 판정 모델이나 외부 보상 모델 없이, 이미 가지고 있는 초기화 모델을 "안전한 교사"로 재활용하는 아이디어는, 데이터 준비 비용을 늘리지 않고도 방어력을 높일 수 있는 실용적 접근으로서 다른 정렬(alignment)/안전 파인튜닝 문제에도 응용될 여지가 있다.
  • 시퀀스 수준 대신 토큰 수준 피드백을 사용하는 것이 "정상 응답과 악성 응답이 한 응답 안에 섞이는" 혼합 응답 문제 전반(프롬프트 인젝션뿐 아니라 유사한 신용 할당 문제를 가진 다른 안전 정렬 과제)에도 유용할 수 있음을 시사한다.
  • 코드와 모델이 공개되어 있어(GitHub, Hugging Face) 실무 적용 및 후속 연구 재현이 용이하다.
