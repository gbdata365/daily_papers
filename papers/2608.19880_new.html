EnvHarness: Awakening Static Worlds for Agent Learning

환경 하네스: 에이전트 학습을 위해 정적인 세계를 깨우다

EnvHarness는 기존의 정적인 에이전트 학습 환경을 수정하지 않고 그 위에 플러그인 형태의 래퍼(Stage, Contract, Chain)를 씌워 동적으로 재구성하는 프로그래머블 레이어이며, EnvRigger는 정책 에이전트의 실행 궤적을 관찰해 이 래퍼들을 자동으로 생성·검증함으로써 에이전트의 약점에 맞춘 학습 환경을 지속적으로 만들어낸다.

한 줄 요약

EnvHarness는 기존의 정적인 에이전트 학습 환경을 수정하지 않고 그 위에 플러그인 형태의 래퍼(Stage, Contract, Chain)를 씌워 동적으로 재구성하는 프로그래머블 레이어이며, EnvRigger는 정책 에이전트의 실행 궤적을 관찰해 이 래퍼들을 자동으로 생성·검증함으로써 에이전트의 약점에 맞춘 학습 환경을 지속적으로 만들어낸다.

배경 및 문제의식

LLM 에이전트는 웹 탐색, 코드 저장소 이슈 해결, 임바디드 제어 등 다양한 상호작용 환경을 통해 학습 신호를 얻는다. 그러나 이러한 환경은 대부분 사람이 직접 상호작용 로직과 검증기(verifier)를 하드코딩해 만든 것이라, 완성된 이후에는 어떤 에이전트가 상호작용하든, 그 에이전트가 얼마나 발전했든 항상 동일하게 동작하는 정적인 구조를 가진다. 이 때문에 (1) 특정 에이전트의 약점을 겨냥한 맞춤형 학습 신호를 제공하지 못하고, (2) 에이전트가 기존 과제를 풀 수 있게 되면 더는 가르칠 것이 없어진다는 근본적 한계가 있다. 최근 자동 환경 생성 연구들이 이를 해결하려 했지만, 도메인별로 별도의 파이프라인이 필요하고, LLM이 생성한 환경과 검증기의 정확성을 보장하기 위해 비용이 크거나 신뢰도가 낮은 필터링 과정을 거쳐야 하며, 결과물 역시 여전히 정적이라는 문제가 남아 있었다.

핵심 기여

  • EnvHarness 제안: 에이전트 하네스(agent harness)가 고정된 LLM에 도구·메모리·스킬 등을 덧붙여 자율 에이전트로 만드는 것과 같은 원리를, 반대편인 환경에 적용한 개념이다. 환경의 reset/step 표준 인터페이스만을 통해 동작하며, 초기 상태, 상호작용 인터페이스, 복합 과제를 각각 재구성하는 세 종류의 플러그인 컴포넌트(Stage, Contract, Chain)로 구체화된다. 원본 환경의 로직과 검증기는 전혀 수정되지 않고 그대로 상속된다.
  • EnvRigger 제안: 목표 정책(policy)을 블랙박스로 취급하며, 그 실행 궤적을 관찰하고 결함을 진단하여 EnvHarness 컴포넌트를 자동으로 합성하고, 새로운 롤아웃으로 검증하는 완전 자동화된 과제-정책 조건부 환경 커스터마이징 워크플로우를 제시한다.
  • 폭넓은 실험적 검증: 4개 도메인, 5개 벤치마크에 걸쳐 기존 정적 환경 및 도메인 특화 환경 생성 파이프라인 대비 최대 9.0점의 성능 향상과 9.8% 적은 실행 스텝을 달성했으며, 강화학습(RL) 환경에서도 우수한 최적화 신호를 제공함을 보였다.

방법론

EnvHarness는 환경을 튜플 E = (S, A, O, T, R, s0)로 정의하고, 컴포넌트 w를 인터페이스 수준에서만 작동하는 변환(E' = w(E))으로 정의한다. 세 가지 컴포넌트는 다음과 같다. - Stage: reset() 직후의 초기 상태에 일련의 상태 조작 액션(δ)을 적용하여 시작 지점을 바꾼다. 예를 들어 ALFWorld에서 컵을 서랍 속에 미리 숨겨 탐색을 강제하거나, 반대로 일부 하위 목표를 미리 완료해 과제를 단순화할 수 있다. - Contract: 행동 공간, 관측 공간, 전이 함수를 재작성하는 세 변환 함수(f_A, f_T, f_O)로 구성되며, 행동 사전조건을 강제하거나 관측을 절단·증강하거나 특정 결과에 구조화된 피드백을 붙인다. - Chain: 외부 환경(E_ext)과 결합 로직(g)을 지정해 여러 기본 환경을 하나의 확장된 에피소드로 연결한다. 목표를 넘어서까지 지속적으로 과제를 수행하는 능력을 학습시키는 데 쓰인다.

세 컴포넌트는 자유롭게 합성 가능하며 순서에 따라 결과가 달라진다(비가환적). EnvRigger는 이 컴포넌트 선택·파라미터화를 자동화하기 위해 Observe(정책의 성공·실패 궤적 수집) → Diagnose(반복 행동 루프, 긴 관측 파싱 실패 등 근본 원인 진단 및 환경을 쉽게/어렵게 만들 방향 결정) → Write(진단에 따라 후보 컴포넌트 합성) → Validate(새 롤아웃으로 성공률·실패 분포를 검토해 수용/거부/수정 결정) 네 단계의 루프를 반복한다. 수용된 컴포넌트만 최종 EnvHarness에 누적되며, Stage의 초기 상태 변형이 재현 가능하도록 결정론적 리셋을 가정한다.

실험 설정 및 결과

ALFWorld(임바디드), WebArena(웹 탐색), SWE-bench Verified(소프트웨어 엔지니어링), OfficeQA와 SpreadsheetBench(오피스 자동화) 등 4개 도메인 5개 벤치마크에서 검증했다. EnvRigger와 정책 에이전트는 동일한 백본 모델(ALFWorld·WebArena는 Gemini-3.1-Flash-Lite, 나머지는 Gemini-3.5-Flash)을 사용해 성능 향상이 더 강한 외부 모델 증류에서 온 것이 아님을 보장했다. 스킬 기반 학습(SL)에서 EnvHarness 환경으로 추출한 스킬은 원본 환경 스킬 대비 ALFWorld에서 최대 9.0점(OOD), WebArena ShopAdmin에서 6.2점, SWE-bench Verified에서 2.70점(평균 스텝은 53.6→49.6으로 감소) 개선되었고, 도메인 특화 생성 기법인 GenEnv(ALFWorld, +5.7점 평균)와 SWE-smith(SWE-bench, +2.46점, 스텝 5.11 감소)도 능가했다. 강화학습(RL) 실험(Qwen3-8B-base, GRPO)에서도 ALFWorld In-Dist 87.9(원본 81.4), WebShop 점수 79.2(원본 75.6) 등 대체로 더 강한 정책을 얻었다. 환경 스케일링 실험에서는 환경 수가 늘어날수록 EnvHarness가 47.67→54.79까지 계속 성능이 오른 반면, 원본·생성 환경은 각각 52.13, 50.37에서 정체되었다. Gemini, Qwen3.6-27B, Claude Sonnet 4.6 등 4개 서로 다른 백본 모델에서도 일관되게 2.7~3.7점의 절대 성능 향상을 보여 모델 크기·종류에 무관하게 일반화됨을 확인했다. Chain 컴포넌트는 두 환경을 이어 붙여 장기 목표 유지 능력을 학습시키며, Stage/Contract와 결합 시 SR과 효율성 모두에서 최상의 결과(SR 54.30, 평균 스텝 43.12)를 보였다.

한계점

논문에 별도의 "한계점" 절은 명시되지 않았으나, 본문에서 언급된 제약 사항들은 다음과 같다. Chain 컴포넌트는 EnvRigger가 결합된 환경들의 내부 상태를 관찰하기 어렵다는 이유로 자동화된 EnvRigger 파이프라인에서 제외되고 별도로 분석되었다. 또한 Stage의 초기 상태 변형이 검증 단계에서 재현되려면 기본 환경이 결정론적 리셋을 지원해야 한다는 전제가 필요하다. RL 실험에서는 ALFWorld OOD 성공률이 원본 환경 대비 소폭(88.8 대 89.6) 하락하는 사소한 트레이드오프도 관찰되었다.

시사점

EnvHarness는 "에이전트 하네스"라는 개념을 환경 쪽에 대칭적으로 적용함으로써, 새로운 환경을 밑바닥부터 만드는 대신 신뢰할 수 있는 기존 검증기를 그대로 유지한 채 환경을 재구성할 수 있음을 보여준다. 이는 도메인에 무관하게 적용 가능한 통일된 인터페이스로 환경 생성의 엔지니어링 비용을 크게 낮추면서도, 정책의 실제 약점을 진단해 겨냥하는 방식이 단순히 학습 데이터(환경 수)를 늘리는 것보다 더 효과적임을 시사한다. 특히 환경과 정책이 반복적으로 공진화(co-evolve)할 수 있다는 결과는, 정적 벤치마크가 정체되는 상황에서도 지속적인 에이전트 능력 향상이 가능한 새로운 학습 신호 획득 경로를 제시한다.
