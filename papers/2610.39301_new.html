Youtu-Parsing-Omni: One Encoder, One Schema, All Modalities

Youtu-Parsing-Omni: 하나의 인코더와 하나의 스키마로 모든 모달리티를 파싱하다

문서·이미지·오디오·비디오를 하나의 공유 인코더(Youtu-Omni-Encoder)와 하나의 통합 출력 스키마(OmniSchema)로 처리하는 5B 규모 옴니모달 파서를 제안하고, 모델이 스스로 생성한 결과를 기준-조건부 자기 자신으로부터 얻은 토큰 단위 목표와 대조해 학습하는 자기진화형 사후학습 기법(OSAD)을 통해 문서 파싱(OmniDocBench v1.6)과 범용 옴니모달 파싱(OmniParsingBench) 모두에서 최고 수준의 성능을 달성한다.

한 줄 요약

문서·이미지·오디오·비디오를 하나의 공유 인코더(Youtu-Omni-Encoder)와 하나의 통합 출력 스키마(OmniSchema)로 처리하는 5B 규모 옴니모달 파서를 제안하고, 모델이 스스로 생성한 결과를 기준-조건부 자기 자신으로부터 얻은 토큰 단위 목표와 대조해 학습하는 자기진화형 사후학습 기법(OSAD)을 통해 문서 파싱(OmniDocBench v1.6)과 범용 옴니모달 파싱(OmniParsingBench) 모두에서 최고 수준의 성능을 달성한다.

배경 및 문제의식

에이전트가 텍스트가 아닌 문서·이미지·음성·영상을 매번 원본 그대로 모델에 입력해 재인코딩하는 방식은 비용이 크고, 답변이 어떤 영역·구간에서 나왔는지 추적하기도 어렵다. "옴니모달 파싱"은 이런 입력을 한 번만 변환해 공간·시간상에 위치가 명시된 구조화된 텍스트 레코드로 만들어, 텍스트 전용 LLM도 읽고 근거를 추적할 수 있게 하는 지각(perception) 계층을 제공한다. 그런데 기존 파서는 이 역할을 부분적으로만 수행한다. 문서 파서는 일반 페이지에는 강하지만 화학구조식·악보 같은 기호 콘텐츠는 여전히 전용 모델에 맡기고, 문서 밖(이미지·오디오·비디오) 파싱은 아직 캡셔닝·질의응답 중심으로 설계되어 있어 공간·시간에 근거가 명시된 구조화 출력이 부족하다. 결과적으로 입력 유형별로 서로 다른 모델과 출력 형식이 쓰이는데, 저자들은 출력이 결국 "공간·시간에 고정된 구조화 레코드"라는 공통 형태를 띠므로 입력별 전문 모델 대신 하나의 파서·하나의 스키마로 통합할 수 있다고 본다. 이를 위해서는 두 가지 난제가 있다. (C1) 모달리티 간 공동 지각: 기존 옴니모달 모델과 선행 파서 Logics-Parsing-Omni는 비전·오디오를 별도로 사전학습된 두 타워로 각각 인코딩해 지각 단계에서 모달리티 간 융합이 없고, 시간축도 서로 독립적으로 색인되며, 모달리티마다 별도 아키텍처·사전학습이 필요하다. (C2) 과업 간 공동 최적화: 10개의 서로 다른 출력 필드를 갖는 과업을 동시에 최적화해야 하는데, 지도 미세조정(SFT)은 참조 접두사에서만 학습하고, 검증 가능 보상 기반 강화학습(RLVR)은 모델 자신의 출력에서 학습하지만 이질적인 기준을 하나의 스칼라 보상으로 압축해야 하고 시퀀스 단위 피드백만 준다.

핵심 기여

  • Youtu-Omni-Encoder: 비전·오디오 전용 두 타워를 하나의 공유 Transformer로 대체한 통합 인코더. 사전학습된 텍스트 언어모델(Qwen3-0.6B-Base)로 가중치를 초기화해 글자 읽기 능력을 강화하고, 모든 모달리티가 같은 공간-시간 좌표계((𝑡, ℎ, 𝑤) 위치 인코딩)를 공유하며, 일부 레이어(fusion layer)에서만 비디오 프레임이 동시간 오디오에 주의를 기울이게 해 지각 단계 안에서 모달리티 간 융합과 시간 정렬이 이루어지도록 했다.
  • OmniSchema: 문서·화학구조·악보·차트·플로우차트·기하도형·자연이미지·오디오·자연비디오·텍스트가 많은 비디오 등 10개 파싱 과업의 출력을 하나의 공간·시간 근거(bounding box 또는 타임스탬프)가 달린 JSON 스키마로 통일, 과업이 달라도 동일한 사후학습 목표 함수를 적용할 수 있게 했다.
  • OmniSchema-Aware On-Policy Distillation (OSAD): 모델이 스스로 만든 롤아웃을, 참조(정답) 파스를 함께 보고 있는 동결된 자기 자신의 복사본이 제공하는 토큰 단위 목표와 비교해 학습하는 자기진화형 사후학습. 매 라운드가 끝나면 학습된 가중치로 "교사" 역할의 복사본을 갱신해 파서와 그 지도 신호가 함께 진화하도록 하며, 손수 설계한 보상이나 별도로 학습된 교사 모델이 필요 없다.
  • 단일 체크포인트로 최고 성능: 5B 파라미터 하나로 OmniDocBench v1.6에서 1위(Overall 96.96), 공개 모델 중 OmniParsingBench 1위(Avg. 75.08, 특히 오디오·비디오에서 우세), 최고 차트 파싱 점수(95.02), 화학구조 정확 일치율 최고, 전용 광학악보인식 모델과 대등한 악보 인식 성능을 동시에 달성.

방법론

아키텍처: Youtu-Parsing-Omni는 텍스트만 출력하는 디코더 전용 언어모델(Youtu-LLM-2B 계열)과, 이미지·오디오·비디오를 입력받는 하나의 지각 인코더로 구성된다. 인코더는 모달리티별 경량 "스템"(비전: 패치를 선형 매핑, 오디오: 로그-멜 스펙트로그램을 strided conv로 다운샘플링)과, 그 뒤를 잇는 공유 Transformer 블록(RMSNorm, SwiGLU, grouped-query attention, QK-Norm, 양방향 attention, RoPE), 그리고 모달리티별 머저(merger)+프로젝터로 이루어진다. 회전 위치 인코딩(RoPE)의 주파수 슬롯을 T(시간), H, W 세 축으로 나누어 할당해 비전 토큰은 프레임 인덱스와 패치 좌표를, 오디오 토큰은 시간 오프셋만(h=w=0) 사용하도록 해 두 모달리티가 같은 시간 좌표계를 공유한다. 비디오는 "독립 경로"(프레임·오디오 구간이 각자 독립적인 attention 윈도우를 가짐)와 "융합 경로"(프레임과 그 구간의 오디오를 하나의 윈도우로 묶어 fusion layer에서 서로 주의를 주고받음) 중 하나를 학습 시 확률 p_fus로 선택하게 해, 추론 시에도 두 경로 모두 쓸 수 있게 한다.

학습 절차: 사전학습은 4단계(Stage 0 지각 정렬: 인코더만 학습, 디코더는 동결해 조밀한 캡션/전사 신호로 학습; Stage 1 옴니모달 사전학습: 전체 파라미터 학습, 1.28T 토큰, 이미지 해상도·비디오 프레임 수 확대, fusion layer 4개 활성화; Stage 2 어닐링: 학습률 코사인 감쇠, 레이어별 학습률 감쇠, 융합 경로 확률 0.8로 일부 확률적 라우팅; Stage 3 장문맥 확장: 최대 128k 토큰·512프레임)으로 총 2.24T 토큰을 사용한다. 사후학습은 (1) SFT로 OmniSchema 형식과 지시 따르기 능력 확립, (2) GRPO 기반 schema-routed RLVR로 디코딩 가능성·페이로드 존재 여부를 게이트로 하고 형식 적합성과 과업별 내용 정확도를 곱한 보상으로 시퀀스 단위 최적화, (3) OSAD로 JSON의 구조 토큰(키·구두점)과 내용 토큰을 구분해 각기 다른 목표로 지도하는 토큰 적응형 자기진화 학습을 6라운드 수행하는 순서로 진행된다.

실험 설정 및 결과

단일 5B 체크포인트를 단일 추론 설정으로 OmniDocBench v1.6, PureDocBench(깨끗함/디지털 저하/실물 재촬영 3개 트랙), OmniParsingBench(차트·기하·자연이미지·오디오·자연비디오·텍스트비디오), Video-MME-v2, ChemOCR, PDMX-Synth 등에서 평가했다. - 문서 파싱: OmniDocBench v1.6에서 Overall 96.96으로 TeleOCR(96.91), OvisOCR2(96.47) 등을 제치고 1위를 차지했으며, 전작 Youtu-Parsing(93.74) 대비 표(TEDS +4.8)와 수식(CDM +3.2)에서 가장 크게 개선되었다. PureDocBench에서도 end-to-end 모델 중 최고(Avg3 76.29)를 기록했지만, 실물 재촬영 트랙에서는 모든 모델이 성능이 크게 떨어지는 공통 한계가 관찰되었다. - 범용 옴니모달 파싱: OmniParsingBench에서 공개 모델 중 평균 75.08로 1위(Logics-Parsing-Omni 72.26), 유일하게 API 모델 Gemini-3-Pro(77.44)만 앞선다. 다만 우위는 균일하지 않아, 오디오·자연비디오·텍스트비디오 같은 시간축 과업에서는 Logics-Parsing-Omni보다 평균 6.5점 앞서지만 자연이미지·기하 같은 정적 과업에서는 평균 2.8점 뒤처진다. 전체 시스템 중 차트 파싱 점수(95.02)는 최고였다. - 기호 콘텐츠: 화학구조 인식(ChemOCR)에서 정확 지문 일치율(Tani@1.0) 54.2로 DeepSeek-OCR2(49.6)를 능가했고, 악보 인식(PDMX-Synth)에서는 문자 오류율(CER) 22.73으로 전용 모델 LEGATO(23.30)와 대등했다. - 인코더 구조 소거실험: 통합 인코더(텍스트 LM 초기화)는 파라미터가 더 적고 두 번째 타워가 없음에도 사전학습된 비전·오디오 두 타워 조합과 Avg-6에서 거의 동등(0.4점 차)하고 OCRBench에서는 오히려 77.2점 앞섰다. 반면 무작위 초기화로 바꾸면 OCRBench에서 크게 뒤지는 대신(130.6점 차) 공간/관계 추론 과업(BLINK)에서는 오히려 텍스트-초기화 버전보다 9.5점 앞서, 텍스트 LM 초기화가 "읽기"에는 크게 도움이 되지만 공간 추론에는 그렇지 않음을 시사했다. - OSAD 기여도: SFT 이후 OmniDocBench v1.6에서 얻은 총 1.99점의 개선 중 RLVR가 0.24점, OSAD 6라운드가 1.75점(88%)을 차지했으며, 라운드가 진행될수록 증가분은 점차 줄어들지만 꾸준히 양(+)의 개선을 보였다.

한계점

저자들은 전작 Youtu-Parsing과 비교해 아직 추론 가속 기법을 적용하지 못했다는 점을 한계로 명시한다. 전작은 공유 인코더 특징을 페이지 내 여러 영역에서 재사용하고 토큰·쿼리 단위 병렬 디코딩을 적용했지만, Youtu-Parsing-Omni는 더 큰 디코더로 처음부터 끝까지 자기회귀적으로 디코딩하기 때문에 표처럼 조밀한 구조화 콘텐츠에서는 처리량(throughput)이 더 낮을 것으로 예상되며, 이에 대한 병렬 디코딩 등 가속 기법 적용은 향후 과제로 남겨두었다.

시사점

이 연구는 모달리티마다 별도 인코더·전용 모델을 두는 대신, 텍스트 언어모델로 초기화한 하나의 공유 인코더와 하나의 통합 출력 스키마만으로도 문서·이미지·오디오·비디오 전 영역에서 전문 모델급(혹은 그 이상의) 성능을 낼 수 있음을 보여준다. 특히 자기진화형 사후학습(OSAD)이 손수 설계한 보상이나 별도 교사 모델 없이도 이질적인 과업 전반에 걸쳐 성능을 꾸준히 끌어올릴 수 있다는 결과는, 서로 다른 출력 형식을 가진 다중 과업 모델의 사후학습 설계에 참고할 만한 방향을 제시한다. 또한 공간·시간에 근거가 명시된 구조화 레코드를 제공하는 "지각 계층"이라는 설계는, 비전·오디오를 직접 소비하지 않는 텍스트 전용 LLM 에이전트도 근거를 추적하며 비텍스트 정보를 활용할 수 있게 한다는 점에서 에이전트 시스템 구축에 실질적인 함의를 가진다. 코드와 모델 가중치가 공개되어 있어 재현 및 후속 연구에 활용될 수 있다.
