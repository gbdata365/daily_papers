Grounded Skill Synthesis from Code at Scale for Agentic Intelligence

에이전트 지능을 위한 대규모 코드 기반 그라운디드 스킬 합성

GitHub의 대규모 실제 코드 저장소로부터 자동으로 "스킬(재사용 가능한 절차적 지식)"을 추출·검증하는 파이프라인 Code2Skill을 제안하고, 이를 약 2만 개 저장소에 적용해 100만 건 이상의 검증된 스킬을 담은 CodeSkillBank를 구축했으며, 이 스킬들이 다양한 모델과 벤치마크에서 에이전트 성능을 일관되게 향상시킴을 보였다.

한 줄 요약

GitHub의 대규모 실제 코드 저장소로부터 자동으로 "스킬(재사용 가능한 절차적 지식)"을 추출·검증하는 파이프라인 Code2Skill을 제안하고, 이를 약 2만 개 저장소에 적용해 100만 건 이상의 검증된 스킬을 담은 CodeSkillBank를 구축했으며, 이 스킬들이 다양한 모델과 벤치마크에서 에이전트 성능을 일관되게 향상시킴을 보였다.

배경 및 문제의식

에이전트형 AI 시스템이 복잡하고 긴 호흡의 작업을 수행하려면 모델 가중치에 내재된 지식만으로는 부족하며, 언제 어떤 절차를 적용해야 하는지를 알려주는 재사용 가능한 "스킬"이 필요하다. 그런데 기존 스킬 합성 방법에는 두 가지 근본적 한계가 있다. 첫째, 에이전트의 실행 궤적(trajectory)으로부터 스킬을 뽑아내는 방식은 궤적을 생성한 에이전트의 역량과 경험 범위에 품질이 종속되며, 모델·도구·환경이 바뀌면 스킬이 낡거나 호환되지 않는다. 둘째, 사람이 작성한 문서(매뉴얼 등)로부터 스킬을 합성하는 방식은 사전 경험 없이도 가능하지만, 실제 실행으로 검증할 근거(evidence)가 없어 신뢰성이 떨어진다. 저자들은 소스 코드가 이 두 접근의 장점을 절충할 수 있는 제3의 substrate라고 본다. 코드는 실행·평가·검증·버전 관리가 가능하며, GitHub 등에는 이미 검증되고 유지보수되는 방대한 절차적 지식이 축적되어 있기 때문이다. 다만 실제 코드는 범용 절차와 프로젝트 특유의 세부 구현이 뒤섞여 있어, 코드가 "무엇을 하는지"뿐 아니라 "언제 적용되는지, 어떤 불변식과 실패 처리, 일반화 경계를 갖는지"를 함께 추출하는 것이 핵심 난제다.

핵심 기여

  1. 소스 코드로부터 신뢰 가능한(grounded) 스킬을 대규모로 합성하는 완전 자동화 파이프라인 Code2Skill을 제안했다.
  2. Code2Skill을 19,769개의 활발히 유지보수되는 GitHub 저장소에 적용해, 100만 건 이상(1,006,822건)의 검증된 스킬로 구성된 대규모 스킬 저장소 CodeSkillBank를 구축했다.
  3. 아홉 가지 모델·추론 모드 설정과 여덟 개 벤치마크에 걸친 72개의 프로토콜 매칭 평가를 통해, CodeSkillBank가 평균 11.7%의 성능 향상(57/72 케이스에서 개선)을 가져옴을 실증했다.
  4. 동일한 다운스트림 인터페이스 하에서 CodeSkillBank가 기존의 궤적 기반 스킬 뱅크(Trace2Skill, ExpeL, SkillRL 계열)를 일곱 개 공유 벤치마크 전부에서 능가함을 보였다.
  5. AI가 생성한 코드로부터도 사람이 작성한 코드와 유사한 품질의 스킬을 추출할 수 있음을 보여, 향후 AI 생성 코드가 늘어나도 스킬 공급원을 지속적으로 확장할 수 있는 가능성을 제시했다.

방법론

Code2Skill 파이프라인은 4단계로 구성된다. 1. 후보 절차적 근거 선정: GitHub에서 별점 500개 이상인 저장소를 대상으로 함수·메서드·CLI 진입점·파일 단위 컴포넌트를 파싱한 뒤, LLM 태거가 재사용 의도·절차적 단계·경계 조건·전이 가능성(transferability)·인터페이스 충분성·비자명성(non-triviality) 등의 루브릭으로 점수를 매겨 사소한 래퍼/게터·세터·보일러플레이트를 걸러낸다. 2. 스킬 레코드 생성: 선정된 소스 단위를 원자(atomic, 단일 함수/메서드 수준), 복합(composite, 여러 연산을 아우르는 순서화된 워크플로), 패턴(recurring-pattern, 단일 구현을 넘어서는 반복 패턴) 세 가지 유형 중 하나로 추상화한다. 각 레코드는 적용 조건, 실행 단계, 불변식, 실패 처리, "하지 말아야 할 것(anti-goal)", 그리고 근거가 되는 소스 스팬(provenance)을 포함한다. 3. 소스 본문 비공개 재구성 및 일관성 검증: 추출된 스킬 명세만(원본 코드 본문은 제외)을 보고 LLM이 코드를 다시 생성하게 한 뒤, 소스 코드를 아는 판정 LLM이 재구성 결과와 원본을 비교해 불일치를 탐지한다. 판정이 직접 동등성을 인정하면 채택(DirectAccept), 그렇지 않으면 별도의 조정자(adjudicator) LLM이 재구성 실패와 스킬 자체의 오류를 구분해 최종 채택(AdjudicatedAccept) 또는 기각(Reject)을 결정한다. 4. 검색 지향 특징 태깅 및 목적 인덱싱: 채택된 레코드에 작업 지향적 검색 메타데이터를 부여하고, 유사한 목적을 가진 저품질/중복 후보를 걸러 목적(purpose) 단위로 대표 레코드를 선정함으로써 검색 효율을 높인다.

다운스트림에서는 스킬을 프롬프트 삽입 시점(생성 전 프롬프트, 계획 단계, 생성 후 검토/보상 단계 등) 중 어디에 어떻게(전체 레코드 vs. 요약, 검색 깊이 k, 목적 인덱싱 여부) 주입할지에 따라 다양한 인터페이스로 실험했다.

실험 설정 및 결과

평가 모델은 DS4-Flash, Qwen3.5-27b, Qwen3.6-27b, Gemini 2.5 Pro, GPT-5.2 등이며, 벤치마크는 BigCodeBench, SWE-bench Verified, TerminalBench, LongCLI-Bench, AgentBench-OS(코딩·소프트웨어 엔지니어링·터미널/시스템 제어)와 AIME 2026, HMMT 2025, GPQA(수학·과학 추론)로 총 8종이다.

  • RQ1 (스킬 뱅크의 효과): 72개의 프로토콜 매칭 비교 중 57개에서 성능이 개선되었고, 모델·추론 모드별로 2.26~7.39점(6.0%~20.7%)의 상대적 향상이 관찰되었다. 매크로 평균 점수는 스킬 미사용 42.90에서 스킬 사용 47.90으로 상승했다. SWE-bench Verified의 모든 9개 비교 쌍에서 개선이 나타났다.
  • RQ2 (궤적 기반 스킬 뱅크와의 비교): 동일한 에이전트 루프 하에서 Code2Skill/CodeSkillBank는 Trace2Skill, ExpeL, SkillRL 적응형 베이스라인을 일곱 개 공유 벤치마크 전부에서 능가했다(평균 49.5 vs. 31.0/27.9/32.8). 벤치마크별로 최강 베이스라인 대비 6.6~13.3점 앞섰다.
  • RQ3 (스킬 주입 위치): 생성 시점 프롬프팅, 계획 단계 안내, 생성 후 검토(post-generation critique) 모두 성능을 향상시켰으며, 특히 생성 후 검토가 가장 폭넓고 안정적인 개선(57/72)을 보였다.
  • RQ4 (검색 설계와 컨텍스트 효율): 검색 깊이(top-k)를 1에서 10으로 늘려도 평균 컨텍스트 길이만 크게 늘 뿐(2.1K→17.8K자) 성능 향상은 미미했다. 반면 k=3에서 전체 레코드 대신 요약본을 제공하면 컨텍스트를 88.9% 줄이면서도(6,352→707자) 성능을 유지하거나 개선할 수 있었다(모델에 따라 효과 편차 존재). 목적 인덱싱은 컨텍스트를 줄이지만 성능에는 혼재된 영향을 보였다.
  • RQ5 (강화학습 내 스킬 통합): SWE-World 코딩 RL 환경(Qwen3-32B 체크포인트)에서 스킬 미사용 대비 정책 프롬프팅(32%), 요약 프롬프팅(31%), 보상 측 검증자 참조(31%), 생성 후 검토(38%, 최고) 모두 해결률이 개선되었으며(베이스라인 24%), 생성 후 검토가 가장 큰 폭(14점)의 향상을 가져왔다.
  • RQ6 (AI 생성 코드로부터의 스킬 확장 가능성): CodeSkillBank에서 25개의 사람 작성 구현을 추출하고, 동일 기능을 수행하는 AI 생성 구현(Codex+GPT-5.1)을 별도로 만들어 50개 스킬로 구성된 병렬 뱅크를 구축했다. LiveCodeBench 400문항 부분집합에서 DS4-Flash로 평가한 결과, 사람 코드 뱅크는 93.00%(372/400), AI 코드 뱅크는 93.50%(374/400)의 통과율을 보여 전체 성능은 비슷했으나, 개별 문제 수준에서는 16개 문항의 해결 여부가 서로 달라 두 소스가 서로 다른 절차적 지식을 제공함을 시사했다.

부가적으로, 사람 평가에서는 최종 CodeSkillBank의 채택 레코드 중 92%가 스킬 설명이 정확하다고 판단되었고, 80%가 보유할 가치가 있다고 평가되었으며, 직접 채택된 레코드의 84%가 올바른 재구성을 지원했다.

한계점

  • RQ6에서 저자들도 인정하듯, 사람 코드와 AI 생성 코드 뱅크의 전체 평균 성능 차이가 작다는 사실만으로는 두 소스가 동등하다고 단정할 수 없으며, 과제별 해결 양상이 다르다는 점은 후속 연구가 필요함을 시사한다.
  • RQ5의 강화학습 실험은 단일 체크포인트(학습 스텝 150)에서 반복 시드나 학습 곡선 없이 수행되어, 학습 속도·수렴성·최종 정책 성능 차이까지는 규명하지 못했다.
  • 검색 깊이와 목적 인덱싱의 효과가 모델에 따라 엇갈려(예: DS4-Flash와 Qwen3.5에서 반대 경향), 최적의 검색 설정이 보편적이지 않을 수 있다.
  • BigCodeBench처럼 이미 강력한 모델이 쉽게 풀 수 있는 짧은 문제에서는 스킬의 이점이 줄어드는 경향이 관찰되었다.
  • 소스 본문 비공개 재구성 기반의 일관성 검증은 테스트 기반 검증(실행 테스트나 형식적 명세 검증)을 대체하는 것이 아니라, 대규모 저장소 수준에서 적용 가능한 보조적 필터로 설계되었다고 저자들이 명시하고 있다.

시사점

이 연구는 에이전트 스킬의 원천을 "에이전트가 스스로 쌓은 경험(궤적)"이나 "사람이 작성한 문서"에서 "이미 검증되고 유지보수되는 방대한 소스 코드 저장소"로 확장할 수 있음을 보여준다. 이는 에이전트가 자체 경험을 충분히 축적하기 전에도 효과적인 절차적 지식을 미리 제공할 수 있는 실용적 경로를 제시하며, 계획 수립이나 생성 결과 검토와 같은 통합 지점에서 특히 효과적임을 시사한다. 또한 AI가 생성하는 코드 비중이 늘어나는 미래에도 동일한 파이프라인으로 스킬 뱅크를 지속적으로 확장할 수 있다는 초기 근거를 제공함으로써, 코드 기반 스킬 합성이 범용 파운데이션 모델과 도메인 특화 전문성을 잇는 장기적이고 확장 가능한 패러다임이 될 수 있음을 보여준다.
