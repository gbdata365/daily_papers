Duopra: From Full-Duplex Conversation to Full-Duplex Agency

한 줄 요약

음성으로 실시간 대화하며 턴테이킹을 처리하는 풀듀플렉스(full-duplex) 모델이 대화 제어뿐 아니라 실제 도구 호출(태스크 에이전시)까지 안정적으로 수행하도록 만든 연구로, 동일한 백엔드에서 Pass@1을 4.7%에서 44.7%로 끌어올렸다.

배경 및 문제의식

풀듀플렉스 음성 모델은 끼어들기, 멈춤, 백채널 등 자연스러운 대화 턴테이킹(conversational agency)에는 강하지만, 실제 작업을 완수하려면 적절한 시점에 도구를 호출하고 사용자의 정정 사항을 반영하는 태스크 에이전시(task agency)가 추가로 필요하다. 기존 프런트엔드-백엔드 구조에서는 프런트엔드가 대화를 담당하고 백엔드가 도구 실행을 담당하는데, 프런트엔드가 백엔드로 요청을 넘기지 않으면(hand-off) 백엔드가 아무리 뛰어나도 작업이 실행될 수 없다는 한계가 있다. 연구팀은 Full-Duplex-Bench v3(FDB v3) 환경에서 기존 시스템(RV-Audio + Harness)이 세션의 11.0%에서만 백엔드로 요청을 넘기고, 이 넘김 비율이 전체 성공률의 상한(hand-off ceiling)으로 작용함을 확인했다.

핵심 기여

  1. 대화적 결정과 태스크 결정을 하나의 인과적 정책으로 통합한 "풀듀플렉스 에이전시"를 형식화하고, 프런트엔드의 요청 개시(initiation), 인자 충실도, 작업 완수를 분석했다.
  2. 백엔드 위임(delegation)과 직접 도구 호출(direct call)을 동일한 액션 인터페이스(query라는 하나의 도구)로 통합한 모델 Duopra를 제안했다.
  3. 프로토콜 SFT, 실행 기반 풀듀플렉스 강화학습(RL), 프로젝터 전용 보정(talker 복원)의 3단계 학습 절차를 설계했다.

방법론

Duopra는 RV-Audio를 기반으로 구축되며, 1초 단위 스트림에서 'thinker'(언어모델)가 듀플렉스 제어 토큰과 텍스트를 생성하고 'talker'(음성 합성기)가 이를 음성으로 변환하는 구조를 유지한다. 핵심 아이디어는 백엔드를 하나의 도구(query)로 취급해 직접 호출과 위임이 같은 call 액션과 성공 기준을 공유하게 만드는 것이다. 학습은 3단계로 진행된다: (1) 프로토콜 SFT는 도구 사용 시연과 대화 유지 데이터를 함께 학습시켜 Duopra-SFT를 만든다. (2) 풀듀플렉스 RL은 Dr. GRPO 알고리즘으로 LoRA 어댑터를 학습시키며, 정답 호출과의 일치·시간 엄수·근거 기반 응답 등을 기준으로 보상을 설계한다(2단계는 직접 호출 과제를 다루는 2a와 의존적·조건적 호출 및 백엔드 위임을 다루는 2b로 세분). (3) thinker가 갱신되며 발생하는 음성 품질 저하를 막기 위해, 원래 RV-Audio의 hidden state 방향을 따라가도록 projector만 재학습(코사인 유사도 손실 + L2-SP 정규화)한다.

실험 설정 및 결과

FDB v3(100개의 비유창한 영어 발화, 12개 시뮬레이션 API)와 FDB v1.0(턴테이킹 평가)을 사용했다. 동일한 Qwen3-8B 백엔드 기준으로 Duopra는 Pass@1을 4.7%(RV-Audio + Harness)에서 44.7%로 크게 개선했으며, 직접 호출만으로도 47.7%, DeepSeek 백엔드 사용 시 49.3%를 달성했다. 분석 결과 기존 시스템의 실패는 백엔드 실행 품질보다 프런트엔드가 요청 자체를 보내지 않는 "개시 단계"에서 주로 발생했으며, Duopra는 기존에 전혀 처리되지 못했던 세션들을 추가로 성공시켜 성능을 끌어올렸다. 또한 Duopra는 FDB v1.0의 세 가지 턴테이킹 지표(발화 종료 시 턴 받기, 중단 시 정지, 멈춤 유지) 모두에서 기존 모델보다 개선되었고, 프로젝터 보정을 통해 중국어 CER과 영어 WER도 낮췄다.

한계점

자발적인 백채널링(backchanneling)은 학습 후에도 회복되지 않았다. 평가에 사용된 상용/오픈소스 비교 시스템들의 수치는 서로 다른 평가 설정과 판정 기준에서 나온 것이라 직접적인 비교에는 한계가 있다. 또한 Duopra는 하나의 베이스 모델과 제한된 음성 종류의 합성 데이터로만 학습되어, 다른 모델이나 더 다양한 음성 조건에도 성능이 일반화되는지는 추가 검증이 필요하다. 평가 역시 사전 녹음된 사용자 요청과 시뮬레이션 API를 사용한 것으로, 에이전트의 응답에 따라 후속 요청이 바뀌는 실제 다중 턴 상황은 다루지 못했다.

시사점

이 연구는 음성 에이전트에서 "대화를 잘하는 것"과 "일을 잘 처리하는 것"이 서로 충돌하지 않고 하나의 정책 안에서 함께 학습될 수 있음을 보여준다. 특히 백엔드 위임과 직접 실행을 동일한 인터페이스로 통합한 설계는, 복잡한 멀티 에이전트 파이프라인 없이도 프런트엔드가 스스로 신뢰할 수 있는 실행 주체가 될 수 있다는 점에서 실시간 음성 비서나 콜센터형 에이전트 설계에 실질적인 시사점을 준다.
